## Implementation-status amendment (2026-11-13)

The HOOK-01/03/13 observations below are the earlier gap assessment, not a fresh measurement. Phase 2 now maps Read, Edit, Write, Bash, PowerShell, Glob and Grep input and available result fields in both directions; LS remains native passthrough pending a resolved current upstream schema. Edit has one hook invocation per pair, repeated side effects, all-pair preflight, one native execution and a shared result. Conflicting targets block; an unsupported candidate otherwise keeps the whole original call with a sanitized notice. Missing original file/type, separated streams, timing and ambiguous counts remain omitted under [HOOKRESULT-01](../../../.planning/BACKLOG.md#hookresult-01-investigate-and-implement-execution-wrappers-for-full-claude-shaped-hook-results). The current [compatibility contract](../../hooks-compatibility.md#current-tool-contract-phase-2-2026-11-13) cites [input and batch owners](../../../test/bridges/hooks/tool-batch.test.ts), [result projection owners](../../../test/bridges/hooks/tool-result-search-shell.test.ts), [Pi boundary](../../../test/integration/hooks-result-boundary.test.ts), and [real tool scenarios](../../../features/hook/tool-use.feature) (D-PG2-01..09).

Exact matcher lists now split on comma/pipe, trim surrounding spaces but preserve internal spaces. Other whole patterns use unanchored JavaScript regex; an invalid pattern drops only its group. Prompt and Stop ignore matcher text. Eight Stop blocks continue; the ninth is overridden. A native tool call and reload reset the budget (D-PG2-10/11; [matcher scenarios](../../../features/hook/matchers.feature), [Stop scenarios](../../../features/hook/prompt-and-stop.feature)). Stop then used `agent_settled`; it now runs on `agent_before_settle`, and a block continues the same run (D-PG5-01). The cap environment variable stays out of scope (D-PG5-04). PowerShell has contract-only tests, not a live executable run. MCP output uses modern-field presence before legacy alias, with the latter limited to real MCP identity; the inspected upstream legacy path remains ambiguous ([both-profile scenarios](../../../features/hook/tool-use.feature)). Phase 1's ambient-child and long-name limits remained then; pi-subagents 0.88.1 has since fixed the ambient-child limit (BACKLOG AGTAMBIENT-01, adopted), and the long-name limit stays (AGTLONGNAME-01). No full result wrapper shipped (D-PG2-06/07/12).

### HOOK-01 -- Tool payloads use Pi's field names, not Claude's

- **Upstream**: `tool_input` for `Read`/`Edit`/`Write` carries `file_path` (always absolute), Edit carries `old_string`/`new_string`, Bash `timeout` is milliseconds (U25, hooks ref "PreToolUse input"). `tool_response` is "the tool's structured `Output` object". `updatedInput` and `updatedToolOutput` use the same Claude shapes. VERIFIED.
- **Current**: `tool_input: event.input` verbatim (`bridges/hooks/payloads/pre-tool-use.ts`, `post-tool-use.ts`, `post-tool-use-failure.ts`). A `Read` hook receives `{"path": …}` (`features/hook/tool-failure.feature:54`). `updatedInput` is written back key by key into Pi's input (`event-adapters.ts:140-157`), so a Claude-shaped rewrite of an Edit (`file_path`, `old_string`) deletes `path` and `edits` and breaks the call. `updatedToolOutput` is honored only as `{content, isError}` (`event-adapters.ts:171-187`). The feature file header says "with the tool call in Claude's shape on its stdin" (`features/hook/tool-use.feature:3-4`), which holds only for `bash`. No decision ID covers this: `rg file_path extensions/` returns nothing, and neither PROJECT.md nor BACKLOG.md mentions input translation. VERIFIED.
- **Enabling capability**: none needed from Pi. The Pi schemas are stable and typed (`pi:dist/core/tools/{read,edit,write,bash,grep,find,ls}.d.ts`). `tool_call` input is mutable (`pi:docs/extensions.md:981-987`). Pi >= 1.5.0.
- **Proposed behavior**: for the eight mapped tools, a hook receives a Claude-shaped `tool_input`: `path` → absolute `file_path` (resolved against `ctx.cwd`, `~` expanded); `edit.edits[0]` → `old_string`/`new_string` (and the full list under `edits` with Claude key names when there is more than one); `bash.timeout` seconds → milliseconds; `grep.ignoreCase` → `-i`. A hook's `updatedInput` is translated back before it replaces Pi's input. For MCP tools, where Pi's result is already the MCP `content`/`isError` shape, `updatedMCPToolOutput` is read like `updatedToolOutput`. Touch points: a new pure mapping module next to `domain/components/hook-tool-names.ts`; the three tool payload translators; `replaceToolCallInput` and `toolResultPatch` in `event-adapters.ts`; the same translators in `async-rewake/registry.ts`.
- **Size / risk**: M. Risk: medium. The Edit multi-edit case and the `tool_response` shape need a decision (see open questions). The `if` evaluator reads Pi's `input.path` and must keep reading the untranslated event.
- **User-visible effect and proof**: a scenario with a scripted `edit` call and a recording hook that asserts `tool input {"file_path":"{project dir}/a.txt","old_string":"x","new_string":"y"}`; a second scenario where the hook returns a Claude-shaped `updatedInput` for `Write` and the file on disk has the rewritten content.
- **How common**: high. 14 non-test files in the 7 official hook plugins mention `file_path`; `security-guidance/hooks/security_reminder_hook.py:3307` reads `tool_input.get("file_path")` and `:792-794` reads `content`/`new_string`; `hookify/core/rule_engine.py:233-242` reads `command`, `content`, `new_string`, `old_string`. Under Pi these hooks see empty values on every Edit/Write/Read and silently do nothing.
- **Confidence**: high. Three-sided evidence is direct.
- **Open questions**: (1) Should a multi-edit Pi `edit` be presented as one `Edit` with the first pair, as legacy `MultiEdit`, or as one hook run per pair? (2) How far to go on `tool_response`: Bash `{stdout, stderr, interrupted, isImage}` can be built from Pi's text content and `BashToolDetails`; Write `{filePath, type}` needs a create/update guess. (3) `Glob`↔`find` and `Grep` option names differ in meaning (D-58-05 already calls `find → Glob` low confidence).
