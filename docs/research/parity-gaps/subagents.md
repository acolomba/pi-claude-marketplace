## Gaps that can be closed

### AGENT-01 -- Bridged agents are forced to the foreground; upstream and pi-subagents both default to the background

- **Upstream (V):** SA: "With nothing configured, a subagent that Claude spawns from your main conversation starts in the background." TR: "Claude Code runs subagents in the background by default". CL 2.1.198: "Subagents now run in the background by default"; 2.1.232 and 2.1.302 extend it. `background: true` only means "keep … in the background even when Claude asks to wait for it".
- **Current (V):** every agent without `background: true` gets `async: false` (C:1035, 1068-1083). D-CF4-05 (`.planning/PROJECT.md:2084`) records the reason as "Upstream runs agents in the foreground by default". That premise is false for 2.1.198 and later, so the recorded license does not hold.
- **Enabling capability (V):** pi-subagents already defaults to the background (`asyncByDefault !== false`, `src/extension/config.js:278`). Omitting the `async` line is enough. No floor change.
- **Side effects of today's choice (V/I):** a foreground child runs with `noExtensions` (PS `child-launch.js:203`, `child-session.js:485`), so this extension is not loaded in it. Plugin hooks do not see the child's tool calls (I, from that code; the only hook-in-child scenario uses a background child, `features/plugin/subagent-child.feature:168`), and plugin MCP tools are unreachable (V `child-launch.js:109`). Upstream applies plugin hooks inside subagents (L6) and gives them MCP tools (L7).
- **Proposed change:** emit `async: true` only for `background: true`; emit no `async` line otherwise. Keep `async: true` for an agent that runs plugin MCP tools (it protects a user who set `asyncByDefault: false`), but reword its warning: the clause "where Claude Code runs it in the foreground" is wrong, and the launch mode is then no divergence at all. Touch: C:1035, 1068-1098, `mcp-async-warning.ts`, `docs/mcp-compatibility.md` (lines 381-393, 592), D-CF4-05/D-CF6-10 text.
- **Size / risk:** S. Risk: D-CF4-05 is Locked, so this is a user decision. Headless `pi -p` differs slightly (upstream lets Claude wait; pi-subagents 0.88.0 waits for background work up to `timeoutMs`). The stored MCP warning bytes are matched by `grant-rewrite.ts` and `legacy-grant-form.ts`, so a rewording needs both the old and new text recognized.
- **User-visible effect / scenario:** `subagent get` shows no `async false` line for a plain agent, and a call that leaves the mode open returns a background acknowledgement, not the child's reply. Replace frontmatter.feature "A call that leaves the launch mode open runs a bridged agent in the foreground". A full background run is blocked in the harness (BACKLOG AGTASYNC-01).
- **Frequency:** affects every bridged agent (40 of 40 in MKT; none sets `background`).
- **Confidence:** high on the upstream fact; medium on product preference.
- **Open questions:** did the 2.1.316 probe behind D-CF4-05 run under `claude -p`? That would explain the foreground reading.

### AGENT-05 -- Source frontmatter is not parsed as YAML: quoted values keep their quotes

- **Upstream (V):** U5. `claude plugin validate` treats agent frontmatter as YAML.
- **Current (V, probe):** F:307-334 takes the value "verbatim, quotes included". Results:
  - `name: "quoted-name"` → `name: demo:"quoted-name"` (quote marks in the agent name).
  - `description: "A math-proof worker: …"` (real file `math-proof/agents/math-proof-worker.md`) → emitted as `description: '"A math-proof worker: … skill."'`; pi-subagents strips the outer pair, so the model and `list` see the text inside literal double quotes. `\n` and `\"` escapes stay literal; `''` stays doubled.
  - `model: "sonnet"` → `unknown model ""sonnet""`; `effort: 'high'` → `unknown effort value`.
  - `tools: Read # note` → `#`, `note` become dropped tool tokens.
  - Only `background: "true"` was special-cased (C:1081-1083). The skills and commands bridges already use Pi's YAML `parseFrontmatter` (`platform/pi-api.ts:49`, `bridges/agents/skill-preload.ts:24`); the agents bridge alone does not.
- **Enabling capability (V, probe):** Pi's `parseFrontmatter` returns the right values for all the cases above. It THROWS on an unquoted description with a colon and a space (`Nested mappings are not allowed in compact mappings`), which upstream accepts and which is common in plugin agents.
- **Proposed change:** parse with Pi's YAML parser first; when it throws, fall back to today's line parser (keeps AG-6). Coerce scalars to strings and lists to comma-joined tokens at the `RawAgentFrontmatter` boundary. Touch: F `parseFrontmatter`, D:138-141, types.
- **Size / risk:** M. Risk: an agent with a quoted `name` changes its generated file name and declared name on the next update; multi-line descriptions (4 files in MKT use `description: |`) could then be emitted as a `|-` block that pi-subagents reads (P3) instead of being flattened.
- **Effect / scenario:** an agent with `description: "Reviews: code."` lists as `Reviews: code.` with no quote marks; `name: "x"` lists as `demo:x`.
- **Frequency:** 4 of 40 MKT agents have a quoted description; 0 have a quoted name/model/effort.
- **Confidence:** high (both sides executed).
- **Open question:** how upstream's parser accepts the colon case (lenient scalar rule or a retry). Not found in the binary.
