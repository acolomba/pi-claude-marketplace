# BLOCKING CONSTRAINTS — Read Before Anything Else

> These are not suggestions. Each constraint below was discovered through failure.
> Acknowledge each one explicitly before proceeding.

- [ ] CONSTRAINT: **Never report a gate's result from a tool-reported exit code** — `npm run check > log 2>&1; echo "exit=$?"` reports the *compound statement's* status (the `echo`, always 0), and a trailing `grep -c '^✖'` exits 1 on *zero* matches. Both misread the same suite this session, in opposite directions: a failing check was reported to the operator as green, then a passing one as failed. Mitigation: `{ npm run check > log 2>&1; echo "CHECK_EXIT=$?" >> log; }` and read `CHECK_EXIT` back out of the log, confirming on a second axis (zero `^✖` lines).

**Do not proceed until all boxes are checked.**

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Exit code of a compound command | `cmd > log; echo "exit=$?"` and `grep -c` report their own status, not the gate's. Misread `npm run check` twice in one session, in both directions. | blocking | Write `CHECK_EXIT=$?` into the log file; read it back; confirm on a second axis. |
| Sweeping a rename across test fixtures | 52 pins referenced the old flat agent name, but they are not interchangeable: emitter-output fixtures must move, while legacy `oldBytes`/`previousBytes` fixtures, index entries and `targetPath`s must stay flat. A regex rewrites the migration tests' own inputs to match their expectations. | blocking | Classify each site before editing. Suites that were already green (`marker`, `unstage`, `frontmatter`, `markers-snapshot`) are ownership-shaped and must not be touched. |
| Trusting the engine's `structured_output` error | "Subagent did not produce valid structured_output" plus "prefer a tool-reliable model" reads like model quality. It hid three distinct causes, including a provider rejection returned as assistant prose. | advisory | Read the agent's `history` in the run's `.events.jsonl` before believing the summary error. |
| Deleting an expectation to make a merged test pass | main's #209 suppresses the success tally on an empty result; the WR-06 test expected one. Deleting it would have left a test whose name claims an ordering it no longer proves. | advisory | Change the *input* so the asserted behavior still occurs. |

<decisions_made>

- Split the agent identity in two. The file keeps its `pi-claude-marketplace-`
  basename — that is what AG-5 ownership detection and the AGENT-01 migration key
  on — while a new `declaredAgentName()` supplies the frontmatter name as
  `<plugin>:<agent>`, which is what both consumers actually resolve (pi-subagents
  as `localName`, the engine as its `agentType` registry key).
- Used a literal `:` rather than `commandNamespaceSeparator()`. That helper spells
  a dot on Windows because command and skill names *become* filenames; this name
  never reaches the filesystem, and a Windows dot would have missed the agentType
  exactly as the flat form did.
- Carried the old flat name as an `aliases` frontmatter entry, so the rename is
  non-breaking: pi-subagents resolves aliases. The engine ignores them, which is
  correct — nothing ever addressed the flat name as an agentType.
- Kept no-elision in the declared name (`acme` + `acme-bot` → `acme:acme-bot`),
  matching `generatedAgentName`: eliding would collide `bot` and `acme-bot`.
</decisions_made>
