# Set up Codex worktree sessions with the worktree init hook

<objective>
Per D-01 to D-07 (orchestrator brief, 2026-10-05, locked): Codex gets the worktree setup that Claude Code subagents already have. `scripts/init-worktree.sh` stops depending on CLAUDE_PROJECT_DIR, which Codex does not set, and the tracked `.codex/config.toml` registers it as a SessionStart hook. A Codex session in a linked worktree of this repository, such as a GSD executor started with `codex exec --cd <worktree>`, then gets its npm dependencies and its own CodeGraph index before its first turn. Claude Code behaves as before.

Purpose: GSD on Codex runs each executor in a fresh worktree that has no `node_modules/` and no index. Without this hook its first `npm run check` fails, and its CodeGraph queries read the main checkout's index.

Output: Task 1 (tracer) changes the two files, proves the path end to end in a scratch Codex session (R3) and against every guard (R2), and commits. Task 2 checks this repository (R5): the main checkout stays untouched, and a fresh linked worktree gets set up, through a live Codex session when the main checkout already holds the commit.

Planning found that one premise of the brief does not hold (F3): Codex reads project hooks from the main checkout, not from each worktree's own copy of `.codex/config.toml`. The design still works, because the file is tracked and the main checkout's working tree carries it. Two consequences follow: the hook is trusted once in the main checkout, and the live check against this repository can run only once the main checkout holds the commit (choice C3).
</objective>

## Decisions (orchestrator brief, 2026-10-05, locked)

- D-01: Host-agnostic detection. A checkout is a linked worktree if and only if `git rev-parse --path-format=absolute --git-dir` differs from `--git-common-dir`. The main checkout is a no-op. Keep the "must be this repository" guard: the common dir must equal the common dir of the repository that owns the script, derived from the script's own location, so that a foreign repository never gets an `npm install`.
- D-02: Keep reading `cwd` from the hook's stdin JSON (both hosts send it). Fall back to `$PWD` when stdin is empty or not JSON, so that the script can also run by hand.
- D-03: Keep the npm-install marker test (`node_modules/.package-lock.json`) and `codegraph init --yes .`.
- D-04: Start the CodeGraph daemon only when CLAUDE_PROJECT_DIR is set (Claude Code). Never under Codex.
- D-05: Add the `[[hooks.SessionStart]]` entry to the tracked `.codex/config.toml`, with matcher `startup|resume|fork` and command `bash scripts/init-worktree.sh`. Keep the existing content intact (it is partly GSD-managed): append, do not reorder.
- D-06: Leave `.claude/settings.json`, `scripts/codegraph-worktree-hook.sh`, and `scripts/stop-worktree-daemon.sh` unchanged.
- D-07: Neither file is a build input, so `npm run check` is not required; `SKIP=npm-check pre-commit run --files <changed files>` is. Conventional Commits, title of 72 characters or fewer.
- Verification expectations from the brief. V-1: the main checkout is a no-op. V-2: a scratch linked worktree of this repository gets the npm marker and `.codegraph/` with CLAUDE_PROJECT_DIR unset, no daemon, an idempotent rerun, and is removed afterwards. V-3: a foreign repository is a no-op. V-4: one live `codex exec --cd <worktree> --dangerously-bypass-hook-trust -c 'model_reasoning_effort="low"' 'Reply with the single word ok.' </dev/null` run shows that the hook ran; the bypass flag is for verification only. V-5: `bash -n` and the pre-commit run pass.

## Choices within the decisions

1. C1. D-01 replaces the CLAUDE_PROJECT_DIR comparison as the detection rule, but R1 still skips a Claude Code session's own checkout (`[[ $top != "${CLAUDE_PROJECT_DIR-}" ]]`). The operator's sessions often run in linked-worktree workspaces. There, a non-isolated subagent's SubagentStart has its cwd at the session checkout, which D-01 alone would treat as a worktree: the script would start a 4-hour daemon that the unchanged SubagentStop script never stops (that script keeps the old test, D-06), and it could run `codegraph init` in the operator's own checkout. Under Codex the variable is unset, so the test never matches. R2 `claude-own-checkout` proves it. The summary flags it.
2. C2. V-1 targets the main checkout found as the first `worktree` entry of `git worktree list --porcelain`, not `$PWD`: an isolated executor's `$PWD` is itself a linked worktree. The real main checkout already has `node_modules/` and `.codegraph/`, so R5 can assert only exit 0 and empty stdout and stderr there. R2 proves the guard where its effects are visible (`codex-main`, `claude-main`).
3. C3. V-4 has two parts because of F3. Task 1 always runs R3: a scratch main checkout that holds the two files under test, a nested linked worktree, and a scratch CODEX_HOME without credentials (F5), so the end-to-end path runs anywhere at no cost. Task 2 runs R5, which makes the brief's live `codex exec` call against this repository only when the main checkout's working tree already holds the committed files. Otherwise R5 sets the worktree up by running the script directly, prints `REAL_CODEX=deferred`, and the summary hands the live run to the orchestrator after the merge.
4. C4. V-2's scratch worktree lives under the main checkout's `.claude/worktrees/` (F6), not /tmp, and R4 removes it with `git worktree remove --force`.
5. C5. V-3 uses a linked worktree of a foreign repository (R2 `codex-foreign`), so only the same-repository test can reject it. A foreign main checkout would be rejected by the git-dir test first.
6. C6. Every harness runs with `env -u TMPDIR` and `/tmp` as the scratch parent (F7), and sets or unsets CLAUDE_PROJECT_DIR explicitly for each case, because an executor's environment may or may not carry it.
7. C7. Comments in R1: one line for the `$PWD` fallback, and the guard comment and the daemon comment each gain the reason for their Claude-only part. No other line changes: 11 lines added and 7 removed.
8. C8. One commit, in Task 1, titled `chore(init): set up Codex worktree sessions` after the existing `chore(init): set up Claude Code worktree subagents`.
