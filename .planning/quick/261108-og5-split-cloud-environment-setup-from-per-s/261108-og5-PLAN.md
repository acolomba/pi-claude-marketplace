# Quick 261108-og5: split the cloud environment setup from the session init

Run inline by the orchestrator. The verification needs this session's
environment: the environment setup run from the checkouts directory, the
SessionStart hook fed a real input, and an empty checkout.

## Decisions (from the user)

- The environment holds only what does not depend on the branch. The npm
  dependencies and the CodeGraph index start empty and install at every
  session start.
- No pre-commit hook-environment warmup: the environment can serve other
  repositories.
- The environment setup lives in a repository script.
- The claude-code-templates mod is skipped: the GitHub proxy refuses its API
  download, and no host allowlist changes that.
- The agent tooling (skills, gsd-core, fallow skill pointers) installs in the
  environment setup, because Claude Code reads agents and skills only at
  startup (tested: an agent or skill added mid-session is not found).

## Task 1: split the scripts

- files: scripts/cloud-env.sh, scripts/cloud-env-setup.sh (new),
  scripts/init.sh, scripts/init-session.sh, scripts/mcp-server.sh (new),
  .mcp.json, .claude/settings.json, CONTRIBUTING.md
- action: `cloud_env_install` installs Node 24, the setpriv wrapper, and
  pre-commit, with no warmup. `cloud-env-setup.sh` runs it and
  `init.sh --tools`. `init.sh` takes `--tools` and `--deps` and runs both by
  default; `--deps` syncs an existing CodeGraph index and builds it in the
  background in the cloud. The cloud SessionStart hook runs `init.sh --deps`
  every session, falls back to `cloud-env-setup.sh` when the environment did
  not run it, and marks node_modules ready for the session. `.mcp.json` starts
  both servers through `mcp-server.sh`, which waits for that mark in the
  cloud; `MCP_TIMEOUT` gives the connect 300 s.
- verify: the setup script from /home/user leaves no tracked change; the hook
  on a warm checkout writes the session mark; in an empty worktree the setup,
  then the hook with the MCP wrapper already waiting, installs everything and
  the MCP server answers; the index finishes in the background; a local
  (non-cloud) `init.sh` run passes; `MCP_TIMEOUT` in settings lets a slow
  server connect.
