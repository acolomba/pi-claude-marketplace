# Run negative controls only when their checker changes

<objective>
Run the six negative controls only when their result can change, and remove the last tests that read planning or skill data, so that those files select no checks.

Purpose: each negative control proves that a checker script still fails on a planted problem. A control's verdict changes only when its checker, the checker's helper modules or configuration, or the toolchain changes. Today every full `npm run check` runs all six. The type-member control alone took 609 s under load; the other five take about 8 s together. Separately, two tests read planning data (`.planning/config.json` and an archived finding-disposition record) or skill Markdown. The selector keeps a reader table and rule only for them. The config-wiring test is not wanted (D-01). The disposition check reads a frozen record against a frozen list, so it cannot fail.

Output:

- Task 1: the reader tests are gone; the selector's reader table and rule are gone; `.planning/**` and skill or instruction Markdown select nothing.
- Task 2: `npm run check` without the controls; a new `npm run check:controls`; a family control for every changed checker file; `npm run check:controls` added to the full fallback only for toolchain changes; a CI step on pull requests; and updated docs and pins.
</objective>
