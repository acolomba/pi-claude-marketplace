# Quick Task 260818-k7f: Bump pi-coding-agent to 0.84.2 and handle deferred Summary

**pi-coding-agent 0.84.2 widened `StopReason` with `"deferred"`, the settle dispatcher's `never` pin caught it as designed, and the new value now joins the defensive no-op group with a test pinning it.**

## Performance

- **Duration:** ~12 min
- **Tasks:** 3 of 3
- **Files modified:** 8
- **Commit:** `b6414110`

## Accomplishments

- Raised the `@earendil-works/pi-coding-agent` devDependency from `^0.83.0` to `^0.84.2` via a targeted `npm install --save-dev`, with the lockfile regenerated by npm and its churn confined to the pi package subtree (four nested transitive entries in, four out; no top-level dependency moved).
- Reproduced the exact failure Dependabot PR #136 hit -- one error, `settle.ts(207,15): TS2322: Type '"deferred"' is not assignable to type 'never'` -- and closed it by adding `case "deferred":` to the existing defensive no-op group in `settleHandlerFor`'s `switch (last.stopReason)`, with a comment anchored on STOP-01 explaining that a deferred request was handed to a batch or asynchronous lane and carries a `DeferredHandle` to poll later, so it is in-flight like `pending` rather than a turn ending.
- Added `STOP-01: stopReason deferred is a defensive no-op` to the settle suite, mirroring the `toolUse` test's structure with its own assertion wording, asserting both `fired` is empty and `sent.length === 0`.
- Refreshed the two doc comments in `settle.ts` that enumerated the no-op set (the module header and the `settleHandlerFor` JSDoc). Both had been stale since before this change -- each omitted `pending` -- and both now state the full set.
- Updated the dev-dependency figure in `CLAUDE.md`, `.planning/PROJECT.md` and `.planning/codebase/STACK.md`, and added an `[Unreleased]` CHANGELOG entry.
