# Quick Task 260819-r3k: Land PR #138 -- hook `timeout` read as seconds

Land external PR #138 (@rakesh-vs, "fix: interpret hook timeout as seconds
(Claude Code parity)") complete: bring the branch up to date with `main`, close
the two gaps review found, and record the adjacent defect it surfaces --
without rewriting the contributor's commit and without bumping the version.

## What the contributor submitted

Claude Code's hooks specification declares a handler's `timeout` in seconds.
The bridge consumed the bare number as milliseconds, so a plugin's `timeout: 2`
armed a 2 ms SIGTERM and killed the handler at spawn. `timeout` is promoted
from an unknown catch-all field to a first-class `number` member of
`HookHandlerEntry` and the schema, and both exec lanes read it through a new
`shared/timeout.ts`.

The fix is correct as submitted. Verification performed before accepting:

- **Upstream, primary source.** `code.claude.com/docs/en/hooks`, Common fields
  table: "`timeout` | no | Seconds before canceling. Defaults: 600 for
  `command`, `http`, and `mcp_tool`; 30 for `prompt`; 60 for `agent`." A bare
  number is seconds, and 600 s is the `command` default the bridge already
  carries.
- **The repository already knew.** `docs/research/claude-hook-config-syntax.md`
  line 60 lists `timeout` as `number (seconds)` and maps it to EXEC-02. The
  defect is an implementation that drifted from research that was already
  right, not a missing finding.
- **Read-site coverage.** `entry.handlerDecl.timeout` has exactly two consumers
  in the tree -- `bridges/hooks/dispatch-exec.ts` and
  `bridges/hooks/async-rewake/registry.ts`. Both are converted; there is no
  third lane.
- **Gate.** `npm run check` is green on the merge commit: 3464 unit, 21
  integration, 0 fail.

## What review found missing

1. **Nothing pins the unit at either call site.** `parseTimeoutMs` is unit
   tested in isolation, but a regression that re-inlines
   `typeof raw === "number" ? raw : DEFAULT_TIMEOUT_MS` at either lane leaves
   the parser suite fully green. Measured, not assumed: planting that exact
   revert at both sites keeps all six `tests/shared/timeout.test.ts` cases
   passing. The gate the fix needs is at the lanes, not at the parser.
2. **`docs/hooks-compatibility.md` still does not state the unit.** Its
   `timeout` row gives the 600 s default and stops -- the same ambiguity that
   produced the defect, on the page a plugin author reads.
