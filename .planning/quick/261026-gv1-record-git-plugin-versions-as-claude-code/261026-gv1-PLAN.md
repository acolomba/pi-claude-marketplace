# Quick task 261026-gv1: git plugin version parity

## Findings

- A git plugin that declares no version records `sha-<12hex>` (D-77-01).
  Claude Code records the bare 12 hex characters.
- A `git-subdir` source gets no path hash; Claude Code appends one.
- A sha-pinned plugin of the `anthropic-plugin-directory` marketplace
  records its declared version alone; Claude Code appends the pin.
- Side items from PR #274 review: five scenarios pin fs errno wording that
  differs between Node majors, and SonarCloud reports S7778 in
  `reconcile/apply.ts` and S7744 in `plugin/update-flow.ts`.

## Plan

1. Read the rules from the Claude Code 2.1.310 binary.
2. Derive the version in `domain/version.ts` (`shaVersion`,
   `declaredVersionWithPin`) and use it at every producer: install, update,
   convergence, list and info candidates, completion upgradable.
3. Treat a legacy `sha-<12hex>` record as the same version as the commit
   version of the same 12 characters (`isSameVersion`), so `update` and
   `list` see no move.
4. Record GV-01/GV-02 in PROJECT.md, superseding D-77-01; update docs and
   CHANGELOG.
5. Read errno wording back from the running Node in the step library.
6. Clear the two Sonar findings.
