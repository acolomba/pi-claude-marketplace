# Replace the check-changed selector with an `npm run check` pre-commit hook

<objective>
Per D-01 to D-05 (operator decision, 2026-10-05, locked): delete the commit-time selector and make the commit hook run the whole gate. A commit that stages a build input runs `npm run check`; any other commit skips it. A passing hook is the full verdict, so the focused, broad, and "full verification pending" scopes leave every live document.

Purpose: the selector (783 lines, a cross-worktree lock, and a run log) saved little time. The operator measured `npm run check` at about 89 s warm on this machine, and the selector's 192 consumer tests for one `shared/errors.ts` edit at 97 s.

Output: Task 1 (tracer) deletes the selector, installs the `npm-check` hook, fixes the CI Lint skip list, and proves both paths of the hook at real commit time. Task 2 rewrites the gate contract in AGENTS.md, CONTRIBUTING.md, and the local-verification skill. Task 3 fixes the two unit-testing skills and the #236 changelog entry, and sweeps the repository.

## Execution rules

- Run sequentially in the main checkout. The commit hook runs `npm run check`, which needs `node_modules`, and trufflehog fails in a linked worktree.
- Stage explicit paths only and use `git rm` for the deletion. Never `git add -A` or `git add .`, never `--amend`, never `--no-verify`. Never stage `.planning/` (the orchestrator commits the plan, summary, and STATE.md), `REVIEW.md`, or the uqn plan. The operator edits files concurrently: leave any other modified file unstaged, because the commit hook stashes it.
- Record each exit code as the last line of its log, never through a pipe. Example: `pre-commit run --files package.json > tmp/9me/precommit-1.log 2>&1; echo "PRECOMMIT_EXIT=$?" >> tmp/9me/precommit-1.log`.
- Run pre-commit before each commit, in the foreground with a 600000 ms timeout. Pass only paths that exist. If a hook rewrites a file or fails, inspect the diff, fix only this task's files, restage, and re-run until the log ends with exit 0. If a run can outlast the limit, background it once and wait for the completion notification. Never poll.
- Before each commit, run `npx fallow audit --format json --quiet --explain --gate-marker agent > tmp/9me/audit-N.json 2> tmp/9me/audit-N.err`. A `fail` verdict blocks the commit. A JSON runtime error does not.
- Write each message to `tmp/9me/commit-N.txt`: Conventional Commits, title 5-72 characters, body lines of 80 characters or fewer, no milestone, phase, plan, or decision labels, and no line that starts with `#`. End it with these two lines:
  - `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
  - `Claude-Session: https://claude.ai/code/session_01Y17L76i3FvJ4cRAFfmHL5W`
- Check each message with `pre-commit run gitlint --hook-stage commit-msg --commit-msg-filename tmp/9me/commit-N.txt`. Then commit in the foreground with a 600000 ms timeout: `git commit -F tmp/9me/commit-N.txt > tmp/9me/commit-N.log 2>&1; echo "COMMIT_EXIT=$?" >> tmp/9me/commit-N.log`. If `COMMIT_EXIT` is not 0, the commit did not happen: read the log, fix, restage, and commit again. After a successful commit, run `git rev-parse HEAD > tmp/9me/commit-N.sha`.
- Do not run `npm run check`, `npm test`, ESLint, or type checking by hand. The hook runs the gate. Do not run the deleted selector.
