<objective>
Three changes to how `/claude:plugin info` reads the state of a plugin's MCP servers.

(1) STATUSLOOKUP-01. `McpStatusLookup` (`platform/mcp-status.ts:88`) is one interface whose `reader` and `implementation` can disagree, and whose `projectTrusted` and `cwd` mean something only under Pi's built-in MCP. Make it a discriminated union with one arm per MCP implementation, where only the built-in arm has `projectTrusted` and `cwd`, built by a single function that picks the reader from `McpStatusReaders`. Move `orchestrators/plugin/info.ts` (`withServerStatus`, around line 3347) and `orchestrators/plugin/info-mcp-status.ts` onto it.

(2) REVIEWSUGG-01, status part: the built-in status lookup is unguarded. `createBuiltinMcpStatusReader` (`platform/mcp-builtin-status.ts:134`) calls `pi.getMcpServers()` and `pi.getAllTools()` and reads each tool's namespace. A throw there (Pi's stale-runtime check, or a tool another extension registered whose namespace cannot be read) escapes `withServerStatus`, and `edge/command-run.ts` turns the whole info command into a command error. Guard it so info still renders, and show the existing closed-set token `status unknown`.

(3) REVIEWSUGG-01, status part: a server whose built-in config is `undefined` reads a bare `not loaded`. Check reachability and either give it the right existing token or record why it cannot happen (the planner's finding is in Disposition 3).

Purpose: info must never fail because of a read it only uses to annotate a row, and the type must stop a status stamp from reading another implementation's reader or the project's trust where it means nothing. AGENTS.md requires a cucumber scenario that fails without the user-visible change.

Output: Task 1 (tracer) ships (2) end to end with its `@builtin-only` scenario. Task 2 ships (1) and records (3) in the stamp module's header. Task 3 updates the docs and the cucumber skill for (2) and (3).
</objective>

   - Not a plain object: cannot happen; `checkClaudeShape` makes a non-object `malformed` (`domain/mcp-server-features.ts:456`).
   - Neither a string `command` nor a string `url`: cannot happen; a supported stdio server has a non-empty string `command` and a supported remote server a string `url` (the schemas at `mcp-server-features.ts:238` and `:266`), `stdioFields`/`remoteFields` copy them, and `substituteAndInject` writes `command` and `url` back as strings (`bridges/mcp/substitute.ts` `writtenField`).

## Design (planner choices; the SUMMARY lists them under Questionable choices)

- `mcpStatusLookup` lives in `platform/mcp-status.ts`, beside `McpStatusLookup` and `McpStatusReaders`, and takes `(readers, implementation, project: { readonly projectTrusted: boolean; readonly cwd: string })`. The arms are spelled inline in the exported union, so fallow sees no private type leak and no export that only tests read. `info-mcp-status.ts` names its arms with module-private `Extract`/`Exclude` aliases.
- The readers are not branded. A hand-built literal (only tests build one) can still pair a reader with the wrong implementation; branding would change both reader factories and every test seed to stop a mistake production no longer makes.
- The cucumber scenario reaches the guard through a harness Pi extension, `features/lib/unreadable-namespace-tool.ts`, that registers one `hidden` tool whose namespace `name` accessor throws. Pi 1.5.0's `getAllTools()` copies a tool's namespace object without reading it (`node_modules/@earendil-works/pi-coding-agent/dist/core/agent-session.js:1117`), `registerTool` stores the definition unread (`dist/core/extensions/loader.js:235`), and Pi reads a namespace name only in tool search, codemode, and its `/mcp` flows, none of which an info scenario runs. The extension's own reads of Pi's tools at load and in `softDepStatus` read `name` and `sourceInfo` only; the registry probe copies `name` and `sourceInfo` only (`features/lib/pi-registry-probe/extension.ts:20`). So the only reader of that name in the scenario is the built-in status reader (`namespaceNameOf`, `platform/mcp-builtin-status.ts:58`). No harness path can make `getMcpServers()` itself throw in a live Pi; the unit cases cover that throw.
