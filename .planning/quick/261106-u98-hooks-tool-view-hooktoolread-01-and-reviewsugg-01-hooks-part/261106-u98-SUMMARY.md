## Backlog dispositions

- HOOKTOOLREAD-01: fixed. A probe with a failed read of Pi's tools or commands keeps no answer, and the next proxy-shaped event probes again. The first failed read of a generation, in `identify` or a probe, writes one `[mcp]` debug line. Nothing reaches the user.
- REVIEWSUGG-01, `HookTool.name` is derivable: fixed. The field and its interface are gone. `identify` returns `McpToolIdentity`, and `claudeFormToolName(tool)` derives the name in `dispatch.ts`.
- REVIEWSUGG-01, `builtin:mcp` defined twice: fixed. There is one exported `BUILTIN_MCP_SOURCE_PATH` in `platform/pi-api.ts`, and the hooks view imports it. It lives in `platform` for three reasons. First, `platform` may import only `shared` (`.fallowrc.json`), so `pi-api.ts` cannot read a constant from the domain or a bridge. Second, the value names Pi's own loader path, which the Pi chokepoint module owns. Third, the `bridges-hooks` to `platform` import is an allowed edge.
- Not in this item: the soft-dependency probe's own trace (261106-u9b).
