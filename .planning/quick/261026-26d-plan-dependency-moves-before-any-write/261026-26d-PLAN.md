# Quick task 261026-26d: plan the whole dependency operation before any write (UPDDEP-REVIEW)

## Findings

The review of 1daa12d0 found five Critical findings with one cause: the move
judge was a partial preflight that ran inside the install or settle lock, and
the moves then ran one by one. Fix the structure:

- plan first, write-free and lock-free (`dependency-plan.ts`): the root's
  installability, every fresh dependency, every move, and each moved
  dependency's new closure read from the version it lands, deduplicated;
- never take the scope lock while it is held: the cascade only plans moves
  under the lock; the plan and the moves run after it is released;
- execute in order, skip a dependency already in range, report the moves that
  landed on every failure;
- `apply` folds its install's moves into its rows (converge policy), as
  `pending` previews them;
- the settle reads the candidate's declarations (CR-04); install reads a
  present mirror offline (NFR-5); moves carry `--partial`, `--map-model` and
  the command's context.

root and a moved dependency whose new version needs an unlisted plugin
