2. The producer picks the state (`runEveryOf` in `mcp-verdict.ts`, module-private). The reader indexes the table directly. The decoding moves to the one place that knows which implementations run each server.
3. `toolNamePrefix` uses interface extension (`AdapterMcpProfile`) and an overload, not a generic or conditional profile type (`rules/types.md`: interface extension over `Pick` and friends; mapped and conditional types sparingly). `resolutionFor` is the overload precedent. No production reader uses the narrower type today: the type now states the adapter guarantee that the doc comment only claimed.
4. `SoftDepStatus` gets readonly members only. The snapshot object is not frozen, because no code writes to one.
5. The `none` fix covers the one read in this item's files. The two `McpStatusLookup` reads go to 261106-u97, whose single builder replaces them. The SUMMARY records that hand-off.
6. The probe trace covers the MCP reads only, on the `mcp` tag: the `getCommands()` read, which feeds only the two MCP checks, and the three MCP checks, through a name parameter on `probeArm`. The pi-subagents and workflow-engine checks keep their silent catches. They are not MCP reads, and a `getAllTools()` failure in a snapshot also fails the pi-mcp-adapter tool check, which writes the line. The line text starts with `soft-dependency probe:` and ends with the error's message through `errorMessage`. It names no path of its own.
7. Server order: every `Record` site stays (parity, point 3). `recordMergedServers` builds its three lists in one loop in object property order, so the neutral `droppedMcpServers` follows the same order. No surface shows it today, so this is a consistency fix with no scenario.
8. `mcpBundle` stays as it is (point 6). A shared writer for the presence flag (like `replaceCompatibility`) would change no type and would touch three sibling-heavy orchestrator files, so it is out of this item.
