# Quick task 261120-i6p: centralize environment allowlisting in the tests

<objective>
Give every test that starts a child process, or whose code under test starts one
from `process.env`, an environment that holds only the variables that test needs,
built by one helper module per tier: `test/platform/process-environment.ts` for the
node:test tiers and `features/lib/child-environment.ts` for the cucumber harness
(D-01). The scope is exactly the shape (a) and shape (b) sites and the two cucumber
gaps of D-02. Windows keeps an OS base list and case-insensitive names (D-03).
concurrent-install forks with PI_CODING_AGENT_DIR under the case's own HOME (D-04).
Nothing under `extensions/` changes (D-05).

Purpose: a large or unusual host environment (a cloud sandbox, a developer shell
full of tokens and `GIT_*` variables) no longer leaks into test children or breaks
them. The hand-rolled fix f2225cc becomes one helper call.

Output: two helper modules, one architecture test, `createHermeticEnvironment` on
the shared ledger, every in-scope site migrated, one `Internal:` CHANGELOG line.
No cucumber scenario: this change alters no `/claude:plugin` behavior a user can
see (AGENTS.md "Behavioral tests"). No version bump.
</objective>

## Call-site rules for the shape (b) helper

- **R-1:** call `useAllowlistedProcessEnvironment` before any other change to
  `process.env` in the case. This includes `withHermeticEnvironment` and
  `enterHermeticEnvironment`, whose own restore must finish inside the case after
  the call. `createHermeticEnvironment` may run before or after it (shared ledger).
  A case may create its temp directories before the call.
- **R-2:** fold a case's whole-case sets into `values` and delete their
  hand-rolled save and restore. A mid-case assignment after the call needs no
  restore of its own: the ledger puts every key back.
- **R-3:** where a case registers its own cleanup `t.after` that stops children,
  call the helper after that registration, so the environment comes back only
  after the children stop (node:test runs `after` hooks in the order they were
  added; verified on Node 24.22).
- **R-4:** expected environments stay built from the pruned `process.env`, never
  hard-coded (research Pitfall 8).

/** Returns the variables of this process's environment that `names` or the OS base list name. */

import type { TestContext } from "node:test";
/** Shape (a): a new environment with the named host variables (and the OS base), then `values`. */
export function allowlistedEnvironment(
  names: readonly string[],
  values?: Readonly<Record<string, string>>,
