## What changed

- `dependency-declaration-read.ts`:
  - `isAbsenceError` holds the D-01-06 ENOENT/ENOTDIR rule in one place.
  - `readContainedCandidate` now takes the owning root and switches over the three containment answers. `admitted` reads in place. `unusable` stays `UNUSABLE` (WR-03). `refused` (a link on a segment from the copy root down to the candidate) goes to the new `readLinkedCandidate`.
  - `readLinkedCandidate` calls `realpath(ownerRoot)` and `realpath(candidate)` in one try:
    - an absence failure answers `undefined`, so the walk goes on (a dangling link, or a target path through a regular file);
    - any other failure (ELOOP, EACCES) answers `UNUSABLE`;
    - otherwise it runs `containment(realOwnerRoot, target, …)`, reads the resolved target on `admitted`, and answers `UNUSABLE` on anything else.
  - The copy-root check and its `NOT_ADMITTED` map are unchanged (D-PL2-12 still answers absent). Only that map's one-line JSDoc was renamed to say it serves the copy-root check.
- `dependency-index.ts` and `convergence.ts` have no code change. Their existing arms already give the decided behavior (see the caller trace).
- Swap hardening: the read opens the resolved target, never the spelled link. The containment walk over the target refuses a link planted on it before the walk. The window between that walk and the open is the residual risk that the `createPathSafetyGuard` TOCTOU note already accepts. `realpath` is called directly from `node:fs/promises`, so `DependencyDeclarationReader` keeps its three members.

## Upstream finding (two lines)

Claude Code 2.1.310 lstats the manifest path below the plugin directory. When a segment is a link, it realpaths the manifest against realpath'd boundary roots (the plugin directory for a cached copy; the plugin and marketplace directories for a plugin loaded in place) and checks dev and inode.
An escaping or unresolvable link fails the plugin's load, and a dangling link counts as no manifest. This plan uses the owning root as the boundary, by user decision. That equals Claude Code's in-place boundary for a path record, and it is wider than Claude Code's boundary for a git record.
