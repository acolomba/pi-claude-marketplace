## What changed

**Task 1 (D-PL9-08 reversed).** `domain/package-lockfile.ts` exports `sanitizeLockfile(input)`, which returns `{ sanitized }` or `{ refusal }`. It follows the plan's `<sanitizer_spec>`. A module-private `LockfileRefusal` unwinds the checks and is caught once. In `package-install.ts` the inputs carry the parsed manifest and the lockfile text. The work dir gets `{}` as package.json first (flag `wx`). When the lockfile holds `"http://`, `npm --git=<workDir>/git-is-disabled config get registry --workspaces=false` runs through the new `runRegistryQuery` port. Then the sanitizer runs. A refusal becomes `skippedNote`. Zero packages returns quietly. Otherwise the rewritten package.json and lockfile are written as two-space JSON. npm rows run with `--git=<workDir>/git-is-disabled` before `NPM_CI_ARGUMENTS`. `DEFAULT_PACKAGE_INSTALL_OPS` binds a second runner with `timeoutMs: 30_000` (coordinator decision). The feature gained the local-folder scenario, a `Given` for a plugin that depends on a local-folder package, and a `localFolders` parameter on `pluginPackageFiles`.

**Task 2 (D-PL9-18).** `PackageManagerHost` (`platform`, `execPath`, `isFile`) and `NODE_PACKAGE_MANAGER_HOST` were added. Non-win32 hosts spawn synchronously, as before. On win32 the runner resolves PATH (any case of the name, `;` split, one quote pair stripped, `path.win32.isAbsolute` only), tries `.exe` then `.cmd`, and maps `npm.cmd` to `execPath` plus `npm-cli.js`. Anything else resolves the run with an Error.

**Task 3 (D-PL9-19).** `signalGroup` was added to the host (production: `process.kill(-pid, signal)`), and `detached` to the spawn options (`true` except on win32). One `stopTree` function replaces both `child.kill` calls of the ladder. It signals the process alone when the pid is not a safe integer above 1. On win32 it runs `<SystemRoot>\System32\taskkill.exe /PID <pid> /T /F` through `options.spawn` with an error listener and a caught launch. On POSIX it sends `signalGroup` and falls back to `child.kill` on any throw. The phase-9 CONTEXT and 05-SUMMARY record D-PL9-08 (reversed), D-PL9-02 (amended), D-PL9-18, D-PL9-19, the PKGDEP-03 narrowing, T-09-08 as mitigate, the resolved Windows follow-up, and uncertain choices 39-56.

## Uncertain choices (39-56, also in 09-05-SUMMARY.md)

39. The registry query is ported rather than refusing every http link, because the sandbox and real local registries use http.
40. The registry query has Claude Code's 30-second limit (`uks`) on a second injected runner (`runRegistryQuery`). The install keeps 60 seconds. A failed, timed-out, or non-http answer leaves the origin undefined, so every http link is refused. (Coordinator decision; it replaces the plan's "query uses the runner's 60 s".)
41. The sanitizer runs only for a contained plugin. The D-PL9-03 note reads no lockfile.
42. bun's format refusal says "this extension", where upstream says "this version of Claude Code".
43. Hostname reading: one trailing `.` is dropped, then every leading `www.`.
44. `cut(x)` is the first 120 characters, and `semver.parse` is the exact-version check.
45. Rewritten files are two-space JSON with a trailing newline.
46. No byte-order mark is stripped. Upstream wraps both texts in `No()`, which may strip one, so a BOM lockfile is "not valid JSON" here.
47. The tarball spec pattern keeps upstream's unescaped middle dot (`tar.gz`), so `x.tar-gz` is refused too.
48. Names are lowered A-Z only before the patterns, as upstream `vT` does. `toLowerCase()` would map the Kelvin sign to `k`.
49. The registry query runs npm for a bun lockfile too, as upstream does.
50. Windows looks for `.exe` and `.cmd` only, with no PATHEXT, `.com`, or `.bat`. `bun.cmd` and Scoop-style shims with no `npm-cli.js` fail with a note. A root-relative entry (`\tools`) counts as absolute.
51. POSIX keeps the bare-name spawn and probes no file.
52. There is no Windows scenario. cucumber runs on Linux.
53. There is no process-tree scenario. No harness knob shortens the 60 s constant, and Pi's environment is run-wide. A real process tree in the unit test proves it. **Handoff for the parent: a Phase 10 harness item, a knob that shortens the 60-second timeout for one scenario, so a cucumber scenario can prove the tree kill.**
54. The group kill falls back on any throw, not only ESRCH. The pid must be a safe integer above 1.
55. Windows is not detached. `taskkill /T /F` runs at both steps from the absolute `SystemRoot` (any case, default `C:\Windows`), with the run's cwd and env, `shell: false`, and an error listener.
56. A detached npm can outlive a Pi that was killed hard, until its pipes break.

5. **Uncertain-choice numbering.** The 09-05 list runs 39-56, 18 items. That is the plan's 14 items with the 30 s change applied, plus four new ones: 46 (BOM), 47 (tarball pattern), 48 (A-Z lowering), and 49 (bun query).
