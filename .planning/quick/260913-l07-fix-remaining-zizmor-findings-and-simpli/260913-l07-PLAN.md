### Corrections to the handed-down brief — read before starting

Two statements in the brief were tested during planning and do not hold as written.

1. **The prettier hook's `files:` pattern must not be `'\.(js|json|ts|mjs)$'`.** The brief
   gives that pattern with the rationale "so the hook's file set matches `npm run format`",
   but the two do not match. `npm run format` covers `**/*.{js,json,ts}` **plus
   `scripts/**/*.mjs`** — not every `.mjs`. A bare `\.mjs$` alternative additionally pulls
   in four files the npm script never touches:
   `.planning/inputs/unit-test-refactor-handoff/{check,generate}-preservation-kit.mjs` and
   `tests/live-uat/{manifest-absence-canary,stop-canary}.mjs`. Neither `.prettierignore`
   nor the pre-commit top-level `exclude:` covers `.planning/`, and both handoff files
   **currently fail `prettier --check`** — so that pattern would silently rewrite two
   archived files on the first `--all-files` run. The plan uses
   `'\.(js|json|ts)$|^scripts/.*\.mjs$'`, which was verified against `git ls-files` to
   select exactly the `npm run format` set (753 files, 9 of them `scripts/*.mjs`) and to
   exclude all four. This honors the brief's stated intent and corrects its expression.

2. **The brief's ordering is silent on where the new hook goes inside the `local` block; it
   has to go first.** `npm-format-check` lives in that same block. A writing `prettier` hook
   placed after it would let `format:check` fail on a file `prettier` is about to fix, in
   the same run. Placing `- id: prettier` at the top of the block restores the
   write-then-check order. As a side effect prettier also moves from position 2 in `repos:`
   to after the `texthooks` writers, which is an improvement — prettier now gets the last
   word on `.ts`/`.json` instead of having `fix-smartquotes` and friends run after it.

### `node_modules/.bin/prettier`, not `npx prettier`

The brief leaves this open. Use `node_modules/.bin/prettier --write`.

`npx prettier` resolves `node_modules/.bin` first, but when that is absent it falls back to
fetching an unpinned copy from the registry — which is the floating-version drift the
deleted `additional_dependencies: [prettier@3.9.5]` pin existed to prevent, reintroduced
through a different door. The relative path runs the repo's own pinned devDependency
(verified: `node_modules/.bin/prettier --version` reports **3.9.6**, the same binary
`npm run format` invokes), never reaches the network, and fails loudly rather than quietly
if someone runs the hook without installing.

The path resolves because pre-commit runs `language: system` entries with the repository
root as the working directory. In CI it resolves because `lint.yml:38`
(`npm ci --ignore-scripts`) runs before `lint.yml:41` (`pre-commit/action`), both
re-confirmed by grep.

Prettier honors `.prettierignore` on explicitly passed filenames — verified by running it
against the deliberately malformed
`tests/orchestrators/marketplace/_fixtures/invalid-manifest/.claude-plugin/marketplace.json`,
which the ignore file lists and which reported clean.

### Verified — do not re-derive, do not revert

- **`$/` is real and safe.** GitHub shipped self-repository syntax on 2026-07-30; it works
  for reusable workflow calls and needs runner 2.336.0+. `actionlint` 1.7.12 rejects it
  ("not following the format ... nor ./path/to/workflow.yml") — that build predates the
  feature and the complaint is a stale false positive. `actionlint` is not in this
  repository's pipeline. If you run it, ignore that one finding.
- **`persist-credentials: false` breaks nothing here.** No workflow runs
  `git push`/`commit`/`tag`. The only tokens travel through `env:` (`GITHUB_TOKEN` in
  `sonarcloud.yml`, `GH_TOKEN` in `publish.yml`), which this setting does not affect — it
  controls only whether a token is written into `.git/config`. `publish.yml`'s `release`
  job has no checkout step at all. The e2e suite clones a public repository
  (`anthropics/claude-plugins-official`), so it needs no credential.
- **Behavior change worth stating in the commit body:** `cooldown: default-days: 7` delays
  Dependabot pull requests until a release is 7 days old.
