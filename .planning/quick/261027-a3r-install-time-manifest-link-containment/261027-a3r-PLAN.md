## Upstream finding (claude-code-compat-research evidence record)

- **Question.** Which manifest reads does Claude Code contain, with what boundary, and what
  happens at install?
- **Evidence.** Binary 2.1.310
  (`/home/linuxbrew/.linuxbrew/Caskroom/claude-code@latest/2.1.310/claude`), grepped 2026-10-27.
  - `VJ` (read manifest) calls `ows(containedIn, pluginDir, name, ".claude-plugin/plugin.json")`.
    `ows` returns at once when the caller passes no `containedIn`.
  - When there is a boundary, `g9n` lstats each segment below the plugin directory. On a link,
    `DHe` realpaths the manifest against realpath'd roots:
    - ENOENT or ENOTDIR, with `stat` also missing: absent (no manifest);
    - any other realpath failure: escapes ("it could not be resolved");
    - outside every root: escapes ("it resolves to …, outside the <boundary>").

    An escape throws `Bz` ("plugin manifest not confirmed inside the plugin"), and the plugin's
    load fails.
  - The load (`q9n` → `$le` → `VJ`) passes the boundary:
    - `[pluginDir]`, labelled "plugin directory", for a cached copy;
    - `[pluginDir, marketplaceDir]`, labelled "plugin directory and its marketplace directory",
      for a plugin loaded in place.

    "In place" is `eje(source, marketplaceSource)`: a string (path) source in a marketplace
    whose source is `file` or `directory` (`Am`). It also covers a path plugin whose cache copy
    failed, which `z9n` loads from the marketplace path with the same anchor.
  - At install, `z9n` reads the manifest for the version as `VJ(path, name, source)`. It passes
    no boundary and swallows errors, so upstream's install-time read is uncontained. The
    containment lands at load, which fails the plugin.
  - `marketplace.json` is read by `Rut` / `nse` with a plain `readFile` (or the v5 storage
    backend). No containment check runs.
- **Confidence.**
  - High for `VJ`/`ows`/`g9n`/`DHe`, `q9n`/`$le`, the `z9n` version read and `Rut` (code read
    directly).
  - Medium for `eje`/`Am`: `Am` is one of several same-named minified functions, and it was
    resolved by its body, `e.source==="file"||e.source==="directory"`.
  - Medium for the v5 storage backend's link handling (not traced).
- **Pi constraints and divergences.**
  - (a) Refusing at install, not at load. This extension has no load step apart from install,
    because it writes the Pi artifacts at install time. So the resolver is where Claude Code's
    load failure lands. License: D-PL2-24, a user decision.
  - (b) Path plugins of git-hosted marketplaces. Claude Code copies them into its cache, so its
    boundary there is the plugin directory. This extension runs every unpinned path plugin from
    the marketplace tree, so the user's "loaded in place" rule gives them
    `[plugin dir, marketplace dir]`. Recorded in D-PL2-17 and returned to the user as an open
    point.
