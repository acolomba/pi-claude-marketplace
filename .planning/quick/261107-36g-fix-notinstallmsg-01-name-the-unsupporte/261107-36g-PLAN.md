NOTINSTALLMSG-01: the `PluginShapeError` not-installable message, `Plugin "<plugin>" is not installable: <reasons.join("; ")>` (`shared/errors.ts` `buildPluginShapeMessage`, about line 1245), ends at the colon when the resolver wrote no note and the only signal is in `unsupportedKinds`. That happens for a plugin whose only problem is a dropped hook (hooks its manifest or marketplace entry declares besides the convention file, D-CF5-20) or an MCP server the active implementation cannot run (an sse server under Pi's built-in MCP, MREC-06; a ws server under both, MREC-07).

The planner reproduced it at BASE `cd19625` in eleven runs (see "Reproduction at HEAD" below). Eight command surfaces show the empty ending: the failed dependency rows of `install`, `update`, and `marketplace update`, the `{dependency failed}` rows of `apply` and `import`, the `enable` stale-gate row, and the refusal to move an installed dependency during `install` and `update` (`... cannot move: Plugin "lib" is no longer installable: . The fix gives every message a reason: when the resolver wrote no note, `requireInstallable` names the closed-set tokens of the unsupported kinds, the same tokens `narrowResolverReasons` gives install's row (PR-6) and the 261106-u99 import cause.
