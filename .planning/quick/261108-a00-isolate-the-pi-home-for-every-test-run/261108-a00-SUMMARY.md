# Quick 261108-a00: Isolate the Pi home for every test run Summary

Every `node --test` run now loads `test/platform/isolated-pi-home.ts` with `--import`, which points `HOME` and `PI_CODING_AGENT_DIR` at a temporary root before any test module loads. The cucumber worker gets a temporary root in `BeforeAll()` and the run's sandbox HOME and agent directory in each scenario. A new architecture gate fails when a test entry point skips either.

## What changed

- `test/platform/isolated-pi-home.ts`: when `PI_CM_TEST_HOME` is unset, makes `<tmp>/pi-cm-test-home-*/home/.pi/agent` (realpath), sets `PI_CM_TEST_HOME`, `HOME`, and `PI_CODING_AGENT_DIR`, and removes the root on `exit`. It touches no git variable.
- `package.json`: all nine `node --test` scripts (`test`, `test:architecture`, `test:unpaired`, `test:modules`, `test:integration`, `test:coverage:integration`, `test:coverage:e2e`, `test:e2e`, `test:e2e:nightly`) now run `node --import "$PWD/test/platform/isolated-pi-home.ts" --test ...`.
- `scripts/test-coverage-direct.mjs`: the per-pair spawn passes `--import <file URL of the module>`. `--test-coverage-include` limits coverage to the pair's source, so the module never shows in `coverage/direct.lcov`. No other script under `scripts/` spawns `node --test`.
- `features/support/isolated-pi-home.ts`: `BeforeAll()` makes a worker root and stores its HOME in `PI_CM_TEST_HOME`. `Before()` sets `HOME`/`PI_CODING_AGENT_DIR` to `currentRun().sandbox.home`/`.agentDir` and registers the restore with `this.onRelease()`, which the world's `After()` runs last. `AfterAll()` removes the root. The module holds no module-level state. The existing `features/support/**/*.ts` glob in every `cucumber.json` profile loads it.
- `test/architecture/isolated-pi-home.test.ts`: five cases: the two modules exist; every npm script command that runs `node` with `--test` has `--import "$PWD/test/platform/isolated-pi-home.ts"` (and `test:unpaired` is among them); every `"--test",` in the coverage script follows `"--import", isolatedPiHomeUrl,` and the URL names the module; every cucumber profile's `import` globs match the cucumber module (`path.matchesGlob`); and the test's own process has `os.homedir()` under `realpath(os.tmpdir())` with `PI_CODING_AGENT_DIR` equal to `<home>/.pi/agent`.
- Skill docs: `local-verification/rules/commands.md` gives the owner-test commands with the `--import`. `cucumber/rules/world-and-stand-ins.md` says in-process steps run inside the run's sandbox, and the launch-environment bullet no longer says the worker's `process.env` is never touched.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Relative `--import` broke forked integration children**
- **Found during:** Task 1
- **Issue:** with `--import ./test/...`, five cases in `test/integration/concurrent-install.test.ts` and `test/integration/load-reconcile-race.test.ts` failed with `child exited 1 before ready`. `fork()` passes `process.execArgv` on, and those children run with another cwd, so the relative module path did not resolve.
- **Fix:** the npm scripts use `"$PWD/test/platform/isolated-pi-home.ts"` (npm runs scripts from the package root and sets `PWD` to it, also when it is started from a subdirectory), and the coverage script uses `new URL("../test/platform/isolated-pi-home.ts", import.meta.url).href`.
- **Commit:** 1bcc2cff

**2. [Rule 1 - Bug] A forked child would have lost the HOME its parent chose**
- **Found during:** Task 1
- **Issue:** with the import inherited, the module would replace the `HOME`/`PI_CODING_AGENT_DIR` that a case passes to a forked child (`load-reconcile-race.test.ts` sets both).
- **Fix:** the module does nothing when `PI_CM_TEST_HOME` is already set. So the root is per runner process: the `node --test` runner makes it, and its test-file children share it, instead of one root per process as the plan said. Isolation from the real `~/.pi` is the same. Cases that skip their own hermetic environment now share a root across concurrent test files. Before this change they shared the real home.
- **Commit:** 1bcc2cff

**3. [Project rule] Module location**
- The plan named `test/support/isolated-pi-home.ts`. The unit-test skill (`pairing-and-design.md`) keeps support next to its concern and forbids catch-all directories (`test/helpers/`, `test/utils/`, `test/mocks/`). So the module is `test/platform/isolated-pi-home.ts`, beside `hermetic-environment.ts`. Pairing (`test:corresponding`) and fallow needed no registration: `hermetic-environment.ts` already sits there as unpaired support, and production-mode fallow does not analyze `test/`.

**4. [Rule 2 - Missing] The documented owner-test command was not isolated**
- `.agents/skills/local-verification/rules/commands.md` told agents to run `node --test <test-path>`, which skips the npm scripts. It now gives `node --import "$PWD/test/platform/isolated-pi-home.ts" --test <test-path>`. `docs/guidelines/typescript-unit-testing-guidelines.md` still shows plain `node --test` in three places; I left it unchanged.
- **Commit:** 1bcc2cff

**5. [Cucumber rule] Scenario restore through `onRelease()`**
- The plan said an `After()` restores the worker values. The cucumber rules say only the world's `After()` releases scenario resources, so the `Before()` registers the restore with `this.onRelease()`. It registers first, so it runs last.
