# Isolate the Pi home for every test run

## Goal

No test, unit, integration, e2e, or cucumber, can read or write the real
`~/.pi`. Every test process starts with `HOME` and `PI_CODING_AGENT_DIR`
pointing at a fresh temporary folder, and a gate fails when a test entry point
skips that setup.

## Root cause

The per-test helpers (`test/platform/hermetic-environment.ts`
`createHermeticEnvironment` and `enterHermeticEnvironment`, plus about a
dozen local `withHermeticHome` copies) are opt-in. Nothing sets a run-wide
floor. The cucumber step `the user requests plugin completions for "…"`
(`features/step_definitions/completion.steps.ts`) calls
`features/lib/plugin-completions.ts`, which runs the completion provider in
the cucumber worker. The worker keeps the real environment, so the user scope
resolves to `~/.pi/agent/`, and `getPluginIndex` rewrites
`~/.pi/agent/pi-claude-marketplace/cache/plugins/valid-marketplace.json`.
Reproduced with `npx cucumber-js --profile builtin
features/mcp-server/verdict-list.feature`.

## Tasks

### Task 1: run-wide isolation for node:test runs

- files: `test/support/isolated-pi-home.ts` (new), `package.json` (every
  `node --test` script: `test`, `test:architecture`, `test:unpaired`,
  `test:modules`, `test:integration`, `test:coverage:integration`,
  `test:coverage:e2e`, `test:e2e`, `test:e2e:nightly`),
  `scripts/test-coverage-direct.mjs` (the `node --test` spawn), and any other
  script under `scripts/` that spawns `node --test`.
- action: the module, loaded with `--import`, makes one temporary root per
  process (`mkdtempSync` under `os.tmpdir()`, `realpathSync`), creates
  `home/.pi/agent`, and sets `process.env.HOME` and
  `process.env.PI_CODING_AGENT_DIR` before any test module loads. It removes
  the root on process exit. It must not change any git variable that
  `test/architecture/hermetic-git-environment.test.ts` checks; read that test
  and the helper it covers first. Existing per-test helpers keep working and
  now restore to the sandbox. Keep the module tiny; it is test support, so
  check whether `test:corresponding` and fallow need it registered (read
  `scripts/check-corresponding-tests.mjs` and `.fallowrc.json`).
- verify: `npm run test:unpaired`; then a one-off
  `node --import ./test/support/isolated-pi-home.ts -e` print of
  `os.homedir()` and `PI_CODING_AGENT_DIR` shows the temporary root.

### Task 2: cucumber worker and scenario isolation

- files: a new `features/support/` file (for example
  `features/support/isolated-pi-home.ts`); `features/support/world.ts` only if
  needed to read the scenario sandbox.
- action: `BeforeAll` (runs once per worker) sets `HOME` and
  `PI_CODING_AGENT_DIR` to a fresh temporary root; `AfterAll` removes it. A
  `Before` sets both to the current scenario's sandbox (`run.sandbox.home`
  and `run.sandbox.agentDir`, see `world.ts` around line 336 and 618), and an
  `After` restores the worker values. Each worker runs one scenario at a
  time, so the mutation is safe. Hook order matters: the scenario `Before`
  must run after the world's sandbox exists; read how `world.ts` creates the
  sandbox and order the hooks to match. Follow the cucumber skill rules
  (`.agents/skills/cucumber/`), and update `world-and-stand-ins.md` to say
  in-process steps run inside the scenario sandbox.
- verify: record
  `stat -c %y ~/.pi/agent/pi-claude-marketplace/cache/plugins/valid-marketplace.json`,
  run `npx cucumber-js --profile builtin features/mcp-server/verdict-list.feature`
  and `npx cucumber-js --profile adapter features/plugin/list.feature
  features/marketplace/market-alias.feature`, and confirm the time is
  unchanged and the scenarios pass.

### Task 3: gate

- files: `test/architecture/isolated-pi-home.test.ts` (new).
- action: the test reads `package.json` and fails when any script that runs
  `node --test` lacks `--import ./test/support/isolated-pi-home.ts` (or the
  form the scripts use); reads `scripts/test-coverage-direct.mjs` and fails
  when its `node --test` spawn lacks the import; reads `cucumber.json` and
  fails when a profile's `import` globs do not load the new support file. It
  also checks, in-process, that `process.env.PI_CODING_AGENT_DIR` and
  `os.homedir()` sit under `os.tmpdir()` (this test itself runs under
  `test:unpaired`, so it proves the import took effect). Respect the D-07-06
  path rules for architecture tests (named paths must exist).
- verify: `npm run test:unpaired`; temporarily drop the import from one
  script and confirm the test fails, then restore (do not commit the
  negative control).

## Final check

Run `npm run check` in the background with output to a log, and confirm exit
0. Record the real cache file's time before and after, and confirm it did not
change.

## Rules

- Never write to the real `~/.pi`. Do not delete the existing residue there.
- Git: plain single commands, no `&&` or `;` chains with git, no variables, no
  heredocs. Commit messages go in a scratchpad file; run
  `SKIP=npm-check pre-commit run --files <files>` is NOT used here, because
  these are build inputs: let the normal hook run `check:commit`. Commit with
  `git commit -q -F <msgfile> -- <paths>`. Titles follow Conventional Commits
  with no phase, plan, or quick IDs. Every message ends with the two
  attribution lines.
- Never `--no-verify`, never `gsd-tools query commit`, never `config-set`,
  never push.
