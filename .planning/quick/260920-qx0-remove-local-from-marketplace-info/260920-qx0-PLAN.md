<objective>
Remove `--local` from `marketplace info` only. `info` is a pure merged read that
never writes configuration, so the flag has no meaning there; after this change
the shim rejects it as an unknown flag like any other (AP-5). `marketplace list`
and `marketplace update` keep the flag.

Purpose: one flag with one meaning. Today `makeSingleNameMarketplaceHandler`
runs `extractLocalFlag` and then discards `localFlag.local`, so `--local` is
parsed and silently swallowed on `info`. The catalog, completions, README,
CHANGELOG, and PRD all advertise a flag that does nothing.

Output: the shim, the usage string, the catalog row, seven test modules, and the
three user-facing docs updated; `npm run check` green; one Conventional Commits
commit staged by explicit path.

Mechanism the executor relies on (verified against the tree, no new code needed):
`parseArgs` (edge/args.ts) consumes `--scope <value>` itself and pushes every
other token, long flags included, into `positional`. `parseCommandArgs`
(edge/args-schema.ts) then rejects the first positional that starts with `--`
with the message `Unknown flag: "<token>".` BEFORE its surplus check and BEFORE
its required-positional check. The shim's `onError` closure forwards any message
other than the bare usage string unchanged into `notifyUsageError(ctx, {
message, usage })`. That is the same call, with the same arguments,
`extractLocalFlag` makes for an unknown flag today, so dropping the scan changes
nothing for `--bogus` and turns `--local` into that same rejection. There is no
need to run `extractLocalFlag` with `--local` unrecognised.
</objective>
