## Design choices (planner discretion; no CONTEXT.md exists for this quick task)

- C1 Cache location `node_modules/.cache/optional-peers`: `node_modules/` is already gitignored; tsc, ESLint, Prettier, fallow, and the test globs never read it; it sits beside the ESLint and tsc caches; `npm ci` clears it together with the dependency tree. It is inside the repository, so a peer that an imported module ever loads lazily resolves from the repository's own `node_modules`.
- C2 `--omit=peer`: the imported modules link no peer (facts above), and omitting peers keeps a second Pi and typebox out of the cache.
- C3 Exact floor: the cache must hold the declared floor exactly. A range check would let a lowered floor pass while the tests prove a higher version.
- C4 No environment override for either peer. The adapter-root variable existed for CI, which now uses the cache. To prove another version, change the floor in `package.json`; the script follows it. An override would let a local run prove a different version than CI, which is the gap this task closes.
- C5 Date cutoff `--before`: with no lockfile (PIFL-03), dependency ranges would resolve to whatever is newest on each machine and each CI run. Capping resolution at the newest floor's publish time gives every machine the same tree and keeps any version published later, such as a hijacked patch release, out. The cutoff comes from the registry, so it moves with `package.json` and needs no constant.
- C6 The script names the two peers in a constant list and derives their versions. No other repository script needs these peers.
- C7 No CHANGELOG entry: the change touches contributors only, and CHANGELOG.md records user-facing changes.
- C8 No unit test for the script, like the other `scripts/*.mjs`. The cold run, the warm run, and the negative controls in `<verification>` are its proof. They are not committed (CONVENTIONS: a gate's run over the real tree is its only committed proof).
