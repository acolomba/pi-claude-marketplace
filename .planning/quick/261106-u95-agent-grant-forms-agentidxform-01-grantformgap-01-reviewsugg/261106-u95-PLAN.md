## Design (decided by the planner; each item is a questionable choice the SUMMARY reports)

1. In-memory row (a). `persistence/agents-index-io.ts` exports `AgentGrantForm` (one stored form: the schema row's `mcpForms` member type by indexed access, so the schema module stays untouched), `StoredGrantForms` (a union of two inline object arms: `mcpImplementation: "adapter"` with `mcpForms.adapter` required and `mcpForms.builtin` optional, and the built-in mirror), `AgentGrantFormFields` (an inline arm with both fields optional `never`, or `StoredGrantForms`), and `AgentsIndexRow` (the schema row with the two fields omitted, intersected with `AgentGrantFormFields`). The discriminant is `mcpImplementation`, and field names and JSON shape stay the on-disk ones, so every `AgentsIndexRow` is a valid on-disk row: no serialize step, and every save writes the bytes it writes today. Keep the forms' arrays mutable as the schema type has them, so a row stays assignable to the on-disk row. Inline arms follow the `SkillPreload` union in `bridges/agents/types.ts`; they avoid fallow's private-type-leak and an exported interface nothing imports. The item's example, one new field holding a discriminated value, needs a serialize step at save and rewrites about six more test files that read rows through `loadAgentsIndex`; it was not taken.
2. Read seam (a). In `loadAgentsIndex`, each schema-valid row passes a module-private type predicate whose body checks exactly the invariant: no implementation and no stored forms, or an implementation whose form `mcpForms` holds. A row that passes is pushed as is (same object). A row that fails, which only a hand edit writes (every writer builds the pair through Design item 4), is pushed without both fields: destructure the two fields out of the row and keep the rest. One `hookDebugLog(..., "mcp")` line names it: `agent <generatedName>: stored grant forms ignored: mcpImplementation <String(mcpImplementation)>, mcpForms [<Object.keys of the stored forms joined by ",">]`. It adds nothing to `corruptions`: a corruption shows a hygiene warning that says the entry was dropped, and dropping the row would orphan its agent file and make the PI-6 check refuse that plugin's next staging. Such a row then reads like any row without stored forms: under Pi's built-in MCP, when its warnings hold the adapter async warning, it is a legacy candidate (P4-DC-06) whose generated file the locked pass translates; otherwise it is left. The next save writes it without the pair. This is the one behavior change of the plan, reachable only by hand-editing `agents-index.json`; it prints nothing, so no cucumber scenario is added, and two unit cases pin it. This is the first `hookDebugLog` in `persistence/`, which may import `shared/` (`.fallowrc.json` boundaries).
3. Save seam (a). `AgentsIndexDocument { readonly schemaVersion: 1; readonly agents: readonly AgentsIndexRow[] }` is what `saveAgentsIndex` takes, and `LoadedAgentsIndex` extends it with `corruptions`. The save builds `const document: AgentsIndex = { schemaVersion: index.schemaVersion, agents: [...index.agents] }`, validates `document` with `AGENTS_INDEX_VALIDATOR`, and writes `document`. The annotation is the compile-time proof that an in-memory row is an on-disk row, and it keeps the schema's `AgentsIndex` export in production use (measurement 2.iii).
4. Writers (a). One exported constructor, `storedGrantForms(held: McpImplementationId, heldForm: AgentGrantForm, otherForm: AgentGrantForm | undefined): StoredGrantForms`, builds a stored pair: `mcpImplementation` is `held`, and `mcpForms` holds `heldForm` under `held` first and `otherForm` under the other id when it is defined (a conditional spread; no nested ternary). Held first is the order the stage writes today, and a stage case pins those saved bytes (`stage.test.ts` around line 1736). `convertAgentGrantForms` returns `recorded: AgentGrantFormFields`, either `{}` or `storedGrantForms(fileForm, storedForm(agent), other === undefined ? undefined : storedForm(other))`, and `storedForm` returns `AgentGrantForm`. `deriveLegacyGrantForms(fileText, row: AgentsIndexRow): AgentsIndexRow | undefined` builds `{ ...row, ...storedGrantForms("adapter", adapter, builtin) }`, where `builtin` is undefined when the translation gives up. The rewrite's `rowForActive(row, active, swap)` builds `{ ...row, ...storedGrantForms(active, swap.active, swap.recorded), warnings: [...swap.active.warnings], droppedTools: [...swap.active.droppedTools] }`. After a swap the new held form comes first in `mcpForms`; nothing reads that order and no test pins it.
5. Readers (a). `grant-rewrite.ts` drops the guards the type proves: the optional chaining on the stored forms and the absent-recorded-form check in `storedSwap`, and the stored-forms absence check in `isLegacyCandidate`. `storedSwap(row: AgentsIndexRow, active)` returns undefined when the row records no implementation or records `active`; otherwise it switches on `row.mcpImplementation` over `"adapter"` and `"builtin"` with no `default` (measurement 2.i). The `adapter` arm passes `row.mcpForms.adapter` as the recorded form and `row.mcpForms.builtin` as the active one to a small module-private helper, which returns undefined when the active form is absent (AG-11, GRANTFORMGAP-01) and `{ recorded, active }` otherwise; the `builtin` arm is the mirror. The guards that stay: a row with no implementation, an implementation equal to `active`, an absent active form, the AG-4 block checks (content, not shape), containment (NFR-10), and the file read. `FormSwap` uses `AgentGrantForm`, and the module's local alias of the form type goes.
6. Pass-through modules (a). Every in-memory row is an `AgentsIndexRow`: `types.ts` (`PreparedAgentsStaged`'s four arrays), `index-mutation.ts`, `unstage.ts`, `stage.ts`, and the three grant modules import it from `persistence/agents-index-io.ts`, and no module under `bridges/agents/` names the on-disk row type. The row-level `warnings` and `droppedTools`, which repeat the held form's, stay: they are required fields of every on-disk row, including rows without stored forms, and every writer sets them from one form.
7. Server sets (b). `StageAgentsInput` loses its adapter server list. Each grant form maps the declared servers its implementation's profile supports: one module-private helper, `serverNamesFor(implementation, declaredMcpServers)`, returns in declaration order the names whose `profileFor(implementation).classify(config).kind` is `"supported"`, and replaces the built-in-only helper. For the adapter this is the list every production caller passes today (`Object.keys(resolved.mcpServers)`, interfaces block). `convertAgentGrantForms(input: GrantFormInput, grantForms)` takes `export type GrantFormInput = Omit<ConvertAgentInput, "mcpServerNames" | "mcpImplementation">`; each form's input adds its implementation and its server names. With no `mcpGrantForms`, the plugin declares no MCP server: the agent converts in the adapter form over no server (the same helper over an empty map), and the row records nothing.
