# Quick 261106-m03: built-in `/reload` scenario in the terminal (P2-DC-100, BLT-01)

<objective>
Add an `@builtin-only` cucumber scenario that proves a plugin's MCP tool still answers after
`/reload` under Pi's built-in MCP: install a plugin with a stub MCP server, run `/reload` in a
Pi in the terminal (Pi's RPC mode cannot run `/reload`), then have the scripted model find the
tool through `tool_search` and call it, and assert the tool's answer. Prove the scenario red once
with an uncommitted scratch edit and record the red run in the SUMMARY.

Purpose: `.planning/milestones/mcp-builtin-phases/02-built-in-materialization/02-UAT.md` check 2
is still manual because no scenario ever ran `/reload` under built-in MCP (P2-DC-88, P2-DC-100).
Pi 1.5.0 rebuilds its extension runtime on `/reload`, with an empty MCP server registry, so the
extension must register the plugin's servers again (D-MB-10). This scenario automates that leg.
The coordinator closes 02-UAT.md after the merge; this item does not edit it or any
VERIFICATION file.

Output: one new feature file, one new When step, a shared terminal reload
(`PiTuiSession.reload()`), a shared scripted-model terminal turn
(`features/lib/scripted-model/terminal-turn.ts`), a world option that starts a terminal Pi with
the scripted model, one updated cucumber rule bullet, and a SUMMARY with the negative control.
Test-only: no file under `extensions/` changes in any commit.

How "reuse the terminal and reload steps of `features/step_definitions/hook/session.steps.ts`" is
met: those step texts cannot be reused as they are, because the hooks terminal Pi has no model and
the hooks reload step waits for a UserPromptSubmit hook run. So the plan reuses their mechanism:
the hooks steps start the terminal through the world's `startTuiSession()`, which gains a
scripted-model option, and the hooks reload sequence moves into `PiTuiSession.reload()`, which both
the hooks step and the new step call.
</objective>
