# Quick Task 260919-c5m

Make `AGENTS.md` the one canonical project-instructions file both Claude Code and Codex read
natively, and delete the two workarounds that existed only to keep `CLAUDE.md` in that role.

## Problem

`CLAUDE.md` is the canonical, hand-maintained project-instructions file. Codex ignores that name in
favor of `AGENTS.md`, so `.codex/config.toml` carries a `project_doc_fallback_filenames` setting
that points Codex back at it. Claude Code 2.1.277+ now reads `AGENTS.md` natively when no
`CLAUDE.md` exists, so the name that needed the workaround is the only reason the workaround
exists. Renaming the file to `AGENTS.md` makes both tools read it with no configuration, which also
means `scripts/init.sh` must stop deleting `AGENTS.md` as a generated artifact — after this change it
is the real file.

## Established findings

Gathered during planning. Do not re-derive these.

- `CLAUDE.md` is 140 lines and contains **zero** occurrences of the string `CLAUDE`
  (`grep -c 'CLAUDE' CLAUDE.md` returns 0). It never names itself, so the rename needs no content
  edit. The `<!-- CODEGRAPH_START -->` / `<!-- CODEGRAPH_END -->` block sits at lines 129-140 and
  rides along with the rename.
- `codegraph install --target codex --location local` upserts its instructions block into
  `<cwd>/AGENTS.md`, and the write is marker-guarded and idempotent: `upsertInstructionsEntry` in
  the installer's `targets/shared.js` replaces the text between the two markers in place and reports
  `unchanged` on a byte-equal re-run. It does not clobber surrounding content. So a tracked
  `AGENTS.md` that already carries the block survives `codegraph install` intact, and the block
  becomes self-healing instead of able to drift silently.
- `codegraph install --target claude --location local` writes `.claude/CLAUDE.md` (its
  `targets/claude.js` joins the local config dir with `CLAUDE.md`). That generated per-tool copy is
  still redundant and still has to be removed.
- `.pre-commit-config.yaml` line 1 excludes `^(\.agents/|\.claude/|\.codex/|...)` for every hook.
  No hook touches `.codex/config.toml` or `.claude/commands/analyze-upstream-releases.md`, so
  neither can be reformatted mid-commit.
- `git check-ignore -v AGENTS.md` exits 1 — the path is not ignored, so it becomes tracked with no
  `.gitignore` edit.
- Deriving the intended index content for `.codex/config.toml` as
  `git show HEAD:.codex/config.toml | tail -n +4` was run in the scratchpad and yields a file that
  starts at `# raises the per-file instructions budget from the 32 KiB default.` and contains no
  `mcp_servers` token.

## Working-tree state this task must preserve

Four pre-existing local-only changes are present and unrelated to this task. They are the
per-machine CodeGraph MCP wiring plus one unrelated skill entry. Repo policy keeps the MCP wiring
uncommitted. All four must still be uncommitted, byte-identical, at the end:

| Path                   | State     | Content                                    |
| ---------------------- | --------- | ------------------------------------------ |
| `.claude/settings.json` | modified  | adds the `UserPromptSubmit` hook            |
| `.codex/config.toml`    | modified  | adds the `[mcp_servers.codegraph]` table    |
| `skills-lock.json`      | modified  | adds an unrelated `herdr` skill entry       |
| `.mcp.json`             | untracked | the CodeGraph MCP server definition         |

`.codex/config.toml` is the hazard: this task edits the top of that same file, so the commit must
take a scoped index entry rather than the working-tree copy.

## Tasks

### Task 1: Rename the file and drop both workarounds

**Files:** `CLAUDE.md` -> `AGENTS.md`, `.codex/config.toml`, `scripts/init.sh`

**Action:** Three edits, in this order.

1. `git mv CLAUDE.md AGENTS.md`. No content edit — the file does not name itself (see Established
   findings). `git mv` stages the rename, which is the explicit-path staging this task wants.
2. In `.codex/config.toml`, delete the first three lines: the `# points Codex at ...` comment, the
   `project_doc_fallback_filenames` assignment under it, and the blank line that follows. The file
   then starts at the `# raises the per-file instructions budget ...` comment. Keep
   `project_doc_max_bytes` — Codex applies that budget to `AGENTS.md` too. Change nothing else,
   and in particular leave the uncommitted `[mcp_servers.codegraph]` table at the end of the file
   exactly where it is; Task 3 keeps it out of the commit.
3. In `scripts/init.sh`, the last two lines are a comment and `rm -f AGENTS.md .claude/CLAUDE.md`.
   Drop `AGENTS.md` from that `rm -f` so it removes only `.claude/CLAUDE.md`, and reword the comment
   above it to say why the remaining removal is still needed: the generated per-tool copy would
   shadow the root file. When wording that comment, name the generated file by its full path or not
   at all — a bare mention of the old root filename would trip the Task 2 gate, while the full
   `.claude/CLAUDE.md` path is exempt from it. Do not add any new removal, regeneration, or restore
   step for the root file, and do not change the `codegraph install --target claude,codex` line —
   both targets now land correctly, codex upserting into the tracked root file and claude writing the
   copy that the `rm -f` deletes.

Do **not** run `scripts/init.sh` or `codegraph install` to check step 3. Either one rewrites
`.claude/settings.json`, `.codex/config.toml`, and `.mcp.json` — the three local-only files this
task must leave untouched. The installer's behavior is already established by reading its source.

**Verify:**

- `test -f AGENTS.md && test ! -e CLAUDE.md` succeeds
- `git diff --cached -M --stat` shows a `CLAUDE.md => AGENTS.md` entry with 0 insertions and
  0 deletions (a pure rename, `R100`)
- `grep -c 'CODEGRAPH_START' AGENTS.md` returns 1
- `grep -rn 'project_doc_fallback_filenames' .codex/` prints nothing and exits 1

- `bash -n scripts/init.sh` exits 0
- `grep -c 'mcp_servers' .codex/config.toml` returns 1 — the local-only table is still in the
  working tree, untouched

**Done:** `AGENTS.md` is the canonical file with the CodeGraph block intact, no Codex fallback
setting remains, and contributor setup removes only the generated `.claude/CLAUDE.md`.
