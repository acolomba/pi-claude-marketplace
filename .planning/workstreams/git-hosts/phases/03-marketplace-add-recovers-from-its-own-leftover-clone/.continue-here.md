<context>
The whole of Phase 3 is verified except one truth, and that one has a narrow, endorsed fix.

`platform/git.ts::listRemotes` line 368 reads
`return origin === undefined ? { kind: "no-origin" } : { kind: "origin", url: origin.url };`
with no check that `origin.url` is a string. isomorphic-git's `_listRemotes`
(`node_modules/isomorphic-git/index.cjs:13043-13053`) enumerates `[remote "<name>"]` subsections
and resolves `remote.<name>.url` as a separate, independently-absent lookup. So a `.git/config`
holding `[remote "origin"]` with a `fetch` line and **no `url` key** yields `{ remote: "origin" }`,
and the wrapper returns `{ kind: "origin", url: undefined }` — violating its own declared
`ListRemotesResult` type.

`add.ts::recognizeLeftover` (~line 725) then calls `stripGitSuffix(remotes.url)` and throws a raw
`TypeError: Cannot read properties of undefined (reading 'endsWith')`. That error matches none of
`classifyAddError`'s `instanceof` arms and carries no `.code`, so it classifies as `undefined`;
`handleAddFailure`'s `if (!orchestrated) { throw err; }` re-throws it raw in standalone mode
(breaking the project's own ATTR-07 "no raw error escapes" discipline), and in orchestrated mode it
degrades silently to `reason: "unparseable"` instead of `reason: "stale clone"`.

Two things make this in-scope rather than a defect to file elsewhere. The shape is produced by
exactly the WR-07 crash window this phase exists to recover from — isomorphic-git's
`GitConfigManager.save` rewrites the whole config file on clone, and an interruption mid-rewrite
leaves precisely this truncation. And both `listRemotes` and the `recognizeLeftover` branch are
artifacts this phase created in Wave 1.

Why the gates were green anyway: the missing behavior is a **missing** branch, not an uncovered
one, so 100%-branch coverage cannot see it. And `createGitOpsFake`'s `listRemotesResult` is typed
`ListRemotesResult`, so the fake cannot express `url: undefined` at all — the fake's own type
safety is what hid the real adapter's type violation. Plan around that: a fake-only test cannot
close this gap, which is why `missing` item 2 demands a real-filesystem fixture.

The endorsed fix, in the verifier's words: "narrow, additive, and reuses the already-tested
`StaleSourceCloneError` refusal path — no new mechanism is required, only a stricter guard on an
existing one, plus the paired test (WR-10) that would have caught this before code review."
Return `{ kind: "no-origin" }` for a present-but-url-less origin. Do not redesign the seam, and do
not let `platform/git.ts` import from `domain/` — the `.fallowrc.json` zone boundary forbids it,
which is why the identity comparison lives in the caller.

One consequence to carry: editing `platform/git.ts` invalidates SC4's evidence, which rests on
`git diff --name-only 50746b81..HEAD -- ':!.planning/'` being empty. The gap plan owes a closing
