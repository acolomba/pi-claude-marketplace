<objective>
Make the credential binding real: `onAuth` refuses to hand back a credential for a URL whose host is
not the host the bundle was built for.

Purpose: plan 01 removed the `undefined`-for-no-provider refusal, which is what capped at two hosts
the blast radius of a bundle whose bound `host` disagrees with the URL being cloned. `onAuth` ignores
its URL argument today — the parameter is literally named `_url` — so a bundle constructed for host A
would silently authenticate a clone of host B. This is the replacement control, and the ROADMAP
requires it inside the same phase, never after it.

Output: a host compare at the top of `onAuth`, the `url` parameter made load-bearing, and two
transport-level proofs that a cancel actually refuses.
</objective>

<what_this_guard_is_and_is_not>
Established during scoping, so the guard is built against the real exposure rather than the assumed
one. State this in the docstring; a reader who finds only "prevents a cross-host leak" will
reasonably conclude the transport was leaking, and it was not.

- `onAuth` is invoked by isomorphic-git ONLY from `discover`, on statusCode 401 or 203, and always
  with the caller's own URL — `node_modules/isomorphic-git/index.cjs:9470`. A redirect target never
  reaches it.
- `simple-get@4.0.1` deletes `authorization` and `cookie` before following a cross-host redirect —
  `node_modules/simple-get/index.js:57-60`.
- `credentialFill` emits `protocol=https` and `host=` and explicitly never a `path=` line —
  `extensions/pi-claude-marketplace/platform/git-credential.ts:194-199` — so
  `git credential fill` is strictly host-keyed.

So PROV-04 / T-79-04 was never the thing preventing a transport-level leak. The exposure being
closed is a CALLER-side host/URL mismatch: an orchestrator that builds a bundle for one host and
clones another URL. The guard turns that into a cancel instead of a credential disclosure.
</what_this_guard_is_and_is_not>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| isomorphic-git → `onAuth(url)` | An untrusted-by-this-seam URL string arrives and decides whether a secret is returned. |
| `onAuth` → `git credential fill` | The bound host, not the incoming URL, keys the lookup — the compare must run before the lookup, or a foreign URL still causes a helper query. |
| `onAuth` return value → https `Authorization` header | Whatever is returned becomes a header on the wire. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-06 | Information Disclosure | `buildAuthCallbacks.onAuth` returning a credential for a foreign URL | high | mitigate | Compare `new URL(url).host` against `opts.host` as the first statement inside `onAuth`'s try and return `{ cancel: true }` on a difference. Proven twice: at the factory (Task 1, `credentialOps.calls` empty) and at the transport (Task 2, no `Authorization` header recorded). |
| T-01-07 | Spoofing | a host that differs only by port (`git.example.invalid:8443` vs `git.example.invalid`) | medium | mitigate | `URL.host` includes the port on both sides of the compare, and `hostFromCloneUrl` already produces `opts.host` through `URL.host`. Task 1 asserts both pairings cancel and that `:443` against a portless bound host still matches, so normalization is symmetric rather than assumed. |
| T-01-08 | Tampering | an unparseable URL bypassing the compare | medium | mitigate | The compare sits inside the pre-existing try; a `new URL` throw lands in the CP-10 catch, which logs and returns `{ cancel: true }`. Asserted directly rather than inferred. |
| T-01-09 | Information Disclosure | the mismatch reason reaching a user-visible surface or a log | low | mitigate | Routed through `hookDebugLog` only, which writes to `console.error` solely under `PI_CLAUDE_MARKETPLACE_DEBUG=1`. | T-01-SC | Tampering | npm/pip/cargo installs | low | accept | This plan runs no package-manager install task and adds no dependency. No Package Legitimacy Audit is required. |
