<objective>
Make a credential already stored in the user's git credential helper reachable on EVERY https host,
and make the no-credential miss fail with an actionable cause line instead of a bare structural 401.

Purpose: `buildAuthForHost` returns `undefined` for any host outside a two-entry registry
(`orchestrators/auth-host.ts:106-110`). `platform/git.ts` builds auth callbacks only when
`opts.auth !== undefined` (`platform/git.ts:139,156,217`), so `undefined` means
`credentialOps.fill(host)` — a fully written, non-interactive, miss-tolerant lookup — is never
called. GAUTH-03 is about REACHING that path, not building it.

Output: `buildAuthForHost` always returns a bundle; the registry gates only the Device Flow closure;
`NO_STORED_CREDENTIAL_CAUSE` replaces `NO_PROVIDER_CAUSE`; the `update.ts` cause attachment is
re-aimed at the failure identity that actually occurs.
</objective>

<decisions_settled_here>
**Do `add` and `install` surface the cause line? NO — and that is not a new call.**

`.planning/PROJECT.md:666` records it as an accepted user checkpoint: *"D-79-03 amended (user
checkpoint 2026-07-11): no-provider cause line only on the update path's synthetic child row"* —
marketplace add and plugin install/reinstall render the bare `(failed) {authentication required}`
row. The mechanism reason is structural: `MarketplaceNotificationMessage` carries no `cause`
(SNM-10 confines `cause` to plugin-level variants), which is why `update.ts` reaches the user only
through a *synthetic failed-plugin child row*. Giving `add` a cause line means adding that
synthetic-child machinery to the add surface — a notification-contract change, and
`orchestrators/marketplace/add.ts` behavior is outside the phase boundary that 01-CONTEXT.md
§ Phase Boundary locks.

`add` and `install` DO get the substantive half of GAUTH-04 regardless: they stop cloning authless,
so a private source on an unregistered host now fails as `{authentication required}` after a real
credential attempt rather than on a bare structural 401.

Consequence for Task 3: `tests/orchestrators/marketplace/add.test.ts:2751` negative-asserts the
retired cause string. Once that string is gone it asserts nothing — a green run that checks
nothing. It must be re-aimed at the new constant.

**`domain/auth-registry.ts` is NOT touched, and PR #153's `kind` discriminant is NOT introduced.**
Per 01-CONTEXT.md § Specific Ideas: PR #153 split `GitAuthProvider` into
`DeviceFlowProvider | StoredCredentialProvider` only because it needed a registry entry for the
no-Device-Flow case. D-1-01 removes that need — the ABSENCE of a provider is the stored-credential
case. Nothing else forces a discriminant, so `GitAuthProvider` stays one interface,
`auth-registry.ts` is unchanged, and `tests/domain/auth-registry.test.ts` needs no edit (confirmed:
it did not fail in the spike).
