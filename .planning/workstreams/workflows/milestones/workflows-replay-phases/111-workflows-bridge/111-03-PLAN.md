<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin-authored `meta.name` -> target path | the untrusted name reaches the filesystem only through the bundle's composer |
| staging tree -> a directory the host engine scans | the commit `rename` is the single crossing, and it is atomic |
| shared saved directory -> this plugin's writes | the directory holds the user's own hand-saved workflows and every other plugin's envelopes |
| recorded previous names -> displacement and removal | a name read back from install state decides which existing file is moved aside |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-111-15 | Tampering | overwriting a user's hand-saved workflow or another plugin's envelope | high | mitigate | `assertTargetsUnoccupied` checks the whole target set after displacement and before the first rename, raising the typed occupancy refusal. The owner test asserts the class, the target path field, an empty `onPlaced` report, an unchanged directory listing and byte-identical foreign content. |
| T-111-16 | Elevation of privilege | a symlink planted at the staging directory between the containment check and the recursive `mkdir` | high | mitigate | The check is anchored one level above the staging directory so the staging segment itself is lstat'ed, and it runs before the `mkdir`, which would otherwise follow a symlinked parent. The owner test plants a link at the staging directory and asserts the refusal. |
| T-111-17 | Tampering | a concurrent engine scan observing a partially written envelope | medium | mitigate | Every byte is written under the staging root; the commit `rename` is the only operation touching a scanned directory. **`prepareStageWorkflows` cases:**

- **The noop short-circuit, and the storage root stays absent.** A plugin declaring a workflows
  directory holding nothing admissible, and no previous names. Assert the prepared handle's kind is
  the noop literal and its whole result object equals an empty staged-names array and the discovery
  warnings array. Then assert the engine's storage root does not exist on disk. That second
  assertion is the requirement: a plugin shipping no workflows must not bring the host engine's
  storage root into existence.
- **The noop is NOT taken when previous names exist.** Nothing admissible but one previous name
  given. Assert the kind is the staged literal, the rename-pairs array is empty, and the previous
  names ride on the handle.
- **The happy path and the envelope bytes.** One well-formed script declaring a literal name and a
  description. Assert the kind, then the whole result object in one comparison, then the rename
  pairs' names and their target paths -- obtaining each expected target from the bundle's composer,
  never by re-joining it in test code. Then read the staged file and assert its COMPLETE text with a
  strict string equality against a transcribed literal carrying the two-space indent, the key order
  name then description then script, and the trailing newline. The bytes are the contract, so this
  case compares bytes and not a parsed object.
- **The description is omitted, not emptied.** A script declaring a name and no description. Assert
  the complete staged file text again, and separately assert the parsed object has no own property
  for the description key -- distinguishing an omitted key from one present as null or as an empty
  string. The engine synthesizes its own fallback at registration, and a description invented here
  would be indistinguishable from a declared one.
- **The stem-fallback envelope is still staged.** A script reaching the stem-fallback arm. Assert
  its generated name appears in the staged names, its envelope exists under the staging root, AND
  its caveat row appears in the prepared result's warnings array with the exact string the discovery

  be mistakable for a refusal.
- **The collision rejects before anything is written.** Two DIFFERENT script files whose declared
  names produce one identical generated name. Assert the rejection by class, assert the reported
  collision carries both file names, and assert the staging directory does not exist afterwards --
  the assert runs before the staging root is created, which is what "before any envelope is written"
  means.
- **First-wins dedup after the assert.** One script reached twice through two declared spellings of
  one directory. Assert exactly one staged name and one rename pair. This is the residual case the
  post-assert dedup exists for.
- **Staging containment, anchored above.** Create the workflow home, then plant a symbolic link at
  the staging directory path pointing at a directory elsewhere. Assert the prepare rejects with the
  symlink refusal class. This is the case that proves the boundary is anchored one level up: a check
  anchored on the staging directory would start its walk there and never lstat it.
- **The write-loop catch appends a cleanup leak.** Force a failure inside the per-file write loop by

  bundle -- comment the seam, since nothing in the repo does this yet and a reader will wonder.

  cleanup in that catch is for.
