<objective>
`update` reassigns five component inventories in place and never touches `resources.workflows`,
and no update path calls the workflows stage at all. A workflow bug fix or security fix
shipped by a plugin author cannot reach the user, and a workflow withdrawn upstream keeps
running.

**Read this before writing any task text:** `update.ts` does NOT use `runPhases`. Its own
header records the deliberate divergence — a hand-rolled three-phase swap with a
heterogeneous-undo flow — and `install.ts` is the only production `runPhases` call site in
the extension. There is no phase array here to append to. The decision that the workflows
slot goes in the position mirroring install's (after `mcp`) stands; the mechanism is four
insertion sites plus a widened closed union and a widened runtime tuple.

Purpose: let a plugin author's workflow change reach the user.
Output: six insertion points in `update.ts` and one widened union in `shared/errors.ts`.
