<objective>
`reinstall` does NOT inherit the cascade fix and must be wired separately. It composes its
own prepared-handle set and never routes staging through the cascade primitive. Today it
carries the old record's workflow names forward verbatim, which was honest while nothing
re-staged — but the moment reinstall actually re-materializes, that carry-forward records
version A's names over version B's artifacts, which is strictly worse than the state it
replaced.

The one genuine design choice in this phase lives here: whether the workflows commit joins
the rollback ledger or commits in place. It commits in place, following the in-file `hooks`
precedent and its written rationale, and it is placed LAST so only the state save can follow
it — whose failure already routes through the manual-recovery path.

Purpose: make reinstall actually replace, and make the record describe the disk it wrote.
Output: a five-member handle set and a `resourcesFromHandles` with one fewer parameter.

**Probe edges authored here:** 3 of 22 (all WLIF-04), all auto-`resolved`
(verification: explicit). 0 flagged assumptions, 0 silent drops.
</objective>
