# Quick Task 260925-r98: Repository-private Pi for tests and scripts.sh

**Every place that launches Pi (e2e runtime smoke, both live-UAT canaries, `scripts/pi.sh`) now resolves the lockfile-pinned `@earendil-works/pi-coding-agent` through one module, `tests/pi-runtime.ts`, and runs it as `node <cliPath>`, never a `pi` on PATH.**

## Accomplishments

- Added `tests/pi-runtime.ts`, the single resolver that finds the repository's own Pi CLI from the installed `@earendil-works/pi-coding-agent` devDependency by reading its `package.json` directly (the package's `exports` map blocks `require.resolve`).
- Wired the e2e runtime smoke, `stop-canary.mjs`, `manifest-absence-canary.mjs`, and `scripts/pi.sh` through that resolver. None of them look up `pi` on PATH anymore.
- Moved `scripts/pi.sh`'s three companion extensions (`pi-mcp-adapter@2.37.0`, `pi-subagents@0.71.0`, `@quintinshaw/pi-dynamic-workflows@3.13.0`) from global npm installs to exact pins in a private npm prefix outside the checkout (`PI_CM_RUNTIME_PREFIX`, default `${XDG_CACHE_HOME:-~/.cache}/pi-claude-marketplace/pi-runtime`), refusing any prefix at or inside the checkout.
- Re-measured the fallow clone set with `duplicates.ignoredClones` cleared: the module-preamble clone the canary edits removed is gone, so dropped that entry from `.fallowrc.json` and both canary headers, keeping only the process-exit epilogue entry.
- Updated `tests/live-uat/README.md`, `CONTRIBUTING.md`, `CHANGELOG.md`, and the two `.planning/codebase` notes to describe the repository-private Pi and the retained single clone entry.

## Decisions Made

- Followed the plan's corrected Decision 2 mechanism: the resolver reads the package manifest by walking Node's own package-lookup order directly (`readFileSync` + `JSON.parse`), never `require.resolve`/`createRequire`, because the package's `exports` map has no `./package.json` export and blocks that resolution (measured, M1).
- Kept the `>= 0.86.1` floor check only on `stop-canary.mjs`, fed by `pi.version` from the resolver; `manifest-absence-canary.mjs` gets no floor check, matching the plan (it never had one).
- Split `${spec%@*}` / `${spec##*@}` on the LAST `@` in `scripts/pi.sh` so the scoped package `@quintinshaw/pi-dynamic-workflows@3.13.0` splits correctly into name and version.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Fixed `local a=$1 b=$2 c="...$a..."` unbound-variable failure in `scripts/pi.sh`**
- **Found during:** Task 2 verification (first live run of `scripts/pi.sh` against a fresh prefix)
- **Issue:** Under `set -u`, bash evaluates every right-hand side on a single `local` statement before any of that statement's assignments take effect, so `local name=$1 version=$2 pkg_json="$prefix/node_modules/$name/..."` referenced `$name` while it was still unset, raising `name: unbound variable` and aborting every `pin_met` call.
- **Fix:** Split the one `local` line into three separate `local` statements (`name`, then `version`, then `pkg_json`) so each variable is assigned before the next line references it.
- **Files modified:** `scripts/pi.sh`
- **Verification:** Re-ran the full `scripts/pi.sh` install/idempotent/broken-extension/prefix-guard verification sequence; all passed.
- **Committed in:** `a57ec74` (Task 2 commit; found and fixed before that commit landed)
