<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin tree -> `previewWorkflows` | the read-only surface reads third-party script bodies and renders strings taken out of them |
| warning string -> rendered `info` row | `redactAbsolutePaths` runs here; the row's bytes are published |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-115-18 | Information disclosure | the gate `note:` line on the `info` row | high | mitigate | `previewWorkflows` maps `redactAbsolutePaths` over every warning before returning (`info.ts:790`, NFR-9). Task 1 asserts the rendered row contains no absolute path from the fixture's temporary home — a positive check on the redaction rather than an assumption about it. |
| T-115-19 | Spoofing | the published catalog block | medium | mitigate | The catalog block is a hand-written fixture driven through the real `notify()` renderer and compared byte-for-byte, and the fixture must round-trip through the formatter unchanged. A block that says something `notify()` does not emit reddens. |
| T-115-20 | Denial of service (against the plugin author) | the `info` row's severity | high | mitigate | The `note:` channel is documented as severity-neutral and carries no closed-set reason token; Task 1 pins status, severity and reasons brace against a gate-free run of the same fixture. No new `REASONS` member is added, so the closed set stays at 45 and its lock tests stay out of this phase. |
| T-115-21 | Tampering | dependency manifests, Sonar properties, changelog | high | mitigate | Task 2's fourth verify command proves none of them was touched. |
</threat_model>
