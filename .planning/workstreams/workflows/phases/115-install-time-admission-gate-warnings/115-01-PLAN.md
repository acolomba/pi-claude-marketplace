<objective>
Read the host engine's six unreplicated-but-detectable admission gates off the acorn
AST `admitWorkflowScript` already produces, carry the gate out as one per-script
warning line, and make a standalone install actually show it.

Purpose: a plugin author who ships a workflow script the engine will refuse learns
it at install time, with the refusing check named, instead of at first invocation.

Output: a closed six-member gate union bound to a total predicate map, a `gate`
field on the two ADMITTED verdict arms only, a sixth `WorkflowOutcomeSite`, one
gate reason sentence per gate, and the `install.ts` reclassification that stops
the standalone install dropping the channel on the floor.
</objective>

<module_boundary_decision>
**The gate reader lives INSIDE `extensions/pi-claude-marketplace/domain/workflow-script.ts`.
No new module.** This decision is made here, explicitly, because it changes the file
list (115-VALIDATION.md "Wave 0 Requirements", RESEARCH Assumptions Log A5).

Reasons:

1. The reader consumes `ParsedScript.ast` and the `MetaElement[]` `findMetaObject`
   returned. Both are module-private. A separate module forces exporting them,
   widening the public surface of a module whose whole contract is that script text
   never becomes a name.
2. WGATE-02's gate ("no second parse") then has exactly ONE scan target.
3. `scripts/check-corresponding-tests.mjs` maps every production module 1:1 onto
   `tests/<rel>.test.ts`. Keeping the reader here means the existing
   `tests/domain/workflow-script.test.ts` satisfies the pairing gate and
   **no new paired test file is required in this phase**. A new
   `domain/workflow-gates.ts` would have required `tests/domain/workflow-gates.test.ts`
   in the same commit.
4. Cost accepted: the file grows past its current 817 lines. There is no file-size
   gate; fallow's `maxUnitSize: 60` is per unit, and every helper this plan adds is
   small by construction.
</module_boundary_decision>

Implement one small predicate per gate, each returning `true` when the engine WOULD
refuse there:
  - check 3: `first?.type` is not `"ExportNamedDeclaration"`.
  - check 4: the `ExportNamedDeclaration`'s `declaration` is absent, is not a
    `VariableDeclaration`, or its `kind` is not `"const"`. This covers `let`, `var`,
    a re-export whose `declaration` is null, and a non-variable first export.
  - check 5: `declaration.declarations.length` is not 1.
  - check 6: the sole declarator's `id.type` is not `"Identifier"`, or its `name` is

    normalization (the `ObjectPattern` arm of this check is unreachable here, because
    `findMetaObject` already settled it as a `no-meta` skip).

    all resolvable; and a `UnaryExpression` with operator `-` over a numeric `Literal`.
