## Settled design calls (do NOT re-litigate at execution time)

- **Delete the probe BLOCK, keep the test case.** CONTEXT says to delete the
  guard; the guard is the block. Deleting the whole case would take with it the
  only assertion in the file where a git-source uninstalled plugin seeded
  through the plain manifest path renders a bare unfetched row. That is thin
  coverage, but it is not zero and it is not this phase's to remove.

- **The deletion is two regions, not one.** The correct sibling's own comment
  points at the block being deleted. Repair that sentence in the same change.

- **Keep the corrected variant-count sentence; restore the enumerable clause.**
  The two documentation sub-edits the review flagged are not the same call. The
  variant count was verified true against the pre-milestone tree, so it fixes a
  genuine pre-existing error — keep it and flag it in the SUMMARY, as the review
  itself offered. The enumerable clause traded a checkable specification
  statement for a pointer at the implementation, in the one document whose job
  is to be the specification — restore it.

- **Type the holder against the domain reason type, not against an
  intersection of its two consumers.** The values ARE that type, and the
  type-only import is a one-line, convention-conformant addition. An
  intersection encodes the current consumer list into a type expression that a
  third consumer would silently not join; the domain type degrades gracefully.

- **The gate header's enumeration is replaced by a pointer, not extended.** A
  hand-maintained list of eleven targets beside an annotated array of eleven
  targets is a second copy that will drift again. The array below it already
  carries per-entry rationale.

- **No new decision IDs.** Cite durable requirement-level IDs.
