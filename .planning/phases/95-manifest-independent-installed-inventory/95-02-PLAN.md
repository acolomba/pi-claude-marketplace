<objective>
Carry the manifest-absence fact onto the LLM tool surface so an agent reading
`pi_claude_marketplace_plugin_list` sees the same thing a human reading
`/claude:plugin list` sees.

Purpose: `projectRowStatus` already flattens `installed`, `upgradable`,
`partially-installed` and `partially-upgradable` into one `installed` tool
bucket, and `pluginReasons` currently drops the reasons for two of those four.
The result is that a degraded install is today indistinguishable from a clean
one in the tool payload and its unsupported-kind reasons are discarded — a loss
that predates this milestone. Without the widening, `{not in manifest}` would
render on the slash command and silently vanish for the agent.

Output: one widened projection in `edge/handlers/tools.ts`, its stale doc
comment corrected, and tool-execute assertions on both the `installed` and the
`partially-installed` arm plus the phase-wide invariant gate.

Requirement mapping: INV-05 (Tasks 1 and 2), per D-95-06 / D-95-07.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| orchestrator row → LLM tool payload | `pluginReasons` is the projection point; whatever it returns reaches a model's context without the human review a rendered terminal row receives. |
| marketplace clone → orchestrator → tool | `marketplace.json` content, remotely authored, now influences a field the agent reads. |

No new input surface, no network call, and no write is introduced by this plan.
The tool is read-only: `loadToolPluginPayload` calls `loadPluginListPayload`,
which is the same offline read path the slash command uses.
