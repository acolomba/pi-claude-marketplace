<objective>
Write the missing owner for the per-verb flag catalog, closing one of the six correspondence-gate
violations this phase owns.

Purpose: `edge/flag-catalog.ts` has no test at its mirrored path (D-116-08). It is the single source
of truth for every per-verb long flag, and four derivation functions read it: `isCatalogVerb`,
`completionFlagEntries`, `parseFlagNames`, and `passThroughFlagNames`. The trap here is that the
natural way to test a derivation is to assert its output, which names the flags — and
`tests/architecture/flag-catalog-drift.test.ts` already pins every verb's flag set exactly. This
owner therefore proves the **transformation**, not the data.

Output: one new owner for `edge/flag-catalog.ts` that owns the four derivations and leaves the
per-verb contents to the gate that already holds them.
</objective>

of `test()` bodies, no `describe()`, no fixture, no context. The module's runtime exports are
`CATALOG_VERBS`, `isCatalogVerb`, `SCOPE_TARGET_FLAG`, `completionFlagEntries`, `parseFlagNames`,
and `passThroughFlagNames`; `CatalogVerb` is a type.

**Frame every promise as a transformation.** Read `tests/architecture/flag-catalog-drift.test.ts`
first: it already pins each verb's completion labels and parse-set exactly. Restating those sets
here is the duplication D-116-12 forbids. Choose the smallest verb that discriminates each branch:

- `info` declares exactly one entry and that entry has a description — use it to prove the
  `description` key is carried through.
- `uninstall` declares exactly one entry, and that entry is the scope-target flag with
  `complete: false` — use it to prove the completable filter drops it and that
  `passThroughFlagNames` returns nothing for a verb whose only parse-accepted flag is the scope
  target. Do NOT use it to prove a description-less completion entry: it never reaches the map
  callback, and after this plan's production edit no such entry can exist at all.
- `fetch` declares no entries — use it to prove the empty-array result of both
  `completionFlagEntries` and `passThroughFlagNames`, and the empty `Set` result of `parseFlagNames`.

Cover:

- `completionFlagEntries` filters to the completable entries only, proven by a verb that carries a
  parse-accepted but never-completed entry: the returned list omits it while `parseFlagNames` for
  the same verb contains it. Name the verb and the flag by reading the catalog, and state the
  relationship rather than the flag list.
- Order preservation. Compare the returned array as one whole value against a hand-authored literal
  in catalog declaration order, and prove the order is a property of the declaration rather than of
  object key iteration or a sort: take a verb with two or more completable entries and assert the
  first element is the one declared first. Do not sort the result before comparing, and do not
  compare as a set.
- Stability when two entries compare equal. No two entries in any verb carry the same description
  text, so that literal target does not exist in the data — record its absence rather than inventing
  a case. Discharge the claim on the axis that does exist: all five `list` entries compare equal on
  `complete`, the only field the derivation inspects, and the whole unsorted array is asserted.
  A `.toReversed()` plant proves that comparison catches a reordering among equal-comparing entries.
- `parseFlagNames` returns a `Set`, and the caller can mutate the returned `Set` without affecting a
  later call — call it twice and assert the second result still holds the entry the case deleted
  from the first.
- `passThroughFlagNames` excludes exactly `SCOPE_TARGET_FLAG`: for a verb whose only parse-accepted
  entry is the scope-target flag, the pass-through list is empty while the parse-set has one member.
  For a verb that carries the scope-target flag alongside others, the pass-through list is the
  parse-set minus that one name, in declaration order.
- `isCatalogVerb` accepts every member of `CATALOG_VERBS` through a row table driven from
  `CATALOG_VERBS` itself, rejects a plainly-unknown string, and rejects an inherited object property
  name such as `toString` or `constructor` — the last is the discriminating proof that the guard
  tests own keys rather than prototype-chain membership.
- `CATALOG_VERBS` is a non-empty list of distinct values and every member satisfies `isCatalogVerb`.
  Do not assert the list's contents or its length.
