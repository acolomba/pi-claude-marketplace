Two pieces of work, in this order.

**First, the owner.** Rewrite `tests/edge/handlers/shared.test.ts` in the G3 helper shape. One
export means no `describe()` is needed: keep a flat sequence of `test()` bodies. Build the Pi
boundary with `createNotificationBoundary` from `tests/helpers/notification-boundary.ts` — never a
hand-rolled context object. `extractLocalFlag` reaches the user only through `notifyUsageError`,
which writes straight to the notification channel and runs **no** soft-dependency probe, so every
case sizes the boundary at zero probes; the accepting cases emit nothing at all and size the
boundary at zero emissions, which is itself the proof that a successful scan is silent.

Cover, asserting the whole `{ local, residualArgs }` object against a hand-authored literal:

- No flags: `local` is `false` and the residual is the input tokens rejoined with single spaces.
- Scope-target flag present: `local` is `true` and the token is **removed** from the residual. Drive
  it leading, trailing, and between positionals through a row table; every row asserts the identical
  whole value, which is the position-independence proof.
- Two scope-target tokens: both are removed and `local` is still `true`.
- A `--scope` pair is consumed by the scanner but **survives in the residual**, because the
  downstream parser consumes it: assert the residual still carries both tokens.
- The scanner does not validate the `--scope` value: an unrecognised value still returns a result
  rather than `undefined`, and emits nothing. This is where the responsibility split lives — the
  value is rejected one layer down, and this owner proves the scanner passes it through.
- `--scope` immediately followed by the scope-target flag: the pair consumption treats the next token
  as the value, so `local` stays `false` while the residual filter still drops the token. Assert the
  whole value; this is a genuine and easily-lost behavior.
- A pass-through long flag supplied in the caller list survives verbatim in the residual and does not
  set `local`. Drive the list from `passThroughFlagNames` for the verb that uses it, so a catalog
  change is a compile-and-behavior link rather than a hand-copied literal — but do not assert the
  catalog contents.
- An unknown long flag rejects: the function returns `undefined`, and the boundary recorded exactly
  one notification whose whole value is
  `{ message: "<the unknown-flag sentence>\n\n<the usage block>", severity: "error" }`. Write both
  halves out by hand from the module source; do not interpolate the usage string the case passed in,
  and do not build the expected message by calling the production formatter. Call `verifyBoundary()`
  at the end of the case.
- An unknown long flag appearing **after** a valid scope-target token still rejects and still emits
  exactly one notification, proving the scan does not stop early.
- A single-dash token is not a long flag: it is preserved as an ordinary residual token.
- Whitespace: repeated interior spaces, a leading space, and a trailing space all produce a residual
  with single-space separators and no empty tokens.
- Empty argument string: `{ local: false, residualArgs: "" }` with zero notifications.
