<objective>
Make an update refresh a disabled record's resolved source and compatibility block when they move
under an unchanged version pin, by letting the disabled-record branch run before the unchanged-version
short-circuit and making the previously-unreachable deep-equal guard load-bearing (D-99-05a,
option 1 of the carrier).

Purpose: the refresh function exists precisely so a disabled record's pin stays current for a later
enable, but the preflight returns the unchanged outcome as soon as the versions match — before the
disabled branch is ever reached. That is right for the version and wrong for everything else the
refresh owns: a path-source marketplace re-added from a different directory, or a manifest entry
that gains or loses an unsupported kind without a version bump, both move independently of the
version. The record then points a later enable at a path that may not exist, or gates it on a stale
availability flag. This is a missing write, not a spurious one — the mirror image of the finding it
was discovered beside, and covered by no earlier review.

The guard is the subtle half. It was drafted during an earlier fix pass and reverted as dead code,
which it was: the current ordering prevents the branch from ever seeing an unchanged record.
Reordering makes it reachable, and reachability that nothing pins will look like dead code again to
the next reader — so the plan requires a test that fails without it.

Output: a self-healing disabled record, an unchanged rendered row, and a guard with a reason to exist.
</objective>
