<objective>
Widen the ENBL-05 disabled-state drift gate so the three twin spellings that escape it today —
destructured `{ enabled }`, bracket access `record["enabled"]`, and `Boolean(record.enabled)`
comparison — are caught, with each new pattern proven in both directions: it flags its planted
twin, and it does not flag the legitimate consumers or the excluded config axis (D-99-02b).

Purpose: the live gate's three regexes all require `!` or a comparison operator adjacent to an
identifier path ending in `.enabled`. A `(` (Boolean), a `[` (bracket) or a bare identifier
(destructured) each break the match, so a natural-looking rewrite of a disabled-state check slips
through a gate whose entire point is that no second definition of "disabled" can exist. D-99-02b
mandates the two-directional proof explicitly.

Output: a strictly stronger gate in the same file, with no production line touched.
</objective>
