# Phase 3.2 Plan 01: Marketplace re-declaration across layers Summary

**`marketplace add` now declares a marketplace the scope already records in the second config layer, matched by `samePlannedSource` before any clone, so the same marketplace can live in claude-plugins.json and claude-plugins.local.json with no second clone and no state write.**

## Accomplishments

- `orchestrators/marketplace/add.ts`: new module-private `redeclareRecordedSource`. In standalone mode it collects the scope's records whose source `samePlannedSource(record.source, rawSource)` reads as `"same"`. On exactly one hit it either throws `MarketplaceDuplicateNameError` (the target layer declares the name, read with `ownValue`) or writes only the target entry through `writeMarketplaceConfigEntry` with the source as typed and returns the name without `tx.save()`. No clone, no git call. The WR-05 header note and the flow diagram now state the present behavior.
- `orchestrators/plugin/bootstrap.ts`: the trade-off paragraph now says that an idempotent re-run meets the duplicate check before any clone, and that a local-only declaration gets declared in claude-plugins.json.
- Scenarios: the LAYER-01 Outline (untagged dir/file rows, `@url`, `@github`), the reverse-direction scenario, and two duplicate-name guards.
- Integration: `tests/integration/marketplace-layer-redeclare.test.ts` (two cases) and one convergence case in `reconcile-plan-convergence.test.ts`.
