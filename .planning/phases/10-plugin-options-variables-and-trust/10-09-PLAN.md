<objective>
Write a plugin option's default into skill, command, and agent content where the content
names `${user_config.KEY}`, with the placeholder for a sensitive option.

Purpose: PG-CORE-03 under D-PG10-08, D-PG10-09, D-PG10-13, and D-PG10-21. Content is filled
at staging, the point where this extension already writes the path variables, because the
agent file is read by pi-subagents and the staged skill and prompt files by Pi. Commands are
filled because Claude Code's commands are skills. The sensitive rule holds although step 1
has only public defaults, so that values a user sets later need no content change. Under
D-PG10-19 (pending maintainer review), a declared default counts as a saved value here, which
is more than Claude Code 2.1.323 does for content.

Output: one content substitution in `shared/vars.ts`, the three stagers and their inputs fed
with options from both ledger hubs, three new feature files, and the corrected note in
`domain/argument-substitution.ts`.
</objective>

## Planner decisions

- **Two functions in `shared/vars.ts`, one pass each.** `substituteClaudeVars(content, vars)`
  keeps its signature and behavior for the hooks bridge. A new exported
  `substituteClaudeContent(content, vars, options)` adds the option references to the same
  alternation for content. Its `options` parameter is required and is either a structural
  value declared in `shared/vars.ts` (a values map and a sensitive set) or `undefined` for a
  plugin that declares no `userConfig`. `ResolvedOptions` of `domain/user-config.ts` satisfies
  that structure; `shared/` imports nothing from `domain/`.
- **New feature files.** `features/skill/options.feature`, `features/slash-command/options.feature`,
  and `features/agent/options.feature`, each `Feature: <Function> options`.
