<objective>
Set one process variable per plugin option on Pi's process, owned through a ledger, so that an
adapter entry can reference an option without holding its value.

Purpose: D-PG10-11 and D-PG10-23 (both pending maintainer review). pi-mcp-adapter reads only
its config file and the process environment, so the process environment is the one place an
option value can be that is not `mcp-adapter.json`. This extension already does this for
`CLAUDE_PROJECT_DIR` (AVAR-01) and owns `PATH` entries through `PI_CLAUDE_MARKETPLACE_PATH`.
The security choice of D-PG10-23 is taken as written: user-scope variables in the awaited
factory, project-scope variables only once the load's trust answer is true. Plan 10-02 proved
against the adapter's own function that the escaped value comes out as the raw default. This plan sets the variables; plan 10-17 writes the references. Setting them first is safe: until
an entry references one, nothing reads it.

Output: the pure ledger core, the new orchestrator pair, the entry-point wiring, and two
scenarios that show the variables in the bash tool's environment, which is the recorded
divergence of D-PG10-11.
</objective>

## Planner decisions

- **Every option of the MCP value map of every enabled record that declares options gets a
  variable.** Which fields reference which key is decided at the stage, so the variables do
  not depend on it. The values are public manifest text in step 1; the exposure to other
  children of Pi is the recorded divergence of D-PG10-11.
- **The ledger tags each name with its scope.** `PI_CLAUDE_MARKETPLACE_OPTIONS` is a
  comma-joined list of `<scope>:<name>` entries. A scope then has three outcomes at an apply:
  fresh names from its state, keep (its state could not be read, or the factory has no trust
  answer for the project yet), or remove (the project is not trusted).
- **One factory-created object holds the last load's working directory and trust answer.**
  The entry point creates it once per extension load; the after-command apply reads them from
  it, so no command adds a trust read.
