<objective>
Fill `${CLAUDE_PROJECT_DIR}` with the session's working directory for a user-scope skill or
command at the invocation step, in the model-read fill, and in `run_plugin_command`.

Purpose: PG-CORE-05 under D-PG10-16 (PRD decision 10, pending maintainer review; amends
SUB-02). Claude Code resolves the three path variables anywhere in the body of skill, command,
and agent content at every scope. This project keeps the literal at user scope because content
was once written only at install, when the project of a later session is not known. The
invocation-time port (D-CF1-01) made that reason stale: the two orchestrators already know the
session's working directory and already fill it at project scope. Every typed, alias,
model-read, and tool path goes through two gates, so removing two conditions is the whole
product change. Agent bodies stay as they are: pi-subagents reads the agent file itself.

Output: two changed orchestrators with their owner cases, four red scenarios, and one guard.
The records (the D-PG10-16 row, `docs/env-vars.md`) are plans 10-19 and 10-20.
</objective>
