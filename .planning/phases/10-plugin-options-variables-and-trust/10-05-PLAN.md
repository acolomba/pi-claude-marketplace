<objective>
Make `userConfig` a parsed input of the resolver instead of an unsupported kind: a plugin
whose options all have a default installs without `--partial`, a malformed `userConfig` makes
the plugin unavailable, and a required option with no default keeps the plugin partially
available.

Purpose: PG-CORE-03 under D-PG10-04, D-PG10-05, D-PG10-06, D-PG10-20, and D-PG10-24. Upstream
treats `userConfig` as an input to hooks, MCP servers, and content, not as a component. The
motivating plugin, `code-modernization`, has seven options, all with defaults, and today needs
`--partial`. This plan changes the resolver's three outcomes and carries the parsed schema on
the resolution for the plans that deliver the values. The reason token of the partial arm and
the `info` breakdown are plan 10-06; here the partial arm keeps today's token, so no install
that is refused today is admitted by an intermediate commit.

Output: the resolver stage with its owner cases, the two note prefixes with their classifier
arms, the completion cache version, and `features/plugin/options.feature` with three scenarios.
</objective>

## Planner decisions

- **The malformed arm reuses `invalid manifest`.** A `userConfig` that fails upstream's schema
  is upstream's "invalid manifest file". Reusing the existing failure-class token adds no
  member to the closed reason vocabulary. The note carries the key or field.
- **The resolution's member is optional.** `declaredUserConfig` is present only when the
  plugin declares `userConfig`, by the entry-or-manifest rule, and absent otherwise, in the
  form of `mcpBundle` and `hooksConfigPath`. The resolver is its one production producer, so
  an optional member cannot be forgotten by a second producer, and absence carries a fact that
  D-PG10-21 needs: a plugin that declares no `userConfig` keeps MCP and content references
  literal. The carriers that have several producers (hooks cache entries, staging inputs, the
  MCP substitution context) take the option data as a required member in plans 10-08 to 10-18.
- **The partial arm's kind is `userConfig`.** A record that an earlier release installed with
  `--partial` because of `userConfig` already holds that kind, so after plan 10-06 both read
  as "options not set" until a restage delivers them (D-PG10-15).
- **Note texts.** `USER_CONFIG_MALFORMED_NOTE = "malformed userConfig"`, followed by `: ` and
  the parser's detail. `USER_CONFIG_UNSET_NOTE = "required userConfig options have no
  default"`, followed by `: ` and the keys joined by a comma and a space.
