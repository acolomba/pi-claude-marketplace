<objective>
Fill `${user_config.KEY}` in the five MCP fields that take variables under pi-mcp-adapter,
without writing an option value into `mcp-adapter.json`.

Purpose: PG-CORE-03 under D-PG10-11, D-PG10-21, and D-PG10-23. Claude Code 2.1.323 fills
options in `command`, `args`, `env`, `url`, and `headers` after the path variables. Both
encodings of this extension go through one walk, `expandClaudeValue`, which today leaves
`${user_config.KEY}` as text because the key holds a dot. Under pi-mcp-adapter the entry gets
a reference to the process variable that plan 10-10 sets and the adapter expands at connect.
Plans 10-12 to 10-15 already leave out, at every staging, a server that names an option with no value
or that an option would turn into a home path, so every reference this plan writes has a
value and is safe to fill. Plan 10-19 fills the same fields under Pi's built-in MCP.

Output: the option pass of the walk, the adapter stage's references and environment overlay,
conformance cases against pi-mcp-adapter, and the adapter scenarios of
`features/mcp-server/options.feature`.
</objective>

## Planner decisions

- **One walk, two forms; the encoder chooses.** The option pass of `expandClaudeValue` emits
  a `ref` segment with the owned name for the adapter encoding and a `text` segment with the
  value for the built-in encoding. It never goes through `segmentFor`. `McpFieldEncoder` says
  which form its encoding takes.
- **The names ride on the adapter's encoder.** The stage builds the adapter's encoder for one
  plugin, with the owned name of each option. So the shared substitution context does not
  change, and no fixture of it changes.
- **The built-in encoding takes no option pass in this plan.** `BUILTIN_FIELD_ENCODER` states
  that, so the config Pi's built-in MCP gets is as before. Plan 10-19 gives it the text form.
  The two encodings are separate plans because each has its own conformance test and its own
  scenarios.
- **Scenario tags.** The reference-only entry is `@adapter-only (PG-CORE-03, D-PG10-11)`.
  The field scenarios are `@adapter-only` in this plan, with PG-CORE-03 in their titles; plan
  10-19 makes each one whose result is the same under both implementations `@mcp`.
