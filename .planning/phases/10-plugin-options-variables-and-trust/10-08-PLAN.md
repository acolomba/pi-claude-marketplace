<objective>
Fill `${user_config.KEY}` in exec-form hook commands and arguments, fail a hook run that
names an option with no value, and refuse a shell-form hook command that names an option.

Purpose: PG-CORE-03 under D-PG10-08, D-PG10-10, and D-PG10-21. D-CF5-15 fills the three path
variables in exec form and keeps `${user_config.*}` literal; this plan amends it. Claude Code
2.1.323's hook runner fills options after the path variables, throws for a key with no value,
and refuses a shell-form command that names an option, because a spliced value would be parsed
again by the shell. It does so for every plugin hook, also one whose plugin declares no
`userConfig`. Both lanes of this extension plan their spawn in one function, and the
synchronous lane already turns a throw before the spawn into a start failure the user sees.

Output: the fill and the refusal in `planSpawn`, two typed errors with upstream's texts, three
new scenarios, and the changed path-variable scenario.
</objective>
