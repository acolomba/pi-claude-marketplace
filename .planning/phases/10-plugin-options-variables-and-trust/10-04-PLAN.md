<objective>
Keep a project-scope plugin's `bin` off `PATH` in a project Pi does not trust, and put a
plugin's `bin` on `PATH` only when the folder exists.

Purpose: PG-CORE-06 under D-PG10-02 and PG-CORE-07 under D-PG10-03, with the three details of
D-PG10-22. Today `recomputePluginPath` reads both scopes whatever Pi's trust answer is, and it
appends `<pluginRoot>/bin` whether or not the folder exists. Claude Code 2.1.323 loads no
project-scope plugin before trust, and its `getEnabledPluginBinPaths` keeps a `bin` only when
`stat` says it is a directory and the path holds no shell metacharacter. The load already
computes the trust answer for the hooks hydrate, 36 lines above the one call of the recompute,
so the gate is one argument. The ledger already removes every entry a scope no longer gives,
so an untrusted project's earlier entries leave with no new code.

Output: the gated and filtered recompute with its owner cases, the load wiring, two red
scenarios, and the corrected comments. The records (PENV-01, `docs/env-vars.md`) are plans 10-20 and 10-21.
</objective>
