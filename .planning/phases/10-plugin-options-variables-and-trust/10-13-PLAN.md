<objective>
Leave out, and report, a plugin MCP server that names an option with no value at update, at
reinstall, and at the load-time MCP move, and drop its notice when the command unstages the
plugin.

Purpose: D-PG10-08 as amended by D-PG10-21. Plan 10-12 made the stage leave such a server out
and report it, and fed the stage from the install ledger. The stage has two more callers: the
update path, which a reinstall also runs, and the load-time move of servers that an earlier
release wrote into `mcp.json`. Both still pass no options, so both write the entry with the
reference as written. This plan gives each its options. It lands before the fill of plan
10-17, so that a restage never writes a reference to a variable that has no value, and a
reinstall writes the same entry as the install did.

Output: the options at the two restage callers, the fold's rule for the notice, and a
reinstall scenario.
</objective>

## Planner decisions

- **The reinstall scenario is in `features/mcp-server/lifecycle.feature`.** That feature holds
  what each plugin verb does to a plugin's servers, and its reinstall scenarios state the
  adapter file after the command. Plan 10-15 changes `features/mcp-server/options.feature`
  in the same wave.
- **The key is one the manifest does not declare.** The scenario's plugin declares an option
  with a default, so it installs and reinstalls with no `--partial`; the server that is left
  out names another key.
- **The fold drops by plugin.** `foldUnstageNotices` drops an `option-blocked` notice of the
  unstaged plugin and scope whatever its server, because a blocked server is never among the
  dropped servers.
- **The move and the fold have owner cases and no scenario.** The move needs an `mcp.json`
  that an earlier release wrote for a server the stage now leaves out, and the fold needs a
  cascade that rolls a staged plugin back; the harness seeds neither. Both call the stage
  that the reinstall scenario and the scenarios of plan 10-12 show.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a plugin's MCP server declaration to a started process or a remote request, at a restage | An update, a reinstall, or the load-time move writes the entries again from the plugin's files. |
| an MCP notice to the terminal and to JSON consumers | A command's result lists the notices of what it staged and unstaged. |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-10-50 | Tampering | a restage path that passes no options, so a server that the install left out is written with the literal reference at the next update, reinstall, or load-time move | medium | mitigate | Both callers pass the options of their resolution through the one options function; owner cases state what each caller hands the stage; a scenario shows the file and the notice after a reinstall. The acceptance check reads every call of the stage. |
| T-10-51 | Repudiation | an `option-blocked` notice that stays in a command's result after the command unstaged the plugin, so the result reports a block on a plugin that is not installed | low | mitigate | The fold drops the notices of the unstaged plugin and scope by plugin, since a blocked server is never among the dropped servers; owner cases cover the plugin, another plugin, and the other scope. |
| T-10-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package installs or version changes. Any changed install scope requires the legitimacy audit and a blocking human gate for assumed or suspect packages. |
