## Phase plan map (13 sequential plans, one per wave)

This phase removes Device Flow in an order that keeps `npm run check` green after every plan:
05-01 pins (this plan); 05-02..05-05 stop threading the injectable credential seams, the Device
Flow transport, and the sign-in memo through the verbs, by family; 05-06 removes Device Flow (the
behavior change); 05-07 removes the `device-flow-prompt` kind; 05-08 removes the sign-in retry and
its one-shot helper; 05-09 replaces the auth-host builders with one pure host binding; 05-10
shrinks the bundle to its host and deletes the credential module; 05-11 removes the print-mode
refusal error and the `credential` git subcommand; 05-12 renames the Device Flow harness and
rewords every comment and test title that still describes Device Flow; 05-13 writes the records
and docs.

## Running checks

Every command runs with the session's injected git config removed (RESEARCH Pitfall 6). The
prefix `env -u GIT_CONFIG_COUNT $(env | sed -n 's/^\(GIT_CONFIG_\(KEY\|VALUE\)_[0-9]*\)=.*/-u \1/p')`
does that and is part of each command below. Tests never reach a real host: the routed profile
Pi refuses every non-loopback host, its CONNECT proxy tunnels only `github.com:443` to the git
host, and the ssh stand-in comes first on PATH (this container has no ssh). Known baseline: the
five `fd`-dependent Glob scenarios of `features/hook/tool-use.feature` (:296 :355 :443 :1696
:1834) fail in this container. Write `PLAN_BASE=$(git rev-parse HEAD)` into the SUMMARY draft
before Task 1. Token values in feature files are plain words such as `env-github-token-value`
and `env-gh-token-value`, never a string shaped like a real GitHub token, so no secret scanner
reads them as one.
