## Why one commit

The bundle's type change breaks every fresh literal that still holds `kind` or `credentialOps`
(`tsc` runs in `check:commit`). The private `DEFAULT_CREDENTIAL_OPS` then has no reader, and an
unused local fails `tsc`. `platform/git-credential.ts` then has no production importer, and
fallow fails an unreachable file. The leak test's git-credential scan fails its D-07-03
existence check once the file is gone, and `no-shell-out.test.ts` expects the importer row the
zone no longer admits. So the type, the composition, the module, its doubles, and the gates
change in Task 1's one commit.

The test edits are mechanical. Grep `kind: "stored-credential"`, `"stored-credential"`,
`credentialOps`, and `createCredentialOpsFake` under `test/`, then:
- make each bundle literal `{ host: "<host>" }`;
- make each `{ kind, host }` projection a whole-bundle `{ host }` assertion;
- drop each credential fake, its import, and the options that carried it.

Task 1 deletes two non-`.test.ts` files under `test/` and edits `gate-targets.ts`, so its
`check:commit` runs every source-test pair; that is expected. The Running checks of
05-01-PLAN.md apply.
