## The threading rule (05-02 to 05-05)

Each threading plan removes, from its verb family: every `deviceFlowHttp` option, field, and
forward; every `authMemo` option, field, allocation, and forward, with its
`AuthAttemptResult` import; and every injectable `credentialOps?` option on a command-level or
forwarding options type. Where a module builds an auth context today from
`opts.credentialOps ?? DEFAULT_CREDENTIAL_OPS`, it now passes `DEFAULT_CREDENTIAL_OPS`. Internal
auth contexts that the builders take (`CloneAuthArgs`, `RefreshOneArgs`, the probes' `auth`)
keep a required `credentialOps` and their `ctx`/`run`: 05-09 removes them with the builders,
after Device Flow is gone. The builders in `orchestrators/auth-host.ts` do not change here.
Comments that name a removed seam or the once-per-host memo are reworded or removed in the same
edit. A test that drives `onAuthRequired` or injects `createDeviceFlowFake` is a Device Flow test
and is deleted (`auth-host.test.ts` and `device-flow.feature` keep covering Device Flow until
05-06). A test that injected `createCredentialOpsFake` only to keep the keychain out stops
injecting it; the case's stored-bundle assertion compares `{ kind, host }`, which are the fields a
request reads. A case that asserts a github.com or gitlab.com bundle has the Device Flow kind
either tests Device Flow (its point is that kind: delete it) or tests something else that the
kind only accompanies, such as a bundle forwarded by reference, the host a bundle binds, or a
clone order: that case asserts its own behavior without the kind (the same object for
forwarding, `host` for binding), so it stays true when 05-06 gives every host a stored-credential
bundle. Run `npm run --silent test:coverage:direct -- <source>` for every touched source: a
deleted case can leave a branch uncovered (RESEARCH Pitfall 5).
