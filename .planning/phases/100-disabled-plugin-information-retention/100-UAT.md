### 1. Disabled plugin stays inspectable after its manifest entry disappears

expected: The row reports `(disabled) {not in manifest}` with the retained description and component inventory (including hooks sourced from the record), and the plugin's hooks do not fire after `/reload`.
result: pass
fixture: `tmp/uat-100/` (path-source marketplace `uat-100`, plugin `hooked-inventory`, five kinds incl. a `UserPromptSubmit` probe hook)
observed: |
  Live-Pi run (pi 0.84.1, worktree build, sandbox `tmp/pi-uat`), 2026-08-12:

  1. Baseline: `HOOKPING` prompt was replaced by the hook's `additionalContext`;
     marker file recorded 1 firing.
  2. After `disable` + manifest-entry drop + `/reload`, `info` rendered:

         ● uat-100 [user] <no autoupdate>
           ◍ hooked-inventory v1.0.0 (disabled) {not in manifest}
             agents: pi-claude-marketplace-hooked-inventory-uat-retained-agent
             commands: hooked-inventory:uat-retained-command
             hooks:
               UserPromptSubmit
             mcp: uat-retained-mcp
             skills: hooked-inventory-uat-retained-skill

  3. A second `HOOKPING` prompt was NOT transformed (the model saw the literal
     word) and the marker stayed at 1 firing -- the hooks are dead after
     `/reload` even though `hooks.json` is still on disk.

  The `hooks: UserPromptSubmit` line is the load-bearing evidence for ENBL-12:
  it is read from the record's `hookEntries`, not from the on-disk file.
note: |
  The checkpoint wording says "the retained description AND component inventory".
  The inventory is retained; the DESCRIPTION is not, and that is the documented
  contract rather than a defect -- `info.ts`'s record-backed arm (INFO-09/10/11,
  D-96-01) treats description and dependencies as manifest-only metadata it does
  not reconstruct. The still-declared sibling (`disabled-declared`) does keep its
  description. Tester accepted the row as correct; recorded as an observation,
  not a gap. The checkpoint prose is the thing that overstates.

Steps:

1. Install a plugin that declares hooks: `/claude:plugin install <plugin>@<marketplace>`
1. Disable it: `/claude:plugin disable <plugin>@<marketplace>`
1. Remove the plugin's entry from the marketplace manifest
1. `/reload`
1. Run `/claude:plugin info <plugin>@<marketplace>`
1. Trigger an event the plugin's hooks subscribe to, and confirm nothing fires

This is the phase's core claim end to end. It spans the Pi extension host
lifecycle, which no automated suite exercises. `100-VALIDATION.md` scoped it
manual-only from the start.

### 2. Concurrent `info` invocations do not interleave

expected: No interleaved partial read. Each run reads one already-loaded state snapshot, because `list` and `info` acquire no lock and perform no write.
result: pass
fixture: `tmp/uat-100/churn.mjs` (write-side driver) + `bulk-skills` (200 skills)
observed: |
  Live-Pi run (pi 0.84.1, worktree build, sandbox `tmp/pi-uat`), 2026-08-12.
  Two halves, because the checkpoint's literal reading (two readers) is weaker
  than the claim deserves:

  - Half A -- two Pi sessions on one sandbox ran `info` and `info --fetch`
    against the same plugin near-simultaneously. No torn read.
  - Half B -- the stronger one. `churn.mjs` drove the REAL extension in-process
    against the same scope, installing and uninstalling the 200-skill
    `bulk-skills` plugin in a loop for 24 cycles while the tester ran `list`,
    `info bulk-skills` and `info hooked-inventory` from Pi. Each cycle held the
    per-scope state lock for a 1.3-2.8s write window, so reads landed inside an
    active writer repeatedly rather than by luck.

  Every rendered row was complete and self-consistent. `bulk-skills` alternated
  `(available)` / `(installed)` between runs -- the writer working, not a tear.
  No partial record, no truncated field, no lock error surfaced on a read path.

  Post-run state inspection: no orphaned `bulk-skills` record and no orphaned
  staged skill directories; the two disabled records still carried populated
  five-kind inventories and `hookEntries`.
note: |
  This upgrades the claim's evidence from inference to observation, but it stays
  a sampling argument: 24 windows is not a proof of the absence of a race. What
  it does establish is that the no-lock/no-write read path survives sustained
  concurrent writes, which is what `verification: backstop` left open.

Steps:

1. Run two concurrent `/claude:plugin info` invocations against one scope
1. Repeat with `--fetch` on one of them
1. Confirm neither run reports a torn or partial record

Marked `verification: backstop` in the 100-02 and 100-04 plan frontmatter, so no
automated concurrency test was written. Code inspection supports the claim (no
lock acquisition, no `saveState` call anywhere on the `list`/`info` path), but
inspection is inference, not evidence.

### 3. A retained inventory is never presented as live

expected: The `(disabled)` status token holds its position at the head of every rerouted row. Description and component lines never displace or soften it.
result: pass
fixture: `tmp/uat-100/` -- three row shapes side by side (`control-declared` live, `disabled-declared` disabled + declared, `hooked-inventory` disabled + manifest-absent)
observed: |
  Live-Pi run (pi 0.84.1, worktree build), 2026-08-12. `list` put all three
  shapes in one frame and `info` was read for each. In every disabled row the
  `(disabled)` token sat immediately after name and version, in the same slot an
  installed row uses for `(installed)`; description and component lines rendered
  below it, never in its place. The manifest-absent row carried
  `(disabled) {not in manifest}` with the reason brace after the status, not
  instead of it. Tester verdict on the populated five-kind inventory of
  `disabled-declared`: it does not read as live.
note: |
  Cosmetic observation, out of phase scope and NOT a gap: a tool-event hook with
  no matcher renders as `PreToolUse()` (empty parens for the match-all matcher).
  This comes from the shared hook-summary renderer
  (`shared/concerns/hooks.ts:115-116`) and renders identically on enabled rows,
  so the ENBL-17 reroute did not introduce it.

Steps:

1. Run `/claude:plugin info` against a disabled plugin with a populated inventory
1. Confirm `(disabled)` still reads at the head of the row
1. Confirm the description and component lines render below it, not in place of it
