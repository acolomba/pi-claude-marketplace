<objective>
Prove the state-only arm never reaches the network, and make the user's
`--fetch` flag visibly account for itself when there is nothing to fetch.

Purpose: before this phase, `info` on a manifest-absent name returned before any
fetch-capable builder existed, so INFO-12 held for free. The arm split dissolves
that accident — the state-only arm now sits downstream of `buildInfoFetchContext`,
and "we do not call the network here" becomes a claim that needs a test that can
fail. D-96-04 adds the other half: a flag that quietly does nothing is a flag the
user will keep typing. The skip note says the fetch was requested and was not
carried out, at warning severity, in the same `(skipped) {not in manifest}`
vocabulary `update` already uses.

Output: zero-call assertions against both injected seams, a `skipped` arm on
info's cascade render map, the emission wiring in both `getPluginInfo` arms, and
two more catalog states — the skip note and the both-scopes fan-out whose shape
the arm split changed.

Requirement mapping: INFO-12 structural guard and zero-call proof (Task 1),
D-96-04 skip note (Task 2), INFO-09 both-scopes fan-out and the user contract for
both (Task 3).

Design decision recorded here, per the discretion D-96-04 grants on shape:
`PluginInfoRow.status` does not admit `skipped` (`notify.ts:1300-1310`), so the
standalone info row cannot carry the note. It becomes a cascade row instead,
following the disabled-inventory precedent this same file already sets — a second
notification beside the info block, with the same commented IL-2 justification the
disabled path carries. Severity is `warning`, matching `update`'s form and the
tri-state reading of the outcome: the lane was requested and was not carried to a
refreshed state. The alternative — a `    fetch: skipped` body line inside the
info block — keeps IL-2 but invents renderer vocabulary for one caller and is
rejected.
</objective>
