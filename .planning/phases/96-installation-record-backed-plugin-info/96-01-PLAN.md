<objective>
Split `buildBlock`'s not-in-manifest arm so an installation record that survives
its manifest entry is described from the record instead of being reported as a
failure, and pin the two boundaries the split must not move.

Purpose: today `plugin info` tells a user that a plugin materialized on their
disk "is not in the manifest" and calls that a failure. The plugin is installed;
the manifest simply forgot it. INFO-09 and INFO-10 make the row state what is
true — installed (or partially installed) at the recorded version, with the
absence as a reason rather than a verdict. INFO-11's four name-list kinds come
along in the same builder because they are the same object literal. BOUND-01 and
BOUND-02 are the two things that must NOT change, so they are pinned first.

Output: one new characterization test in the existing info suite, one new
orchestrator suite, one three-line dispatch reorder plus two new file-private
functions in `info.ts`, and two new byte-gated output-catalog states.

Requirement mapping: BOUND-01 (Task 1 pin), INFO-09 / INFO-10 / INFO-11 four
name-list kinds (Task 2), BOUND-02 (Task 2 structural + existing pin re-run),
catalog contract for INFO-09 / INFO-10 / D-96-01 (Task 3).

Task 2 is the tracer: it wires one manifest-absent record through the dispatch
split, the new row builder, the renderer, and a byte-exact end-to-end assertion
in one slice. Task 1 precedes it only because the standing "characterize before
change" rule requires the BOUND-01 pin to exist against unmodified production
code — the pin is the tracer's safety net, not a layer of it.
</objective>
