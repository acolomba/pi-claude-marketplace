<objective>
Settle the last open question this milestone inherited: which manifest a
cross-scope folded row is describing. Ratify the answer with executable pins, then
close the question everywhere it is written down.

Purpose: the previous phase hardened absence into a single `ManifestLookup` value
judged against the record's own manifest, but three places still tell the reader
the question is open — a source comment in `list.ts`, a comment in the fold test,
and a sentence in the binding output catalog. D-96-02 ratifies the existing
semantics for all three facts a folded row states (absence, upgradable,
description) and keeps BOUND-01's wholesale non-render under a failed owning
manifest as contract. This plan makes the ratification testable and then makes the
documents agree.

Output: four regression pins in the list suite, three prose closures, and no
production behavior change.

Requirement mapping: BOUND-01 wholesale non-render and the own-manifest authority
pins (Tasks 1 and 2), BOUND-02 regression re-run (Task 2).

This plan touches no `info.ts` code. Research confirmed info has no cross-scope
fold: `getPluginInfo` emits one block per scope holding the marketplace and never
folds, so D-96-02's pins belong in the list suite.
</objective>
