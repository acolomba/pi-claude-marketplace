<objective>
Write each of the seven named backlog items' terminal disposition in place, in one vocabulary,
distinguishing what shipped from what remains evidence-only or deferred.

Purpose: `CLOSE-02` is the honesty half of this phase. A backlog that says `CLOSED` where the
milestone delivered part of an item, or that reads as implemented where the record says "not
implemented", is the drift the closure ledger exists to prevent — and it can only be prevented by
writing the disposition into the backlog itself, where the next reader will find it.
Output: seven entries and one todo carrying explicit terminal dispositions, each drawn from the
same five-word set the closure ledger uses.
</objective>

<disposition_vocabulary>
The closed set from D-09-14, and what each word means here. Nothing outside this set may appear as a
verdict in this plan or in the closure ledger.

| Word | Means |
| --- | --- |
| `implemented` | A change landed that satisfies the item, and a requirement ID and a passed phase verification carry it. |
| `evidence-only` | The item's history is retained for traceability, and it authorizes no implementation. The record says why. |
| `superseded` | Another item or requirement subsumed this one, and that one is named. |
| `deferred` | The item is real and unaddressed, and it is routed forward rather than closed. |
| `unresolved` | The item cannot be settled from inside this repository, and what would settle it is named. |
</disposition_vocabulary>
