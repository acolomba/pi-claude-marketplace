## Edge assumptions

- Plans 05-05, 05-07, and 05-08 have completed. Their summaries are authoritative for final runtime, cache, transaction-port, and adapter identifiers.
- One call of `claudeMarketplaceExtension` defines one extension lifecycle and constructs one runtime/cache/adapter graph. All closures registered by that call capture values from that graph.
- Pi callback disposal is not proven. Generation invalidation therefore remains part of the production hook registration transition, and the stale-callback regression must not depend on unregister behavior.
- Required ports retain their real adapters at the extension composition point. "Real default" means an explicit production value supplied by composition, never an optional parameter or fallback selected inside a consumer.
- Production order remains exact: await hook registration; register resources discovery; register session environment behavior; register the command; register tools. Inside resources discovery, hydrate the project runtime before reconcile, then recompute PATH before resource aggregation.
- Reconcile and command phase order, commit eligibility, rollback, cleanup, warning collection, Error identity, diagnostic text, notification count, severity, and bytes remain exact.
- Cache invalidation remains targeted post-commit behavior. A failed or rolled-back mutation must not evict completion state as if it succeeded.
- applyReconcile and bootstrapClaudePlugin are the only approved behavioral-composition exceptions. This plan neither adds a third exception nor changes the breadth of those two.
- Existing Fallow suppressions remain byte-identical and this plan adds none.
- Phase 6 owns global-patch removal and the approved large-module split program. Hook staging, PID-table policy, plugin-info splitting, and uninstall decomposition remain outside this plan.

## Trust Boundaries

| Boundary                                                       | Description                                                                                                                              |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Extension factory -> hook/edge registrations                   | Runtime, cache, and adapter identities cross into long-lived callbacks; a duplicate graph can split mutation state from observations.    |
| Prior hook registration -> replacement registration            | Pi may retain old callbacks, so a stale callback can dispatch or mutate current state unless generation invalidation is effective.       |
| Command/reconcile mutation -> cache invalidation -> completion | Invalidation through another cache leaves the registered completion callback observably stale.                                           |
| Persisted state/configuration -> transaction -> runtime/cache  | Commit, rollback, hook routing, and completion state must agree after success, partial failure, or compensation.                         |
| Edge registration -> apply/bootstrap composition               | Test-shaped child substitution can conceal order, persistence, notification, or diagnostic regressions in the two approved compositions. |
