## Edge assumptions

- Plan 05-09 supplies one runtime and captured generation to callback construction. Use its executed signatures.
- Plan 05-06 already exposes the fixed runtime operations needed by this row; do not modify `runtime.ts` or expose state containers.
- Genuine input and registration/reload are the only production transitions that clear settle or pending state.
- A callback can become stale while awaiting hook execution. The second generation check must run after the await and before mutation or messaging.
- Plan 05-11 migrates dispatch execution's async child state. This plan does not alter PID behavior or `SpawnDeps`/`OrphanProbes`.

## Trust Boundaries

| Boundary                                 | Description                                                                                     |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Registered event to runtime route bucket | Plugin-controlled event data selects entries and reducers within one lifecycle instance.        |
| Hook result to pending/settle state      | Results can add system context or cause follow-up turns and require exact attribution and caps. |
| Awaited hook work to reloaded lifecycle  | A generation can become stale during an await and must not mutate or message the new lifecycle. |
