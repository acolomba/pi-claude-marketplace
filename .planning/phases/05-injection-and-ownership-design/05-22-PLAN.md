## Trust boundaries

| Boundary                           | Description                                                                                                  |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| Install request -> durable ledger  | User-selected plugin and marketplace cross validation, containment, preparation, and transactional mutation. |
| Durable success -> lifecycle cache | Incorrect eligibility or identity can expose stale or nonexistent completion status.                         |
| Refresh failure -> public outcome  | A hygiene failure must not rewrite committed state or misreport standalone/orchestrated results.             |

| T-05-97   | Tampering                          | invalidation eligibility   | high     | mitigate    | Drop only after durable success and prove every failure and rollback arm leaves cache eligibility unchanged. |
