# Phase 3.1 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| user-owned `claude-plugins.local.json` -> migration, refusal, and write-back decisions | A hand-edited file, possibly corrupt or prototype-keyed, decides what the shared file may hold and whether a command is refused | Per-machine config |
| first-run migration and write-backs -> committed `claude-plugins.json` | Anything written there may be committed and shared with a team | Marketplace and plugin declarations |
| standalone install/enable/disable/update/reinstall -> committed `claude-plugins.json` | A command could declare a plugin under a marketplace that only the per-machine file declares | Plugin declarations |
| refusal row -> notifications and json/rpc payloads | The cause line and the reinstall `cause` slot reach user-visible and machine-readable output | Notification text |
| Pi child -> project scope files (scenarios) | Scenarios run a real Pi whose cwd is the sandbox project | Sandbox config and state |
| docs and gate record -> users and verifier | The catalog and CHANGELOG describe output and manual cleanup; the SUMMARY is the gate evidence | Docs |
