# Phase 6.1: Reload Keeps SessionStart Context - Context

**Gathered:** 2026-11-23
**Status:** Ready for planning

<domain>
## Phase Boundary

A product fix for an upstream-parity gap the migration found (HKRL-01). Today a Pi `/reload` before the first prompt drops the SessionStart `additionalContext` a hook produced at startup. Claude Code 2.1.330 writes that context into the conversation as soon as the hooks finish, and `/reload-plugins` leaves the conversation alone, so the context reaches the model on the first prompt (`06.1-UPSTREAM-EVIDENCE.md`). The user chose to fix it in this milestone (2026-11-22).

In scope:
- The hooks bridge (`extensions/pi-claude-marketplace/bridges/hooks/`, e.g. `event-router.ts`, `routing-state.ts`, the runtime) and `index.ts` where the runtime is created, so startup SessionStart context survives a `/reload`.
- Unit tests beside each changed source (100% direct coverage).
- The scenario at `features/hook/additional-context.feature:230` flipped to expect the context on the first prompt after a reload; the integration case HOOK-E2E-04 in `test/integration/hooks-additionalcontext-end-to-end.test.ts` flipped or deleted once the scenario covers it.
- `docs/hooks-compatibility.md` updated.
- A CHANGELOG parent line in the SUMMARY (the milestone PR writes CHANGELOG.md).

Out of scope: the headless-only late SessionStart run for plugins that load after a session starts (an upstream behavior research found; a BACKLOG parent line if Pi lacks it).

</domain>

Lessons from Phase 1 (2026-11-21), for planners and executors:
- The cucumber summary formatter prints a failed scenario as `  N) <title> # <file>:<line>`, not `Scenario: <file>:<line>`. A verify command that proves a break failed a scenario must match that form.
- `fallow audit` gives `weakened-tests` (`warn`) for every deleted test file. User decision 2026-11-21: no `.fallowrc.json` change; do not edit it or the CI workflows. Record the finding in the SUMMARY and move on; it is not a gap.
- A break must be applied and reverted in the plan's own worktree (helper roots itself at `git rev-parse --show-toplevel`), never the main checkout.
