<objective>
Wire the same strict changed-pair gate into scoped local pre-commit and a dedicated authoritative
CI job, with fail-closed base and pair selection.

This is `RCOV-03`, and `D-07-16` assigned the wiring of an already-correct gate to this phase.
`selectBase` and `changedPaths` already implement `D-07-13`'s ordered, printed base selection and
`D-07-14`'s discriminated zero-selection outcome; plan 04 added the explicit base and the pin
comparison. What is left is two config files and an honest cost statement.

Two measured facts shape the wiring. First, `actions/checkout` defaults to a depth-1 clone in which
`origin/main` does not exist, so the ordered chain would silently fall through to `HEAD~1` and diff
one commit while reporting a resolved base. Fail-closed base selection is worth nothing if the base
it closes on is the wrong one, so the job uses `fetch-depth: 0` — the house answer, already used by
`lint.yml`'s `fallow-audit` job — and asserts both that `origin/main` resolves and that the gate
printed it.

Second, the branch-scoped selection reaches roughly 150 pairs and six to seven minutes on a
long-lived branch and grows with branch length. That is right for a pull request and wrong for a
per-commit hook: `CONTRIBUTING.md` already argues that a job red on every run reports nothing, and a
six-minute hook developers routinely skip is the same failure in a different costume. So the hook
passes a commit-scoped base while remaining the same implementation at the same strictness.

One hazard is worth naming because the obvious formulation is wrong: piping the gate into a logging
command makes the pipeline exit with the logging command's status, and GitHub's default shell does
not enable `pipefail`. A coverage job that has never failed is the failure mode this whole phase
exists to end.

This plan goes last because the hook and the job must be green the moment they land, which needs
every shortfall closed and the pin final.

Purpose: make the gate run where it can catch a regression rather than only where someone
remembers to invoke it.
Output: one hook, one CI job, one npm script, and a cost statement that tells the truth.
</objective>

   redirect and no pipeline at all, which has no such hazard; choose one and do not mix them.

   request is the authoritative change set.
