<objective>
Build the record and the enforcement layer: a committed machine-readable pin the gate compares
against exactly and bidirectionally, and the explicit base argument that lets one gate
implementation serve two named scopes.

`D-08-05` reuses `D-07-19`'s pinned-snapshot mechanism. The distinction it drew must be
restated in the pin's own header: an allow-list forgives named entries silently and forever; a
pinned set fails on an addition, on a removal, and on a swap. A module that falls short and is
absent from the pin fails. A pinned module whose reading changed — better or worse — fails. A
pinned module that now reads complete fails as a stale pin. A pin row naming a module no longer
in the tree fails with no test run at all.

`D-08-19` keeps three instruments in three jobs. `scripts/test-coverage-direct.report.mjs`
measures and files no verdict. The pin records. The two module-private gate arms enforce.
`assertCompleteCoverage` stays pure — it answers one question — and the comparison is a layer
the arms call. The one unavoidable touch to the reporter is the opposite of a leak: it loses a
duplicated regex and gains nothing about the pin.

`D-08-A07` adds the explicit base. The changed-pair gate selects 147 pairs and about 6.5
minutes on this branch because `changedPaths` diffs `origin/main...HEAD` and the branch is 935
commits ahead. CI keeps that branch-scoped chain, which is the authoritative change set for a
pull request. The hook plan 09 writes passes a commit-scoped base. One implementation, one
strictness, two explicitly named scopes — and an explicitly named base that does not resolve is
an error, never a fallback.

`D-08-18` proves all of it by planting, not by reading configuration. The five cases attach to
`scripts/test-coverage-direct.negative.mjs`, which already plants refusals against this exact
gate through an injected root and already runs inside `npm run check`.

Purpose: put the pin machinery under `npm run check` even though the slow sweep stays out of it.
Output: a committed pin, a pure bidirectional comparator, the comparison wired into both gate
arms, a fail-closed explicit base, and five planted controls.
</objective>
