**The ordering proof.** The leak messages a replacement rollback accumulates are produced by three
stages in a fixed order — remove each renamed replacement, restore each backup by rename, then
clean up the staging and backup roots — and `rollbackReplacementCommon` freezes them into one
array. That ordering is the contract. In each bridge's owner test, add a case that faults MORE

whole-value `assert.deepStrictEqual`, in the order the stages ran. One message per leaking stage,

fault and the expected message cannot drift apart.

The array and its order are the promise.

the claim — "some residue leaked and some did not" — and either half alone is satisfied by a
cleanup that did nothing.
