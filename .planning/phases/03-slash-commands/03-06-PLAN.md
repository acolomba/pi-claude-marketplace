<objective>
The commands bridge records the project commands this user installed in the
user's project ledger, and forgets them on removal (the writer half of
D-CF3-07; plan 03-07 adds the check at invocation).

Decisions implemented: D-CF3-07 (commit records the committed command files at
project scope with the SHA-256 of each staged file; unstage forgets them; same
file and schema as the skills ledger; the commands bridge does not import
`bridges/skills/`, Phase 2's files stay unedited, and no near-copy of
`bridges/skills/project-installs.ts` lands), with the D-CF2-13 hardening it
follows: WR-02 (content this version cannot update fails the install and is
kept), WR-04 (a removal reports a ledger it could not update as a warning),
IN-02 (cleanup before the ledger write), and IN-06 (one ledger file per
project). D-CF3-13 allows the minimal call-site edits in the orchestrators.

Purpose: a project's repository can carry `.pi/pi-claude-marketplace/` with
staged commands whose `!` commands would run on whoever opens it; only the
user's own record, outside the project, can tell an install apart from a
clone. This plan writes that record for commands.

Output: `bridges/commands/project-ledger.ts` (new), the record in
`commitPreparedCommands`, the forget in `unstagePluginCommands`, the three call
sites, and the ledger scenarios.
