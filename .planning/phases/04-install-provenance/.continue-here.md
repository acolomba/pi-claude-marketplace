## Decisions carried into planning (these supersede Phase 3's artifacts)

1. **The desired-state config holds ONLY explicit plugins.** Cascade-installed
   dependencies are NOT written to `claude-plugins.json`. They are already
   derivable from the marketplace records. Operator decision, 2026-09-15:
   *"don't write dependencies to config... the desired state configuration only
   contains explicit plugins."* This reverses the shape of Phase 3's CR-01 fix
   (`writeOrchestratedDeclarations`, `install-flow.ts:1351`, plus the orchestrated
   `dependencyPluginPatches` arm at `install-flow.ts:1346`).

2. **Provenance is mode-only: `"explicit" | "dependency"`.** No declaring-plugin
   list — that would be a cache of another plugin's manifest and would drift.
   `--prune` re-derives "does anything still need this?" at prune time using the
   offline `dependency-declaration-read`.

3. **schemaVersion 2 -> 3; absence defaults to `"explicit"`; the upgrade is
   SILENT.** Truthful rather than a guess: no released version through v0.18.3 had
   a cascade, so every pre-existing record genuinely is explicit. Records Phase 3
   wrote on development trees are mislabelled — the ROADMAP already accepted this
   ("lands on development trees only, and this milestone releases as a single
   version").

4. **PROV-04 needs rewording** in `.planning/REQUIREMENTS.md`. As written it
   demands "reported as stale rather than silently repaired", which the silent
   upgrade does not satisfy. Proposed: *"an install record written before this
   milestone is upgraded to the current schema with a truthful default, and no
   record is misreported as a dependency."* The MIGR-01 guard-wording question
   (notify text + recovery command for "stale state, absent config") returns to
   MIGR-01 and is NOT answered in this phase.

5. **RECOMMENDED, UNCONFIRMED — the whole reversal lands in Phase 4**, in the
   order: provenance field -> reconcile skips `provenance: "dependency"` ->
   remove the config write. Phase 3 stays closed and verified; the config write is
   a bridge Phase 4 retires. CR-01's regression test stays honest throughout (it
   asserts the dependency survives a reload — still true, new mechanism).

## Consequences worth knowing

- Two earlier gray areas collapse once decision 1 holds: "is a config-named plugin
  explicit?" becomes trivially yes, and reconcile/import need no special rule,
  because config will only ever name explicit things.
- Decision 3 stays safe under decision 1: a legacy record reads as `explicit`, so
  reconcile keeps it. Nothing is swept by the upgrade.
- `compat-01-no-expansion.test.ts` pins the install record's key set by
  enumeration equality and its failure message currently sanctions only OPTIONAL
  additive keys. A required field plus a schemaVersion bump means that message and
  the schemaVersion union both need deliberate amendment. Do NOT loosen the
  equality assertion into a subset check.
