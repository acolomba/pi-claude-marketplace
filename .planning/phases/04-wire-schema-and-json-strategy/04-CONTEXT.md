<domain>
## Phase Boundary

A versioned typebox wire schema and a JSON strategy turn every model kind
(the structured notification kinds and the Phase 3 raw-surface kinds) into a
schema-valid payload that discloses nothing the text form does not. The JSON
strategy is a format-only peer of the text strategy, validated as a pure
function. Its first production consumer is the LLM tool surface (LLMT-01). The
model gains credential redaction (PMOD-04), the only sanctioned text-byte
change of the milestone.

Requirements: WIRE-01, WIRE-03, WIRE-04, WIRE-05, WIRE-06, WIRE-08, WIRE-09,
JOUT-02, PMOD-04, LLMT-01.

Out of this phase:

- `ctx.mode` selection, `appendEntry`, and threading the sink (Phase 5). If
  the LLM tools cannot use the strategy, ROADMAP's note moves the
  structured-path sink wiring forward; the planner decides only if needed.
- `origin`, the machine command id, `invocationId`, and the `internal-error`
  payload (Phase 6).
- Mode refusals and docs (Phase 7).

**Upstream contract:** Claude Code's `--json` exists only on the shell CLI
(research FEATURES.md, 2.1.283 binary). Locked decisions D1-D8 already fix the
vocabulary: verbatim closed-set tokens, no snake_case `failureCode`, no
`installPath`/`projectPath`, `id: "<name>@<marketplace>"` mirroring upstream's
plugin id. No new upstream research was needed.

<decisions>
## Implementation Decisions

### Envelope, kinds, and files

- **D-01:** Every payload carries `schemaVersion: 1` (integer literal),
  `kind`, `severity`, and `needsReload` now, plus `summary` (warning and error
  only, WIRE-05) and a numeric `tally` where the model has one. Phase 6 adds
  `origin` and the command id (WIRE-02) without bumping `schemaVersion`
  (additive). Raw kinds carry `needsReload: false`.
- **D-02:** Kind names are the model's existing kind strings, verbatim, for
  structured and raw kinds alike. There is one vocabulary; the wire does not
  rename kinds.
- **D-03:** Files: `shared/notification-wire.ts` holds the typebox schema (one
  union keyed by `kind`), `shared/notification-json.ts` holds the explicit,
  total-map converter from the resolved model to the DTO (Phase 1 D-09: JSON
  serializes a built DTO, never the model, never with a replacer). A JSON
  Schema file generated from the typebox source is committed at
  `schema/claude-plugin.schema.json`, listed in `package.json` `files`, and
  regenerated by a `scripts/` generator. Exact names are the planner's choice
  within this layout; no new fallow zone.
- **D-04:** Row and block fields follow research FEATURES.md "Per-verb payload
  content": plugin rows carry `status`, `name`, `id`, `version?`, `scope`
  (always, for install-scoped rows), `description?`, `reasons[]`,
  `dependencies[]?`, full `from`/`to` on updates, hint ids, `partial?`,
  `causeChain?` with `truncated`, `rollbackPartial?`; marketplace blocks carry
  `name`, `scope`, `status?`, `details?`, `reasons?`, `plugins[]`.
  `marketplaces: []` replaces the `(no marketplaces)` sentinel. The update
  no-op cascade carries `noOp: true`. Optional fields are absent, never
  `null`; empty collections are `[]`; arrays keep model order; versions and
  timestamps are raw (WIRE-03..06).

### Credential redaction (PMOD-04)

- **D-05:** Redact URL userinfo and token-shaped strings: GitHub token
  prefixes `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`, plus
  `Bearer <token>` and `x-access-token:<token>` forms.
- **D-06:** Replacement forms: userinfo becomes `***@` (for example
  `https://***@github.com/o/r`); a token becomes `***`.
- **D-07:** One redaction function, applied in resolve at every serialization
  site (cause chains and their rollback entries, manual-recovery leaks, the
  reconcile-aborted cause, and any other model string that can carry a thrown
  message), so text and JSON both get it. The AUTH-09 gate is extended to the
  JSON path.
- **D-08:** Corpus: entries whose bytes change because of redaction are
  recorded in a ledger with exact before/after triples and checked
  mechanically (the Phase 2 D-07 / Phase 3 D-17 pattern). Any other corpus
  change is a defect. If no fixture carries a credential, the corpus stays
  unchanged and redaction is proven by owner tests.

### LLM tools and proofs

- **D-09:** Both LLM tools (`edge/handlers/tools.ts`) build their `details`
  from the JSON strategy's plugin-row and marketplace-block converters, the
  strategy's first production consumer. `upgradable` stays `upgradable`. The
  tools' line-format text content does not change.
- **D-10:** WIRE-08 proof: a whole-payload walk over every catalog fixture and
  raw kind finds no absolute path that the fixture's text form does not show,
  and no live `Error` (prototype walk).
- **D-11:** WIRE-09 proof: a test regenerates the JSON Schema from the typebox
  source and deep-compares it with the committed file; a test asserts the
  path is in `package.json` `files`; a plan verification step runs
  `npm pack --dry-run` and checks the file is listed.
- **D-12:** Validation runs in tests only (a compiled typebox validator over
  every catalog fixture and raw kind, plus a planted invalid fixture and a
  converter-returns-`{}` control, JOUT-02). Production never validates
  payloads (REQUIREMENTS Out of Scope).

### Research follow-ups resolved by the orchestrator (2026-10-03)

These apply D-04's rule ("emit what the text form shows, no more") and
D-01/WIRE-04's absent-never-null rule; they are not new user decisions.

- Catalog scope: the contract pins 21 modules, 260 states (the ROADMAP's
  "205" is stale). The four `emit`-closure fixtures (two plugin-list, two
  update no-op) get a harness hook so `noOp: true` is proven.
- `dependencies` appears on wire rows only where the text form shows it; the
  planner carries it on resolved rows if needed for that, otherwise the wire
  omits it by explicit decision recorded in the plan.
- LLM tool `details` (LLMT-01) use the wire marketplace-block and plugin-row
  shapes. `source.raw` is dropped (it can carry URL userinfo and the text does
  not show it); `pluginCount` stays only if the text form shows it. The plugin
  tool resolves rows through `LIST_CONTEXT.rowPolicies` with
  `openNotificationRun(pi)` so `details.reasons` matches `/claude:plugin list`.
- `noOp` is present only when true (absent otherwise).
- `lastUpdatedAt` is emitted whenever the model has it (research FEATURES:
  display gating is text policy, and a timestamp is not a path disclosure).
- Redaction: minimum token length 16 for prefix-matched tokens; `Bearer `
  and `x-access-token:` prefixes are kept and only the secret becomes `***`;
  the scp-style `git@host:owner/repo` subject is not userinfo and is left
  alone. Research measured zero redaction diffs over the 3134 corpus entries
  and the catalog, so D-08's ledger is expected to be empty.

### Corpus exception (approved after code review)

- **D-13:** On 2026-10-03 the user approved ("Approve with ledger") adding
  exactly 9 test-only corpus entries emitted by
  `tests/architecture/no-credential-leak.test.ts` once review fix WR-05 routed
  the gate's text leg through the production `notify` path. All 9 show the
  redacted form. Record them in `04-CORPUS-CHANGES.json` (Phase 3 D-17 format:
  exact entries, owner file, multiplicity, preserved behavior) and splice them
  into the baseline in a separate, mechanically verified commit. No existing
  entry changes or goes missing; production bytes and the catalog are
  unchanged.
