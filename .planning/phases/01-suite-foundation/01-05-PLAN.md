## Trust Boundaries

| Boundary | Description |

| world -> second Pi process | A per-scenario child process with its own working directory |
| fixture -> published marketplace files | The output style write must stay inside the publication |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-09 | Tampering | startSessionInAnotherProject (a second Pi that reaches the real HOME or a directory inside the repository) | high | mitigate | The second Pi reuses the run's sandbox HOME and agent dir; its cwd comes from mkdtemp under the run's temp root; `PiProcess.start` passes every location through `resolveSandbox`, which rejects a path outside the OS temp directory or inside the repository; the environment is the same allowlist with PI_OFFLINE |
| T-01-10 | Denial of service | the second Pi and its directory (a process or directory that outlives the scenario) | medium | mitigate | The world registers a release that stops the Pi (process-group kill after a grace period) and one that removes the directory, both before the session is read; the method also stops the Pi as soon as it has read the session |
| T-01-11 | Tampering | publishOutputStyle (a write outside the published plugin) | low | mitigate | The write goes through writePublishedPluginFile, which refuses a target outside the publication root (ownedTarget) and refuses to replace a file (flag wx) |
| T-01-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no package |
