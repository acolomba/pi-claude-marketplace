<objective>
Make the written grammar of dependency resolution match what Phases 7-01 and 7-02 shipped, and record the one outstanding divergence from upstream that the document does not yet name.

`docs/dependency-resolution.md` is the user-facing contract for this feature and its §"Only a git-backed dependency can be version-constrained" is now simply false: a path source resolves constraints against the marketplace repository's own tags, and a no-match installs the current copy instead of failing. The document also explains that an element carrying a `sha` is refused without ever saying that upstream accepts the field, which is the fact DIVG-01 asks for.

Purpose: a reader who follows the current text would declare their path-source dependencies with no version, permanently, to avoid a failure that no longer happens.
Output: the rewritten resolution sections, the `sha` divergence sentence, and a gate case that binds the fallback prose to the reason the composer actually stamps.
</objective>

State the divergence in one sentence: Claude Code reports this same fallback as a warning; this extension reports it as a plain note, because nothing has gone wrong at install time and the load-time check is what decides whether anything is wrong at all (D-07-03).
