<objective>
Replace D-14's in-place refresh of marketplaces with upstream's model:
an `ls-remote` freshness check, then a re-clone into staging and a swap
through a backup directory, with recovery of an interrupted swap and a kept
copy when the checkout is in use. Add `CLAUDE_CODE_PLUGIN_KEEP_MARKETPLACE_ON_FAILURE`
as upstream reads it. Re-baseline the `marketplace update` tables once.

Purpose: SG-TRN-03 (D-SG-10) and SG-TRN-06 (D-SG-15). D-14's user-visible
contract stays: after `update`, the checkout matches the remote's ref, and a
moved branch or tag is followed. Decisions recorded here: the backup lives in
`sources-backup/<name>` (orchestrator-accepted; a marketplace name may hold a
dot, so `sources/<name>.bak` could collide); the kept outcomes reuse the
closed reasons `network unreachable` and `permission denied` with the existing
cause shape (orchestrator decision 3; Phase 6 owns the wording). The plugin
update sync and the mirror refresh move in the next plan.

Output: `orchestrators/marketplace/clone-swap.ts`, the backup getters,
`update.ts` on the swap, the gate names, and the re-baselined tables.
</objective>
