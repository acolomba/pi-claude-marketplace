<objective>
Prepare the cucumber stand-ins for a product that runs system git: a loopback
`CONNECT` proxy that keeps git's request host `github.com` while the bytes go to
the local git host (D-SG-14: credentials are keyed by the request host, so the
Device Flow scenarios need git to ask for `github.com`), a certificate the tunnel
can verify, an honest answer when `git http-backend` refuses a want, and two new
variables in the hermetic leak check.

Purpose: harness groundwork for SG-TRN-01 (Device Flow scenarios after the
swap), SG-TRN-02 (the missing-pin and v0 ladder rows), and SG-TRN-05/06 (the
variables). No scenario uses the proxy yet; its own architecture test does. The
Device Flow profile is switched to the proxy in the transport swap, together with
the request-table re-baseline.

Output: `features/lib/github-device-flow/connect-proxy.ts`, its architecture
test, the certificate name, the forwarding fix, and the planted variables.
</objective>

| the developer's shell to the test processes | variables that steer git or the product could change a test |
