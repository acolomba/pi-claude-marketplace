<objective>
Settle the marketplace ref cases of the new transport: refuse a marketplace ref
that is a commit id cleanly before git runs (orchestrator decision 4), and pin
with scenarios that `marketplace update` follows a moved default branch and a
moved tag and recovers from an interrupted or failed update.

Purpose: SG-TRN-02 (a ref git would misread is refused before git runs) and
ROADMAP success criterion 3 for SG-TRN-03 (moved default branch, moved tag,
an update that fails or is interrupted leaves the previous checkout usable, and
the next run succeeds). The swap itself landed in 03-07; these scenarios prove
it through a real Pi and the git host stand-in.

Decision recorded here (orchestrator decision 4, reversible): `git clone
--branch=<40 hex>` fails as `Remote branch ... not found`, and no scenario or
test adds a marketplace at a commit, so `marketplace add` refuses such a ref
with `{unsupported source}` until SG-PIN-01 (Phase 7) adds upstream's SHA path.
A record that an earlier version stored with a commit-id ref is not refused:
03-07's freshness check compares it with `HEAD` and runs no `ls-remote`.

Output: the refusal, the branch and tag Givens, the interrupted-update Given,
and five scenarios.
</objective>
