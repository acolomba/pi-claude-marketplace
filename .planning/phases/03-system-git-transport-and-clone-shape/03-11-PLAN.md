<objective>
Settle the marketplace ref cases of the new transport: refuse a marketplace ref
that looks like a commit id with capital letters cleanly before git runs, as
Claude Code does, and pin with scenarios that `marketplace update` follows a
moved default branch and a moved tag and recovers from an interrupted or failed
update.

Purpose: SG-TRN-02 (a ref git would misread is refused before git runs) and
ROADMAP success criterion 3 for SG-TRN-03 (moved default branch, moved tag,
an update that fails or is interrupted leaves the previous checkout usable, and
the next run succeeds). The swap itself landed in 03-07; these scenarios prove
it through a real Pi and the git host stand-in.

Upstream parity (maintainer decision, no new D-ID): Claude Code 2.1.330 refuses
only the capital-letter form before its marketplace clone (`wCn`: "Refusing to
clone: this marketplace's `ref` (<x>) looks like a commit id with capital
letters..."), because git would read such a ref as a branch name that can
move. A lower-case 40- or 64-hex ref reaches git as `--branch=<ref>` and fails
clean, as today, as a missing remote ref (`Remote branch ... not found`,
`{source missing}`), until SG-PIN-01 (Phase 7) brings upstream's SHA path. A
record that an earlier version stored with a commit-id ref is not refused:
03-07's freshness check compares it with `HEAD` and runs no `ls-remote`. The
refusal's wording parity belongs to Phase 6; this plan reuses the existing
`unsupported source` reason through `UnsupportedSourceError`.

Output: the refusal, the branch and tag Givens, the interrupted-update Given,
and six scenarios.
</objective>
