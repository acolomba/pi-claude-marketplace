<objective>
Close the SURF-01 cross-surface reason divergence introduced by the D-90-05 fix
(90-REVIEW.md WR-01, still unresolved on HEAD), and carry forward the outstanding
live-Pi retest of UAT Test 3 (G-90-3) as a human checkpoint.

The gap: a plugin that is BOTH structurally `unavailable` (broken manifest
reference, malformed hooks.json, etc.) AND carries a `contains <non-carve-out-kind>`
note (e.g. `contains monitors`) renders `{unsupported source}` on `list`/`info`
but `{unsupported component}` on the install-failure surface — for the identical
plugin. list/info route the note through `shared/probe-classifiers.ts::
classifyResolverNote` (catch-all -> `unsupported source`); install routes the same
note through `narrowUnsupportedKinds` (-> `unsupported component`), crossing the
structural-vs-partially-available axis boundary that docs/output-catalog.md:1489
documents.

Decision (WR-01 Option 2 — the single truthful axis): on the structural
`unavailable` arm a `contains <kind>` note stays on the SOURCE/note axis and
renders `{unsupported source}` on BOTH surfaces; the component-axis token
`{unsupported component}` belongs to the partially-available arm only. This is
mandated by the durable resolver-state ground rule (structural arm = note axis;
soft-degrade/component axis = partially-available arm only), by
docs/output-catalog.md:1489, and DECISIVELY by 90-02-PLAN.md's own prohibition
("MUST NOT change the note-path classifier away from `unsupported source` — ONLY
the per-kind path fallback becomes `unsupported component`"). WR-01 Option 1 (add
a `contains <kind>` arm to `classifyResolverNote`) would violate that prohibition
and leak the component-axis token onto the structural arm — rejected.

Implementation: `narrowResolverReasons` (install.ts) gains an arm discriminant
`partialable` (already carried on the thrown `PluginShapeError` shape as
`err.shape.partialable`, resolver.ts:1494) and branches its `contains <kind>`
handler — routing through `narrowUnsupportedKinds` on the partially-available arm
(unchanged), emitting `unsupported source` on the structural `unavailable` arm
(mirroring `classifyResolverNote`'s catch-all). `shared/probe-classifiers.ts` is
NOT touched. No closed-set token is minted (length lock stays 38).

Purpose: restore the SURF-01 same-plugin-same-reason byte-identity invariant across
install/list/info through the shared note-axis seam, without special-casing a
renderer and without regressing the D-90-05 partially-available per-kind behavior.
Output: an arm-aware install classifier + a note-axis parity test that pins the
unavailable-arm agreement (previously untested), plus a human-verify checkpoint for
the live-Pi G-90-3 retest.
</objective>
