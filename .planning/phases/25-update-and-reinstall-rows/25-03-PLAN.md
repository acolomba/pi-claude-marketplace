<objective>
UPR-02, update side: a same-version update that moved to a new commit names
both commits, in the user's form with the house `v` prefix:
`v1.0.0 (abc1234) → v1.0.0 (def5678)` (ROADMAP Phase 25 decision; D-05).
Upstream counts a new commit at the same version as an update and names short
commits in 7 hex characters (D-01); there is no upstream position on Pi's row
grammar itself (D-04), so the parenthesized form follows the user's decision.

Purpose: today such an update renders `v1.0.0 → v1.0.0 (updated)`, which reads
as a no-op. Plan 04 widens the same mechanism to `partially-installed` and
`failed` rows and Plan 05 to `reinstalled` rows.

Output: `VersionCommits` and `PluginUpdatedMessage.commits`, the grammar's
commit-aware `composeVersionArrow`, the wire fields `fromCommit`/`toCommit`
(schema, JSON docs), the outcome fields and the swap literal that stamps them
(D-06), `update-row.ts::revisionCommits` (the D-05 rule), a commit run token
and the `git-source-update.feature` columns, the autoupdate proof (D-10), and
one new catalog state.
</objective>
