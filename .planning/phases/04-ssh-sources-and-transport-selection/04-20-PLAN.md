## Upstream evidence (Claude Code 2.1.332, `/opt/claude-code/bin/claude`, grepped 2026-11-26)

- `zHi` (the plugin `github` clone) starts with
  `if(!/^[a-zA-Z0-9-_.]+\/[a-zA-Z0-9-_.]+$/.test(e))throw Error(`Invalid GitHub repository format: ${e}. Expected format: owner/repo`)`,
  before `PJt()` (the HTTPS force) and before any probe. `e` is the string both clone URLs are
  built from (`git@github.com:${e}.git`, `https://github.com/${e}.git`).
- The same pattern appears only in `KHi` and `Uze`, where it decides the git-subdir
  `owner/repo` shorthand and refuses nothing. `zmt` (tag reads) has no check.
- Pi's `GIT_SUBDIR_SHORTHAND` in `domain/source.ts` is already that pattern
  (`/^[A-Za-z0-9_.-]+\/[A-Za-z0-9_.-]+$/`; upstream's `-` after `0-9` is a literal).
- Pi's manifest parser accepts any one-slash `repo` (`parseOwnerRepo`), so `evil:x/ghp` parses
  as owner `evil:x` today and reaches the clone.

## Where the refusal sits

`orchestrators/github-transport.ts::pluginCloneTransport` builds the plan of every plugin GitHub
clone: `install-clone-probe.ts`, `update-preflight.ts` (a mirror's clone, re-clone, and freshness
check), `fetch.ts`, and `info.ts` all call it, and the clone runner awaits the plan before it
records a note or runs an attempt (`clone-cache.ts::runCloneStep`). A plan that rejects there
runs no probe, no skip check, no `ls-remote`, and no clone, which is where `zHi`'s first line
stops upstream, forced HTTPS included. The refusal applies to a `github` source only: a
git-subdir url that fails the pattern is not a shorthand and already goes through the D-SG-17
validator.
