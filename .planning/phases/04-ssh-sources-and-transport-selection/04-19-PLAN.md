## The fetch remote row (checker finding, measured 2026-11-26)

`fetch.ts::fetchOne` reads each candidate after the seam's clone, and `freshRow` returns `remote`
only for a `cold` read. An unpinned fetch refreshes the mirror and reads it under the scope lock,
and the mirror materialize ends by resolving `HEAD` (it throws `local-ref-missing` otherwise), so
the read finds the mirror. A pinned fetch clones to `pluginCloneKey(cloneUrl, pin)`, the key the
probe reads. Only another process that removes a pinned clone, which takes no lock, between the
clone and the read reaches the `remote` row after a clone. No public input does, so this plan
gives `PluginRemoteMessage` no clone member, and the cold arm stays as it is: in that race,
`remote` is the honest row. 04-26 records this in the D-SG-22 outcome and appends no WINDOWS
entry for it.
