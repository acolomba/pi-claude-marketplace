## The #137 fault (measured 2026-11-26)

Inside the scope's extension root, `state.json` is replaced by a link to a copy in a new
read-only subdirectory. The load reads the record through the link, the state lock lives in the
writable extension root (`with-state-guard.ts` locks with `lockfilePath` and `realpath: false`),
and the atomic save fails with `EACCES`, because `write-file-atomic` resolves the link and
creates its temporary file beside the real file. A probe script confirmed each step under the
harness's `/opt/pi-claude-marketplace/bin/node` wrapper, which drops `dac_override` from the
bounding set so root obeys file modes; every process the run starts inherits that bounding set,
the Pi processes the harness spawns with `process.execPath` included (CI runs unprivileged).
The read-only skill directory fault relies on the same rule. The save error names the temporary file
`state.json.<number>`, whose number differs per run, so the error token must match any number.

difference is a regression to fix in the code; the #136 decision adds no exception.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| clone URL and label → notification | the member's URL and key are printed and serialized on the root's row |
| ledger failure → row | the merged enable ledger's failing member decides whose note the root row carries |
| harness fault → sandbox | the Given changes a directory mode inside the scenario's sandbox |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-75 | Information disclosure | the root's failed row | medium | mitigate | the row reads only the failing member's key or its own; the URL is redacted where the note is made and in `resolveRows`, and the label through `redactRowName` (04-19, CR-A-01) |
| T-04-76 | Spoofing | the labelled note | low | mitigate | the label is the failing phase's own key, recorded by that phase's catch, so a note can never be shown under another member's name; unit cases pin a member failure, a root failure, and a config-phase failure |
| T-04-77 | Repudiation | the enable failure output | medium | mitigate | the root row's status, reasons, and cause are unchanged (maintainer decision), and the rebaseline rule has no exception, so no failure is hidden or reworded |
| T-04-78 | Denial of service | the read-only directory the Given leaves | low | mitigate | the Given's release restores the mode through `onRelease`, so the sandbox cleanup can remove it; the directory lies inside the scenario's own extension root |
| T-04-SC | Tampering | npm installs | high | mitigate | no package is added |
</threat_model>
