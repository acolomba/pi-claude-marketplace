## Placement decisions (CONTEXT Claude's Discretion: "how the transport note sits in the notification")

| Path | Shape |
|---|---|
| failing cascade member (#136) | the install precedent (`composeCascadeFailureMessage`, 04-14 D3): the member whose phase failed gets its own `(failed)` row, named by its key, with the reasons the root row reads today (`narrowEnableFailure`), the cause, its rollback phases, and its clone note; the root row reads `{dependency failed}` with no cause and the root key's note. A note needs a row, and this is the row Pi already shows when an install's dependency fails. When the root's own phase fails, today's shape stays and only the note is added |
| failure after the ledger (#137) | the standalone transaction-throw row reads the root key's note. A cascade member's records were not saved on this path, so the notification composes no member row, as today |
| fetch remote row | `withFetchCloneNote` notes the `remote` row as it notes the fetched and failed rows (04-16); the base `skipped` row has no clone field and is never reached after a clone |
