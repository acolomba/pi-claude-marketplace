<objective>
Make `marketplace add` of a GitHub `owner/repo` source choose its first transport as Claude
Code does (SG-SSH-02, SG-SSH-03; 04-EVIDENCE Q18 and "Progress lines and errors"): upstream's
`ssh -T` probe from the one spawn site, SSH first only on `configured`, HTTPS first
otherwise. CLAUDE_CODE_PLUGIN_PREFER_HTTPS and the GitHub base override give one HTTPS
attempt and no probe (D-SG-24, D-SG-21/OQ-2). `CLAUDE_CODE_REMOTE` is not read (capability
gap, D-SG-24). The runner records the D-SG-22 note on a collector; 04-08 attaches it to rows.

This is the first half of the marketplace transport work. Its scope is the probe and the
order of the attempts. A failed first attempt fails the add as it does today; 04-05 adds the
retry with the other transport, the both-failed error, the ssh stand-in's refusals, the
scenario variables with their PREFER_HTTPS and CLAUDE_CODE_REMOTE scenarios, and the Device
Flow re-baseline. The retry lands with the Device Flow re-baseline because a refused sign-in
starts the SSH retry, which changes those scenarios' failure tables; this plan's gate stays
green because no existing table changes here. The refusing `ssh` of
`scripts/isolated-pi-home.mjs` lands here, in the same commit as the probe, so that no unit or
integration test ever runs the machine's ssh. The `NETWORK_SEAM_NAMES` gate lands here too,
in the same commit as `DEFAULT_GITHUB_SSH_OPS`, so no later plan runs without it.

Purpose: a user with an SSH key adds a private `owner/repo` marketplace over SSH (issue #325).
Output: the probe launch and verb, the `GitHubSshOps` port and its gate, the pure plan, the
runner's first attempt with the note collector, the add seam wrap, the transport force
reader, the refusing test ssh, the no-override profile without a sign-in, and the probe and
order scenarios.
</objective>
