<objective>
Make the release-tag reads use SSH by default for GitHub `owner/repo` sources, as upstream's
`zmt` does, unless `CLAUDE_CODE_PLUGIN_PREFER_HTTPS` or the base override forces HTTPS
(D-SG-20, D-SG-21, SG-SSH-03, SG-SSH-04). Both reads change: a constrained dependency's own
tag list (D-03-03) and a path-source dependency's marketplace tag list (D-SG-09). D-SG-20 as
amended on 2026-11-25: when a `github`-source dependency's SSH listing fails, Pi retries it
once over HTTPS before it counts as `tag-listing-failed`, so a user with no SSH key still
pins the release tag. Path-source dependencies keep the TAGS-02 current-copy fallback.

Purpose: parity with upstream's constrained installs, with the maintainer's one divergence
for `github`-source dependencies; the accepted consequence for a user with no key is the
TAGS-02 current-copy fallback for a path-source dependency only.
Network: the retry runs only inside an install or update that already lists this
dependency's tags (NFR-5's D-03-03 read); it adds no network use to `list`, `info`, or a load
without autoapply. 04-18 records it in the NFR-5 text.
Output: `tagReadUrl`, the two probes using it with the chosen URL as the memo key, the
dependency listing's HTTPS retry, and the tag-read scenarios.
</objective>
