## Measured facts this plan relies on (2026-11-26)

- Import installs each plugin with the opinion Claude Code's `enabledPlugins` gives it, so DFEN-04
  never lands an import install disabled: `import/execute.ts` composes no `installs disabled`
  row (its `disabled` arm is an enable outcome, read as already installed). Only apply's
  `landedDisabled` branch (`reconcile/apply.ts` line 787) reports #130's row.
- #138 has no scenario. The only harness fault that makes a rollback fail is the read-only skill
  directory of a local publication (`features/lib/published-marketplace.ts::publishReadOnlySkillDirectory`,
  whose doc says git stores no directory mode), and every other undo removes only what its own
  do wrote first, so no Given can make a cloned plugin's rollback fail. The existing dir-source
  scenarios (`features/plugin/apply.feature` line 343, `features/plugin/import.feature` line
  1147) clone nothing and keep their bytes. The unit cases below prove the dependency row's note;
  the SUMMARY records the reason, and 04-26 carries it into the D-SG-22 outcome.
- Independence from 04-21: this plan's apply and import rows read each install call's own view
  (04-17); 04-21 changes only the standalone install's composers, so either order gives the same
  rows (04-21 declares the pair in `coupling_justified`). The optional collector this plan adds
  to `AddMarketplaceOptions` is set only by bootstrap; the D-MF-04 add that 04-21 reads keeps
  recording under the marketplace's name as today.
