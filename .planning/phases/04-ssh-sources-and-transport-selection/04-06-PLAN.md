<objective>
Make `/claude:plugin install` of a GitHub plugin choose its transport as the shell
`claude plugin install` does (D-SG-18, SG-SSH-04; 04-EVIDENCE Q7, Code Examples `Qmt`,
`zHi`): the skip checks in upstream's order, the probe once per command, HTTPS first then
SSH only when every check passes, SSH only otherwise, and one both-failed error. The
command's transport context reaches required dependency installs and the bare-name retry.

Purpose: a user with no SSH key keeps installing GitHub plugins over HTTPS, and a user with
a key or an ssh setting gets SSH (issue #325).
Output: the `-G`, `--get-url`, and override checks; the pure plugin plan; the context; the
clone-cache wrap of the clone step; the install-root threading; the plugin transport
scenarios. Sequencing inside the phase: `update`, `reinstall`, dependency moves, `fetch`,
and `info --fetch` call clone-cache without the install root, so they pass no transport and
keep their one `networkUrl` attempt until 04-11 (update, reinstall, dependency moves) and
04-12 (fetch, info --fetch) give them contexts; 04-12 makes the field required. `apply` and
`import` reach installs through the install root, so each install call they make builds its
own context here; 04-17 gives each of those commands one context. `enable` re-materializes
through the guard-free ledger with no context, so until 04-12 it takes the no-context arm of
step 6 (SSH only unless forced). That arm is temporary: D-SG-19, extended by the maintainer
on 2026-11-25, makes `enable` follow the install's probe and fallback, and 04-12 creates its
context at its command root and removes the arm.
</objective>
