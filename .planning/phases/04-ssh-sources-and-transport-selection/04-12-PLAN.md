<objective>
Give `fetch`, `info --fetch`, and `enable` the install's transport choice, one context per
command root (OQ-7; D-SG-19, extended by the maintainer on 2026-11-25 to `enable`, which
re-clones a git plugin whose clone is gone). The enable root creates its context and
forwards it through the enable cascade, so one enable command probes once. Then remove the
SSH-only no-context arm 04-06 kept for `enable`, and make the clone-cache transport required
on all five entry points, which compiles only now that every caller passes one.

No-context default: after this plan no production path reaches a plugin clone without a
command root's context. Install (04-06); update, reinstall, dependency moves, and the
converge entry (04-11); and fetch, info --fetch, and enable (this plan) each create one at
their root when the caller gave none. `apply` and `import` reach those roots, which build a
context per call until 04-17 passes one per run. The only remaining default is the one
`probeInstallClone` creates for a direct caller of the guard-free ledger that passes no
context; no production module is such a caller after this plan, and that default follows the
install's rules, so no path is SSH only for want of a context.

Purpose: a user with no SSH key keeps working HTTPS fetches and re-enables, and a user with a
key gets SSH.
Output: the fetch, info, and enable contexts, the enable cascade threading, the removed arm,
the required transport, and their scenarios. Their rows' notes are 04-16's; apply and import
pass their run context to the enable option in 04-17.
</objective>
