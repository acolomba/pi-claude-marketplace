Upstream (Claude Code 2.1.310 `omn`): `... is installed at <v>, which does not
satisfy: <ranges>. To look for a version in range, run \`claude plugin update
<key>\`` -- the hint appears only when the root declares the dependency directly
(E5). House style for a command hint in a cause is `run /claude:plugin <verb>
...` with no backticks (`shared/notification-mcp.ts`, `reconcile.messaging.ts`).

Probed today (RESEARCH Pattern 4) with `lib` a url git dependency installed at
1.0.0, a remote tag `lib--v2.0.0`, `app` needing `lib@^2.0.0`, and the git host
dropping the connection for `lib`: the lib row reads `Dependency "lib@tools" is
installed at version 1.0.0, which does not satisfy ^2.0.0, and cannot move: the
release tags could not be listed (network unreachable) -- required by
"app@tools"` with reasons `already installed, version conflict`; app reads
`{dependency failed}`.

Data flow: the text is built in `install-cascade.messaging.ts::rangeConflictFacts`
(around line 358). Its subject comes from `dependency-plan.ts::unmovable(request,
cause)` (around line 150), which holds `request.requesters` (every plugin of the
graph that declares the dependency, as `GraphRequester`s) but no root key; the
messaging has `rootKey`. `unmovable` is called from two places in the plan; both
reach the same function. `checkInstalledMember` builds the same arm with no
`moveRefusal` (no move judged), which must get no hint (RESEARCH Pitfall 9).
`moveRefusal` can be `errorMessage(err)` text that already ends with a period.

Pins of the refusal text that change (the named plugin declares the dependency
directly in each): install-dependencies.feature scenarios "Installing a plugin
whose installed dependency no release moves inside its version constraint fails
as a version conflict and keeps only the dependency", "Installing a plugin whose
installed dependency another plugin holds outside its version constraint fails
as a version conflict and changes nothing", and "Installing a plugin whose
installed dependency no release moves into range keeps the mirror a fetch
warmed"; update-dependencies.feature "Updating a plugin whose new version needs a
dependency version no release offers fails and keeps the installed versions"
(update's settle passes the updated plugin as the root); install-flow.test.ts
"UPD-DEP-D1: installing refuses a plugin whose installed dependency no release
moves inside its range"; the catalog state `dependency-installed-version-conflict`
(`helper@official` declares `formatter@tools`). `grep -rn "cannot move"` over
`features/`, `test/`, and `docs/` finds every pin; re-run it before Task 2 ends.
