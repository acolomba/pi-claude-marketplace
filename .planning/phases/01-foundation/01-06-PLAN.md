<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pi process to the network | A Pi without the GitHub base override sends GitHub requests to github.com; only the in-process redirect keeps them local. |
| stand-in token to git credentials | The product stores the issued token with `git credential approve`; it must land only in the sandbox HOME's store. |
| stand-in to TLS trust | The stand-in serves with the git host's key, which Pi trusts through `NODE_EXTRA_CA_CERTS`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-1-13 | Information disclosure | `github-device-flow/extension.ts` | high | mitigate | Every non-loopback host other than github.com is refused with an error that names it; every decision is logged; the seeds state the log whole with no refused row; the unit cases pin the refusals; the world refuses a launch without the GitHub base override that loads no extension, and the terminal session inherits the extension; `PI_OFFLINE=1` and `--offline` stay set. |
| T-1-14 | Spoofing | fixed access token and the credential store | medium | mitigate | The token is a fixed fake that only the run's git host accepts; `GIT_CONFIG_GLOBAL` points at the sandbox HOME, so `git credential approve` writes only `{home}/.git-credentials`. |
| T-1-15 | Tampering | patched `https.request`, `http.request`, `fetch` | medium | mitigate | Loopback requests pass through unchanged, so the git host, the hosted catalogs, and the MCP stand-ins keep working, proven by the regression features. |
| T-1-16 | Information disclosure | reuse of the git host's private key | low | accept | A one-day self-signed P-256 key made per run in the run's temporary root, for `127.0.0.1` only; removed with the run. |
| T-1-SC | Tampering | npm/pip/cargo installs | high | accept | This plan installs no package; there is nothing for the package-legitimacy gate to check. |
</threat_model>
