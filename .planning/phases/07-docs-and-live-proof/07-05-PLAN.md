Status token meanings (docs/output-catalog.md "MCP server status", lines 2592-2607): `connected`; `cached, connects on first use` and `not connected` are the resting states of a lazy server that has not connected yet, not failures; `needs authentication`; `pending approval` covers all three project-trust block reasons (the project is not trusted, approval is required, approval was denied); `disabled`; `failed` shows only while the adapter holds the server in its failure backoff, and Claude Code's status text says `not connected` for a failed server while its `/mcp` panel says `failed`; `status unknown` (the adapter is absent, has not published in this session, last sent its empty session-start or shutdown snapshot, or sent a malformed or newer snapshot); `not loaded` (a snapshot that does not list the server: a plugin installed in this session that the adapter has not read yet, or an old `mcp.json` entry the move left in place); `overridden by project scope` (a user row whose server the project scope's entry replaces). Info shows no state on `(disabled)` rows, on rows that are not installed, for left-out servers, or on `components: not resolved` rows, and the state never changes the severity.

pi-mcp-adapter 5.2.0 facts (read-only source, verified during planning):
- `init.ts` lines 303-346: at startup the adapter connects only servers whose lifecycle is `keep-alive` or `eager` and servers without a valid cached tool list (it reads the list, saves it, and stops a lazy server again); a lazy server with a valid cached list starts on first use.
- `index.ts` lines 751-773 (`getDeferredSessionSnapshot`): a deferred session needs no project-file server, every enabled server lazy, and a valid cache for each; it then publishes nothing after the empty session-start snapshot until the first MCP use (a tool call, `/mcp` or `/mcp-adapter`).
- `project-server-trust.ts` lines 181-224: every server from a project file, `<project>/.pi/mcp-adapter.json` included, is a project server; an untrusted project blocks it; a trusted interactive session asks "Allow project MCP server ...?" with "Don't allow" first (the default); a session without UI blocks it as approval-required unless the user-global config sets `settings.projectServers` to `"allow"`; the approval is keyed by project, server name and a hash of the whole entry.
- `domain/clone-key.ts` (this repository): a git-source plugin clone lives under a key that includes the commit sha, so every update of such a plugin moves its root and changes its entry.
- D-07-08 effects, from the research table: `PI_MCP_CONFIG_MODE=exclusive` reads only the user file (`<agent dir>/mcp-adapter.json`, or the `--mcp-config` path), so project-scope plugin servers do not load (it also skips shared imports, Pi's `mcp.json` files, ancestors and Claude plugin loading); `--mcp-config <file>` replaces the user file path, so user-scope plugin servers do not load while the project files are still read; `MCP_DIRECT_TOOLS=<server>[/<tool>],...` replaces every entry's `directTools` (a named server's tools are always in the prompt, an unnamed one gets no direct or search tools, `__none__` selects nothing), and the `mcp` proxy tool still reaches every configured server. Link `https://github.com/nicobailon/pi-mcp-adapter/blob/main/docs/configuration.md`.
- Claude Code 2.1.294 evidence for D-07-06: E1 (per-tool `_meta["anthropic/alwaysLoad"]`: a tool reported with `true` stays in the prompt even when its server is deferred; under a server `alwaysLoad: true`, a tool with `false` stays deferred) and E2 (Claude Code asks approval only for `.mcp.json` project servers; plugin servers never wait), as recorded in 07-CONTEXT.md `<compat_evidence>`.
- 5.2.0 Security entry: the MCP SDK moves from 2.0.0 to 2.3.1, which fixes GHSA-6qxp-vccf-f47h (with 2.0.0, a malicious or compromised MCP server could point sign-in at its own authorization server and receive the refresh token and client secret saved from an earlier sign-in); a server URL that redirects to a different host is no longer followed; a redirect from `http` to `https` on the same host still works.
