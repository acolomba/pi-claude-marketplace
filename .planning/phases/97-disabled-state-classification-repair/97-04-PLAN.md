<objective>
Make load-time reconcile a fixed point for a disabled partially-installed record.
Two independent paths break that today: the planner pushes a disable on every pass
because the pre-collapse predicate never recognized the record (fixed by plan
`97-01`, pinned here), and the backfill scan filters only on availability, so a
disabled partial whose manifest supported set grew is re-materialized AND
re-enabled at load time with no prompt.

Purpose: a pass that reverts the user's disable is not steady state. The
requirement text names only the disable re-plan, but the backfill path falsifies
the same claim, so both are in scope.

Output: a two-line early return in the backfill scan, its regression test over a
manifest-present grown-set fixture, a corrected seam comment, and the two-pass
planner fixed-point test.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| load-time reconcile → artifact materialization | `resources_discover` runs unattended at every Pi load. Anything this path materializes is installed without a user command, so it is the highest-consequence surface in the phase. |
| `state.json` + merged config → planner | The planner is pure (DIFF-01) and its purity is enforced by a token-grep architecture gate; it decides what the applier will do. |

The planner performs no I/O. The backfill scan resolves cache-only (NFR-5) and performs no network
call. No new input surface.
