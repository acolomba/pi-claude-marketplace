  <action>
Read the gate in full first. It already resolves every relative specifier a test file imports OR
re-exports, and it already has an injectable project root that the existing control drives a fixture
tree through. Both facts are what make this change small.

**The change.** In the loop over production modules, the branch that fires today when an owner's
resolved imports do not include its own source path currently emits one verdict. Split it: before
emitting, ask whether any module the owner DOES import re-exports the owner's pair. Reuse the gate's
own specifier-resolution helper against each imported path to get that module's own import and
re-export targets, and check whether the pair's source path is among them. If it is, emit the
proxy-owned verdict; otherwise emit the existing one. Use the exact verdict spelling `proxy-owned`,
which is the operator's word in D-117-21 — research's draft used a different one and the operator's
wins.

Guard the lookup. An imported path may not exist on disk, may be a directory, or may not be a
TypeScript file; reading it unguarded makes the gate throw where it should report. A gate that
crashes is not a gate that fails closed. Existence-check before reading and treat anything unreadable
as "does not re-export the pair".

Look only one level. A barrel that re-exports a second barrel that re-exports the pair is not in
scope: it is rarer, it costs a graph walk with a cycle guard, and nothing in the tree needs it. State
that limit in the script's own comment so the next reader does not assume otherwise.

Change nothing else. Do not touch the spelling, order or exit behaviour of any existing verdict, and
do not touch the supplemental-companion rule. Two other scripts and an architecture suite read this
gate.

**The control.** Extend `scripts/check-corresponding-tests.negative.mjs` following the shape it
already uses: build a clean fixture tree, assert the check returns an empty array, then mutate ONE
thing, assert the exact violation array, and restore before the next mutation. Add a barrel to the
fixture — a module beside the existing fixture source that re-exports it — and then plant two states
in turn:

1. the owner imports ONLY the barrel: assert the array is exactly one proxy-owned violation naming
   the owner's path;
2. the owner imports neither the barrel nor its pair: assert the array is exactly one wrong-import
   violation naming the same path.

Those two plants together are the whole proof. The first shows the new branch is taken; the second
shows the old one still is, and that the two are not collapsed. Assert the arrays as whole values with
a deep strict comparison, exactly as the existing plants do, and restore the fixture between them.

Add a third state only if you can name what it would catch that the two above do not. Do not add a
plant for the undecidable case — an owner importing its pair directly with a barrel beside it — and
do not make the gate guess at it. Record in the summary that the case is undecidable from the import
list, that deciding it needs call-site analysis, and that the gate deliberately stays silent.

**What a green gate run does and does not prove here.** The branch this task splits is EMPTY on the
current tree: every owner imports its pair directly, so the enclosing branch is never entered. Running
the gate after the change therefore proves only that nothing regressed — it proves nothing about the
new verdict. Say that plainly in the summary. The control is the evidence.

Note that `scripts/` is covered by neither the ESLint target nor the prettier glob nor the fallow
file pattern, so nothing formats or lints these two files for you. Match the surrounding style by
hand and keep the diff minimal.

Change no production file and change no test file.
