<objective>
Make the HTTPS git-host stand-in ready for a product that speaks system git:
system git trusts it through `GIT_SSL_CAINFO`, it serves a fetch by SHA, and a
refusing arm makes that fetch fail for the fallback path a later phase drives.
Give every cucumber Pi the run's CA file for system git, and let the run state
Pi's `PATH`.

Purpose: SG-HRN-02 and CONTEXT [HTTPS stand-in] ("How does system git trust the
HTTPS stand-in?", "How does the stand-in serve fetch by SHA, and how does the
refusing arm refuse it?"). RESEARCH experiment X3 measured each behavior
against the real `HttpsGitHost` (cases A-K). The two new `RpcGitEnvironment`
members land in one change, so each literal site is edited once; plan 01-07
puts the SSH stand-in's directory first on the run's `PATH`.

Output: `ShaWantPolicy`, `httpBackendArguments`, the `refuse-sha-want` arm,
`HttpsGitHost.repositoriesRoot`, `RpcGitEnvironment.GIT_SSL_CAINFO` and `PATH`,
and the harness self-checks under `test/architecture/`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| system git client to the loopback HTTPS stand-in | TLS trust; a client could be made to accept the server by weakening verification |
| HTTP request to the CGI | request headers become CGI variables; upload-pack settings must not travel as environment |
| run environment to Pi | Pi's CA file and PATH come from the run, never from the shell |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-15 | Spoofing | TLS trust of the stand-in | high | mitigate | `GIT_SSL_CAINFO` names the run's own certificate; a case proves a clone without it fails certificate verification; the acceptance guard finds no option that turns verification off in `features/` or `test/` |
| T-01-16 | Tampering | `GIT_CONFIG_*` reaching the CGI | medium | mitigate | `httpBackendArguments` passes the upload-pack settings as `-c` arguments; the CGI environment stays `hermeticGitEnvironment` plus CGI keys (guarded by grep; plan 01-08 asserts the key set under planted variables) |
| T-01-17 | Tampering | the shell's `GIT_SSL_CAINFO` or PATH reaching Pi | medium | mitigate | `rpcChildEnvironment` copies only the run's members; the hermetic test plants the shell's `GIT_SSL_CAINFO` and asserts the exact key set |
