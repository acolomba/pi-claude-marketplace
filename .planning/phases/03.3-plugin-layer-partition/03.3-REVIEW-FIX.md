### WR-02: The target-only marketplace gate writes a plugin key without its marketplace when the record has no string `source.raw`

**Status:** fixed: requires human verification
**Files modified:** `extensions/pi-claude-marketplace/shared/errors.ts`, `extensions/pi-claude-marketplace/orchestrators/plugin/shared.ts`, `extensions/pi-claude-marketplace/orchestrators/plugin/install-flow.ts`, `extensions/pi-claude-marketplace/orchestrators/plugin/enable-disable.ts`, `tests/shared/errors.test.ts`, `tests/orchestrators/plugin/{shared,install-flow,enable-disable}.test.ts`, `tests/integration/plugin-layer-verbs.test.ts`, `tests/architecture/catalog-uat/{catalog-contract,catalog-parser,catalog-wire}.test.ts`, `tests/architecture/catalog-uat/fixtures/plugin-install.ts`, `docs/output-catalog.md`
**Commit:** 3dafcdf7
**Applied fix:**

- `undeclaredMarketplaceSource` (formerly `synthesizeUndeclaredMarketplaceSource`) returns a discriminated `declared | source | unknown` result. A record with no string `source.raw` falls back to the source the other layer declares, the string the merged view already reads.
- `writeAdoptingConfigEntries` throws the new `MarketplaceSourceUndeclarableError` before it writes anything when no source is known for the plugin's own marketplace. It never writes the plugin key alone.
- The new `undeclarableMarketplaceRefusal` refuses `install`, `enable`, and `disable` before any state change, with `{unsupported source}` and a cause naming the layer file to declare the marketplace in. Install generalizes its FIX-03 arm to `{ kind: "refused", refusal, reason }`. Enable and disable check it inside `refuseMarketplaceDeclarationWrite` (formerly `refuseLocalOnlyMarketplace`), under the same "would write" gate.
- A marketplace the scope does not record yet is never refused, because the install that adds it records its source.
- New catalog state `failure-marketplace-source-undeclarable`. Pins: 287 to 288 states, 297 to 298 presented, 45,871 to 46,148 bytes (measured).

**RED (before the change):** the two integration cases failed. The fallback case wrote the local layer as `marketplaces: {}` plus `alpha@mp`, which is exactly the shape the reload stops on. The refusal case rendered `(skipped) {already installed in shared layer}` and wrote the dangling key. The two enable and disable owner cases failed on behavior. The errors, shared, and install-flow owner files failed at import of the new exports.
**Why human verification:** the reason token for the refusal (`unsupported source`, reused from the closed set) and the refusal's existence for the pre-existing S4 "no layer declares it" arm are design choices made under the caller's disposition ("refuse before writing"). That arm wrote a dangling plugin key before this phase and is now refused too.
