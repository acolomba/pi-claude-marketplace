### IN-05: The nameless `update --local` / `reinstall --local` never cover the dependencies of local-layer plugins

**Status:** fixed: requires human verification (two judgment calls, below)
**Decision (user, 2026-10-17):** the nameless `--local` forms cover the plugins the local layer declares and the dependencies those plugins need, walked transitively through undeclared dependency records, but not dependencies that only shared-layer plugins need. Without the flag, the nameless forms keep covering every installed plugin. Recorded as D-15 "Amended" in `03.3-CONTEXT.md`.
**Files modified:** `extensions/pi-claude-marketplace/orchestrators/plugin/shared.ts`, `tests/orchestrators/plugin/shared.test.ts`, `features/plugin/update.feature`, `features/plugin/reinstall.feature`, `docs/output-catalog.md`, `CHANGELOG.md`, `.planning/phases/03.3-plugin-layer-partition/03.3-CONTEXT.md`
**Commit:** 0da916be
**Applied fix:** `keepLocalLayerTargets` keeps its signature, so `update-flow.ts` and `reinstall-flow.ts` are unchanged. Per scope it now reads both layers through `selectDeclaringConfigWriteTarget({ local: true })` and the scope's state, then walks forward from every key the local layer declares. Each installed plugin's declarations come from `readRecordDeclarations` (the offline D-05-06 read in `dependency-index.ts`). A dependency the shared layer does not declare joins the covered set and the walk continues from it. A plugin the shared layer declares ends the walk. This is the LAYER-08 `declaredNeedersByLayer` walk read in the other direction: a dependency is covered exactly when a plugin the local layer declares (alone or with the shared layer) needs it. The catalog's update and reinstall paragraphs and the CHANGELOG sub-bullet now name the dependencies.
**RED (before the change):** the new scenarios "Updating every plugin with --local also updates the dependencies the local plugins need" and "Reinstalling every plugin with --local also reinstalls the dependencies the local plugins need" failed (`tally success count` 1, expected 2; the `lib@tools` row was missing). Two of the four new `keepLocalLayerTargets` unit cases failed (the transitive dependency case and the unreadable shared layer case). The other two (a shared-declared plugin ends the walk; an unreadable declaration adds nothing) pass on old code by construction and guard the boundaries against an over-wide walk. All passed after the change.
**Why human verification:**

- A plugin whose declarations cannot be read (its marketplace manifest fails to load, the manifest no longer lists it, or its own manifest is present but unusable) adds no dependency, and the command goes on. Update and reinstall remove nothing, so the D-05-07 fail-closed rule does not apply, and that plugin's own row still runs and reports its own problem. The alternative is to fail the whole `--local` command with `{unreadable}`, as `uninstall` and `marketplace remove` do.
- An unreadable `claude-plugins.json` now stops a nameless `--local` form with `LayerFileUnreadableError` (CFG-03), because it decides which plugins are undeclared. Before, only an unreadable local layer stopped it.
