# Phase 3.3: Plugin Layer Partition - Discussion Log

> **Audit trail only.** Do not use as input to planning, research, or execution agents.

**Date:** 2026-10-17
**Areas discussed:** failure reasons, undeclared plugins, install/uninstall across layers, marketplace in another layer, both-layer declarations, terminology

The discussion ran in plain text. The user asked what "the file" meant; the questions were restated in terms of the shared and local configuration files, and the user then asked to fix the scope/layer terminology project-wide.

- **q1 reasons:** recommended pair accepted.
- **q2 undeclared plugins:** an installed but undeclared plugin is a dependency; uninstall refuses with the plugins in the target layer that need it, and it is really uninstalled only when no plugin in the other layer needs it either.
- **q3/q5 both layers:** the user reversed the "one layer per plugin" rule. Both layers may declare the same plugin, installed once per scope; install into the second layer is a no-op `{already installed in [shared|local] layer}`; uninstall from one layer is a no-op `{still installed in [shared|local] layer}` with the hint to repeat [with|without] `--local`.
- **q4 marketplace elsewhere:** a plugin declared without its marketplace in the same layer is a configuration file error (whole-layer, like an invalid file).
- **Terminology:** scope = user/project (owns clones and installs); layer = shared/local declaration file; a new Phase 3.4 renames existing text and identifiers after 3.3.
- **Merge:** plugin entries merge field by field, local winning (reverses 3.2 D-10).
