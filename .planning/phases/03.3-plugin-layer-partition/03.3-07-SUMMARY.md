# Phase 03.3 Plan 07: Retire the Update and Reinstall Write-Back Summary

**Update and reinstall now change the installation and its record only: neither writes a plugin declaration, so a bare update, a named reinstall of a dependency, and the load-time backfill's reinstall all leave dependencies undeclared, and the write-back family and its unreadable-layer rows are deleted.**

## Accomplishments

- `update-swap.ts`: `finalizeUpdateRecord` returns `void` and no longer calls the write-back; its guard callback is synchronous now (ESLint `require-await`). The S5 row function `notifyInvalidConfigWriteBack`, the `invalidConfigFile` carrier in `swapPluginUpdate`, and the unused `notifyWithContext` and `UPDATE_CONTEXT` imports are gone. The finalize JSDoc states the rule (LAYER-04 / D-MF-03).
- `update-flow.ts`: the comment on the `local` field now says it picks the layer a named update acts on.
- `reinstall-flow.ts`: the write-back call before `tx.save()`, `LockedSuccess.invalidConfigFile`, the `render: "none"` spread, the single-plugin S5 row, `notifyInvalidConfigWriteBack`, and `surfaceReinstallInvalidConfigFiles` are gone, with the now-unused `ReinstallOutcomeBase` import. `reinstallPluginWithTransaction` and `reinstallPluginsWith` each lost a branch.
- `orchestrators/types.ts`: `invalidConfigFile` removed from the reinstalled outcome.
- `orchestrators/plugin/shared.ts`: `LayerWriteBack`, `selectLayerWriteBack`, `flaglessLayerWriteBack`, and `maybeWritePluginConfigBack` deleted. `localOnlyMarketplaceRefusal` kept (install, enable, disable).
- `orchestrators/reconcile/backfill.ts`: no comment named the write-back, so it is unchanged. Its tests now pin that the backfill leaves no `claude-plugins.json`.
- `docs/plugin-enablement.md`: the row that named `maybeWritePluginConfigBack` now says neither verb writes a layer file.
