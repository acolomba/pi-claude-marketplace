<objective>
Run every plugin-clone cleanup under the state lock of the operation's scope
(GLK-03, D-PL7-05, D-PL7-13), so no cleanup deletes a clone that a locked
`fetch`, `info --fetch`, or update preflight is reading.

Purpose: today every GC call runs after its operation released the lock, with
no lock at all; a concurrent locked reader can lose the clone under it.
Output: `collectPluginClonesLocked` and `listUnreferencedPluginClonesLocked` in
`clone-gc.ts`, every call site switched to them, and the unlocked bodies made
module-private so the lock cannot be skipped.
</objective>

## Trust Boundaries

| extension -> filesystem | GC recursively deletes directories under `<scopeRoot>/pi-claude-marketplace/plugin-clones/` |

## STRIDE Threat Register
