<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git host -> extension -> user output | the host's HTTP answer becomes a reason token and the row's first cause link |
| process -> process (same scope) | a fetch reads a mirror tree another command may refresh or a cleanup may delete |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-15 | Tampering | fetch row read after the lock is released (a concurrent cleanup or refresh changes the tree being classified) | medium | mitigate | One `withExistingScopeLock` body covers the materialize and the row read on the unpinned arm (D-PL7-07); GLK-05 unit case observes the lock during the read; the pinned clone is immutable and GC now takes the lock (07-02). |
| T-07-16 | Information disclosure | the frame URL in the fetch row's cause | medium | mitigate | The frame is an Error message in the cause chain; `serializeCauseChain` redacts credentials in every link (`grep -n "redactCredentials(linkMessage" extensions/pi-claude-marketplace/shared/errors.ts`). |
| T-07-17 | Elevation of privilege (policy) | fetch.ts reaching the git surface directly | low | mitigate | fetch.ts imports `classifyGitFailure` from `shared/` and the list rule from `list-candidate-version.ts`, never `platform/git.ts`; ESLint BLOCK F (`npm run lint` in check:static) rejects otherwise. |
| T-07-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs or upgrades no package; package.json and package-lock.json are not in files_modified. |
