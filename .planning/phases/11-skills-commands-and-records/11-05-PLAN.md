<objective>
Attach the files that a skill's author mentioned when the user types the skill or one of its
aliases, inside Pi's skill block.

Purpose: PG-SKILL-01 for skills, under D-PG11-02, D-PG11-05, and D-PG11-07. Plan 11-04 built the
reader and the one function that scans, reads, and appends; this plan calls it from `fillSkill`.
Two points differ from the command wiring. The blocks go into the body of Pi's skill block,
because Pi shows any text after the closing `</skill>` line as the user's own message. And the
skill invocation builds its own scan input, so it needs its own guard that a typed argument never
names a file. The model's read of a staged `SKILL.md` attaches nothing: Claude Code's Skill-tool
path is unverified, and that work is deferred.

Output: the skill wiring, one scenario through an alias that is red before the change, and one
guard scenario that is shown able to fail.
</objective>
