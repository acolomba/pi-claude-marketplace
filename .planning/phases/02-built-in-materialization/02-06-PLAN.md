## Flagged assumptions (spec-less edge probe)

- BLT-06 idempotency: a second new session with no record change registers the same servers with the same configs; inside one load, the resync re-registers nothing whose config JSON is unchanged (unit-proven in plan 02-01 and shown here by the single `initialize`). Pi itself reconnects every server at a new session, because the registrations die with the runtime; that reconnect is Pi's, not a re-registration.
- Pi's `new_session` over RPC binds the extension twice (`features/lib/pi-commands.ts`), so session_start runs twice in such a session; the sync is idempotent, so the scenarios hold either way.
