Purpose: Plan 04-03 stores both forms at staging and Plan 04-04 swaps them at load (D-MB-03). Neither can start until the bridge renders the built-in form and the row can hold it. No caller passes the implementation yet, so no visible output changes in this plan.
Output: per-implementation rendering in `convert.ts`, a new warning-text module, the frontmatter block emitter, the schema fields, their unit pairs, and an integration conformance test against pi-subagents' own resolver.
</objective>
