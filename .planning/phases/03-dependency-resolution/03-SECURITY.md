# Phase 03 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| Cloned marketplace repo -> `marketplace.json` -> cascade | Untrusted third-party JSON supplies the dependency graph this phase walks and materializes from | plugin names, marketplace names, version ranges |
| Cloned plugin tree -> `plugin.json` -> cascade | Same, for a plugin's own manifest; the file is opened by path during install planning | manifest bytes, `dependencies` value |
| Cascade -> `state.json` / `claude-plugins.json` / scope artifact roots | The cascade writes records and artifacts on behalf of plugins the user never named | install records, staged artifacts |
| Declared range text -> `intersectDependencyRanges` -> notification reason | Untrusted strings drive a combinatorial computation whose synthesized output reaches a line-oriented row | semver range text |
| Accumulated constraints -> network query | Untrusted range text decides whether and where a tag query is made | intersected range, source URL |
| Remote git host -> tag advertisement -> install pin | Attacker-controllable ref names and object ids cross into the install pin | tag names, commit ids |
| Host credential bundle -> tag query | Credentials for a private source are used on a new code path | auth callbacks |
| Recorded install state -> satisfaction check | A recorded version string of this project's own making crosses into a version evaluator | `hash-<12hex>` / `sha-<12hex>` / semver strings |
| npm registry -> `node_modules` | A new runtime dependency (`semver`) enters the supply chain | package tarballs |
| Stated constraints / user docs -> future implementers and user trust decisions | The network carve-out and the unadded-marketplace rule are the documented statements of where trust boundaries sit | prose |
