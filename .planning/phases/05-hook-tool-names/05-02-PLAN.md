<objective>
Limit pi-mcp-adapter's `mcp` proxy special case (D-CF5-12) to sessions where the adapter is the active MCP implementation (MHK-02, D-P5-06), read lazily once per bridge generation (D-P5-07), and turn the Phase 1 `@adapter-only` hook scenario into an `@adapter-only` and `@builtin-only` pair (D-P5-11), with a built-in scenario whose cut tool name looks like a proxy call (D-P5-10).

Purpose: under Pi's built-in MCP there is no proxy, so the rule can only skip real tool calls. A built-in tool whose name Pi cut inside the namespace has no second `__`, and a call with a string `tool` in its input then runs no guard hook at all.
Output: `proxyRuleApplies` on the view, the gated proxy check in both tool handlers, one view per generation in the router, and three scenarios in `features/hook/tool-use.feature`.
</objective>
