a new platform spawn module, for a plugin whose root lies inside the extension root and ships package.json plus a
supported lockfile. It also lands every gate the new spawn site needs. Task 2 adds the refusals Claude Code makes
before it spawns anything.

entry. So the platform module, its one consumer, the ledger wiring that makes that consumer reachable, and the
whitelist must land in one commit. The gate edits are a few lines each.

Out of this plan: the note for a plugin root outside the extension root (D-PL9-03 note) and the update hook
(D-PL9-07). Plan 09-03 adds both; until then such a root is skipped silently and never written. The behavioral
scenarios are plans 09-02 and 09-04.

Purpose: a plugin whose hooks or MCP servers need their own npm packages works after install, and a package
install that fails never blocks the plugin.
Output: two new production modules with paired tests, one ledger phase, the spawn whitelist and rule pack entry,
and the ESLint seam zone.
