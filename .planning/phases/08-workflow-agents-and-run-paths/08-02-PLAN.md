<objective>
Say at install, at update, and in `info` when a workflow script names an agent type that its plugin does not install, prove that a script's `agentType` runs the plugin's own agent, and correct the compatibility row that says otherwise.

Purpose: Claude Code 2.1.323 stops a workflow step whose `agentType` names no agent: `agent type '<x>' not found`. The workflow engine logs one line and runs a default agent with default tools and model, so a plugin whose script names a missing agent runs with no sign that anything is wrong. The engine resolves agent types, so this project cannot stop the run; it can say so when the plugin is installed. The compatibility page says today that an unresolved agent type is no error on either side, which is wrong for Claude Code. The divergence is licensed by a Pi-side gap (D-PG8-06).
Output: the join in extensions/pi-claude-marketplace/orchestrators/plugin/discover-names.ts with its owner cases, one renamed member in three consumers, features/workflow/agent-types.feature with seven scenarios, the corrected row of docs/workflows-compatibility.md, and one catalog state with its fixture.
</objective>
