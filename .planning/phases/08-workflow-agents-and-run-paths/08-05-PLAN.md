<objective>
Ask the maintainer whether a bridged agent may hold the workflow engine's `workflow` tool, and, if the answer is no, record why the grant is dropped and pin the drop.

Purpose: PG-WF-05 assumes that an agent whose source grants `Workflow` can start workflows in Claude Code. Research found that it cannot when it runs as a subagent: Claude Code's documentation, its 2.1.323 binary, and the one official agent that lists the grant all say that `Workflow` is removed from every subagent. Every bridged agent on Pi is a pi-subagents child, so parity is to keep dropping the grant, and granting it is a divergence that needs the maintainer's decision with an ID. The project rule sends that question to the user: "our way is more useful" does not license a divergence. Spike S5 says whether the grant could work at all; it does not say whether parity wants it.
Output: the recorded choice in the summary. Under option A: one guard scenario, one passage and one bullet in docs/mcp-compatibility.md, and one sentence in each README. Under option B: nothing more here; plan 08-06 follows.
</objective>
