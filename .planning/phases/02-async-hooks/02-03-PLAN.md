## Interfaces this plan consumes

- `reapOrphans(runtime, loc, probes = DEFAULT_ORPHAN_PROBES)` (`registry.ts`): inside `runtime.runPidTableOperation(pidTablePath(loc), ...)` it reads the table, kills each live row whose `/proc/<pid>/environ` marker equals the row's `dispatchId` (soft-skips on other platforms), then unlinks the table. `writePidTable`, `unlinkPidTable`, `readPidTable`, `pidTablePath` (`pid-table.ts`; atomic, contained in `loc.dataRoot`, never throw).
- `runtime.pidTableEntries(loc)` returns this runtime's live children of that scope as table rows; `runtime.isProjectTrusted(cwd)` returns the answer the last project hydrate recorded (`runtime.ts`).
- `event-router.ts`: `registerHooksBridgeWith` (factory reap per hydrated scope; the `session_start` wrapper runs `hydrateProjectScopeForCwdWith(reader, ctx.cwd, ctx.isProjectTrusted(), routingState, generationIsCurrent)`, then the generation check, the rebuild, the shared data directories, the reload return, and the SessionStart dispatch); `createHooksHydration(runtime, reader).hydrateProjectScopeForCwd(cwd, projectTrusted)`, which `index.ts` calls from `resources_discover`. Pi 1.5.0 emits `session_start` before `resources_discover` in every load, and a terminal Pi draws `[Extensions]` only after both (02-RESEARCH.md, "Pi re-runs the extension factory").
