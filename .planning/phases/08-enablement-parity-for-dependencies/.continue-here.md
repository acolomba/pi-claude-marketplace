- [ ] CONSTRAINT: execute-phase-isolation-sentinel — Dispatching a `gsd-executor` Agent() while the dispatch-isolation sentinel still reads `harness-worktree` (the default) is REJECTED by the PreToolUse isolation guard with an explicit error, even after `worktree base-check` correctly reports `shouldDegrade: true` for this repo (fork-base mismatch, #683 — same as every prior phase in this milestone). Calling `gsd_run query dispatch-isolation --raw --force-isolation none` sets the sentinel to `none`, but a SUBSEQUENT bare `gsd_run query dispatch-isolation --json` (or any other non-forced call) silently RESETS it back to `harness-worktree` — this is the exact failure that happened once this session before being caught. — **Structural mitigation:** run `gsd_run query dispatch-isolation --raw --force-isolation none` as the LAST tool call immediately before every single `Agent(subagent_type="gsd-executor", ...)` dispatch, with zero other `gsd_run` calls (especially no bare `dispatch-isolation` query) in between. Do this before EVERY dispatch, not just the first.

**Do not proceed until this box is checked.**
