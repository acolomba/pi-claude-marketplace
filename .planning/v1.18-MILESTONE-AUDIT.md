## Integration — 5/5 seams wired (0 blockers, 0 warnings)

Checked by reading source in the worktree and re-running the gates, not by reading
planning documents. The four warnings the previous audit raised are gone — each is now
either a value consumers take or a gate that fails on drift.

1. **Manifest-absence authority.** `domain/manifest-lookup.ts` exports the
   `ManifestLookup` discriminant and `lookupDeclaredPlugin`; `list.ts:878`,
   `info.ts:860`, and `update.ts:1033` all call it and narrow on `kind === "absent"`.
   The return type cannot express what a failed read means, so a `kind: "unverified"`
   read can never set the absence flag (BOUND-03). `tests/architecture/manifest-lookup-drift.test.ts`
   walks the whole extension tree with three non-global patterns, proves each catches a
   planted twin without over-reaching, and carries a staleness clause so an exemption
   cannot outlive its site. **The previous audit's top warning — three independent
   implementations of one rule — is closed.**
2. **`isRecordedButDisabled`.** One definition (`persistence/state-io.ts:160`), consumed
   as a value by list, info, enable-disable, reconcile (plan + apply), plugin-path,
   plugin-state-classifier, and update (three call sites). No local re-derivation
   survives anywhere in production code. The ENBL-05 drift gate now carries four
   patterns — operator-adjacent plus the destructured, bracket-access, and
   `Boolean()`-coercion twins the previous audit found escaping — each self-tested
   against a planted twin and negative controls, and none is `/g` (a global regex would
   silently skip files via `lastIndex` carry-over across the walk). **Closed.**
3. **`LedgerDegradationSignals` field collision.** The boolean signals keep the
   `stagedAgents`/`stagedMcpServers` spellings; the string arrays are renamed to
   `stagedAgentNames`/`stagedMcpServerNames` on both `ReinstallReinstalledOutcome` and
   `PluginUpdateUpdatedOutcome` (`orchestrators/types.ts:36-37,181-182`). The two now
   occupy distinct namespaces, so the type confusion the previous audit predicted cannot
   be written. Worth recording precisely: `enableRowDependencies` is called only from
   `enable-disable.ts:1022` and `reconcile/notify.ts:559`, never with a reinstall
   outcome — so the specific `enableRowDependencies(reinstallOutcome)` scenario was
   always hypothetical. The rename removes the trap regardless. **Closed.**
4. **Update-verb degradation signals (WR-12).** `PluginUpdateUpdatedOutcome` inherits
   `LedgerDegradationSignals` directly, and `orchestrators/plugin/update-row.ts::updatedRowFromOutcome`
   is the sole composer of the `(updated)` row — called by `plugin/update.ts:2349`
   (standalone) and `marketplace/update.ts:751` (autoupdate cascade), with no bypass on
   either path. A degraded update cannot render a clean row on a surface the cascade
   reaches with no user flag. **Closed — this was a user-visible defect, found by Phase
   99's own review loop rather than by the earlier audit.**
5. **COMPAT-01 closed-set pins.** `tests/architecture/compat-01-no-expansion.test.ts`
   imports the live constants and asserts exact membership and order across REASONS,
   STATUS_TOKENS, PLUGIN_STATUSES, MARKETPLACE_STATUSES, the glyph roster (7 code points
   plus an 8th-glyph tripwire), the install-record key set, and the schema-version union.
   Mutation-tested both directions. **WIRED.**
