# Architecture — import, containment and source-scan gates

**Scope:** `tests/architecture/{import-boundaries,no-credential-leak,no-orchestrator-network,no-shell-out,no-split-01-cast-reads,no-telemetry-deps,no-lifecycle-default-enabled-read,source-scan,unit-suite-glob-completeness,peer-floor,extension-version-sync,integration-materialization-gate,reconcile-planner-purity}.test.ts` plus the `source-scan.ts` test-support module, and the production modules directly imported by those tests (`bridges/mcp/parse.ts`, `bridges/mcp/stage.ts`, `persistence/locations.ts`, `shared/extension-version.ts`).
**Test files reviewed:** 14 (13 `.test.ts` + 1 test-support module, `source-scan.ts`)
**Production modules reviewed:** 4

## Summary

Most of this file set is exactly what the project's own doctrine asks for: real regex scans over real source files (`assertNoForbiddenSurface`-based gates, the SPLIT-01 cast/assignment scans, the D-11 ledger-import scans, the DIFF-01 purity scan) that would genuinely fail the moment someone plants the violation they guard against, plus `source-scan.test.ts` and the SPLIT-01 "walker" cases, which are model instances of gate-the-gate testing — they prove the regex itself against synthetic offender and benign strings rather than trusting it by inspection. `unit-suite-glob-completeness.test.ts` and `integration-materialization-gate.test.ts` are the strongest files in the set: independently-derived comparisons and real behavioral assertions with correct `assert.strictEqual`/`assert.deepStrictEqual` usage and proper AAA structure.

Against that, one real security-relevant defect: four of the seven `no-credential-leak.test.ts` scans still use a bounded-prefix regex (`[^)]*...`) that the file's own docstrings prove is bypassable by a literal `)` in the message text before the credential interpolation — and two sibling scans in the *same file* were already patched for exactly this bug. This is the fixing pass's first priority. Second priority: a handful of narrower gaps (a static config-string check standing in for an actual planted-cycle test in `import-boundaries.test.ts`; a missed real-world package name in the telemetry denylist; a duplicated `stripComments` in `reconcile-planner-purity.test.ts` that should delegate to the shared helper). Third, lower-value: nearly every file in this set uses non-strict `assert.equal`/`assert.deepEqual` where the project rule calls for the strict variants, and most lack the AAA phase comments that the two strongest files in the set do carry — both are cheap, mechanical, low-risk fixes given the data types involved (strings, string arrays, booleans).

## Unit test findings

### `tests/architecture/no-credential-leak.test.ts`

- **[BLOCKER] Four of seven AUTH-09 scans use the bounded-prefix regex this same file already proved bypassable** — `test('AUTH-09: platform/git-credential.ts never interpolates a password in an Error message')` (regex at line 131), `test('AUTH-09: domain/github-auth.ts never interpolates a token in an Error or notifyFn message')` (regex at line 163-164), `test('PROV-05: every provider file is scanned for token interpolation ...')` (regex at lines 288-289), `test('AUTH-09: orchestrators/marketplace/{add,update}.ts never interpolate a credential field ...')` (regex at lines 327-328).

  All four use the form `new\s+Error\s*\((?:[^)]*\$\{[^}]*(...)|...)`. The `[^)]*` run cannot cross a literal `)` character. This file's own docstring for the `hookDebugLog` gate (lines 246-256) documents the exact proven bypass: `onAuthFailure: reject() threw for ${opts.host}` defeats a `[^)]*`-bounded scan because the `)` in `reject()` appears before the interpolation, so the scan never reaches it. The fix for that gate (lines 261-280) and for the `reason:` gate (lines 201-238) is to capture the *complete* template literal with `fullTemplateLiteralsAfter` (defined at lines 81-91) and scan the whole captured string, not a bounded prefix.

  That fix was never propagated to the other four `new Error(...)`/`notifyFn(...)`/`ctx.ui.notify(...)` scans in this file. Concretely, a leak such as `new Error(\`credential fill() failed: ${cred.password}\`)` in `platform/git-credential.ts`, or `notifyFn(\`request() rejected: ${r.accessToken}\`)` in `domain/github-auth.ts`, would pass all four of these tests silently, because the literal `()` before the interpolation breaks the bounded scan at exactly the point the file's own comments describe.

  **Fix:** for each of the four call sites, add a second check that mirrors lines 269-280 exactly: build a marker regex capturing the complete template literal after `new\s+Error\s*\(`, `notifyFn\s*\(`, or `ctx\.ui\.notify\s*\(` (e.g. `` /new\s+Error\s*\(\s*(`(?:[^`\\]|\\.)*`)/g ``), pass it to `fullTemplateLiteralsAfter`, and assert none of the returned literals match the forbidden-field regex. This is the identical shape already written twice in this file (lines 229-237, 269-280) — copy the pattern rather than re-deriving it.

  **Planting negative control:** add `new Error(\`op() failed: ${cred.password}\`)` to `platform/git-credential.ts` (or the analogous `notifyFn(...)`/`ctx.ui.notify(...)` form to the other three targets) and confirm the affected test currently stays green — it will, which is the bug.

### `tests/architecture/import-boundaries.test.ts`

- **[WARNING] "npm run fallow runs dead-code unfiltered" is a static config-string check, not a planted-cycle test** — `test('D-11: npm run fallow runs dead-code unfiltered, so cycles are gated')`, lines 132-187. This test greps the `fallow` npm script string and enforces a token allow-list; it never actually runs `fallow dead-code` against a real or synthetic import cycle. Its own docstring (lines 115-131) explicitly acknowledges the reason (`fallow` is a separate CLI, not invokable cheaply from `node --test`), and this is a defensible stand-in given that constraint. Still, per the project's own stated principle that a gate wants a test proving it "actually fires on a real (or planted) violation," this test cannot detect a regression where `fallow dead-code` itself stops reporting cycles for a reason other than an added CLI flag (e.g., a `.fallowrc.json` change, a fallow version bump that changes default behavior). If there is no `tests/integration/**` coverage that spawns `fallow dead-code` against a two-file cycle fixture and asserts a non-zero exit, add one; if it already exists, cross-reference it from this test's docstring so the limitation reads as "covered elsewhere" rather than "accepted gap."
- **[WARNING] The zone-shape checks plus the canary do not verify the real project's `files` glob** — `test('import-x/no-restricted-paths defines exactly 8 zones ...')` (line 270) and `test("each zone's target+from set matches the D-11 allowed-imports matrix")` (line 283) inspect only the `zones` array's `target`/`from` shape from the real `eslint.config.js`. The canary test (line 303) proves the underlying ESLint rule mechanism fires correctly, but does so with a synthetic `overrideConfig` scoped to `tests/fixtures/bad-imports/**`, not the project's real config block (`eslint.config.js:179`, `files: ["extensions/pi-claude-marketplace/**/*.ts"]`). No test in this file confirms that the real block's `files` glob and `basePath` actually scope the rule onto real extension source files. Risk is low today (the glob is simple), but a future edit that narrows or breaks that `files` glob would pass all three tests here. Add an assertion that a known real path (e.g. `extensions/pi-claude-marketplace/edge/router.ts`) matches the compiled `files` pattern on the block that carries the `import-x/no-restricted-paths` rule.

### `tests/architecture/no-telemetry-deps.test.ts`

- **[WARNING] `FORBIDDEN_DEP_PATTERNS` misses the real npm package name for Datadog's Node tracer** — `test('no telemetry / analytics dependencies in package.json (IL-4)')`, lines 18-28, 37-62. The list includes `"datadog"`, but Datadog's actual Node.js APM package is `dd-trace`, which contains no `"datadog"` substring and would not be caught. Segment's legacy unscoped package `analytics-node` is similarly missed by the `"segment"` pattern (only the newer scoped `@segment/analytics-node` would match). **Fix:** add `"dd-trace"` to `FORBIDDEN_DEP_PATTERNS`, and consider adding `"analytics-node"` for Segment's older package name.

### `tests/architecture/reconcile-planner-purity.test.ts`

- **[WARNING] Hand-rolled `stripComments` duplicates the shared helper** — lines 47-51 define a private `stripComments` that is logically identical to the exported one in `tests/architecture/source-scan.ts` (lines 42-46). `source-scan.ts`'s own header explains this mechanic was extracted specifically "so the two share ONE implementation instead of duplicating it." This file is a third, un-shared copy of the same logic, and it also hand-rolls the read/strip/match loop instead of calling `assertNoForbiddenSurface`. **Fix:** import `stripComments` (and, if the single-target/no-`allowMissing` shape fits, `assertNoForbiddenSurface`) from `./source-scan.ts` and delete the local copy.

### Cross-cutting (most files in this set)

- **[WARNING] Non-strict `assert.equal`/`assert.deepEqual` used where the project rule calls for `assert.strictEqual`/`assert.deepStrictEqual`.** Representative sites: `import-boundaries.test.ts:244,263,276,295`; `no-credential-leak.test.ts:103,132,165,194,223,233,263,276,305,344`; `source-scan.ts:99`; `no-shell-out.test.ts:112,126`; `no-split-01-cast-reads.test.ts:100,107,121`; `no-telemetry-deps.test.ts:57`; `reconcile-planner-purity.test.ts:63`; `peer-floor.test.ts:24-25,39-43`; `extension-version-sync.test.ts:20,27`; `source-scan.test.ts:67`. Given the compared values are string arrays, strings, and booleans, this is unlikely to let a realistic wrong implementation pass today, but it is a straightforward, safe, mechanical fix: replace `assert.equal` → `assert.strictEqual` and `assert.deepEqual` → `assert.deepStrictEqual` throughout this file set. `unit-suite-glob-completeness.test.ts` and `integration-materialization-gate.test.ts` already use the strict forms correctly and can serve as the reference.
- **[WARNING] Most files lack `// arrange` / `// act` / `// assert` phase comments.** Every file in this set except `unit-suite-glob-completeness.test.ts` and `integration-materialization-gate.test.ts` omits AAA markers, even where the test has a distinguishable setup step (e.g. `import-boundaries.test.ts`'s package.json-script-parsing tests). For the common single-expression-body shape (`await assertNoForbiddenSurface(...)` as the entire test body), add `// act & assert`; for tests with a real setup step, add the full three-comment form. Use `unit-suite-glob-completeness.test.ts` (lines 96-107) as the in-tree model.

### `tests/architecture/unit-suite-glob-completeness.test.ts` — explicit assessment requested by the assignment

This test genuinely proves reachability, not just configuration presence. It parses the **actual** `test` and `test:coverage:unit` script strings out of the real `package.json` at run time (not a hardcoded copy), extracts every double-quoted `tests/`-prefixed substring, expands each with `globSync`, and compares the result against an independently-computed list of every `*.test.ts` file under `tests/` (via a real recursive `readdirSync`, filtering out only the separately-scripted `e2e`/`integration` roots). Both sides are derived independently — neither reads the other — so their disagreement is real evidence of a gap. Checked against the live `package.json` in this repo: both scripts quote exactly `"tests/{architecture,bridges,domain,edge,orchestrators,persistence,platform,shared,transaction}/**/*.test.ts"` and `"tests/index.test.ts"`, with no other quoted arguments, so the `foreign`-argument guard (lines 65-70) does not trip, and today's two brace-glob sets are identical between `test` and `test:coverage:unit`. A hypothetical test file placed outside all nine listed roots (e.g. `tests/helpers/foo.test.ts`) would appear in `unitTestFilesOnDisk()` but not in `pathsMatchedByScript("test")`, and the `assert.deepStrictEqual` at line 103 would correctly fail — this was verified by static trace of the matching logic, not by running the suite. One caveat: it proves glob *reachability* only, not that every matched file actually registers a runnable `test()` case; that is out of scope for what "reachability" means here and is not a defect.

## Production code findings

### `extensions/pi-claude-marketplace/bridges/mcp/stage.ts`

- **[WARNING] Module-level `WeakMap` used as a private companion store for `McpReplacement` objects** — lines 44-51 (`mcpReplacementInternals`) and its use in `replacePreparedMcp`/`rollbackMcpReplacement`/`finalizeMcpReplacement` (lines 327-388). This is module-level mutable state holding data (`oldText`) that isn't part of the public `McpReplacement` type. It does not currently create cross-test pollution risk — each `replacement` object is a fresh literal, so keys can never collide across cases — but it is still a hidden collaborator: any caller of `rollbackMcpReplacement`/`finalizeMcpReplacement` depends on a global registry that isn't visible in either function's signature. Given the project bans `#private` class fields and favors plain interfaces over classes, a factory-owned-state alternative is limited here; if this file gets touched again, consider carrying `oldText` as a genuinely private field on a small closure-returned handle instead of a shared module-scope `WeakMap`, so each `replacePreparedMcp` call owns its own state rather than registering into a singleton.
