# Shared — notify (the single UI output surface)

**Scope:** `tests/shared/notify.test.ts` paired with `extensions/pi-claude-marketplace/shared/notify.ts`
**Test files reviewed:** 1 (6659 lines, ~194 `test()` call sites, some inside data-driven `for` loops)
**Production modules reviewed:** 1 (4217 lines)

## Summary

The suite is disciplined where it matters most: every case builds fresh state inline (no `before`/`beforeEach`, no shared mutable fixtures), phase comments are present and ordered on all ~209 cases, naming is clean (no `result`/`sut`/`data`), data-driven cases use one `test()` per row via `for` loops, and the large majority of assertions compare the *whole* rendered string against a hand-typed literal via `assert.equal`/`assert.deepStrictEqual` — including good positive tests that the severity/token/reasons axes are genuinely orthogonal (e.g. the same `(skipped)` token routing to both `info` and `warning` by stamped severity alone). The production module is a legitimately dumb renderer for the severity/reload-hint/reasons contract: `computeSeverity`, `shouldEmitReloadHint`, and `countRowsBySeverity` all reduce caller-stamped fields, never re-derive from `status`.

Three themes for a fixing pass, in priority order: (1) about 20 cases use `.includes()`/`startsWith()`/`endsWith()` as their *only* content check where the full expected string is fully known from the arranged input — the highest-yield fix, since a wrong implementation that renders the wrong body but happens to contain/start/end with the checked substring would still pass; one case asserts no body content at all. (2) every single call into `notify()`/`notifyDiagnostic()`/`notifyAsyncRewakeSummary()`/`notifyStopHookOverrideCap()`/`makeRawNotifyFn()` (178 call sites) casts its hand-rolled `ctx`/`pi` double through `as never` because `notify()`'s parameters are typed against the full third-party `ExtensionContext`/`ExtensionAPI` host interfaces, defeating type-checking at every call site; narrowing the parameters to a small consumer-declared port (notify.ts only ever reads `ctx.ui.notify` and `pi.getAllTools()`) would let the existing test doubles typecheck for real and remove the casts entirely. (3) the production module is the largest file in the extension (4217 lines) and visibly mixes five concerns — closed-set types/constants, grammar-rendering primitives, severity/tally computation, info-surface rendering, and dispatch orchestration — that could be split along those seams without touching the single documented import path.

## Production code findings

### `extensions/pi-claude-marketplace/shared/notify.ts`

- **[BLOCKER] `notify()`, `notifyUsageError()`, `notifyDiagnostic()`, `notifyAsyncRewakeSummary()`, `notifyStopHookOverrideCap()`, and `makeRawNotifyFn()` all type their context parameter against the full `ExtensionContext`, and `notify()`/`emitContextCascade()`/`emitCascadeWith()`/`emitUpdateNoOpCascade()`/`emitReconcileAppliedContextCascade()` type `pi` against the full `ExtensionAPI`, even though this file reads exactly one member of each** — `ctx.ui.notify(...)` (the only `ctx` access anywhere in the file) and `pi` is only ever forwarded to `softDepStatus(pi)` (`platform/pi-api.ts`), which itself only calls `pi.getAllTools()`. Both host interfaces come from the third-party `@earendil-works/pi-coding-agent` package and carry many more required members, so no lightweight object literal can satisfy them structurally — which is exactly why every test call site in `notify.test.ts` resorts to `as never` (178 occurrences; see the paired **Unit test findings** entry above). Fix: declare two narrow, consumer-declared port types in this file (or import minimal ones), e.g.
  ```ts
  export interface NotifyCtx {
    readonly ui: { readonly notify: (message: string, severity?: Severity) => void };
  }
  export interface SoftDepProbePi {
    readonly getAllTools: () => ReadonlyArray<{ readonly name?: string }>;
  }
  ```
  then change every exported function's `ctx: ExtensionContext` to `ctx: NotifyCtx` and `pi: ExtensionAPI` to `pi: SoftDepProbePi` (and narrow `softDepStatus`'s own parameter in `platform/pi-api.ts` the same way, since `hasLoadedPiSubagents`/`hasLoadedPiMcpAdapter` only call `.getAllTools()` too). A real `ExtensionContext`/`ExtensionAPI` value trivially satisfies the narrower interfaces (structural typing allows passing an object with extra members), so no production call site changes; only the test doubles gain real type-checking and the `as never` casts can be deleted.

- **[WARNING] `notify()`'s single `softDepStatus(pi)` probe is a render-time read of live extension-host state, not a caller-stamped field** — `line 3822` (inside `notify()`), and the same call repeated at `line 3915` (`emitCascadeWith`) and `line 3979` (`emitUpdateNoOpCascade`). This is long-documented (SNM-16, the file's own header comment at `lines 25-33`) as a deliberate single, bounded probe used only to decide whether to append a `{requires pi-subagents}`/`{requires pi-mcp}` marker into an already-caller-supplied `reasons` brace — it does not influence `status`, `severity`, or `needsReload`, so it does not violate the tri-state severity contract. Still, per the "notify is a dumb renderer" rule it is the one place this module reads something other than the message it was handed. If the project wants to close this gap (matching the "move render-time probes into orchestrators" direction noted for v1.16+), the natural owners are the callers that already build the `dependencies: readonly Dependency[]` field on `PluginInstalledMessage`/`PluginUpdatedMessage`/`PluginReinstalledMessage`/`PluginPartiallyInstalledMessage` rows — `orchestrators/plugin/install.ts`, `update.ts`, `enable-disable.ts`, and the `list`/reconcile row producers — which could call `softDepStatus(pi)` once themselves and fold the marker directly into `reasons[]` at construction time, the same way they already stamp `severity`/`needsReload`. This would let `notify()` drop the `pi` parameter (and the `SoftDepProbePi` port above) entirely. Not urgent — no incorrect behavior results today — but worth naming since the check explicitly asks for it.

- **[WARNING] `computeSeverity`'s `plugin-info` arm derives severity from the row's `status` token rather than a caller-stamped severity field** — `line 2886`: `case "plugin-info": return message.plugin.status === "failed" ? "error" : undefined;`, mirrored in `buildSummaryLine` at `line 3077`. This is the one place severity is inferred from content instead of reduced from a stamped field, and it is explicitly called out and locked in the file's own comments (`lines 2862-2873`, "Q1 LOCKED... a kind lookup, NOT reason inference") because the read-only info-surface variants carry no per-row `severity` array to reduce. It is a narrow, closed, two-state lookup (not general reason/content inference), so it does not appear to create an incorrect result today, but it is worth flagging explicitly since the review's severity/token/reasons-orthogonality check calls this pattern out by name.

- **[WARNING] The module is the largest file in the extension (4217 lines) and visibly mixes five separable concerns that could be split along clean seams without changing the documented single import path** — concretely:
  - **Types/constants** (`REASONS`, `STATUS_TOKENS`, `PLUGIN_STATUSES`, `MARKETPLACE_STATUSES`, `Severity`, `MessageBase`, every per-variant `Plugin*Message`/`Mp*` interface, the `NotificationMessage`/`PluginNotificationMessage`/`MarketplaceNotificationMessage` unions) — roughly `lines 65-1719`. This is the closed-set "source of truth" the header comment (`lines 39-47`) already calls out as living in one place; it could become its own module (e.g. `shared/notify-types.ts`) without weakening that invariant, since a single file can still be the one place these tuples are *declared* while `notify.ts` re-exports them.
  - **Grammar-rendering primitives** — icons, `joinTokens`, `renderScopeBracket`, `renderVersion`, `composeVersionArrow`, `composeReasons`, `pluginRow`/`partiallyInstalledRow`/`installedLikeRow`, the `render*Row` helpers, `renderMpHeader`, `renderPluginRow`, `composePluginLines(With)` — the bulk of `lines 1721-2694` plus `lines 3338-3349` and `4098-4146`.
  - **Severity/summary/tally computation** — `computeSeverity`, `cascadeSeverity`, `buildSummaryLine(ForCascade)`, `countFailedOperations`/`countSkippedOperations`/`countRowsBySeverity`, `summaryPhrase`, `composeTally`, `foldTallyAndHint`, `shouldEmitReloadHint` — `lines 2817-3288`.
  - **Info-surface rendering** — `renderMarketplaceInfo(Cascade)`, `renderPluginInfo(Cascade)`, `renderMarketplaceNotAdded`, `appendResolvedComponentLines`, `wrapDescription`, `pluginInfoStatusGlyph`, `composeMpInfoHeader` — `lines 3352-3686`.
  - **Dispatch/entry points** — `notify`, `dispatchInfoMessage`, `emitWithSummary`, `emitContextCascade`, `emitCascadeWith`, `emitUpdateNoOpCascade`, `emitReconcileAppliedContextCascade`, plus the standalone helpers `notifyUsageError`/`notifyDiagnostic`/`notifyAsyncRewakeSummary`/`notifyStopHookOverrideCap`/`makeRawNotifyFn` — would remain in `notify.ts` as the public surface, importing from the four modules above.
  - `redactAbsolutePaths` (`lines 268-299`) and `compareByNameThenScope`/`Sortable` (`lines 4180-4197`) are both general-purpose leaf utilities consumed well outside this file's own rendering path (`redactAbsolutePaths` is called from five different orchestrator modules) and would fit more naturally as their own small `shared/` modules than inside the presentation file.

  This is a maintainability recommendation, not a correctness bug: fallow's `health` thresholds are per-function (`maxUnitSize: 60` etc.), not file-level, so the current file is not failing the automated gate purely on size. The split is worth doing because five genuinely different responsibilities are interleaved in one file (e.g. `composePluginLinesWith` at `line 4107`, a grammar-composition function, sits physically inside the block otherwise dedicated to dispatch/entry points), which is what makes the file feel large rather than merely long. A layered split (types → grammar → severity → info → dispatch, each importing only from earlier layers) avoids introducing a cycle.
