# Architecture — notify and vocabulary gates

**Scope:** `tests/architecture/{notify-grammar-invariant,notify-producer-wire-coverage,notify-stamp-coverage,notify-will-reload-agreement,notify-closed-set-locks,cross-surface-reason-parity,partial-vocabulary-guard,markers-snapshot}.test.ts`, and the production modules they exercise: `shared/notify.ts`, `shared/notify-context.ts`, `shared/notify-reasons.ts`, `shared/markers.ts`, `shared/probe-classifiers.ts`, `bridges/agents/marker.ts`, `persistence/locations.ts`, `orchestrators/reconcile/notify.ts`, and `orchestrators/plugin/{install,enable-disable,uninstall,update,reinstall}.messaging.ts`.
**Test files reviewed:** 8
**Production modules reviewed:** 13

## Summary

This area splits cleanly into a good half and a bad half. `notify-producer-wire-coverage.test.ts`, `cross-surface-reason-parity.test.ts`, `partial-vocabulary-guard.test.ts`, and `markers-snapshot.test.ts` are well-built: correct one-`test()`-per-row data-driven structure, `strong-mock` used idiomatically where an interaction is the promise, and real source-tree scanning used exactly the way this project's own conventions prescribe for a "planting" architectural gate. `notify-grammar-invariant.test.ts` and `notify-will-reload-agreement.test.ts` are the opposite: both hand-roll a `MockCtx`/`MockPi` pair and force it past the compiler with `ctx as never` / `fixture.pi as never` at every call site, which is exactly the "double assertion hiding an invalid double" pattern the review brief calls out, and both import the process-wide `mock` from `node:test` instead of `t.mock`. The two files also duplicate the same fixture-harness code near-verbatim. A third, smaller theme: several tests loop many fixtures inside one `test()` body (stopping at first failure) where a `for`-loop-of-sibling-`test()`s was the better fit, and `notify-stamp-coverage.test.ts` uses loose `assert.deepEqual` where `assert.deepStrictEqual` is the house rule. On the production side, the reviewed modules (`notify.ts`, `notify-context.ts`, `notify-reasons.ts`, `markers.ts`, `probe-classifiers.ts`, `marker.ts`, `locations.ts`, and the five `*.messaging.ts` command modules) are consistently well-documented, typed, and free of hidden dependencies or `any`/`!` abuse; the only structural note is `notify.ts`'s size. A fixing pass should prioritize: (1) replace the two `MockCtx`/`MockPi`+`as never` files' doubles with the `strong-mock` harness pattern `notify-producer-wire-coverage.test.ts` already demonstrates, (2) fix the `assert.deepEqual` calls, and (3) split the fixture-array-in-one-`test()` cases into sibling `test()`s per fixture.

## Unit test findings

### `tests/architecture/notify-grammar-invariant.test.ts`

- **[BLOCKER] Hand-rolled `MockCtx`/`MockPi` forced past the compiler with `as never`** — `lines 39-61` (interfaces/factories), used at `lines 398, 438, 553, 581, 615, 686, 719`. Every call site reads `notify(ctx as never, fixture.pi as never, fixture.message)`. `MockCtx`/`MockPi` only implement `{ ui: { notify } }` / `{ getAllTools }`, a small fraction of the real `ExtensionContext`/`ExtensionAPI` surface, and `as never` disables all structural checking for both arguments — a parameter-order swap, a renamed field, or a genuinely incompatible double would still compile and could fail confusingly at runtime instead of at the call site. `notify()`'s interaction with `ctx.ui.notify` is exactly the kind of "public behavior" the project's own sibling file already mocks correctly: mirror `tests/architecture/notify-producer-wire-coverage.test.ts`'s `createWireHarness` — build `mock<ExtensionContext>({ exactParams: true, name: ... })` and `mock<ExtensionAPI>({ exactParams: true, name: ... })`, stub `ctx.ui` and `pi.getAllTools()` with `when()`, capture `ui.notify` calls into a plain array the same way, and `verify()` every mock at the end of the case. Delete `MockCtx`/`MockPi`/`makeCtx`/`piWithBothLoaded` and the `as never` casts entirely.
- **[WARNING] Process-wide `mock` imported from `node:test`** — `line 28`: `import test, { mock } from "node:test";`, used via `mock.fn()` in `makeCtx()` (`line 44`). The rule is `t.mock`, not the process-wide export. None of the 7 `test()` cases take a `t` parameter, so the mechanical fix is: give each case `(t) => { ... }` and call `t.mock.fn()`. (This finding is superseded if the BLOCKER above is fixed by switching to `strong-mock`, since `mock.fn()` would no longer be needed at all.)
- **[WARNING] Fixture arrays looped inside a single `test()` instead of one sibling `test()` per row** — `test()` bodies starting at `lines 395, 435, 550, 571, 612, 683, 716` each run `for (const fixture of ...)` inside one case. A failure on fixture 1 of N hides whether fixtures 2..N would also fail, and the loop body contains no branching so splitting is mechanical: hoist the `for` loop to top level and call `test(\`${fixture.label}\`, () => { ...single-fixture body... })` per fixture, exactly like the pattern already used correctly in `cross-surface-reason-parity.test.ts` and `partial-vocabulary-guard.test.ts`.
- **[WARNING] File header describes a retired summary grammar** — `lines 12-14` document the summary line as `` `N (plugin|marketplace) operation(s) [and M (plugin|marketplace) operation(s)] (failed|skipped).` ``, but the actual `SUMMARY_GRAMMAR` regex the tests assert against (`lines 70-71`) and the production `summaryPhrase()` function (`shared/notify.ts:2994-3012`) both produce `` `[A|Some] [<subject> ]operation[s] has/have failed | needs/need attention.` `` — a different grammar. The header is stale narration of a shape the code no longer has (per this repo's own comment policy). Update the file header comment to state the grammar actually tested, matching the accurate description already given at `lines 64-68`.

### `tests/architecture/notify-stamp-coverage.test.ts`

- **[WARNING] `assert.deepEqual` used where the house rule is `assert.deepStrictEqual`** — `lines 162, 192, 209`. Loose `deepEqual` performs coercive comparison (e.g. would not distinguish `1` from `"1"`, or an extra prototype); switch all three to `assert.deepStrictEqual` to match the whole-value-comparison rule and the strict style used everywhere else in this test area.

### `tests/architecture/notify-closed-set-locks.test.ts`

- **[WARNING] Per-test comments read as an incremental changelog rather than a statement about the current code** — `lines 30-48` (`REASONS` test), and similarly `lines 55-60`, `65-71` for the other three tests. Each comment chains a sequence of "+1 for X (32 -> 33)", "+1 for Y (33 -> 34)" deltas tied to now-superseded intermediate counts. This is a deliberate design (the file's own header explains it as a "deliberate-bump tripwire," and each delta cites a real decision ID, which this repo's comment policy allows), so this is not a hard violation, but the delta-chain form is close to the "narrates a shape the code no longer has" pattern the comment policy discourages elsewhere. Consider condensing to a single list of "current members and the decision ID that added each," dropping the intermediate before/after arithmetic, next time this file is touched.

## Production code findings

### `extensions/pi-claude-marketplace/shared/notify.ts`

- **[WARNING] File size stresses the module's reviewability** — 4217 lines. The centralization is intentional and documented (IL-2: the sole sanctioned `ctx.ui.notify` call site) and the file is well-sectioned with banner comments and thorough JSDoc, so this is not a defect, but it mixes several distinct levels of concern in one file: the closed-set vocabulary tuples (`REASONS`/`STATUS_TOKENS`/`PLUGIN_STATUSES`/`MARKETPLACE_STATUSES`, `lines 93-364` alone), low-level string composition helpers, mid-level row/marketplace composers, and the public dispatch API. This project has already established the precedent of pulling a topic-grouped view out into its own file without moving the byte-critical source of truth (`shared/notify-reasons.ts` does exactly this for `REASONS`). The same move for the vocabulary tuples (e.g. a `shared/notify-vocabulary.ts` re-exported from `notify.ts`) would reduce the single file's size without touching the "one sanctioned notify surface" invariant. Non-blocking; worth considering on a future pass through this file, not as a standalone change.
