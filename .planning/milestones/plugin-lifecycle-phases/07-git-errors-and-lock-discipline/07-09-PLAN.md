<objective>
Make `info --fetch` report a host 404 or 5xx as fetch, install, and update do
(GLK-01), and read its row inside the lock that guards the materialize
(GLK-05).

Purpose: `info --fetch` reads a 404 as `{unreadable}` (its probe ladder's
fallback), and builds the row after the lock is released, so a concurrent
cleanup can remove the tree it is reading.
Output: `info.ts` fetch-path changes, unit cases, and a cucumber scenario that
fails without the change.
</objective>
