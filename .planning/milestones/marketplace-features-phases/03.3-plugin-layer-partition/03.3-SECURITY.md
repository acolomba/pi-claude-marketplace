# Phase 3.3 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| user command -> plugin orchestrator | The typed `--local` flag alone picks which user-owned layer file a named command may change | Plugin keys, layer flag |
| layer files -> layer verdict and merged view | Hand-edited or pulled JSON keys decide which layer declares a plugin, the effective `enabled`, and whether a refusal fires | Per-scope layer config |
| state record -> layer file | The recorded marketplace source is copied into a layer file a user may commit | Marketplace source strings |
| state records and layer keys -> cause lines | Plugin keys from state or a user file are interpolated into refusal, skip, and load-error causes | Plugin keys, file basenames |
| user command -> network | A named update may build credentials, clone, or list tags of a git source; a refusal must not (NFR-5) | Credentials, clones, tag lists |
| update, reinstall, and load-time backfill -> layer files | These verbs used to author declarations; the backfill reinstalls records the user did not name | Plugin declarations |
| layer files -> load | One inconsistent layer stops its scope's reload (D-05) | Per-scope config |
| test step -> sandbox | The one writing config step writes a layer file inside the scenario sandbox | Layer files |
| docs and gate record -> users and verifier | The CHANGELOG, READMEs, guides, and catalog describe behavior; the SUMMARY is the gate evidence | Docs, rows |
