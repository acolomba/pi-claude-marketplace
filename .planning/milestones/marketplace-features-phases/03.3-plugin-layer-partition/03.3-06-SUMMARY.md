**A named update or reinstall now refuses a plugin only the other layer declares (before any network step for update), stops on an unreadable layer with `{invalid manifest}`, acts on a dependency, and the nameless forms with `--local` cover only the local layer's plugins.**

## Accomplishments

- `shared.ts`: `namedPluginLayerRefusal` builds on `selectDeclaringConfigWriteTarget` and `pluginLayerVerdict`. It returns the verdict's refusal for `other-only`, an `InvalidMarketplaceManifestError` (`Config file "<basename>" failed schema validation.`) for an unreadable layer, and `undefined` otherwise. `keepLocalLayerTargets` reads each distinct scope's `claude-plugins.local.json` once (`Object.keys`, so own keys only) and filters the targets by a scope-qualified key set. Both share the module-private `unreadableLayerError`. `writeBackRefusal` is deleted with its describe.
- `update-flow.ts`: `refuseOtherLayerUpdate` (renamed from the FIX-03 check) throws what `namedPluginLayerRefusal` returns, only for the `single` cardinality outside the cascade, before `preparePluginUpdate`. `narrowDirectFailReason` maps the two new classes; the `MarketplaceDeclaredLocallyError` arm is gone. `enumerateTargets` now wraps the old body (`enumerateScopeTargets`) and applies `keepLocalLayerTargets` for a nameless form with `--local`.
- `reinstall-flow.ts`: `refuseOtherLayerReinstall` (renamed) runs at the same hook with `namedPluginLayerRefusal`. The new module-private `selectTargets` does the selection and the `--local` filter inside the existing `try`, so `reinstallPluginsWith` lost a branch instead of gaining one.
- `reinstall-record.ts`: `isLayerRefusal` / `layerRefusalReason` map the two new classes and `InvalidMarketplaceManifestError` to their reasons and attach the error as `cause`; the local-only-marketplace arm is gone.
- `features/plugin/reinstall.feature` (new), and two scenarios each in `update.feature` and `reinstall.feature`.
