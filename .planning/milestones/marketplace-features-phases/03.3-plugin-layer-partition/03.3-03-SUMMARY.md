# Phase 3.3 Plan 03: Flag-only layer for install, enable, disable, and the same-layer marketplace Summary

**`install`, `enable`, and `disable` now write the layer their `--local` flag names, a named enable or disable of a plugin only the other layer declares fails with `{plugin declared locally}` / `{plugin declared in shared config}` and changes nothing, and every layer a command writes a plugin into also declares that plugin's marketplace.**

## Accomplishments

- `selectDeclaringConfigWriteTarget({ locations, local })` (no `key`): flag-only target through the private `selectConfigWriteTarget`; loads both layers; an invalid target returns `unreadable` naming it, then an invalid other layer returns `unreadable` naming that file; `sibling` is a readable `ScopeConfig` (absent reads as `{ schemaVersion: 1 }`). `resolveTargetIsLocal`, `localFileLeavesTargetUnknowable`, `readableConfig`, and `InvalidConfigLoad` are deleted (`grep -c 'resolveTargetIsLocal\|localFileLeavesTargetUnknowable'` = 0).
- `localOnlyMarketplaceRefusal` and `writeAdoptingConfigEntries` take a readable sibling; their unreadable-sibling arms and doc sentences are gone, and `synthesizeAdoptedMarketplaceSource` is folded away.
- `enable-disable.ts`: `refuseOtherLayerDeclaration(selection, write)` computes `pluginLayerVerdict` and throws `EnableRefusedError(verdict.reason, verdict.refusal.message)` on `other-only`, skipped for orchestrated calls; `grep -c 'pluginLayerVerdict('` = 1. Header, closure, and `configBasename` comments state the flag-only rule.
- `overwriteDisabledMemberEntries({ locations, keys })`: loops both layer files, overwrites an existing `enabled: false` with `enabled: true` through `writePluginConfigEntry`, skips an absent or invalid file. Both callers dropped the `state`/`select`/`write` arguments.
- `writeAdoptingConfigEntries`: the plugin's own marketplace is synthesized when the TARGET layer lacks it; `addedMarketplaces` keep the both-layer gate (A-05). Docs of `synthesizeUndeclaredMarketplaceSource`, `writeAdoptingConfigEntries`, the install write-back comment, and `writeEnabledFlagBack` state the LAYER-06 rule; the S4 note is unchanged.
- Two new feature files and two install scenarios, all ending on observable state (files and, for refusals and the remove, a new session's skills).
