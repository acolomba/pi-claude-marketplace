<objective>
Build the walking skeleton of the url source kind: a loopback HTTPS git stand-in that the run
starts before Pi, that Pi clones from with TLS verification on, and that records every request,
proven end to end by one scenario that adds a url marketplace and asserts the request log
(HOST-01, HOST-04, D-01, D-02, D-04). The stand-in lives on the run's one `PiRun`, is reset and
asserted empty before every scenario (HOST-02), and Pi, the stand-in, and the fixture git all run
with hermetic git environments (DRV-03, D-10, D-12). Plan 09-02 then pins the CGI parser and the
environment builders with unit cases (D-11, unit half) and amends the cucumber rules for the new
lifetime (HOST-02).

Purpose: the research flag asks the first plan to prove that Pi's `--offline` RPC child lets the
extension's HTTPS through and that the clone really reached the stand-in. Every later plan of the
phase builds on this skeleton: plan 09-02 pins its parts and writes its lifetime into the rules,
plan 09-03 fills the remaining url arms, plan 09-04 adds arming. The one task commits once at a
green checkpoint (the host runs in every worker) and once at the end, so a resumed executor
continues from the checkpoint instead of starting over.
Output: the stand-in modules, the typed Pi git environment, the url publish arm, the
`{git host}` token, the request window and log step, and `features/marketplace/url-source.feature`
with one scenario.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cucumber worker -> loopback git host | The worker serves git over HTTPS to the Pi child; a socket on a non-loopback interface would expose fixtures to the network |
| Pi child -> developer git config | `git credential fill` inherits Pi's environment; an inherited variable or a system config could reach the developer's helpers and keychain |
| fixture and CGI git -> this repository | A git process that inherits `GIT_DIR` or `GIT_INDEX_FILE` from a hook-run worker writes into this repository |
| request path -> git http-backend | The URL path becomes `PATH_INFO` under `GIT_PROJECT_ROOT` |
