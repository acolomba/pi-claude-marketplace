# Phase 3.2 Plan 02: Field-level marketplace merge Summary

**`mergeScopeConfigs` now merges a marketplace both layers declare as `{ ...shared, ...local }`, so a local declaration without `autoupdate` inherits the shared value. Plugin entries still replace whole. A real Pi shows the inherited `autoupdate true` through `marketplace list`.**

- **Tasks:** 2 of 2

## Accomplishments

- `persistence/config-merge.ts`: the local marketplace loop reads the shared entry from the `Map` already filled from the base file and sets `{ entry: { ...shared, ...entry }, source: "local" }`. The plugin loop is unchanged. The outer maps are still `Map` plus `Object.fromEntries` (2 occurrences). The module header and the function JSDoc now say that the field is the override unit for marketplace entries (D-MF-03), that plugin entries are replaced whole (DFEN-05), and that provenance is `local` whenever the local file has the key. The anti-deepmerge sentences are gone; the D-16 paragraph stays.
- `features/marketplace/autoupdate.feature` (new): `Feature: Marketplace autoupdate` with the scenario `A local declaration without autoupdate takes the setting from the shared declaration`.
- UAT-05 comments in `orchestrators/plugin/shared.ts` (the JSDoc of `synthesizeUndeclaredMarketplaceSource`, `synthesizeAdoptedMarketplaceSource`, `writeAdoptingConfigEntries`) and `orchestrators/plugin/install-flow.ts` (the block above the `writeAdoptingConfigEntries` call) now give the reason that still holds: the scope already declares the marketplace, and a second declaration in a file the user never named would keep it after a later `marketplace remove` from the other file (LAYER-02 / D-MF-03).
