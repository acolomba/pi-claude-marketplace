# Phase 3.2 Plan 06: Autoupdate layer partition Summary

**`marketplace autoupdate` and `noautoupdate` now act per config layer. A named flip writes `{ autoupdate }` only into the entry its target layer already declares, and fails with `{marketplace declared locally}` or `{marketplace declared in shared config}` when only the other layer declares it. An unnamed flip sets the flag in every layer that declares each marketplace, or in `claude-plugins.local.json` only with `--local`. Idempotency reads the target layer's own value, so `noautoupdate --local` over a shared `true` creates a per-machine override that `marketplace list` shows.**

## Accomplishments

- `orchestrators/marketplace/autoupdate.ts`:
  - `planFlip(names, layersOf, enable)` is the one planner. A name with no layer gets no row. A name is changed when any of its layers lacks the value, and each such layer gets the name in its batch. `writeFlipPlan` makes one `writeBatchedConfigEntries` call per layer file, patching `{ autoupdate }` only.
  - `layerAlreadySet`: an absent shared value reads as off (MAU-4). An absent local value is no value, so a flip always writes it.
  - Named (`planNamedFlip`): CFG-03 load of the target, the record lookup, then (standalone only) `requireTargetDeclares` runs the plan 04 gate. `refused` throws the module-private `FlipRefused`, `undeclared` throws `MarketplaceNotFoundError`, and `other-unreadable` throws `InvalidMarketplaceManifestError` naming the other file's basename.
  - Unnamed (`planEveryFlip`): both layers flagless (an invalid one aborts, CFG-03), or the local layer alone with `--local`. Each recorded marketplace, in state order, flips in the layers that declare it.
  - `flipScopes` collects not-found and refusals per scope. Any other error renders at once, as before. `setMarketplaceAutoupdate` then renders the rows, or for a named flip with no row the first refusal (`marketplaceFailureRows` through the flip context, cardinality `single`), or the not-added message.
  - Removed: `reclassifyByConfigTruth`, `buildAutoupdatePatch`, `writeAutoupdateBack`, the `writeBackSkipped` flag and its `(failed) {not found}` row, and the `shouldCollectNotFound` and `missingEverywhere` helpers. The file header's flow block states the new flow.
- `orchestrators/marketplace/shared.ts`: `classifyAutoupdateFlip` and `AutoupdateFlipResult` are removed, with their header entry.
- `features/marketplace/autoupdate.feature`: eight new scenarios (nine in all).
- `tests/integration/marketplace-layer-autoupdate.test.ts`: six cases across the add orchestrator, both config files, the state file, and `loadMarketplaceListEntries`.

## Decisions Made

- **Bare-scope not-added bracket.** A named flip with no `--scope`, no row, and no refusal means both scopes threw not-found, so the bracket is `opts.scope ?? "project"`, the first scope in SC-6 order. This is today's behavior, without tracking the not-found scopes.
- **Orchestrated mode.** Named and unnamed orchestrated flips classify and write nothing (WR-09). A named one skips the gate, so its target layer need not declare the marketplace.
- **Refusal shape.** `FlipRefused` carries the gate verdict out of the lock. The scope loop collects it, and `notifyFlipFailure` takes `{ reason, cause }`, so `autoupdateFailedReason` did not grow.
- **Interim Task 1 state.** Task 1 kept the old unnamed path (classifier, reclassification, synthesis) so the commit stayed green at 100% coverage. Task 2 removed it.
