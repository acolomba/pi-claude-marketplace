# Phase 3.2 — Security

> Per-phase security contract: threat register, accepted risks, and audit trail.

---

## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| user-typed source -> add orchestrator | The typed source decides whether an existing record is reused instead of cloned | Marketplace source strings |
| add, remove, flip, install -> scope config files | A write lands in the committed `claude-plugins.json` or the per-machine `claude-plugins.local.json` | Marketplace and plugin declarations, `autoupdate` |
| hand-edited config files -> merged view and layer gate | Two user-owned files, possibly corrupt or prototype-keyed, decide the effective settings and what a remove may delete | Per-scope config |
| plugin and marketplace manifests -> declaration index | Third-party manifest content decides which dependencies a remove keeps | Dependency declarations |
| remove orchestrator -> staged artifacts and clones | A remove deletes skills, prompts, agents, hooks, MCP entries, workflows, data directories, and git clones | Installed artifacts |
| project install -> marketplace source host and credential helper | NFR-5 as amended by D-MF-04: a project install clones a git marketplace only the user scope records | Network clone, credentials |
| notification vocabulary -> JSON consumers and docs | The closed reason set, schema, and catalog are the published output contract | Reasons, rows, wire ids |
| tests -> host environment | Integration tests drive real orchestrators that would otherwise reach the network and the real home | Sandbox state |
| docs and gate record -> users and verifier | The catalog, READMEs, CHANGELOG, and guide describe behavior; the SUMMARY is the gate evidence | Docs |
