# Phase 3.1 Plan 03: Enable/Disable Refusal and Hermetic Write-Back Summary

**A standalone enable or disable that would write its flag into `claude-plugins.json` under a marketplace only `claude-plugins.local.json` declares is now refused before anything is written. The update and reinstall write-back (also used by the load-time backfill) no longer copies a `--local` plugin, or any plugin of a local-only marketplace, into the shared file, and the update's S5 row names the file it could not read.**

## Accomplishments

- `enable-disable.ts`: module-private `refuseLocalOnlyMarketplace({ selection, marketplace, orchestrated })` next to `readEnabledDependents`. It returns for orchestrated calls and otherwise throws `EnableRefusedError("marketplace declared locally", refusal.message)`. The locked closure calls it as one statement right after the `not-recorded` return. The `EnableRefusedError` JSDoc and the standalone catch comment now name this refusal beside EDEP-01 and EDEP-02.
- `shared.ts`: module-private `LayerWriteBack` type and `selectLayerWriteBack` (plus its flagless half `flaglessLayerWriteBack`). It reads both files once and decides in the plan's order: target by flag (unreadable target -> `unreadable`), key in target -> `declared`, `--local` -> `add`, unreadable local file -> `unreadable` with the local path, key in local file -> `declared`, `localOnlyMarketplaceRefusal` -> `local-only-marketplace`, else `add` for the base file.
- `maybeWritePluginConfigBack` is rebuilt on the selector with the inline return type `{ readonly invalidConfig: false } | { readonly invalidConfig: true; readonly filePath: string }`. Only `add` writes.
- `update-swap.ts`: `finalizeUpdateRecord` returns `{ invalidConfigFile }`; `swapPluginUpdate` passes it to `notifyInvalidConfigWriteBack(args, filePath)`, which renders `path.basename(filePath)`.
- `reinstall-flow.ts` is unchanged (`git diff --quiet a8b1e1d0` exits 0); it reads only `invalidConfig`.
