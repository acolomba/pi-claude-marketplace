# Phase 3.1: Local Declaration Leak Fix Verification Report

**Phase Goal:** A marketplace added with `--local` never reaches the scope's `claude-plugins.json`, even when the next load runs the first-run config migration, so `remove --local` stays removed after a reload.
**Verified:** 2026-10-21
**Status:** passed
**Re-verification:** Yes. The earlier report (2026-10-16) was stale because Phases 3.2 to 3.4 (layer partition and terminology) and the github-source phase changed files it covers. Every truth was re-judged against HEAD.

## What changed since the earlier report

- The reason `marketplace declared locally` became `marketplace in local layer only` (error class `MarketplaceInLocalLayerOnlyError`, `shared/errors.ts`). The refusal predicate is still `localOnlyMarketplaceRefusal` (`orchestrators/plugin/shared.ts:694`), now keyed on `TargetLayers` (`targetIsLocal`, `current`, `other`).
- `locations.configLocalJsonPath` and `configJsonPath` became `localConfigJsonPath` and `baseConfigJsonPath`.
- Phase 3.3 (`5b2cc071`, `747da09e`, LAYER-04/06/08) made `update` and `reinstall` write no plugin declaration at all. The write-back family the old report cited (`selectLayerWriteBack`, `flaglessLayerWriteBack`, `maybeWritePluginConfigBack`, `writeBackRefusal`, `MarketplaceDeclaredLocallyError`) is deleted under a fallow dead-code check. Named `update` and `reinstall` are now refused by the plugin-layer verdict (`plugin in local layer only` or `plugin in base layer only`).
