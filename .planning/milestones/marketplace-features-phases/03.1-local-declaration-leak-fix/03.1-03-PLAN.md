<objective>
Extend FIX-03 to `enable` and `disable`, and make the post-success write-back of `update` and
`reinstall` hermetic per layer (D-08, D-MF-03): the write targets the shared file without `--local`
and the local file with it, never adds a `--local` plugin to `claude-plugins.json` on a flagless
command, and never writes a shared declaration under a marketplace only the local file declares.

Purpose: research probed a real Pi and found that a flagless `update` or `reinstall` of a plugin
installed with `--local` writes `"<plugin>@<marketplace>": {}` into `claude-plugins.json`, the same
leak class as FIX-02, and that the load-time backfill reinstalls through the same write-back. The
user ruled (D-08) that these verbs keep the flag as their target, not the declaring file, so this
plan keeps the flag-only target and adds the hermetic rule to the one write-back both verbs share.
The named-form refusal for `update` and `reinstall` (FIX-03's failed row) follows in the next plan,
on top of the selector this plan adds.
Output: the enable and disable refusal; `maybeWritePluginConfigBack` rebuilt on a module-private
flag-hermetic selector whose invalid arm names the unreadable file; the S5 row of `update` naming
that file; and the cases that prove the leak is closed for both verbs.
</objective>
