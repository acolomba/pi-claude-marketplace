<objective>
Refuse a standalone `install` that would write a plugin declaration into the scope's
`claude-plugins.json` while only `claude-plugins.local.json` declares the plugin's marketplace
(FIX-03, D-06, D-MF-02). First enroll the new reason `marketplace declared locally` in the closed
reason set (D-07), then add the one predicate every authoring verb will share and the install
refusal, then prove it on a real Pi.

Purpose: a shared declaration that names a marketplace only one machine declares cannot be
resolved by a teammate who reads the shared file. The predicate reads the selection each authoring
path already makes inside its lock, so the rule and its cause text have one definition; enable,
disable, update, and reinstall reuse it in the next plans. Upstream parity: Claude Code resolves a
plugin's marketplace across every settings tier and refuses nothing here; the user's decision
D-MF-02 licenses the divergence (AGENTS.md parity rule; research F3).
Output: the enrolled reason, `MarketplaceDeclaredLocallyError` and `localOnlyMarketplaceRefusal`
in `orchestrators/plugin/shared.ts`, the install refusal, its unit cases, one cucumber scenario,
and the `declares no plugins` step.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| standalone command -> committed `claude-plugins.json` | A plugin declaration the command writes may be shared with a team that cannot see the per-machine file |
| user-owned `claude-plugins.local.json` -> refusal decision | A hand-edited file decides whether the command is refused |
| refusal row -> notifications and json/rpc payloads | The cause line reaches user-visible and machine-readable output |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03.1-07 | Information disclosure | a shared plugin declaration naming a marketplace only the per-machine file declares | high | mitigate | `localOnlyMarketplaceRefusal` refuses the standalone install before the promotion and the cascade; the install cases and the scenario pin it |
| T-03.1-08 | Tampering | a partial write when the refusal fires (state, config, staged artifacts) | high | mitigate | The closure returns the refusal arm before any ledger, promotion, or `tx.save()`; the case pins state bytes and mtime, both config files, and the scope tree |
| T-03.1-09 | Information disclosure | an absolute path in the refusal cause line | medium | mitigate | The message is built from a safe marketplace name and fixed text; every case compares the whole message |
| T-03.1-10 | Denial of service | refusing an orchestrated install would fail a reload or an import | medium | mitigate | The check runs only when the install is not orchestrated; the orchestrated case pins it (D-06) |
