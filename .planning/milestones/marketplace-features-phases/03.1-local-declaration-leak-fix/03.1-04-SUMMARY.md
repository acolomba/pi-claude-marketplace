# Phase 3.1 Plan 04: Named Update and Reinstall Refusal Summary

**A named `update` or `reinstall` without `--local`, whose write-back would declare the plugin in `claude-plugins.json` under a marketplace that only `claude-plugins.local.json` declares, is now refused before anything is staged or replaced. Its failed row reads `{marketplace declared locally}` with the cause line that suggests `--local`. The reinstall S5 row names the file it could not read. FIX-03 is complete for install, enable, disable, update, and reinstall.**

## Accomplishments

- `shared.ts`: exported `writeBackRefusal({ locations, local, marketplace, plugin })`. It runs the module-private `selectLayerWriteBack` that plan 03 built and returns the `refusal` of the `local-only-marketplace` arm, else `undefined`. Plan 03's hermetic write-back is unchanged; this plan only reads its decision.
- `update-flow.ts`: module-private `refuseLocalOnlyMarketplaceUpdate(args)`, called as one statement in `runPluginUpdate` between the preflight verdict return and `swapPluginUpdate`. It returns for the cascade and for `plural` cardinality. `narrowDirectFailReason` maps `MarketplaceDeclaredLocallyError` to `"marketplace declared locally"`, so the existing catch renders one failed row with the D-07 cause and stops the batch.
- `types.ts`: `ReinstallFailedOutcome.cause?: Error`. `reinstall-record.ts`: `reinstallReasonsFromError` maps the refusal to `["marketplace declared locally"]`, and `failedOutcome` sets `cause` only for that error. `reinstall.messaging.ts`: the plain failed arm spreads `cause` when present; the manual-recovery arm is untouched.

The module-private `refuseLocalOnlyMarketplaceReinstall(locations, opts)` runs right after the already-disabled return and before `loadCachedEntry`. `LockedSuccess.invalidConfigWriteBack?: boolean` became `invalidConfigFile?: string`, and the S5 row renders `path.basename(locked.invalidConfigFile)`.

**1. [Test literal] Update refusal: "installed skill bytes" asserted as nothing staged**
- `seedPathMarketplace` writes a state record only; it materializes no skill under `skillsTargetDir`. The update case therefore asserts `skillsTargetDir` is still absent after the refusal, which shows that nothing was staged. **2. [Test literal] The refused outcome's notes hold the composed message**
- The plan wrote `notes: [<the message>]`. `failedOutcome` builds notes through `composeErrorWithCauseChain`, which measures as `"<message>\n\ncause: <message>"`. The record and reinstall-flow cases pin that measured composition.

**3. [Already covered] An ordinary Error composes with no `cause`**
- The existing case `composes ordinary, typed, errno, and manual-recovery failures` already compares the ordinary-error outcome whole with `deepStrictEqual`, so a stray `cause` key would fail it. It was left as is rather than extended.

**4. [Test shape] Data-driven non-refusal rows and small helpers**
- The four `writeBackRefusal` non-refusal rows are sibling tests from one loop over typed rows. Each row writes both files as raw bytes, so the body has no conditional.
- `seedLocalLayerUpdate` gained an `offeredVersion` parameter (default `1.0.1`) for the up-to-date case. `localOnlyMarketplaceBytes(cwd)` (update tests) and `LOCAL_ONLY_MARKETPLACE_CAUSE` (reinstall tests) keep the new cases free of new clone groups.
