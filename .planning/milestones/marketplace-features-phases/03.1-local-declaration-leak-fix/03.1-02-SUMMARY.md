# Phase 3.1 Plan 02: Install Refusal Under a Local-Only Marketplace Summary

**A flagless standalone install that would declare a plugin in `claude-plugins.json` while only `claude-plugins.local.json` declares its marketplace is now refused with `⊘ <plugin> (failed) {marketplace declared locally}` and a `--local` cause line, before anything is written. The rule lives in one exported predicate that the other authoring verbs will reuse.**

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - lint/complexity] The standalone gate takes the options object, not a boolean**
- **Found during:** Task 2.
- **Issue:** A helper `(orchestrated: boolean, selection, marketplace)` failed `sonarjs/no-selector-parameter`. Inlining the ternary pushed the locked closure to cognitive complexity 16 under both ESLint sonarjs and fallow health.
- **Fix:** the module-private `standaloneLocalOnlyRefusal(opts: Pick<InstallPluginOptions, "notifications" | "marketplace">, selection)` reads `opts.notifications?.mode === "orchestrated"` itself. The closure adds one `if`, and both gates pass.
- **Files modified:** `extensions/pi-claude-marketplace/orchestrators/plugin/install-flow.ts`. **Commit:** `34403e7e`.

**2. [Rule 1 - test strength] The prototype-named predicate row**
- The plan asked for the marketplace `constructor` with empty own maps on both sides. With an empty `current.marketplaces`, a non-own-key lookup on the current file finds `Object.prototype.constructor` and returns `undefined` anyway, so that row could not catch a broken sibling lookup. The row uses `current: { schemaVersion: 1 }` (no map) and `sibling.marketplaces: {}`. A plain-index sibling lookup would then refuse, and the own-key one does not.

**3. [Rule 3 - type] `declaredNames` reads the member through `Object.hasOwn` and `Reflect.get`**
- `member in config ? config[member] : {}` with a union-typed key failed with TS7053 (no `in` narrowing for a union key). The helper uses `Object.hasOwn(config, member) ? Reflect.get(config, member) : {}`, typed `unknown`. The failure message of `declares no marketplaces` now also prints the file content, because the two steps share the helper.

**4. Stronger assertions than the plan required (no behavior change)**
- The refused fresh install also asserts the whole returned outcome (`status`, `error` as `MarketplaceDeclaredLocallyError("mp")`, `cause`).
- The refused promotion compares the whole state document with the pre-promotion document, not only the dependency's `provenance`. It also asserts that the base file stays absent.
- The `--local` and orchestrated cases compare the whole returned outcome. The orchestrated case also asserts that nothing was notified.

Every other step ran as written.
