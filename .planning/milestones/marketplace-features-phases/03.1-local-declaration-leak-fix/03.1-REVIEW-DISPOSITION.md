# Phase 3.1: Review Disposition

**Date:** 2026-10-16

## CR-01: accepted as designed (user decision)

**Finding:** the first-run migration leaves out a marketplace that only the local file declares, together with every plugin recorded under it. When `claude-plugins.json` is absent, the reload then uninstalls those plugins and deletes their data.

**Ruling:** accept the uninstall. The user ruled that the design starts from the state the new code writes and does not carry the earlier state forward. Backward compatibility will be removed eventually. Under the new rules (FIX-03), a shared plugin cannot be declared under a local-only marketplace, so the case cannot arise from data written by this code. The pending test that expects `○ p1 (will uninstall)` pins the intended behavior. No code change, and no CHANGELOG note.

## WR-02 consequence: confirmed (user decision)

The named-update refusal runs before `preparePluginUpdate`, so a flagless named update under a local-only marketplace is refused even when the plugin is up to date. The user confirmed this on 2026-10-16. For a git-source plugin, the preflight fetches the plugin mirror (no pin), clones on a cache miss (pin), or lists tags (constraint), so "up to date" is not known without the network. The extension does not contact the network only to fail a command aimed at the wrong layer.
