## Artifacts this phase produces

This plan owns these new contracts and paths:

- `MarketplaceManifestDocument` and `loadMarketplaceManifestDocument(manifestPath)` in `domain/manifest.ts`: a read-only `manifest` and a `comparisonJson` string captured from the complete parsed JSON before dependency normalization. The existing loader returns the same cached `manifest` reference as before.
- Optional marketplace-state `lastSuccessfulManifest: string`: the serialized comparison JSON from the last successful add or refresh, with no schema-version change.
- `PublishedMarketplace.manifestPath`, `publishExternalMarketplace`, `republishMarketplace`, and `rewritePublishedManifest` in `features/lib/published-marketplace.ts`; `writeManifestText` and an explicit manifest-file argument on existing local writers in `features/lib/path-marketplace.ts`. These keep fixture source identity separate from the cleanup/plugin root.
- New `features/step_definitions/marketplace/update.steps.ts` and `features/marketplace/file-source-update.feature` (`Feature: Marketplace file source update`). Existing publishing steps own source publication; the new step module owns update-specific setup.

No change to `domain/manifest-cache.ts` is planned: its loader/cache already carries `unknown`, so it can cache the document without a new cache API. No dependency installation is needed.

## Assets and trust boundaries

Assets are the user's original manifest, scoped registration/install state, source identity, and the last successful comparison snapshot. Untrusted manifest bytes cross the domain validator; typed documents cross into state persistence; persisted source/root values reach filesystem readers and plugin containment checks. The external file is a read source, never a write destination.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan | Verification |
| --- | --- | --- | --- | --- | --- | --- |
| T-06-01 | Tampering | update.ts local manifest selection | high | mitigate | Read record.manifestPath; preserve independent marketplaceRoot; never search for a replacement source | Task 1 regression and Plan 02 missing-file/decoy test |
| T-06-02 | Tampering | manifest.ts and lastSuccessfulManifest | high | mitigate | Capture full parsed JSON before normalization, validate first, atomically save comparison metadata with successful state | Document owner cases and Task 3 failed-save/invalid-source cases |
| T-06-03 | Elevation of privilege | add.ts resolved paths and plugin roots | high | mitigate | Resolve the input once against add context, preserve root/containment convention and managed write locations | Add/update owner path cases and retained containment suite |
| T-06-04 | Tampering | snapshotAfterRefresh | medium | mitigate | Read fresh locked state, save once, cascade only after save; retain concurrent-removal behavior | Task 3 stateTransaction/lock cases |
| T-06-05 | Information disclosure | behavioral fixtures and info | medium | mitigate | Sandbox-owned fixtures and cleanup, run tokens in complete payloads, existing single output transport | Cucumber regression, info owner tests, full gate |
| T-06-SC | Tampering | package installation | high | mitigate | No npm/pip/cargo installation is planned; any added install requires the legitimacy audit and blocking human gate for ASSUMED/SUS packages | Verify no dependency diff |
