<objective>
Judge a local-config entry that has no `autoupdate` value by the value it inherits, test-first
(D-02 to D-04), and fail closed when that value would come from an unreadable base config (D-05).
A local flip then writes an explicit value only when it changes the effective value, and a nameless
flip without `--local` leaves a valueless local entry to inherit the new base value.

Purpose: the flip's "already" agrees with what `list` and `info` show (the merged value), and no
flip writes a per-machine override the user did not need. This is the phase's riskiest change: one
judgement function changes, and every test that pinned the old always-writes rule moves with it in
one commit.
Output: the inheritance in `orchestrators/marketplace/autoupdate.ts`, the D-03 and D-04 scenarios,
the reworked owner, integration, and edge-handler tests, two explicit-value pins, and 07-02-RED.json.
</objective>

## Decisions this plan applies

- D-05 leaves the planner to choose when the base is read. Choice: every flip whose target can hold
  a local entry reads the base config once with `loadConfig` (it never throws), and the flip fails
  only when a local entry without a value asks for the inherited value while that read is invalid.
  So a `--local` flip whose local entries all carry a value still succeeds over a broken base. This
  follows D-05's wording ("when the inherited value is needed") and 07-RESEARCH.md Pattern 1.
- Found during planning and not listed in CONTEXT.md or RESEARCH.md: two cases in
  `tests/edge/handlers/marketplace/autoupdate.test.ts` pin D-04's old outcome (`flips every
  marketplace in both scopes when no scope flag narrows the command` and the two rows of `flips the
  ${scopeValue} scope alone when --scope ${scopeValue} is supplied`). The commit hook does not run
  that pair unless it is staged, so this plan stages and fixes it.
