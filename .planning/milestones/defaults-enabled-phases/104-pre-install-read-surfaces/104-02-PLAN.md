<objective>
Expand the proven slice sideways across the list surface: the cold `(remote)` row
and the `(partially-available)` row start carrying the same entry-derived token,
and both `(unavailable)` paths are proven to stay clean.

The `(remote)` half is the one that carries the phase's real argument. A cold
git-source plugin has no local tree at all — no clone, no manifest, nothing to
resolve — and it can still say what an install would do, because the claim comes
from the marketplace entry the cached manifest already holds. That is why the
entry-only source is not a limitation to apologize for but the thing that makes
criterion 3 reachable offline.

Purpose: a user browsing a marketplace they have never fetched from is exactly
the user who most needs to know a plugin installs disabled, because they are
furthest from having run the install. Making the unfetched row silent would put
the warning only where it is least needed.

Output: one more optional message field, one render arm, two more stamp sites,
three comments that stop asserting what the code no longer does, and four list
assertions — one positive per new arm, two negatives, and the no-op parity pair.
</objective>

## Settled design calls (do NOT re-litigate at execution time)

- **D-104-06 — the bare-`(remote)`-row rule NARROWS, it does not reverse.** The
  existing rule says the remote row carries no reason brace at all. Its real
  content is that the row makes no claim it cannot substantiate from a tree it
  does not have: no probe-derived reason, no soft-dependency marker. An
  entry-derived token needs no tree, so it is admitted. Every comment and doc
  sentence asserting the absolute form is amended to the narrowed one. This is a
  narrowing of a documented contract, so it is done deliberately and in one pass,
  not opportunistically.

- **D-104-06 (the two other arms) — leave them alone, and say why in one line
  each.** The remote shape is rendered by three arms: the central row renderer,
  the list map, and the fetch surface's own map. Only the list arm starts
  forwarding. The fetch surface's producer builds remote rows and never stamps
  reasons, so nothing changes there today; editing it would cross this phase's
  boundary for no observable gain. Add a one-line comment at the central arm and
  at the fetch arm recording that the drop is correct by construction. The
  central arm's existing bare-row sentence needs the same narrowing the list
  arm's gets.

- **D-104-04 — a row that is simultaneously reporting a READ FAILURE still
  carries the token.** The two facts are orthogonal: one says the fetch or the
  read failed, the other says what an install would do. The claim is
  entry-derived and stays true regardless of whether the clone could be read.
  Suppressing the combination would need per-arm logic, which is what the single
  stamp site exists to avoid. On the list surface this combination is not
  reachable — a probe failure routes to `(unavailable)`, which is excluded — so
  it is the info surface's plan that pins it. Nothing here suppresses it.

- **Order is tail-append, and it is observable.** The brace composer joins in
  array order and there is no per-row sort. The closed-set tuple's order governs
  membership, not render order. So append at the tail of the existing array and
  pin the resulting bytes.

- **The `(unavailable)` exclusion covers BOTH paths.** The structural resolver arm
  and the probe-failure catch each return an unavailable row, and neither is
  stamped. Two paths, one rule; assert both.
