<objective>
Put the three new rows under the byte-equality runner, and stop two documents
from asserting the rule this phase narrowed.

The output catalog is not descriptive prose here — it carries a runner that
renders every documented state from a fixture and compares bytes. A row that is
not in the catalog is a row nothing guards at the contract level, which is why
these blocks land in this phase rather than being swept up later with the rest of
the documentation reconcile.

Purpose: the gate runs in both directions. A documented state with no fixture
fails, and a fixture with no documented state fails. That symmetry is what makes
the catalog trustworthy, and it is also why the block and its fixture are one
task: separating them produces a commit that is red by construction.

Output: three block/fixture pairs, two narrowed prose passages in the catalog,
and two corrected sentences in the message-shape reference.
</objective>

## Settled design calls (do NOT re-litigate at execution time)

- **Exactly THREE new states, named by CONTEXT.** The list surface's `(available)`
  and `(remote)` install-disabled rows, and the info surface's `(available)`
  install-disabled row. The two-token combinations — the partially-available row
  and the degraded unfetched row — are NOT catalog states in this phase. They are
  covered by orchestrator-level byte assertions in the preceding plans, and adding
  blocks for them would exceed what CONTEXT locked. Do not add a fourth.

- **Block and fixture land together, in one commit.** The gate walks both
  directions; either half alone is a failing tree.

- **The existing unfetched-row block does not change bytes.** Its fixture's entry
  declares nothing, so its row is unaffected. What changes there is its PROSE
  sentence, and the parallel sentence in the status-token reference table. Amend
  the sentences; do not touch the fenced block or the fixture.

- **Reuse the section's own canonical fixture names.** A reader diffing two
  adjacent blocks should see only the delta that matters. Use the unfetched-row
  block's existing marketplace and plugin names for the new unfetched state, and
  the info section's existing single-scope available names for the new info state.
  For the new list `(available)` state, reuse the plugin name the install
  section's install-disabled block uses, so a reader can put the pre-install row
  and the post-install row side by side for the same plugin and see the whole
  story of the token in two blocks.

- **Markdown is formatted by the repository's markdown pipeline.** The
  JavaScript formatter's check script covers only the code file types; running it
  in write mode over these documents reflows text a different tool owns. Let the
  commit hook normalize them.
