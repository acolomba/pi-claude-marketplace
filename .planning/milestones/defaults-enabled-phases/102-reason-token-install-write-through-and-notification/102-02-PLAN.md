Pin the two halves of the phase that are easy to get wrong quietly: the
precedence rule that decides WHEN `defaultEnabled` may act at all, and the
failure window where the ledger has already succeeded and the disable half then
throws.

landed. Neither is expected to require a production edit — but if one does, the
implementation is wrong and the assertion is right.

Purpose: DFEN-05 is the requirement that makes this milestone safe to ship. A
plugin author who can flip a value the user typed would make `claude-plugins.json`
untrustworthy; the rule that stops that is a three-valued read whose third value
(absent) is the only one `defaultEnabled` may answer, and a test that only
exercises two of the three values would pass while the rule was wrong.
Output: the precedence matrix in both directions, the caller-opt-in proof at the
import seam, and the failure-window characterization.
</objective>
