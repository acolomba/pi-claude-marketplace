## Settled design calls (do NOT re-litigate at execution time)

- **Three surfaces need new coverage, and `update` is this plan's one.**
  `reinstall` and `reconcile` are the next plan's. `list`, `info` and `install`
  are NOT re-proven: they are already covered at the notify layer and by the
  existing install-time precedence case.

- **The triple is self-contained. No baseline file, ever.** Pre-milestone, the
  declaration field was an unknown key under the lenient-tolerance rule and
  therefore inert, so a declared-true entry and a silent entry were literally
  the same input to the old tree. The declared-true row agreeing with the silent
  row IS the pre-milestone claim. The pre-milestone byte forms are recorded
  verbatim in RESEARCH.md and are transcribed into the assertion as literals;
  nothing is captured from a detached worktree and nothing is committed.

- **Both the declared-true case and the absent case appear explicitly.** A
  precedence test over a three-valued key that covers two values passes while
  the gate asks the wrong question. Two plugins, not one.

- **All three plugins are installed through the SAME production path**, each
  with the install-time opt-in flag set, because that is what the real install
  handler and the reconcile apply path both pass. The whole point is that the
  flag changes nothing for two of the three.

- **The flip carries its own control.** The marketplace manifest is served from
  a process-lifetime cache keyed on file metadata, so a rewrite the cache
  declines to notice would leave the verb reading the OLD entry and the
  enablement assertion would then pass for the wrong reason. Each plugin's own
  `plugin.json` omits its version, so the entry's version is what reaches the
  record: a version that moved is the proof the flipped manifest was read.

- **Whole-body assertion, plus an explicit row-to-row equality.** The whole-body
  literal pins row order, the tally and the trailer. The row-to-row equality is
  the parity claim itself and must be stated separately — two literals that
  happen to agree today can drift apart while both stay green.

- **The tally line legitimately differs from the pre-milestone tree.** The
  declaring-false plugin is skipped, so the realized-transition tally counts two
  where the old tree counted three. That is the fixture's own sibling changing
  the tally, not a parity break. This is exactly why the parity claim is stated
  about ROWS.

- **No new decision IDs.** Cite the durable requirement-level IDs. This phase's
  own work includes retiring anchors that archive with a phase directory;
  minting more of them here would be self-contradictory.
