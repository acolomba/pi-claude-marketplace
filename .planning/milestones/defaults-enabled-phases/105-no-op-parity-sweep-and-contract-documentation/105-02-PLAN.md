<objective>
Clone the tracer's parity shape onto the two remaining uncovered surfaces, and
close the one fixture-helper gap the phase actually has.

`reinstall` is a near-transcription: its seeder already carries the declaration
knob and the install-time opt-in flag, and it builds a multi-plugin marketplace
by repeat calls against a shared root. `reconcile` is the harder one and the
more valuable one — it is the only surface that legitimately READS the
declaration, so no source-level gate can express its boundary and only behavior
can. It is also the surface where the naive assertion shapes fail: the three
plugins share one notification whose tally counts all three, and the declaring
plugin's write-back rewrites the whole configuration file.

here, covered by the tracer, or deliberately not re-proven because it was
covered a phase ago.

Output: two new parity cases, and one fixture helper that reads the same as its
already-widened sibling instead of drifting from it.

## Settled design calls (do NOT re-litigate at execution time)

- **The assertion shape is the tracer's, transcribed.** Whole-body equality
  against a literal, PLUS an explicit row-to-row equality between the
  declared-true row and the silent row. Read the tracer's SUMMARY for the shape
  before writing either test.

- **Each file keeps its own harness idiom.** The reinstall suite records
  notifications into an array; the reconcile suite reads them off the mocked
  notify call list on its context factory. A test that assumes the other shape
  will not compile or will assert against nothing. Do not port one idiom into
  the other file.

- **The reinstall triple needs no declaration flip.** The flip discipline exists
  to separate "never re-read the field" from "re-read it and got the same
  answer", which is the lifecycle-non-reapplication claim — and the reinstall
  suite already pins that with its own flip case. DFEN-08's claim is narrower
  and is proven by the triple in one run. Do not duplicate the existing flip
  case.

- **The reinstall tally is correct as it stands.** Two reinstalled rows plus one
  informational skip render a three-success tally, because the default tally
  counts operation rows uniformly by stamped severity and the already-disabled
  reason is in the idempotent set. The catalog already documents the identical
  pattern for a different idempotent skip. Comment it in the test so a later
  reader does not "fix" it; do not chase it.

- **The reconcile fixture helper is widened, not wrapped.** Adopt the plugin-map
  signature of the already-widened sibling helper in the update suite, keeping
  the reconcile helper's own conditional-spread entry emission so an absent knob
  writes NO key — which is precisely the silent third arm. Convert all three
  existing callers. Do not add an extra-plugins parameter beside the scalars;
  that is the divergence the widening exists to prevent.

- **The reconcile second pass is in scope.** The fixed-point tests already pin
  silence for the declaring arm. Extending it to the declared-true and silent
  arms is one extra assertion in a fixture that exists anyway, and it is the
  clearest single expression of "nothing about these plugins changed".

- **No new decision IDs.** Cite the durable requirement-level IDs.
