<objective>
Stop the read-surface rules from being anchored to identifiers that expire.

Seventy-three citations across fourteen files point at six decision IDs minted
by the previous phase. Those IDs live in a phase directory that is archived at
milestone close, so a reader who meets one of these comments a year from now can
resolve the requirement IDs beside it and nothing else. Two of the affected
comments are the load-bearing guards against a future change that would reopen a
settled divergence — the ones that tell a reader NOT to "fix" the surface toward
what the install path reads. A guard whose justification cannot be looked up is
a guard that loses an argument.

This is not a cosmetic sweep. The previous phase's review caught the sharp
version of this failure: comments in this same family cited a requirement that
owns a completely unrelated divergence, so a reader following the only in-source
pointer landed somewhere that would never describe the topic and would
reasonably conclude the shipped behavior was a bug. Re-anchoring onto a
requirement that does not cover the rule would reproduce that exactly, which is
why this plan carries an explicit one-to-one mapping rather than an instruction
to use judgment.

Purpose: after this plan every citation in the read-surface family resolves to a
requirement that survives the archive and genuinely owns what the comment
claims, and the contract document written earlier in this phase is the durable
home the deepest of them points at.

Output: a comment, test-title and documentation-prose sweep across fourteen
files, with zero change to any expression, assertion, fixture value or
documented byte form.
</objective>

## The mapping (fixed; do NOT improvise a substitution)

Every retired identifier maps to the requirement that genuinely owns its rule.
Read the requirement's text before applying its row; if a row's requirement does
not cover what the comment in front of you claims, STOP and surface it rather
than substituting anyway.

| Retired ID | The rule it names | Re-anchor to |
|---|---|---|
| `D-104-01` | The marketplace entry is the ONLY source the two read surfaces consult, and only a literal false claims — true, absent and a non-boolean past the validator are all silent | `OUT-05` and `DOC-02`; the full argument lives in `docs/plugin-enablement.md` |
| `D-104-02` | The closed reason set does not grow, because the token already exists and already has a home in the topic partition | `OUT-01` |
| `D-104-03` | The token rides not-installed CANDIDATE rows only; both structurally-unavailable arms and every installed-record row are permanently excluded | `OUT-02` on the list surface, `OUT-03` on the info surface |
| `D-104-04` | A row already reporting a read failure carries BOTH facts in one brace, the failure first | `OUT-03` |
| `D-104-05` | The stamp is applied at the single not-installed consumer, behind a total status map, never per builder | `OUT-03` |
| `D-104-06` | The bare unfetched-row rule NARROWS rather than reverses — probe-derived and soft-dependency-derived reasons stay excluded, one entry-derived token is admitted — and the two other render arms for that shape deliberately drop the field | `OUT-05` and `RSTA-01` |

Rules for applying it:

- **Substitute in place, preserving the list's existing order.** A citation list
  reading `OUT-03 / D-104-03 / D-104-05` becomes `OUT-03` after substitution and
  deduplication; one reading `OUT-02 / OUT-05 / D-104-06` becomes
  `OUT-02 / OUT-05 / RSTA-01`.
- **Collapse duplicates; never leave a list empty.** A comment whose only anchor
  was a retired ID takes the mapped requirement ID.
- **Do not reword the rationale.** Only the identifier tokens move. The prose
  around them stays byte-identical apart from whitespace the substitution
  itself forces.
- **Add the contract-document pointer at ONE site only** — the canonical
  predicate docblock in the domain resolver, which is where a reader chasing the
  predicate lands. Every other site inherits it by citing the same requirement
  IDs. Duplicating the pointer seventy-three times is the drift surface this
  phase is closing.
- **Mint nothing.** No new phase-scoped decision ID, anywhere.

## Settled design calls (do NOT re-litigate at execution time)

- **All six IDs, not one.** The phase context names one by number; the
  orchestrator widened the scope to the whole family. Correcting one and leaving
  five is the drift pattern this closes.

  fenced byte form or fixture value moves. The comment-stripping gates and the
  byte-equality catalog runner are unaffected by construction, and the
  acceptance criteria prove it rather than assuming it.

- **The near-verbatim rationale duplication across many sites is NOT fixed
  here.** It is a real, recorded finding with its own argument, and folding a
  prose deduplication into an identifier substitution would hide the
  substitution inside a rewrite nobody can review. Surface it in the SUMMARY; do
  not act on it.

- **Split by tree, three tasks.** The production tree, the test tree and the
  documentation tree. Each is independently verifiable and each has a different
  gate to keep green.
