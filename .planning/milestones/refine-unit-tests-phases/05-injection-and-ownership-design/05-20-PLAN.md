- Use Plan 05-19's executed cache/edge identifiers and preserve one cache identity across add, remove, and completions.
- Marketplace removal's locked transaction decides invalidation eligibility. Invalidation occurs after commit and before data/clone hygiene.

- Names schema-2 and plugin-index schema-6 behavior remains exact. Cache operations do not own business classification or result construction.
- Invalidation and data/clone cleanup retain current independent error handling and exact warning/notification policy.
- Preserve both full-observation exceptions, Phase 6 machinery, exact Fallow comment, and excluded stage/PID/info/uninstall boundaries.

## Trust boundaries

| Boundary                                        | Description                                                                                  |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------- |
| Remove target -> locked destructive transaction | Persisted and user target data selects configuration, state, route, data, and clone effects. |
| Committed/partial state -> cache invalidation   | Wrong timing or target selection can hide live entries or retain stale completions.          |
| Invalidation -> data/clone hygiene              | Later failures must not corrupt committed state or suppress exact operator outcomes.         |
