  <files>scripts/test-coverage-direct.pin.json</files>

  <action>
    Work in two passes, and do not overlap them with any edit to a measured file. The sweep runs the
    owner test for `scripts/revalidation.mjs`, and that test reads the live `.planning/REQUIREMENTS.md`
    — a half-applied edit to either during a run reports as a coverage failure that is not one. Both
    passes take roughly eight minutes each; budget about sixteen minutes of wall clock and let them
    finish.

    **Pass 1 — enumerate.** Run `npm run test:coverage:direct:report`. It writes one JSON row per
    pair to `coverage/all-pairs-report.ndjson`, each carrying a `verdict` of `complete`, `type-only`
    or `accepted-shortfall`, and files no verdict of its own — a zero exit says the report was
    written and nothing more. Record the row count and the full list of `accepted-shortfall` rows
    verbatim.

    **Pass 2 — regenerate the pin and compare.** Rebuild the pin's `rows` array from the
    `accepted-shortfall` rows of the fresh report: for each such row carry its `sourcePath`, its
    `reading` string exactly as the gate printed it, its `findingIds`, and its `reasons`, preserving
    the committed file's `version: 1` envelope, its row ordering, and its per-site `reasons` text.
    Normalize the result with `npx prettier --write scripts/test-coverage-direct.pin.json`. Then run
    `git status --porcelain scripts/test-coverage-direct.pin.json`.

    - **Empty output is the expected result and a pass**, not a no-op: it proves the pin was
      regenerated from a fresh enumeration and the bytes agree. Make no commit for it. Record the
      empty output, the row count, and both readings verbatim in the SUMMARY.
    - **Non-empty output means a reading moved.** Do not accept it silently and do not widen the pin
      to absorb it. Establish which module moved and why, confirm the movement is a consequence of
      this phase's port and not a regression, and if and only if it is, commit the regenerated pin
      with a message that names the module and the old and new reading. A shortfall on a module that
      carries no pin row is a failure of this plan, not a pin update — stop and report it.

    **Pass 3 — the verdict arm.** Run `npm run test:coverage:direct:all`. It must exit 0 over the
    whole enumeration with `assertPinnedReadings` confirming the bidirectional match. Record its
    final summary line verbatim.

    If the pin is committed, run `SKIP=trufflehog pre-commit run --files scripts/test-coverage-direct.pin.json`
    and iterate until clean before `git commit`.
  </action>

  <acceptance_criteria>
