<assumption_delta_decision>
**Noun in transition:** the scan root. `tests/architecture/source-scan.ts` moves from one implicit
root (the module-level `REPO_ROOT` constant read at `:77`) to a caller-supplied root.

**Decision: promote.** The injected root becomes the primary way a scan names its base, and
`REPO_ROOT` is demoted to that parameter's default value — `opts.root ?? REPO_ROOT` — exactly the
form `scripts/test-coverage-direct.mjs:305` already uses (`selectedProjectRoot = projectRoot`).
This is not add-alongside: after this plan there is no second code path that reads `REPO_ROOT`
inside the scan loop, so a caller cannot accidentally get the old behaviour while believing it
injected a root.

**Rationale:** the house precedent's own doc block (`scripts/test-coverage-direct.mjs:297-303`)
records why a root that reaches only half the answer is "a wrong answer wearing the shape of a
pass". A promoted root is one place; an add-alongside root is two places that can disagree.

**Invariant test:** the `D-07-06` meta-gate does *not* cover this — it compares path literals
against the registry, not root usage. The invariant is encoded instead in
`source-scan.test.ts`: a scan run against a temp root whose copy of a real target carries a
planted violation must FAIL, while the same scan run with no `opts.root` against the same target
list must PASS. Only a fully promoted root can satisfy both in one file; a scan that still read
`REPO_ROOT` under the loop would pass both against the real tree and never fire.

**Second transition, same ruling:** the ESLint gates move from "the config" to "one of several
configs". `07-07-PLAN.md` promotes that the same way — every resolution goes through one
`resolveEffectiveConfig(targetRel, appendedBlocks)` whose empty-appended-blocks call *is* the
benign control, rather than adding an offender path beside a config-reading path.
</assumption_delta_decision>
