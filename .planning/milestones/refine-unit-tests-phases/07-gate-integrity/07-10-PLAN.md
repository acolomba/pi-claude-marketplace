<objective>
Remove `ReplaceReinstalledPluginInput.__operations` and give the physical bridge operations a
production-owned home on the transaction that already owns the rest of the reinstall schedule.

Purpose: `MF-DEC-07` and `D-05-01` forbid a `__deps`-shaped bag outright, and `D-07-18` requires
the offender to be gone before the gate that fires on it ships — a gate that lands red against its
own tree teaches people to ignore it. The collaborator is not invented for this: `ReinstallTransaction`
is already the production seam `reinstall-flow.ts` takes as an explicit parameter, and the
22-member bridge-operations record is the one member of the schedule that was never enrolled in it.

Output: a required second parameter on `replaceReinstalledPlugin`, `replaceOperations` on
`ReinstallTransaction`, and both owner tests reaching the real operations through the transaction
rather than through an input bag.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-27 | Tampering | `ReplaceReinstalledPluginInput.__operations` | high | mitigate | An optional input member that swaps the physical bridge operations is a substitution point reachable by any caller that can build the input. Making the operations a required parameter supplied by the transaction removes the optional path entirely: there is no longer an input shape that changes which bridges run. |
| T-07-28 | Tampering | compensation using different operations than replacement | medium | mitigate | `ReinstallReplacement.operations` is retained so rollback and finalize compensate through the same record the replacement used. A schedule that replaced through one set and compensated through another could leave a partially-replaced plugin; the retained field is what forecloses that. |
| T-07-29 | Repudiation | behaviour drift during the move | high | mitigate | Ordering, invocation-count, and fault-injection assertion counts are recorded before and after in both suites, because end-state assertions alone are order-insensitive and a rollback that unwinds forward leaves every byte identical with the suite green. |
| T-07-SC | Tampering | npm/pip/cargo installs | high | mitigate | Not applicable by construction: this plan installs no package and changes no `package.json` line. |
