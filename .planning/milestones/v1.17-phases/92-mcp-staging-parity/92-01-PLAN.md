<objective>
Build the deep-substitution + env-injection engine for MCP staging and wire it
end-to-end through the real prepare/commit path, so a plugin's own MCP entries
land in `mcp.json` with `${CLAUDE_PLUGIN_ROOT}` / `${CLAUDE_PLUGIN_DATA}`
substituted to real install paths (D-92-01, MENV-01). This is the tracer slice:
one path — a project-scope install with a plugin-root reference in `command` —
proven end-to-end through `prepareStageMcpServers → commitPreparedMcp → mcp.json`,
plus a focused pure-walker unit suite pinning the substitution surface.

Purpose: `stampServers` writes entries verbatim today — the milestone's biggest
env-parity gap. This plan makes staging deliver Claude-Code-equivalent path
substitution and establishes the threading (`pluginRoot`/`pluginData` on
`StageMcpInput`) that MENV-04 re-derivation and the Plan 02 injection/scope tests
build on.
Output: `bridges/mcp/substitute.ts` (new pure engine), two new `StageMcpInput`
fields, `stampServers` wired to substitute before it stamps, all three
orchestrator call sites threaded, and `tests/bridges/mcp/substitute.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin-declared MCP entry → mcp.json | Untrusted plugin-controlled string values (command/args/env/cwd/headers/url) are substituted and written into the user's scoped `mcp.json`. |
| resolver source servers → substitution engine | The engine consumes the resolver's SOURCE `servers` (placeholders intact), never a read-back of the prior `mcp.json`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-92-01 | Tampering | substituteLeaf / write target | high | mitigate | Substitution writes strings into a JSON VALUE slot only; the write target `mcpJsonPath` is a hard-coded suffix on `scopeRoot` (NFR-10). A crafted value cannot redirect the write. `pluginData` was containment-checked upstream by `locations.pluginDataDir`. |
| T-92-02 | Tampering | substituteLeaf re-expansion | high | mitigate | Single-pass alternation regex with a function replacer; each `${VAR}` site resolves exactly once against the map; output is never re-scanned; unknown tokens pass through untouched. |
| T-92-03 | Tampering | marker (_piClaudeMarketplace) | medium | mitigate | Marker is stamped from `buildMarker` AFTER the walk; it never enters `deepSubstitute` and object keys are never substituted, so it cannot be forged or stripped via crafted values. |
| T-92-04 | Tampering | theirs partition isolation | high | mitigate | `substituteAndInject` runs only on the plugin's own `servers` argument (the `stamped` branch); the `theirs` partition is merged verbatim and never walked. |
| T-92-SC | Tampering | npm/pip/cargo installs | low | accept | No package installs in scope — this plan is pure in-repo TypeScript (RESEARCH confirms no external deps). No Package Legitimacy Gate applies; no install checkpoint needed. |
</threat_model>
