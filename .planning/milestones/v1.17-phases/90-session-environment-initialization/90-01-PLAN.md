<objective>
Establish the milestone's shared runtime env-injection groundwork: at session start / load the extension mutates Pi's live `process.env` so every bash child spawned through Pi's bash tool sees Claude-Code-parity environment.

Two disjoint concerns on disjoint key sets (D-90-03):
1. Session vars (SENV-01/02/03) — a `session_start` handler sets `CLAUDECODE="1"`, `CLAUDE_CODE_SESSION_ID=<Pi session id>`, and the pi-only `CLAUDE_SESSION_ID` alias, overwritten fresh on every event so the value tracks the active session.
2. Plugin PATH (PENV-01) — after `applyReconcile` in the existing `resources_discover` handler, append each installed enabled plugin's `<resolvedSource>/bin` (both scopes) to `process.env.PATH`, tracked by a pi-only env-var ledger (`PI_CLAUDE_MARKETPLACE_PATH`) so stale entries are removed on recompute even across `/reload`.

Purpose: Phase 91 (hook env) leans on this; it is the runtime-injection foundation for the whole v1.17 env-parity milestone.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| extension → `process.env` | The extension mutates the shared live process environment at session start / load. |
| `process.env` → bash children / MCP servers | Pi's `getShellEnv()` spreads the full live `process.env` into every child spawn (no `PI_*`-prefix scrub); a bad mutation reaches every later child. |
| install state (`state.json`) → PATH | `resolvedSource` (which for path-source marketplaces is an external root outside managed containment dirs) becomes a `PATH` entry. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-90-01 | Elevation of Privilege | `recomputePluginPath` PATH append | medium | mitigate | Append plugin `<bin>` dirs AFTER existing entries (never prepend), so a plugin binary cannot shadow a system/Pi binary; Pi's own managed bin dir is prepended by `getShellEnv()` and wins. Behavior pinned by the append-not-prepend test. |
| T-90-02 | Tampering | `applyPathLedger` removal step | medium | mitigate | Remove only entries recorded in the `PI_CLAUDE_MARKETPLACE_PATH` ledger; non-owned PATH entries are never removed or reordered; ledger rewritten from the freshly-derived set each recompute. Pinned by the non-owned-entry-survival test. |
| T-90-03 | Spoofing | `applySessionEnv` key set | low | mitigate | Set only the three sanctioned session keys; never set host-identity/entrypoint vars that would misrepresent Pi. The non-interference snapshot test enforces an exactly-three-key delta. |
| T-90-04 | Denial of Service | `recomputePluginPath` state read | high | mitigate | `loadState` throws on malformed JSON / schema-invalid state; wrap the recompute call in a try/catch that swallows + `hookDebugLog`s so it never propagates past `resources_discover` and never blocks Pi load (NFR-2). Pinned by the malformed-state test. |
| T-90-05 | Information Disclosure | `PI_CLAUDE_MARKETPLACE_PATH` ledger visible to children | low | accept | The ledger holds only plugin bin directory paths (non-secret); documented as a pi-only bookkeeping var (Phase 94). Child visibility is accepted. |
