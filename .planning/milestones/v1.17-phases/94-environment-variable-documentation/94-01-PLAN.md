<ground_truth_facts>
The shipped behavior the doc transcribes (verified against the read_first code):

Two mechanisms:
- **S (install-time textual substitution)** — `shared/vars.ts::substituteClaudeVars`
  replaces the four content tokens `${CLAUDE_PLUGIN_ROOT}`,
  `${CLAUDE_PLUGIN_DATA}`, `${CLAUDE_SKILL_DIR}` (skills only), and
  `${CLAUDE_PROJECT_DIR}` (project-scope only) in skills/commands/agents content
  at install time; `bridges/mcp/substitute.ts::substituteAndInject` deep-substitutes
  the three tokens `${CLAUDE_PLUGIN_ROOT}`, `${CLAUDE_PLUGIN_DATA}`,
  `${CLAUDE_PROJECT_DIR}` (project-scope only) across an MCP entry's
  command/args/env at stage time. Absent value → literal pass-through (never
  empty string).
- **E (runtime env injection)** — `shared/session-env.ts::applySessionEnv` sets
  `CLAUDECODE=1`, `CLAUDE_CODE_SESSION_ID`, `CLAUDE_SESSION_ID` on Pi's live
  `process.env` at every `session_start` (bash children see them); the PATH
  ledger appends plugin `bin` dirs and records them in
  `PI_CLAUDE_MARKETPLACE_PATH`. Hook lanes `prepareEnv`
  (`bridges/hooks/dispatch-exec.ts`) and `prepareAsyncEnv`
  (`bridges/hooks/async-rewake/registry.ts`) spread `...process.env` then add
  `CLAUDE_PROJECT_DIR`(=cwd), `CLAUDE_PLUGIN_ROOT`, `CLAUDE_PLUGIN_DATA`,
  `claudeSessionEnvFor(sessionId)`, and — SessionStart lane only —
  `CLAUDE_ENV_FILE`. `CLAUDE_CODE_REMOTE` is deliberately unset. MCP servers
  inherit Pi's live `process.env` via pi-mcp-adapter 2.10.0
  `server-manager.ts::resolveEnv` (`{...process.env, ...interpolated(config.env)}`).

Pi-only vars (Claude Code column —): `CLAUDE_SESSION_ID` (alias; bash children +
both hook lanes) and `PI_CLAUDE_MARKETPLACE_PATH` (PATH ledger).

Threat dispositions to cite (do not restate): 91-SECURITY.md WR-02 note +
T-91-01 (accept, session-id not a secret); 92-SECURITY.md T-92-06 (user-scope
CLAUDE_PROJECT_DIR key omitted).
</ground_truth_facts>
