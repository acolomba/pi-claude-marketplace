<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin-authored `meta.name` -> filesystem path | an untrusted string derived from third-party script text becomes a path segment under a writable root |
| host environment -> extension | `$HOME` is read indirectly through `os.homedir()`; the value roots every workflow artifact |
| project directory name -> storage path segment | an attacker-influenced basename becomes the middle segment of the project-scope saved directory |
| test process -> host filesystem | `HOME` and `PI_CODING_AGENT_DIR` are mutated process-wide for the duration of one case |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-111-01 | Tampering | `workflowArtifactPath` composing an untrusted name | high | mitigate | `assertSafeName` runs BEFORE `path.join`, refusing an empty or whitespace-only name, the `.` and `..` segments, both path separators and ASCII control characters; `assertPathInside(workflowsSavedDir, candidate, ...)` then walks the composed leaf. The owner test asserts a refusal for each class rather than only asserting the happy composition. |
| T-111-02 | Elevation of privilege | a symlink planted at the artifact leaf inside the saved directory | high | mitigate | `assertPathInside` lstats every segment from the boundary down to the child inclusive and throws `SymlinkRefusedError`. | T-111-03 | Tampering | a second, unguarded path composer appearing elsewhere in the tree | high | mitigate | `workflowArtifactPath` is the sole composer and every consumer routes through it. | T-111-04 | Tampering | the project-key segment climbing out of the workflow home | medium | mitigate | The derivation's character class is `[a-z0-9._-]` with every other run collapsed to one dash, the dash strip runs over that result, and an empty result falls back to the literal `project`.
