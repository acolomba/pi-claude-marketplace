<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host session tool list -> the write decision | Whether the engine is loaded is host-controlled input; if it reached the write path it would let a third party's extension registration decide whether a user's artifact is written. |
| `bridges/workflows/` -> the user's `~/.pi/workflows/` tree | The bridge writes executable-script envelopes outside every scope root. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-114-10 | Denial of service | `bridges/workflows/stage.ts` | high | mitigate | If the write ever became conditional on the probe, a user whose engine is not yet installed would get a reported install with no artifact and no diagnostic path, and recovery would need a reinstall rather than a reload (NFR-2). The forbidden-surface gate over all five bridge modules makes the branch impossible to write; the byte pair proves it absent today. |
| T-114-11 | Repudiation | the byte-equality test | high | mitigate | Two agreeing runs prove nothing if neither degraded, or if neither staged a workflow. The four non-vacuity assertions -- marker present on the engine-absent run, absent on the engine-present run, plus the record deep-equality -- are what make the equality a claim rather than a coincidence. |
| T-114-12 | Tampering | the purity gate's target list | medium | mitigate | A glob would silently cover zero files after a directory rename. Targets are enumerated explicitly and `assertNoForbiddenSurface` FAILS on a missing target (WR-06); the missing-target planting run is required evidence. |
| T-114-13 | Information disclosure | envelope contents in test output | low | accept | The compared bytes are a fixture script authored in the test itself; no user data reaches the assertion diff. |
| T-114-SC | Tampering | npm dependency manifest | high | mitigate | No package-manager install task exists in this plan; `package.json` and `package-lock.json` stay out of the diff (CONTEXT D-114-07). No package-legitimacy checkpoint is required. |
