<objective>
Write the contract of a bridge that installs executable code, in the one shape this project
already uses for a per-component-kind contract, and put a pointer to it where a plugin author
will actually see it.

Purpose: a plugin author deciding whether to ship a workflows directory is deciding whether to
ship JavaScript that will execute on other people's machines. What they need is the sandbox
comparison, the list of shapes this bridge admits that the engine will refuse at invocation,
and an honest statement of which claims were measured and how. None of that exists anywhere
today, and neither README mentions the kind at all, so the whole capability is undiscoverable.

Output: `docs/workflows-compatibility.md`, the README pair updated in both languages, and the
three stale prose surfaces the closed-set growth left behind.

`## Naming` — where the command name comes from, that it is extracted by a static parse and

name: the exact generated form, the engine's own length and trimming limits, no case folding

`## Storage and discovery` — both scope paths, the derived project key, the discovery
precedence and its first-wins rule, and the deprecated legacy project path this bridge refuses

`## Script semantics: guaranteed versus divergent` — what a verbatim copy does and does not
preserve. Carry the agent-failure finding here with THREE explicitly separated evidence grades:
Claude's behaviour resolves to a null value on failure with a documented filtering pattern and
is documented upstream; the rejected engine's counterpart throws and was measured at runtime;
the host engine's counterpart rejects — every failure branch in its agent implementation throws
— and that was read from the shipped source at the pinned version and was NOT driven at runtime,
because driving it needs real spawn machinery. Write the grade of each claim in the text, not in
a footnote. Never let one grade pass for another.

`## Admit-versus-run divergence` — the mandatory table. One row per gate the engine runs before
a script can execute, in the engine's own order, each row carrying the engine's refusal message
and a replicated-or-not column. Exactly one row is marked replicated. Follow it with a second
table mapping each shape this bridge admits that the engine refuses onto the gate that refuses
it, with both template-literal arms as separate rows: a template literal with no interpolation
resolves in the engine to a name this bridge does not install under, while a template literal
WITH interpolation is refused outright. Close with the framing sentence: the failure is bounded
and visible — the artifact installs, the command registers, and the engine reports the failure
by name at invocation — but it is a documented divergence, not a guarantee.

`## Determinism` — the engine's raw-text blocklist quoted verbatim, why a raw-text test cannot
tell code from comment, why this bridge pre-validates before writing anything, and why a
rejection is reported in its own words rather than by repeating a message that names a rule the
script does not violate.

`## Install-time disposition` — the direct analogue of the hooks document's most useful section,
and the one four of whose five entries are documented nowhere else a plugin author would look.
One entry each for: a script with no readable metadata declaration, skipped with a warning while
its siblings install; an unparseable script, refused rather than name-scavenged; two scripts
resolving to one name, a hard error that fails the install; a script the engine's preprocessor
would refuse, skipped and reported by filename with the real reason while the plugin still
installs; and the host engine absent, where every envelope is still written, the install still
succeeds, and the row carries the degradation marker at warning severity because installing the
engine and reloading makes them run with no reinstall. State here that a plugin shipping an
EMPTY workflows directory installs, declares no host-engine dependency, and carries no marker.

`## Registration and reload` — an edit to an installed workflow takes effect without a reload
because handlers load by name from live storage; a NEW workflow needs a reload; and removal is
asymmetric, because the host exposes no unregister call, so a removed workflow's command lingers
for the session and the remedy is stated on the row.

`## Further reading` — the upstream reference and the host engine's own documentation, matching
the sibling document's two-link shape.
