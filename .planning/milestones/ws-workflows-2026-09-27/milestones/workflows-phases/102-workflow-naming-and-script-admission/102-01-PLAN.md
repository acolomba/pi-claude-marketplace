real script from source text to an admitted command name end to end.

Declare the verdict as a discriminated union over a closed outcome discriminant, one exported
`interface` per arm, `readonly outcome: "<literal>"` as the FIRST field and every other field

- `named`: `outcome`, `fileName`, `metaName`, `generatedName`, optional `description`
- `stem-fallback`: `outcome`, `fileName`, `generatedName`, optional `description`
- `skipped`: `outcome`, `fileName`, `reason` (human-readable), `cause` (closed literal union)
- `refused`: `outcome`, `fileName`, `reason` (human-readable), `cause` (closed literal union)

Also export `type AdmittedWorkflow = NamedWorkflow | StemFallbackWorkflow` — the two arms that carry
a `generatedName` — because the collision assertion added later narrows on exactly that pair. Under
`exactOptionalPropertyTypes` an optional field may not be assigned `undefined` explicitly; build the
object with a conditional spread or a conditional assignment, the way
`shared/errors.ts::StaleSourceCloneError` handles its optional field.

Export the entry point `admitWorkflowScript(pluginName: string, fileName: string, source: string):
WorkflowVerdict`. It derives the file stem itself by stripping a trailing `.js` from `fileName`;
callers pass the file name, never a pre-computed stem, so "the name Claude would give it" is decided
in one place. Its body is a flat sequence of early returns in ONE fixed order, and a comment above
the body states that order as the module's contract: unparseable first, then the engine's text-level
pre-validation, then the `meta` walk, then name safety. The order is load-bearing — acorn pushes
into the comment and token arrays as it scans and then throws, so on a parse failure those arrays are
only partially filled and any classification built on them would be unsound. In this task only the
first and third steps exist; leave the sequence shaped so the second and fourth slot in without
restructuring.

Private helpers, each small enough that `sonarjs/cognitive-complexity: 15` is comfortable:
`parseScript(source)` returning the AST plus the collected comment and string/template ranges, or
`undefined` when `parse()` throws; `findMetaObject(ast)` returning the `Property[]` of the `meta`
object literal or `undefined`; `metaPropertyKey(p)` narrowing the key; and a reader that pulls the
string-literal values of `name` and `description` off those properties.

`parseScript` makes exactly ONE `parse()` call, with `ecmaVersion: "latest"`, `sourceType: "module"`,
`allowReturnOutsideFunction: true`, `allowAwaitOutsideFunction: true`, and both `onComment` and
`onToken` pointed at local arrays. That single call yields the AST, the comment ranges and — by
filtering the tokens on `tokTypes.string` and `tokTypes.template` — the string-literal ranges, which
is why no AST-walker package is needed. Collect the string ranges now even though nothing consumes
them until the next plan; re-parsing later would be waste.

Two typing details the verified skeleton establishes: acorn types `Property.key` as the full
`Expression` union, so narrow it explicitly to `Identifier` or a string-valued `Literal` and reject
`p.computed` outright; and write guards as optional chains (`d.init?.type !== "ObjectExpression"`)
rather than explicit null comparisons, which `@typescript-eslint/prefer-optional-chain` rejects.

For this task, implement only the `named` arm: `meta` is an object literal, its `name` property is a
string `Literal`, and the arm returns `outcome: "named"` with `generatedName` from
`generatedWorkflowName(pluginName, metaName)` and `description` captured when `meta.description` is
also a string literal. The description is not consumed by anything in this phase; it is captured
because the artifact envelope built later needs it and parsing a second time there would be waste.
Every other input may fall through to a single provisional `skipped` return for now.
