**Step F — stage and commit.** Create
`extensions/pi-claude-marketplace/bridges/workflows/stage.ts`.

`prepareStageWorkflows(input)` follows the five-step ordering the commands analog fixes as the
contract: discover; `assertNoWorkflowNameCollisions` over the FULL verdict array of every
discovered record before anything is deduped or filtered; the materialization gate returning the
`noop` arm when there are no admitted verdicts and no previous names; create

without recomputing the join, build the envelope, and `writeFile` the serialized bytes into the
staging file. Push the rename pair and the staged name. Wrap the loop so any throw becomes
`appendLeakToError(err, await cleanupStaging(stagingRoot, "workflows staging directory"))`.

The envelope is built from exactly one variable for both the file name and the `name` field —
`generatedName` — so the two can never diverge. `description` is included only when the verdict
carries one, via a conditional spread; under `exactOptionalPropertyTypes` an optional key must
not be assigned `undefined`. `script` is the source bytes already in hand from discovery,
unaltered. Serialize with `JSON.stringify(envelope, null, 2)` plus a trailing newline, and build
the object literal in the order name, description, script so the serialized key order is fixed.

Do NOT use the shared JSON helper in `shared/atomic-json.ts`. Its own header scopes it to files
that participate in the state guard, and using it would land the envelope at its final path with
nothing to unstage — which dissolves the whole reason staging sits where it does. Atomicity here
comes from the rename.

`commitPreparedWorkflows(prepared)` lifts the commands commit verbatim with `.json` for `.md` and

name's target, tolerating ENOENT; `mkdir` the saved directory recursively, which creates both the
projects and key levels for project scope; apply the rename pairs sequentially while tracking
