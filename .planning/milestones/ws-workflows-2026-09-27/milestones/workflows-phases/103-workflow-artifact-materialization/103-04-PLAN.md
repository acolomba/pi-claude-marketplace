<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin-authored script bytes -> the `info` rendering path | Untrusted script contents are read on a read-only surface for the first time, to produce display names. |
| plugin-authored plugin name -> the decision layer's throwing check | A name the safe-name rule rejects reaches a surface that must not fail. |
| the live driver -> a real host-engine instance and the developer's environment | An out-of-suite driver creates and deletes real directories. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-103-16 | Denial of Service | `info` rendering over a malformed plugin | high | mitigate | The workflows discovery is caught locally and falls back to directory entries, so a plugin name the safe-name rule rejects costs one line's fidelity rather than the whole plugin's view. Pinned by a case using a rejected plugin name that still expects a rendered row. |
| T-103-17 | Elevation of Privilege | reading script bytes on a read-only surface | high | mitigate | The same static decision path the install uses; no evaluation, no dynamic module resolution, no subprocess. `info` gains a local file read and no new execution site, and remains offline, so the network constraint is untouched. |
| T-103-18 | Spoofing | display names on the `info` surface | medium | mitigate | Source names are rendered, matching every other component kind on that surface; the one row that renders generated names is documented as such. A malformed script renders its file name rather than disappearing, so a script cannot hide from the listing by being unparseable. |
| T-103-19 | Tampering | the live driver's sandbox | medium | mitigate | The driver builds a disposable home and working directory, installs through the extension's own path rather than planting files, and always uninstalls and deletes the sandbox including on failure. It is not reachable from any offline script. |
| T-103-20 | Tampering | a supply-chain coupling to a 0.x package | high | mitigate | The engine stays out of every dependency block, asserted by a criterion that reads all four blocks. The live driver resolves it from the environment it is run in and exits non-zero with a reason when it cannot, so an absent engine is reported rather than silently skipped. |
