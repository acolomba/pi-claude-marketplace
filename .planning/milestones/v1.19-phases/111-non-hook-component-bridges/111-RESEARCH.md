## User Constraints (from CONTEXT.md)

### Locked Decisions

### Fixture ownership

- **D-01:** Every mirrored owner case constructs its complete source tree locally,
  including complex frontmatter, malformed inputs, and byte-preservation cases. Owner
  tests do not read shared static source fixtures.
- **D-02:** Remove an existing shared fixture when its last legitimate supplemental or
  integration consumer is gone. Do not retain unused fixtures as historical reference.
- **D-03:** Small concern-local factories may create fresh directories or return fresh
  setup values. Each case still supplies its distinguishing input and independently
  authored complete expected result; factories must not become complete scenario oracles.
- **D-04:** Retain supplemental bridge cases only when they prove a genuine cross-module
  or orchestrator-facing contract. Absorb and delete cases that merely duplicate one
  mirrored owner's behavior. — **Reversibility:** costly — Restoring duplicated suites
  later would weaken the milestone's one-source-to-one-owner structure across four bridge
  families.

### Milestone test contract carried forward

- **D-05:** Normalize and re-prove all 31 owners, including accepted-HEAD `PASS` tests.
  Baseline triage is input, not completion evidence.
- **D-06:** Every runtime case uses separate lowercase `// arrange`, `// act`, and
  `// assert` phases with the canonical blank lines. Lowercase `// act & assert` is
  limited to one `assert.throws()` or `assert.rejects()` expression. Data rows use
  separate phases.
- **D-07:** Type-only evidence uses positive `satisfies` checks and targeted negative
  `@ts-expect-error` checks without artificial runtime cases or phase comments. Barrel
  owners directly prove the intended public bindings without widening the production
  surface.
- **D-08:** Each case owns and restores its filesystem, environment, mock, and other
  mutable state. Staging and unstage cases use fresh real temporary trees; production
  modules gain no test-only exports, reset hooks, state readers, or test modes.
- **D-09:** Expected generated bytes, complete public values, warning order, filesystem
  effects, and rollback results are authored independently from production builders and
  constants. Existing public behavior remains the authority.

### the agent's Discretion

- Choose the exact names and file locations for small concern-local fresh-value factories,
  provided they remain beside the owning bridge concern and comply with D-03.
- Choose which existing supplemental cases are genuinely cross-module, documenting the
  owner contract that prevents each retained case from becoming duplicate evidence.
- Choose the exact case breakdown and ordering within each owner while preserving complete
  public-contract and direct-coverage proof.

## Summary

Phase 111 is a test-ownership refactor, not a bridge redesign. The repository already has the production seams needed to test discovery, conversion, parsing, staging, replacement, rollback, finalization, and unstage behavior through public APIs. The plan should therefore create exactly 31 pair-atomic plans in ROADMAP order, with each plan owning one production source and its mirrored test. Existing `PASS` results are only baseline information; every owner must be normalized to the milestone structure and re-proved. [VERIFIED: .planning/ROADMAP.md:222-271] [VERIFIED: .planning/phases/111-non-hook-component-bridges/111-CONTEXT.md:7-14,37-54]

The largest planning risk is moving shared-fixture or supplemental assertions without establishing a single owner. Owner cases must construct complete source trees locally, while expected strings, bytes, warnings, public records, and filesystem outcomes remain independently authored. The current supplemental inventory contains mostly single-owner evidence: `integration.test.ts`, `integration-foreign-content.test.ts`, and `agents/convert-byte-identity.test.ts` should be absorbed into their relevant owners and deleted after their last case moves. In `integration-materialization-gate.test.ts`, the MCP-only isolation case is genuine cross-bridge evidence; retain only that case, rewrite it to a case-local complete tree, and document its contract as “running MCP staging alone cannot materialize agents, commands, or skills targets.” [VERIFIED: tests/bridges/integration.test.ts:54-278] [VERIFIED: tests/bridges/integration-foreign-content.test.ts:41-204] [VERIFIED: tests/bridges/agents/convert-byte-identity.test.ts:75-281] [VERIFIED: tests/bridges/integration-materialization-gate.test.ts:57-199]

Ten mirrored owner tests do not yet exist. Of the 21 existing owners, only five currently pass the exact direct-coverage gate; all 21 still require policy normalization. The direct-coverage carrier already creates an isolated LCOV directory, runs only the mapped test, accepts missing LCOV only for a transpilation-confirmed type-only module, and rejects any non-100-percent branch, function, or line count. Use it unchanged as the per-pair executable proof. [VERIFIED: scripts/test-coverage-direct.mjs:25-69,166-235,237-288] [VERIFIED: direct coverage audit, 2026-08-30]

**Primary recommendation:** plan 31 pair-atomic owner refactors, absorb duplicate supplemental evidence into those owners, retain only the MCP cross-bridge isolation case, and gate every pair with focused `node --test`, exact direct coverage, and typecheck before the repository gate. ### Pattern 1: Pair-Atomic Owner Test

**What:** one test module directly imports one production module, organizes cases by exported entrypoint, and proves public return values plus externally visible filesystem effects. [VERIFIED: .claude/rules/typescript-unit-testing.md:32-45,204-219]

**When to use:** every one of the 31 pairs. A plan may absorb supplemental assertions or remove a now-unused fixture, but it must not bundle a second production owner. [VERIFIED: .planning/PROJECT.md:13-25,343-354] [VERIFIED: .planning/phases/111-non-hook-component-bridges/111-CONTEXT.md:31-35]

**Example:**

```typescript
import assert from "node:assert/strict";
import test from "node:test";

import { safeSet } from "../../../extensions/pi-claude-marketplace/bridges/mcp/safe-set.ts";

test("copies __proto__ as an own data property without changing the prototype", () => {
  // arrange
  const accumulator: Record<string, unknown> = {};
  const expected = { owned: true };

  // act
  safeSet(accumulator, "__proto__", expected);

  // assert
  assert.equal(Object.getPrototypeOf(accumulator), Object.prototype);
  assert.deepEqual(Object.getOwnPropertyDescriptor(accumulator, "__proto__"), {
    value: expected,
    enumerable: true,
    writable: true,
    configurable: true,
  });
});
```

This concrete Wave 0 case uses the project-mandated phase comments and proves the exact `"__proto__"` special key plus the source's exact `enumerable: true`, `writable: true`, and `configurable: true` descriptor. [VERIFIED: extensions/pi-claude-marketplace/bridges/mcp/safe-set.ts:1-24] [VERIFIED: .claude/rules/typescript-unit-testing.md:42-45,101-113]

### Anti-Patterns to Avoid

- **Shared fixture as owner input:** it obscures the meaningful source bytes and violates D-01. Write complete trees in the case. [VERIFIED: .planning/phases/111-non-hook-component-bridges/111-CONTEXT.md:23-30]
- **Scenario factory as an oracle:** it couples input and expected output. Limit helpers to fresh resources or small concern-local values. [VERIFIED: .planning/phases/111-non-hook-component-bridges/111-CONTEXT.md:28-30]
- **Coverage by a supplemental suite:** direct coverage executes only the mirrored test; move single-owner evidence into it. [VERIFIED: scripts/test-coverage-direct.mjs:25-69,237-264]
- **One loop pretending to be many cases:** data rows still require separate arrange/act/assert phases, and interaction-rich scenarios should be named cases. [VERIFIED: .claude/rules/typescript-unit-testing.md:42-45]
- **Test-only production seams:** no reset hook, state reader, private export, injected mode, or surface widening. [VERIFIED: .planning/phases/111-non-hook-component-bridges/111-CONTEXT.md:45-51]
- **Deleting a shared fixture on sight:** current tests outside the immediate owner can still reference fixture roots. Re-run `rg` before deletion and remove only after the final legitimate consumer moves. [VERIFIED: .planning/phases/111-non-hook-component-bridges/111-CONTEXT.md:26-27,106-110]

## Common Pitfalls

### Pitfall 1: Treating a Baseline PASS as Completion

**What goes wrong:** a pair has 100-percent counters but still violates owner-local fixture, phase-comment, complete-value, or cleanup policy.  
**Why it happens:** coverage measures execution, not test design.  
**How to avoid:** normalize all 31 owners and run the focused test, direct carrier, and typecheck after the rewrite.  
**Warning signs:** an unchanged PASS test still reads `tests/bridges/_fixtures`, lacks lowercase phases, or asserts partial fields. [VERIFIED: .planning/phases/111-non-hook-component-bridges/111-CONTEXT.md:37-54]

### Pitfall 2: Hiding Complete Scenarios in a “Helper”

**What goes wrong:** a helper writes the meaningful source document or calculates the expected output, so the case no longer states its contract independently.  
**Why it happens:** stage trees and long frontmatter documents create pressure to deduplicate.  
**How to avoid:** factories may allocate a fresh tree or return fresh small values only; each case owns its meaningful source and full expected result.  
**Warning signs:** one helper receives a scenario label, imports a production constant, or returns both input and expected output. [VERIFIED: .planning/phases/111-non-hook-component-bridges/111-CONTEXT.md:23-30,145-151]

### Pitfall 3: Leaving Single-Owner Evidence in Supplemental Suites

**What goes wrong:** the mirrored owner lacks direct coverage while an integration test duplicates the same public operation.  
**Why it happens:** historical suites accumulated before the one-pair contract.  
**How to avoid:** move byte-identity, foreign-agent, MCP no-op, and agent no-op evidence to their direct owners; delete each redundant suite after its last case moves.  
**Warning signs:** a supplemental case imports only one bridge family or asserts only one module's result. [VERIFIED: tests/bridges/integration-materialization-gate.test.ts:57-148] [VERIFIED: tests/bridges/integration-foreign-content.test.ts:63-204] [VERIFIED: tests/bridges/agents/convert-byte-identity.test.ts:75-281]

### Pitfall 4: Deleting a Fixture Before Its Last Consumer

**What goes wrong:** later orchestrator or architecture tests fail even though the owner refactor passes.  
**Why it happens:** `tests/bridges/_fixtures` is not used only by mirrored bridge owners.  
**How to avoid:** run a repository-wide `rg` for the exact fixture path at deletion time; delete only when all remaining consumers are either absorbed or genuinely do not need it.  
**Warning signs:** a plan removes an entire fixture root without listing every current consumer. [VERIFIED: .planning/phases/111-non-hook-component-bridges/111-CONTEXT.md:26-27,106-110]

### Pitfall 5: Asserting Only the Happy Lifecycle

**What goes wrong:** commit passes, but abort cleanup, replacement rollback, finalize, malformed input, foreign content, containment, or missing-file branches remain uncovered.  
**Why it happens:** staged bridges have multiple public transitions and error arms.  
**How to avoid:** build an explicit lifecycle matrix per stage/unstage owner and assert the whole return record plus exact filesystem state after each transition.  
**Warning signs:** branch counts trail line counts; backup/staging directories are never inspected after cleanup. [VERIFIED: extensions/pi-claude-marketplace/bridges/agents/stage.ts:325-564] [VERIFIED: extensions/pi-claude-marketplace/bridges/mcp/stage.ts:201-400]

### Pitfall 6: Losing Byte, Order, or Foreign-Content Contracts

**What goes wrong:** a normalized parse-equivalent object passes while CRLF bytes, warning order, top-level foreign keys, or rollback bytes change.  
**Why it happens:** deep partial assertions ignore serialization and ordering.  
**How to avoid:** independently author complete strings/records and check pre/post bytes for conversion, MCP merge, agents-index, and rollback cases.  
**Warning signs:** snapshots, `includes`-only assertions, or expectations derived from parsed actual data. [VERIFIED: .planning/phases/111-non-hook-component-bridges/111-CONTEXT.md:52-54]

### Pitfall 7: Using Runtime Tests for Erased Types

**What goes wrong:** meaningless runtime assertions are added or production gets a runtime export solely to create LCOV.  
**Why it happens:** type-only modules emit no runtime statements.  
**How to avoid:** use positive `satisfies` plus targeted `@ts-expect-error`; let the direct carrier return exact mode `"type-only"` when transpilation proves no runtime statements. The quoted mode is verbatim.  
**Warning signs:** `test("types exist")`, `assert.ok(true)`, or a new production constant mirroring a union. [VERIFIED: .claude/rules/typescript-unit-testing.md:205-219] [VERIFIED: scripts/test-coverage-direct.mjs:166-235]

### Pitfall 8: Mutating Shared Environment State Without Restoration

**What goes wrong:** collision and staging cases become order-dependent or touch the developer's Pi directory.  
**Why it happens:** `PI_CODING_AGENT_DIR` influences local path resolution.  
**How to avoid:** snapshot the exact variable, point it at a fresh root, and restore/delete it in the same test context.  
**Warning signs:** file-scope environment mutation or cleanup only at suite end. [VERIFIED: tests/bridges/mcp/collision-slots.test.ts:15-30]

### Pitfall 9: Weakening Security Guards to Reach Coverage

**What goes wrong:** tests bypass path containment, symlink refusal, ownership markers, first-declarer collision order, or literal `"__proto__"` copying.  
**Why it happens:** malicious and foreign cases are harder to construct.  
**How to avoid:** construct hostile local inputs and assert the current public rejection/preservation behavior through the owner.  
**Warning signs:** private function exports, mocked path modules, or unsafe fixture symlinks shared across cases. [VERIFIED: extensions/pi-claude-marketplace/bridges/mcp/safe-set.ts:1-24] [VERIFIED: extensions/pi-claude-marketplace/bridges/mcp/collision-slots.ts:20-42]
