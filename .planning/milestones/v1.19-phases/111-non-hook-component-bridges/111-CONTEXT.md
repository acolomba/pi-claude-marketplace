# Phase 111: Non-Hook Component Bridges - Context

**Gathered:** 2026-08-30
**Status:** Ready for planning

<domain>
## Phase Boundary

Deliver compliant mirrored owner tests for the 31 non-hook bridge modules under
`bridges/agents`, `bridges/commands`, `bridges/mcp`, and `bridges/skills`. Each pair must
reach 100 percent direct function, line, and branch coverage while preserving conversion,
discovery, generated names, frontmatter, substitutions, diagnostics, component bytes,
atomic staging, rollback, containment, foreign-content, unstage, barrel, and type-only
contracts. This phase does not redesign bridge behavior or widen production APIs for tests.

</domain>

<decisions>
## Implementation Decisions

### Fixture ownership

- **D-01:** Every mirrored owner case constructs its complete source tree locally,
  including complex frontmatter, malformed inputs, and byte-preservation cases. Owner
  tests do not read shared static source fixtures.
- **D-02:** Remove an existing shared fixture when its last legitimate supplemental or
  integration consumer is gone. Do not retain unused fixtures as historical reference.
- **D-03:** Small concern-local factories may create fresh directories or return fresh
  setup values. Each case still supplies its distinguishing input and independently
  authored complete expected result; factories must not become complete scenario oracles.
- **D-04:** Retain supplemental bridge cases only when they prove a genuine cross-module
  or orchestrator-facing contract. Absorb and delete cases that merely duplicate one
  mirrored owner's behavior. — **Reversibility:** costly — Restoring duplicated suites
  later would weaken the milestone's one-source-to-one-owner structure across four bridge
  families.

### Milestone test contract carried forward

- **D-05:** Normalize and re-prove all 31 owners, including accepted-HEAD `PASS` tests.
  Baseline triage is input, not completion evidence.
- **D-06:** Every runtime case uses separate lowercase `// arrange`, `// act`, and
  `// assert` phases with the canonical blank lines. Lowercase `// act & assert` is
  limited to one `assert.throws()` or `assert.rejects()` expression. Data rows use
  separate phases.
- **D-07:** Type-only evidence uses positive `satisfies` checks and targeted negative
  `@ts-expect-error` checks without artificial runtime cases or phase comments. Barrel
  owners directly prove the intended public bindings without widening the production
  surface.
- **D-08:** Each case owns and restores its filesystem, environment, mock, and other
  mutable state. Staging and unstage cases use fresh real temporary trees; production
  modules gain no test-only exports, reset hooks, state readers, or test modes.
- **D-09:** Expected generated bytes, complete public values, warning order, filesystem
  effects, and rollback results are authored independently from production builders and
  constants. Existing public behavior remains the authority.

### the agent's Discretion

- Choose the exact names and file locations for small concern-local fresh-value factories,
  provided they remain beside the owning bridge concern and comply with D-03.
- Choose which existing supplemental cases are genuinely cross-module, documenting the
  owner contract that prevents each retained case from becoming duplicate evidence.
- Choose the exact case breakdown and ordering within each owner while preserving complete
  public-contract and direct-coverage proof.

</decisions>

<code_context>

## Existing Code Insights

### Reusable Assets

- Existing owner tests under `tests/bridges/{agents,commands,mcp,skills}/` contain broad
  contract inventories that are migration input, not automatic completion evidence.
- `tests/bridges/_fixtures/` contains byte-rich plugin, frontmatter, and foreign-agent
  examples. D-01 replaces owner-test dependencies on these with case-local source trees;
  D-02 preserves only fixtures with a legitimate remaining supplemental consumer.
- Each bridge exposes public prepare, commit, abort, replace, rollback, finalize, and
  unstage seams suitable for direct owner testing against real temporary trees.
- Prepared and replacement discriminated unions expose public lifecycle handles while
  keeping underscore-prefixed commit state bridge-internal.

### Established Patterns

- Agents, commands, MCP, and skills occupy separate architecture zones and may not import
  sibling bridge kinds.
- Discovery is deterministic and preserves kind-specific collision policy: generated-name
  first-wins warnings, hard collisions, directory skips, and foreign ownership remain
  distinct public outcomes.
- Replacement stages new artifacts, backs up prior owned content, rejects or preserves
  foreign content according to the bridge contract, and exposes rollback/finalize effects.
- Type-only modules centralize the public records and discriminated unions used across each
  bridge; barrel modules expose the intended orchestrator-facing surface.

### Integration Points

- `tests/bridges/integration.test.ts`, `integration-foreign-content.test.ts`, and
  `integration-materialization-gate.test.ts` are candidate supplemental suites. Retain only
  cases whose assertions truly cross owner boundaries.
- Install, update, and reinstall orchestrators consume the bridge lifecycle handles and
  recorded component rows. Phase 111 freezes those contracts without claiming completion
  for later orchestrator owners.
- MCP staging shares scoped `mcp.json` with foreign entries and four collision slots;
  agents use the persisted agents index; commands and skills materialize separate Pi
  artifact directories.

</code_context>

<specifics>
## Specific Ideas

- Long or malformed documents stay readable as local multiline literals beside the case
  whose behavior they distinguish.
- A setup factory can create a fresh tree, but it cannot hide the case's meaningful source
  bytes or compute the expected conversion result.
- The exact runtime phase comments remain lowercase: `// arrange`, `// act`, and
  `// assert`; lowercase `// act & assert` applies only to one throwing or rejection
  expression.

</specifics>
