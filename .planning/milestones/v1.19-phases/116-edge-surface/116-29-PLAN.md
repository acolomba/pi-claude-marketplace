**Doubles.** Build the handler record as `mock&lt;…&gt;({ exactParams: true, name: "subcommand handlers" })`
created inside each case, with its type taken from the module's own exported record type rather than
restated. State exactly one promised call per dispatch case with both arguments written out — the
remaining argument text and the context — and call `verify()` as the last line. Use no wildcard
matcher and no unbounded-count expectation. Build the Pi boundary with `createNotificationBoundary`:
dispatch cases size it at **zero** emissions, which is itself the proof that a successful route is
silent; usage-error cases size it at one emission and zero probes, because the usage-error path runs
no soft-dependency probe.

**Dispatch matrix.** Drive it from the two exported subcommand name lists so a name added to a list
without a dispatch arm fails here. For each name, state which handler member it must reach — that
mapping is written out by hand in the row table, never derived by calling the router. Cover:

- Every top-level subcommand name, including the list alias, each reaching its own handler member
  exactly once with the remaining argument text.
- Every marketplace subcommand name, including the remove alias and the list alias, each reaching its
  own handler member.
- **Alias identity.** For each alias, drive the alias and its canonical name in the same case against
  the same mock and assert both reached the **same handler member** with the same remaining argument
  text. Two separate cases would not prove identity; one case with two acts against one stated
  expectation does.
- **No alias shadows a canonical name.** Assert the two exported name lists contain no duplicate
  entries, and that no marketplace name reachable through the marketplace dispatch is also handled by
  the top-level dispatch under a different handler member. State the mapping by hand.
- The marketplace token routes into the second dispatch rather than to a handler: driving a
  marketplace subcommand through the top-level entry point reaches the marketplace handler member,
  not a top-level one.

**Argument passing.** The remainder must reach the handler byte-for-byte:

- Extra interior whitespace between the subcommand and the rest is stripped from the front only; the
  interior is preserved.
- Leading whitespace before the subcommand is stripped.
- Quotes and flags in the remainder survive untouched.
- A subcommand with no remainder passes the empty string.
- A subcommand followed only by whitespace passes the empty string.

- Empty top-level input: the usage-error sentence with the top-level usage block.

- Unknown marketplace token: the unknown-marketplace-subcommand sentence naming the token verbatim.
