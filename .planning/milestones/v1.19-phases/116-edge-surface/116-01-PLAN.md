The module exports `PositionalSpec`, `ParsedCommandArgs`, and `parseCommandArgs`; only
`parseCommandArgs` is runtime. Its one collaborator, `onError: (message: string) =&gt; void`, is a
declared parameter, so the double is a plain recorder closure — `const usageErrors: string[] = []`
with `(message) =&gt; { usageErrors.push(message); }` — asserted as a whole array. It is not a
strict interaction mock: the module's result is the promise, not the callback's call count.

Cover every branch of the module, derived from the source rather than sampled:

- Success with two required positionals and no `--scope`: the result is the exact object
  `{ marketplace: "official", plugin: "alpha" }` and `usageErrors` is `[]`.
- Success carrying scope: the same schema with `--scope project` yields
  `{ marketplace: ..., plugin: ..., scope: "project" }`. Prove `--scope` is position-independent by
  driving it before, between, and after the positionals through a row table, each row asserting the
  same whole value.
- Optional tail positional present: a schema whose second entry is `{ name: "name", required: false }`
  sets the property.
- Optional tail positional absent: the property is **omitted from the result object**, not present
  as `undefined`. Assert the whole value so the difference is visible.
- Optional tail positional supplied blank: a quoted whitespace token reaches the branch guarded by
  `value.trim() !== ""` and is omitted, with `usageErrors` still `[]`.
- Required positional absent: `onError` receives the schema's `usage` string **verbatim** — write
  that string out by hand in the case, do not read it back from the schema object the case built —
  and `parseCommandArgs` returns `undefined`.
- Required positional present but whitespace-only: same outcome. The tokenizer only produces a
  blank token from a quoted run of spaces, so drive it that way.
- Tokenizer throw: `--scope bogus` makes `parseArgs` throw, `parseArgsOrNotify` catches it, and
  `onError` receives the thrown error's own message. Author the expected string by hand:
  `Invalid --scope value: "bogus". Must be "user" or "project".` The result is `undefined` and no
  positional validation ran, proven by the schema declaring a required positional that the input
  does satisfy.
- `--scope` with no value: drive `--scope` as the final token, and separately drive
  `--scope ""` (an empty double-quoted value, which the tokenizer discards entirely). Both reach the
  missing-value throw, so `onError` receives `--scope requires a value: "user" or "project".`
- Empty argument vector: `parseCommandArgs("", schema, onError)` against a one-required-positional
  schema calls `onError` with the usage string and returns `undefined`. Drive a bare verb with no
  operand the same way, and against a zero-positional schema assert the empty vector succeeds with
  the empty object `{}` and no error.
