`describe("makeSingleNameMarketplaceHandler")` — cover:

- Accepted arity of exactly one positional: the delegate receives `{ ctx, pi, name, cwd }` with
  every member stated and no `scope` key, and the boundary recorded zero notifications.
- One positional with a scope flag: the delegate receives the same object plus `scope`, and the
  scope key is present only in this case. Drive both scope values as a row table.
- One below the accepted arity — no positional at all: exactly one notification whose whole value is
  the collapsed missing-argument sentence followed by a blank line and the usage block, and the
  delegate is **never called**. Prove the second half by creating the mock with no expectation at all
  and calling `verify(run)`: a mock with no stated call throws on any call, so a green case is a
  proof the delegate was never reached.
- One above the accepted arity — two positionals: state the observed outcome from the module source.
  The single-positional schema ignores the extra token, so the delegate is called with the first
  positional; assert that whole options object rather than assuming a rejection.
- A parse diagnostic that is not the usage string, such as an unrecognised scope value, reaches the
  user verbatim rather than being collapsed to the missing-argument sentence. This is the
  discriminating case for the collapse rule; without it the collapse assertion passes for any
  message.
- The factory closes over `pi`: two handlers built from the same `pi` both forward that identical
  reference. Assert the delegate options carry the same `pi` the case constructed.

`describe("openMarketplaceCommand")` — cover:

- Positional plus scope-target flag: the whole returned object is
  `{ [positionalName]: value, local: true }`, and with a scope flag it additionally carries `scope`.
  The returned positional key is the caller-supplied name — drive two different names so the key is
  proven to come from the caller rather than being hard-coded.
- Flag before the positional and flag after the positional yield the identical whole value. This is
  the ordering proof: if positional parsing ran first, the flag token would be consumed as the
  positional and the returned value would differ.
- The scope-target flag alone, with no positional, is rejected with the collapsed missing-argument
  sentence — one notification, and the function returns `undefined`.
- An unknown long flag is rejected by the flag scan before parsing: exactly one notification carrying
  the unknown-flag sentence, and `undefined` returned.
- A parse failure after a successful flag scan returns `undefined` with exactly one notification.
- No positional and no flags: the collapsed missing-argument sentence.

Write every expected notification out by hand as one whole value, including the blank line between
the sentence and the usage block. Do not interpolate the usage string the case passed in, and do not
