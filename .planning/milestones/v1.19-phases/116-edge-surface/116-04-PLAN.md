`{ lines, cursorLine, cursorCol }` against a hand-authored literal in every case. Cover:

- Two spaces straddling the cursor collapse to one: the character before the cursor and the
  character at the cursor are both spaces, and exactly one space survives. `cursorLine` and
  `cursorCol` come back unchanged — state both in the expected literal.
- A run of three spaces collapses to one. This is the case that enters the `while` loop body at
  `normalize.ts:38-39`; a two-space input never enters it. Add a four-space case as a second row so
  the loop iterating more than once is covered by behavior, not by accident.
- No-op when the character before the cursor is not a space.
- No-op when the character at the cursor is not a space, including the end-of-line case where the
  cursor sits past the last character.
- No-op at column zero, where there is no character before the cursor.
- Cursor line outside the lines array: the function reads `lines[cursorLine] ?? ""` and returns the
  input lines unchanged. Drive it with a `cursorLine` beyond the array length and assert the whole
  value.
- Other lines are untouched: a multi-line input where only the cursor line changes.
- The returned `lines` array is a copy: mutate the returned array after the act and assert the input
  array the case constructed is unchanged. Compare the whole input array against a hand-authored
  literal, not against a value derived from the result.
