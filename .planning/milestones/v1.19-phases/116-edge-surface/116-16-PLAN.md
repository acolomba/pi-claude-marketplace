object. Every rejection here goes through the usage-error path, which runs no soft-dependency probe,

`describe("parseFetchTarget")` — assert the whole `{ target, scope? }` object against a
hand-authored literal in every case:

- No positional: the all form, with no `scope` key.
- No positional plus each scope value, as a row table: the all form carrying `scope`.
- A bare marketplace reference — a leading separator followed by a name: the marketplace form
  carrying that name with the separator stripped.
- A plugin reference: the plugin form carrying both halves.
- A lone separator with nothing after it: read the module guard, which requires length beyond the
  separator, and state the observed outcome. It falls through to the reference split, so assert the
  malformed-reference rejection rather than the marketplace form.
- One below and one above the accepted arity: zero positionals is accepted, so the "one above" case
  is two positionals — exactly one notification carrying the too-many-arguments sentence with the
  fetch usage block, and `undefined` returned. Add a three-positional row.
- A long flag among the positionals: exactly one notification whose sentence names the offending
  token verbatim, and `undefined` returned. Drive it as the only positional and alongside a valid
  reference, so the scan is proven not to stop early.
- An unrecognised scope value: the tokenizer throws and exactly one notification carries the thrown
  error's own message with the usage block appended.
- A malformed plugin reference: exactly one notification whose sentence names the offending token
  verbatim. Drive all three malformed shapes as a row table.
- Mutually exclusive scope selectors supplied together — a scope flag plus the scope-target flag:
  this handler accepts only the scope flag, so read the module and assert which rejection fires.
