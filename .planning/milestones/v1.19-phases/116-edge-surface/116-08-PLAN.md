Purpose: `edge/handlers/marketplace/autoupdate.ts` sits at 13/14 branches, 3/4 functions, and 58/61

consumes it. Any workflow notification would be a second access past the stated count, which throws
at the call site and makes `verifyBoundary()` fail with an unexpected-call report. A green case is
therefore a proof the workflow never ran — not merely that an error surfaced (D-116-06).

normative excerpt.

**Harness.** Build the Pi boundary with `createNotificationBoundary` from
`tests/helpers/notification-boundary.ts` — never a hand-rolled context object with a cast. Every
rejecting case sizes it at one emission and **zero** probes, because the usage-error channel writes
straight to the notification channel and runs no soft-dependency probe; inheriting a derived probe
count is the trap the wave-1 helper change removed. Delegating cases reach the workflow, which emits
its own notification and probes per emission — read the module and state both counts. Delegating
cases state `ctx.cwd` through the boundary `cwd` option with the read count the handler performs;
rejecting cases omit it because they never reach that read. Own one `mkdtemp` tree per case with the
environment saved and restored in a `t.after()` registered before the act.

**The normative negative-delegation case.** Write this one first and record it verbatim in the
summary as the form the other twelve seamless-handler owners copy:

Arrange the boundary at one emission and zero probes, build the handler from the boundary Pi handle,
act by calling it with an input carrying an unknown long flag, then assert the recorded
notifications equal exactly one whole value — the unknown-flag sentence, a blank line, and the
usage block for the arm the factory was built with — and call `verifyBoundary()`. State in the case
title that the workflow did not run, because that is what the sizing proves.

**Matrix.** Drive every case through both factory arms as a row table wherever the outcome differs
only by the usage block, so the enabling and disabling forms are both exercised without duplicated
bodies:

- Accepted arity of zero positionals: the workflow runs and the boundary records the workflow
  notification count. Assert the on-disk autoupdate record the workflow wrote, seeded and read
  through `tests/helpers/marketplace-seed.ts`, as the minimal observable effect. Do not re-derive
  the workflow notification body; its own pair owns that at 100 percent direct coverage.
- Accepted arity of one positional name: the name reaches the workflow, proven by the record it
  wrote naming that marketplace and no other.
- One above the accepted arity — two positionals: state the observed outcome from the module
  source. The optional single-positional schema takes the first token; assert what actually happened
  rather than assuming a rejection.
- The boolean the factory was built with selects the usage block: prove it by driving the same
  invalid input through both arms and asserting the two notifications differ in exactly the usage
  block. Write both blocks out by hand.
- The boolean also reaches the workflow: the enabling arm and the disabling arm leave opposite
  recorded states for the same input.
- Scope omitted, and each scope value supplied, as a row table; the scope member is present in the
  workflow options only when supplied, observable through the record location.
- Scope-target flag supplied and omitted, driven before and after the positional, asserting the
  identical outcome.
- Mutually exclusive scope selectors supplied together — a scope flag and the scope-target flag in
  the same command: read the module and the helper first, then state the observed outcome. If the
  module accepts both, say so explicitly and assert what reaches the workflow; if it rejects, assert
  exactly one notification and prove the workflow never ran.

  exactly one notification carrying the parse diagnostic and the usage block, and the workflow never
  runs.
- An unknown long flag rejected by the flag scan, and separately an unknown long flag that survives
  the scan and is rejected by the parse: both prove the workflow never ran.
