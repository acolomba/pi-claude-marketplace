<objective>
Make the shared Pi notification boundary usable at the edge tier, and remove the two traps that
would otherwise cost twenty of the thirty owner plans a wasted debugging cycle each.

Purpose: `tests/helpers/notification-boundary.ts` is the one sanctioned way to size IL-2 emissions,
and roughly twenty of this phase's plans depend on it. Three things block that today. Its `ctx` is
typed `ExtensionContext`, but every edge handler signature takes `ExtensionCommandContext`, so an
owner using the helper as-is would be pushed into the double assertion the milestone exists to
remove. Its `toolProbes` defaults to `emissions * 2`, which is right for `notify()` and wrong for
`notifyUsageError`, the path the great majority of this phase's cases exercise — the default leaves
an unmet `getAllTools()` expectation and `verifyBoundary()` fails naming a probe the case never
wanted. And `ctx.cwd` cannot be stated at all, so a handler that forwards `cwd` into its
orchestrator dies inside path joining with a message that names nothing about the mock.

This is wave 1, and it is the only plan in the phase permitted to change
`tests/helpers/notification-boundary.ts`. Every plan after it pins that file with
`git diff --quiet`, so a later plan cannot quietly reshape the shared boundary to ease its own
proof.

Output: one helper change plus its mechanically-updated call sites, every consumer suite still
green with unchanged sizing, and a recorded plant proving the boundary still fails on an
over-emission.
</objective>

  <action>
Change three things in `tests/helpers/notification-boundary.ts` and nothing else.

Command-context typing. Build the context mock as `mock&lt;ExtensionCommandContext&gt;` instead of
`mock&lt;ExtensionContext&gt;`, import `ExtensionCommandContext` from
`extensions/pi-claude-marketplace/platform/pi-api.ts` alongside `ExtensionAPI`, and declare the
`ctx` member of `NotificationBoundary` as `ExtensionCommandContext`. `ExtensionCommandContext`
extends `ExtensionContext`, so this is a widening of the returned type: every existing consumer
that hands `ctx` to an orchestrator taking `ExtensionContext` keeps compiling unchanged. Keep the
`NotificationUi` alias sourced from `ExtensionContext["ui"]["notify"]` — the UI shape does not
change. Keep `NotificationSeverity` exported with its current derivation.

Required `toolProbes`. Change the signature to
`createNotificationBoundary(emissions: number, toolProbes: number, cwd?: ...)` and delete the
`= emissions * 2` default. That default is the trap: `notify()` runs one soft-dependency probe per
emission and each probe reads `pi.getAllTools()` twice, but `notifyUsageError` writes straight to
`ctx.ui.notify` and never probes, so a usage-error case inheriting the default fails
`verifyBoundary()` with an unmet `getAllTools()` expectation that names nothing about the case's
real mistake. Requiring the argument forces every caller to state the count its path actually
spends.

Optional stated `cwd`. Add a third parameter
`cwd?: { readonly value: string; readonly reads: number }`. When supplied, state
`when(() =&gt; ctx.cwd).thenReturn(cwd.value).times(cwd.reads)`. When omitted, state no `ctx.cwd`
expectation at all. Give `reads` no default — an implicit count is the same class of trap this
task removes. Every edge handler reads `ctx.cwd` exactly once on the path that reaches its
orchestrator and zero times on a rejection path, so a delegating case passes `{ value, reads: 1 }`
and a rejection case omits the parameter.

Rewrite the file header comment and the `createNotificationBoundary` doc comment to describe the
new contract: what `toolProbes` counts, why it is stated rather than derived, and that `cwd` is
stated only when the case's path forwards it. Cite `IL-2`, `WR-08`, and `D-116-06` as traceability
anchors. Cite no plan, phase, wave, or task.

Change nothing under `extensions/`. Add no export beyond the widened `ctx` type. Do not add a test
module for this helper: test support needs no meta-test, and the correspondence gate reports a
`tests/helpers/*.test.ts` file as an unexpected test, which would move the gate the wrong way.
  </action>
