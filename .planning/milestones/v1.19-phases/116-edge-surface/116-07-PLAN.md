**Harness.** Copy the hermetic scope shape from `tests/orchestrators/edge-deps.test.ts`: one
`mkdtemp` working root and one `mkdtemp` home root per case, the home and agent-directory
environment variables saved with an own-property check and restored in a `t.after()` **registered
before the act**, and a context-owned replacement of the global network entry point that throws on
any call, exposing its call count. The agent-directory variable must be deleted, not merely
overwritten, because the agent-directory resolver reads it before the home directory. Do not write a
`finally` block — it leaks when a case throws before the `try`.

Build the Pi boundary with `createNotificationBoundary`, never a hand-rolled context object. The
delegating cases reach the add workflow, which emits its own notification and runs a
soft-dependency probe per emission; size the boundary from the module source and state both counts
explicitly. The rejecting cases reach only the usage-error channel, which runs no probe, so they
size the boundary at one emission and zero probes. Every delegating case states `ctx.cwd` through
the boundary's `cwd` option with the read count the handler actually performs.

Build the port with `createGitOpsFake({ boundary: "memory", ... })` from
`tests/platform/git-ops-fake.ts` — never a hand-rolled object literal of git functions. It is
already typed against the production port and already records calls.

**The forward proof.** Drive a git-source value that the add workflow must clone, and assert the
fake's call recorder holds exactly the clone the workflow performed, compared as one whole value
against a hand-authored literal. That recording is only possible if the identical port object the
handler was constructed with reached the workflow, which is the exact-argument proof this tier can
give. Do not re-derive the workflow's outcome value or its notification body — the marketplace add
workflow is owned at 100 percent direct coverage by its own pair, and re-deriving it here is the
duplication this milestone removes. Assert the handler's own promise: the port arrived, the scope
that arrived is the one the flags selected, and the notification count is what the edge sized for.

**Edge-side matrix**, which is what this owner really owns:

- Accepted arity of exactly one positional source: the workflow runs.
- One below the accepted arity — no positional: exactly one notification carrying the collapsed
  missing-argument sentence, and the workflow never runs. Prove the second half by sizing the
  boundary at one emission: the workflow's own notification would be a second access past the
  stated count, which throws at the call site and fails `verifyBoundary()`. Additionally assert the
  git port recorder is empty.
- One above the accepted arity — two positionals: state the observed outcome from the module
  source. The single-positional shape takes the first token; assert what actually reaches the
  workflow rather than assuming a rejection.
- Scope omitted: the user scope default reaches the workflow. Prove it by driving a source into the
  user scope tree and asserting the resulting on-disk record location, or by the notification's own
  scope bracket — whichever the module makes observable. State which one you used.
- Scope supplied: both values, as a row table.
- Scope-target flag supplied: the flag reaches the workflow; omitted: it does not. Drive the flag
  before and after the positional and assert the identical outcome, which is the ordering proof
  inherited from the helper.
- Mutually exclusive scope selectors supplied together — a scope flag and the scope-target flag in
  the same command: state the observed outcome from the module source. If the module accepts both,
  say so explicitly and assert what reaches the workflow; if it rejects, assert exactly one
  notification and an empty git recorder. Do not guess: read the helper and the workflow first.
- An unknown long flag: exactly one notification carrying the unknown-flag sentence, an empty git
  recorder, and the workflow never runs.
- An unrecognised scope value: exactly one notification carrying the parse diagnostic, an empty git
  recorder, and the workflow never runs.

Assert the fail-fast network boundary was never reached in the path-source cases, by its call count
