<objective>
Rewrite the owner for the registration glue — the last plan in the phase, and the one whose coverage
gap is entirely about callbacks that are registered but never invoked.

Purpose: `edge/register.ts` is 143 lines and sits at 9/10 branches and **7/9 functions** with every
line covered. Two registered callbacks are never called by the existing thirteen-case suite: the
suggestion pass-through inside the autocomplete wrapper and the file-completion trigger, whose
fallback arm is the missing branch. Both are reachable only by capturing the callback off the
registration and invoking it.

It runs last because it composes every handler factory in the tier plus the router, the completion
provider, and the tool registrations. It also holds the one sanctioned read of the process working
directory, captured at registration time and closed over by the completion callback — which is a
behavior worth its own discriminating case.

Output: one exhaustive, hermetic, offline-proven owner for `edge/register.ts`.
</objective>

**Capture and invoke — this is the whole point of the plan.** For every registration the module
performs, capture the object it passed off the mock's recorded call and then **invoke** each callback
it carries. Merely asserting that registration happened leaves the callback bodies unexecuted, which
is why two functions are uncovered today.

`describe("registerClaudePluginCommand")` — cover:

- The command is registered exactly once, under its declared name, and the recorded options carry the
  declared description as a whole-value string written out by hand.
- The captured command handler routes: invoke it with an argument string and a context, and assert
  the routed effect. Use the smallest observable the router produces — a usage error for an unknown
  subcommand is enough, sized on the notification boundary at one emission and zero probes. Do not
  re-derive the router dispatch matrix; `tests/edge/router.test.ts` owns it.
- The captured completion callback resolves against the working directory captured at **registration
  time**: register while the process working directory is one hermetic root, change the process
  working directory to the second root, then invoke the callback and assert the candidates came from
  the first. Without the change-after-registration step this case passes for a callback that reads
  the working directory on every invocation, so the two-root form is the discriminating one.
- The session-start listener is registered exactly once, under its declared event name.
- The captured session-start listener installs an autocomplete provider: invoke it with a context
  whose provider registration is a mock, and capture the provider factory it passes.
- Invoke the factory with an underlying provider stub and exercise **all three** members of the
  returned provider:

    one whole value — this is one of the two uncovered functions;

    recogniser accepts, and returns the underlying result untouched otherwise. Cover both arms, and

    and falls back to permitting the trigger when it does not. Both arms — the fallback is the
    missing branch.
- The completion application when the cursor line index is outside the lines array: the recogniser
  reads an empty string, so state the observed outcome and assert it.

nothing else, by stating both registration calls on the mock and verifying it: an unexpected third
registration would fail at the call site.
