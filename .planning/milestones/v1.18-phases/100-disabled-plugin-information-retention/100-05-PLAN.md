<objective>
Give the rerouted disabled info row a byte contract and real coverage. Today the
catalog's info-surface disabled paragraph defers to the list surface for its bytes —
a cross-reference the reroute retires, because the info row now carries description and
component lines the list row does not have. That makes this an ADDITION of a catalog
state, not a relocation of one.

Also close the prose gap the fetch-skip carrier opens: the mixed skip state's paragraph
currently describes its two causes as belonging to different scopes, which is no longer
guaranteed.

Purpose: the new row form cannot regress silently, and the catalog stops describing
behavior the code no longer has.
Output: one catalog state with its paired fixture, three rewritten paragraphs, and the
info-surface coverage for the retained inventory.
</objective>

  <action>
Author the info-surface coverage using the suite's existing helpers and its
whole-message byte-equality style — one `join("\n")` literal per assertion, never a
partial regex, so a single comparison pins the status token, the reason brace, the
description line and every component line together.

Add four cases:

First, the central case: seed a disabled record that is manifest-absent, carries a
populated skills inventory and carries recorded hook entries, then assert the whole
rendered message. The expected literal contains the disabled glyph and token, the
version, the manifest-absence brace, the description line and the component lines
including the hooks block. This is the row the phase exists to produce.

Second, the still-declared control: the same disabled record with a manifest that DOES
declare the plugin. Assert the disabled status token is present and the manifest-absence
brace is absent. This proves the reason is derived from the manifest lookup and not
from disabled-ness.

Third, the zero-network proof: run the manifest-absent disabled case with the fetch
flag through the existing injected clone-cache and credential seams and assert both
call counters are zero. Extend the existing counter suite rather than writing a second
network-guard mechanism — the seam and the assertion style already exist.

Fourth, the skip-note survival case: a fetch over a marketplace whose only found scope
is disabled must still emit the skip note. Assert on the rendered note rather than on
an internal field, so the test would catch a carrier that silently stopped reporting.

Add a row-scoped negative assertion after each positive one where a regression could
otherwise pass quietly — for example that the manifest-absent disabled row carries no
unsupported-kind token and no soft-dependency marker — so a regression names itself
rather than merely failing an equality.
