<objective>
Make the installation record self-sufficient for describing a plugin's hooks. Today
the record holds only the hooks CONTAINER SLUG, so `info` has to read the materialized
configuration back off disk — and a disabled plugin, whose configuration disable
deletes, has nothing left to read. Add a top-level optional `hookEntries` key
following the `resolvedSha` precedent (optional, additive, no schema-version bump, no
migrate fill), populate it at every write site, and make `info` prefer the record with
the existing disk read surviving as the legacy fallback.

Purpose: the record describes the installation rather than pointing into artifacts
that must be inspected. Output: the new key, its three write sites, its read ladder,
and the amended enumeration gate.

Scope exclusion (D-100-09): NO backfill and NO persist-on-read. `list` and `info`
stay lock-free, network-free and mutation-free. Records self-heal on the next
install, update, reinstall or enable.
</objective>
