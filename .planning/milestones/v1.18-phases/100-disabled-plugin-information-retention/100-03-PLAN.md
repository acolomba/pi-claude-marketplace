<objective>
Make the list surface tell a user what constrains them next. A disabled plugin whose
marketplace manifest no longer declares it cannot be re-enabled — enable re-runs the
install ledger, which resolves from that manifest — and today's bare row gives no
warning before the attempt. Add `{not in manifest}` to the disabled row and nothing
else (D-100-07), keep the row otherwise byte-identical under a retained inventory
(D-100-06 / ENBL-15), and retire INV-04 properly rather than leaving four artifacts
asserting the opposite.

The governing rule to record for future authors, a refinement of the existing
durable-versus-transient guidance: render durable facts that constrain what the user
can do next; suppress facts about runtime behavior that is currently suspended.

Purpose: the disabled row stops hiding a fact that blocks the user's next action.
Output: the reasons field, the stamp, a new catalog state with its byte fixture, and
the INV-04 supersession recorded in every place that asserted it.
</objective>
