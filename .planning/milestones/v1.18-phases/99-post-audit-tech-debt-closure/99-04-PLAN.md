<objective>
Thread the malformed-component degradation signal through the update verb so a degraded update
stops rendering a clean row: collect the signal at the success-outcome site, carry it on the
updated outcome, add the optional reasons to the updated message variant, and render it on BOTH
the central and the verb-local surfaces, with the catalog state, byte fixture and style-guide
amendment shipping alongside (WR-12 / D-99-03).

Purpose: update stages through the same skills and commands bridges as install, enable and
reinstall, and those bridges return the same degraded-record list when a source component's
frontmatter will not parse. Nothing in update reads it. The observable defect is a plugin whose
skill has been written to disk in synthesized, non-model-invocable form while the row reporting
the transition says nothing about it — and `list`, one command later, renders the record's real
state. That is the same contradiction class the reinstall verb already closed; this plan copies
that closure verbatim rather than inventing a second shape.

This plan MUST run after plan 99-01. The shared degradation-signal shape declares the two staged
signal names as optional booleans; until 99-01 renamed the updated outcome's identically-named
string arrays, inheriting that shape is a TS2430 incompatible-property error, and the alternative
is a Pick/Omit workaround that becomes permanent because nobody remembers to widen it later.

Output: a truthful `(updated)` row, one composer, and a documented, fixture-pinned degraded state.
</objective>
