<objective>
Land the two remaining Phase-97 review carriers.

WR-02 (D-98-03): a failed enable whose persisted gate is stale gains a remediation affordance
pointing at `update --partial`, riding the existing hint-trailer mechanism rather than a new
emit site.

WR-04 (D-98-04): `update` offers the disabled records it is the only remedy for. D-98-04 left the
direction to plan time; this plan records the choice.

**Decision (D-98-04, direction 2 — make the disabled short-circuit reachable without the flag).**
The alternative was a distinct `disabled` classification consumed by the completion path. Direction 2
wins on D-98-04's own stated tiebreaker — keeping `classifyPluginState`'s existing consumers
byte-stable — because it touches `classifyInstalledRecord` ZERO times: the classification union,
the completion-cache row union, both completion status buckets, the parity drift-guard in
`tests/orchestrators/edge-deps.test.ts`, and five classifier pins all stay untouched by
construction. It also dissolves the discoverability problem rather than patching it: with no flag
required, the record is offered under plain `update`, which already spans the installed-inventory
statuses. The mechanical change is one gate expression in `preflightUpdate`; the record is already
in scope there and the disabled predicate is already imported by that module. The strict-gate
rationale — do not silently materialize a degrade the user did not consent to — does not apply,
because a disabled record stages nothing: the refresh rewrites only version, resolved source,
resolved sha, compatibility, and the updated-at stamp, inside a state guard.

Purpose: D-98-05 requires all four carriers to land before the COMPAT-01 gate is authored.
Output: one optional message field, one widened render gate, one cause-narrowing arm, one gate
expression, the catalog amendments both byte changes require, and the rewrite of the in-tree
suite-header prose direction 2 falsifies.

Tracer: Task 1 is the vertical slice — it wires one enable-failure path from the orchestrator
narrowing through the message contract and the renderer to a byte-pinned catalog fixture. Task 2
expands along the update surface.
</objective>

| persisted installation record -> update candidate gate | a stored boolean widens which resolver verdicts are admissible |
| typed error cause -> rendered failure row | an error object reaches a user-visible surface |
