# Make commit-time checks incremental only

<objective>
Make the pre-commit `check:changed` hook run incremental checks only. Whole-suite verification moves to the larger checkpoints: GSD phase/merge gates, PR handoff, and CI.

Purpose: the full fallback runs `npm run check` (about 23 minutes) on any configuration, tooling, CI, removal, e2e, or unknown input, and on checker scripts that have no `tests/scripts` test. Most of that time is unit coverage, the integration suite, and member analysis. The user's principle: "on pre-commit, we should run incremental checks as much as possible. Only at larger intersections should we start running more globally." This plan replaces the full fallback with a broad set of cached or incremental whole-repository static checks, gives checker scripts a narrow selection, and turns on the ESLint cache. The docs then state where the whole suite runs.

Output:

- Task 1 (tracer): the selector's broad scope, checker rule, cached ESLint, and lock on broad runs; the updated selector control; `npm run lint` with the cache; CI clears the cache; the hook comment. Proven end to end by the real pre-commit hook and by a planted-lock broad run.
- Task 2: AGENTS.md, the local-verification skill, CONTRIBUTING.md, and the type-member doc describe the policy. Then one explicit `npm run check` and one explicit `npm run check:controls` over the final tree for the PR handoff.
</objective>
