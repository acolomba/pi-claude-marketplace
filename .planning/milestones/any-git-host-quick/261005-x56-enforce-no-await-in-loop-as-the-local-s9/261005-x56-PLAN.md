## Reason rules

1. Write one short clause that names the property of THIS loop that makes running in order
   necessary, or harmless when nothing forces it (rule 6). Match the style of the restored 19:
   lowercase start, no trailing period, ASCII only, ideally under 60 characters. Backticks around
   identifiers are fine.
2. Base the reason on the code you read. Cite a decision or requirement ID only when the nearby
   code names that ID for this ordering, as with TR-01 (rename tracking), TR-02 (the failing
   phase's own undo), or D-01-07 (the first existing manifest candidate wins).
3. Give each await line its own directive, and make sure the reason holds for that line. Repeat a
   reason across the lines of one loop only when it holds for each line.
4. A reason that only asserts intent, design, or necessity is a review blocker. The google-style
   skill requires that "the reason holds for that line". The Task 2 verify greps for the common
   forms of such reasons and for reasons under 15 characters.
5. Do not reference planning artifacts or narrate earlier code (skills/typescript-comments). Do not
   write TODO or FIXME, because sonarjs flags both. Do not edit any existing comment.
6. If a loop has no ordering constraint, do not invent one. State the bound that makes running in
   order harmless (for example `at most two scopes, one local state read each`), and add the loop
   to the Promise.all candidate list. Never rewrite a loop in this task.

Vocabulary. These are examples only; check every reason against its own loop:

| What the loop depends on | Example reason |
| --- | --- |
| A per-call lock with `retries: 0` | `each install locks the scope (retries: 0)` (restored) |
| Read-modify-write of one file | `read-modify-write of the local config file` (restored) |
| A later iteration reads an earlier write | `each stamp reads the previous stamp's write` (restored) |
| A shared set, map, cache, or routing table | `first-seen dir wins the shared dedup sets` (restored) |
| Rollback or compensation order | `rollback walks completed renames in reverse` |
| Rename tracking for rollback | `TR-01: one rename at a time so rollback knows which landed` |
| A catch around the loop that cleans up | `the failure catch removes staging; no write in flight` |
| First match, precedence, or early stop | `D-01-07: the first existing manifest candidate wins` |
| A running digest or accumulator | `the hash digests entries in sorted order` |
| Protocol pacing | `RFC 8628: each poll waits the server interval` |
| A resource bound | `bounded memory: one clone read at a time` |
| An await on a path that leaves the loop | `runs once: the failure path returns after it` |
| Ordered side effects inside the callee | `each cascade row notifies in manifest order` |
| No ordering constraint (candidate) | `at most two scopes, one local state read each` |

Promise.all candidate criteria: the iterations share no mutable state, take no lock, write nothing
a later iteration reads, emit no order-dependent side effect, and never stop early. The bound is
small and fixed, such as the two scopes or a fixed candidate list. For each candidate, record the
final file:line, what each iteration does, the bound, and what a parallel form must keep (result
order, which error wins).
