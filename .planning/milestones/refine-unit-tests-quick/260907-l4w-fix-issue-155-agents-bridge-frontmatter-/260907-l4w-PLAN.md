## Locked design decisions (user-approved — non-negotiable)

- Rework `parseFrontmatter` into an indent-aware state machine mirroring
  pi-subagents 0.47.x block-value semantics.
- Accept the FULL block header syntax on the input side: `/^[>|][+-]?\d*$/`. This is
  broader than pi-subagents' four forms because sources are Claude-authored real YAML.
  We never EMIT block scalars, so the D-82-02 round-trip doctrine governs output only.
- Keep AG-6 colon tolerance: the value side of a column-0 `key: value` line is taken
  verbatim after the first colon. No real-YAML strictness, no quote stripping.
- Keep AGSK-01 dash folding exactly (D-82-01/D-82-03), including at column 0 (#86).
  Dash lines under an explicit block header are TEXT, not list items.
- Only column-0 lines can start keys. Indented lines are continuation lines or
  ignored — never lifted into top-level keys.
- NO emitter change. `emitYamlScalar`, `sanitizeProvenanceValue`, `convertAgent` and
  `emitGeneratedAgentFile` stay untouched.
- Keep the lenient key charset (split on the first colon, any key text) so unknown-key
  droppedFields provenance keeps working. Do NOT adopt pi-subagents' `[\w-]+` restriction.
- An empty-value key followed by non-dash indented lines collects a plain multiline
  block value; the first continuation line's shape (dash vs non-dash) decides
  list-fold vs block-collect.

Replace `FoldState` and `applyFrontmatterLine` with this state machine. Module-private,
no new exports (fallow dead-code gates unused exports).

State: `lastKey: string | null` and `lastKeyFoldable: boolean` keep their current
AGSK-01 meaning; add `awaitingKey: string | null`, holding the empty-value key whose
continuation shape is not yet decided; add `pending: { key, folded, lines } | null`,
the block currently being collected.

`applyFrontmatterLine` becomes a dispatcher that reads, in this order: if
`collectBlockLine` consumes the line, return; otherwise `flushPendingBlock` (a no-op
when nothing is pending) and then, on the trimmed line, return on blank, fold on a
dash line, start an implicit block on an indented line, and otherwise apply a key line.
Because the dash test precedes the indented test, a dash beneath a non-empty inline
value is still ignored (D-82-03) and never starts a block.

`collectBlockLine` returns false when nothing is pending; otherwise it pushes the RAW
line (indentation intact) and returns true when the line is blank or indented, and
returns false when the line reaches column 0 with content, which is what terminates a
block. Blank lines are collected for implicit blocks too — a deliberate divergence
from pi-subagents, which terminates an implicit block at the first blank line; the
trailing trim makes the two agree on every non-pathological input and case G pins ours.

`foldDashItem` keeps the current AGSK-01 body verbatim (bare `-` yields an empty item,
items are comma-joined, a `?? ""` read tolerates an absent property) and additionally
clears `awaitingKey`, which is how the first continuation line decides list-fold.

`startImplicitBlock` returns when `awaitingKey` is null; otherwise it opens a pending
block keyed on `awaitingKey` with `folded` false and the raw line as its first line,
then clears `lastKey`, `lastKeyFoldable` and `awaitingKey`. Read the key out of
`awaitingKey` rather than asserting on `lastKey` — non-null assertions and casts are
unavailable in `extensions/`.

`applyKeyLine` splits on the FIRST colon, returns when there is no colon or the key
trims to empty, and then branches three ways on the trimmed value. A value matching
the header regex `/^[>|][+-]?\d*$/` opens a pending block with `folded` set from a
leading `>`, and clears `lastKey`, `lastKeyFoldable` and `awaitingKey`; a quoted value
such as the two-quote-wrapped indicator cannot match this regex, which is exactly why
AG-6's verbatim value keeps working. Any other value is assigned with plain
`raw[key] = value`, sets `lastKey`, and sets both `lastKeyFoldable` and `awaitingKey`
from whether the value is empty. Keep the eager assignment for the empty-value case —
it is what preserves the existing empty-key and intercepted-setter cases.

`flushPendingBlock` returns when nothing is pending; otherwise it strips the common
indent, assigns the folded or literal value with plain `raw[key] = ...`, and clears
`pending`. It must have exactly ONE definition and be called from two sites — the
dispatcher and once after the loop in `parseFrontmatter`. Do not inline a second copy
of the flush body; `fallow dupes` has a threshold of 3.

`stripCommonIndent` takes the collected lines, derives the prefix from the leading
whitespace of the first line with content (falling back to the empty string), and
returns each line with that prefix removed when it starts with it. Use `startsWith` +
`slice`, not a constructed RegExp — that drops pi-subagents' `escapeRegex` helper and
the injection surface with it.

`foldBlock` is the port of the reference helper, taking the stripped lines. Track
`hasContent`, `previousIsMoreIndented` and `blankLines`; a line that is empty after
`trimEnd` increments `blankLines` only once there is content; a content line appends a
separator when there is content already, then the line itself. Detect more-indented
with a single `current !== current.trimStart()` comparison. Return the result trimmed.
Extract the separator into its own tiny helper returning a run of newlines when blank
lines are pending and a single newline or a space otherwise — that split is what keeps
both cognitive-complexity gates satisfied. The literal value is the stripped lines
joined on newlines and trimmed.

`  Second paragraph.`; `    more indented literal`; a blank line;

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin author -> parser | A marketplace plugin's agent markdown is attacker-controllable text fed straight into `parseFrontmatter`. |
| parser -> generated agent file | Parsed values are re-emitted into a file that pi-subagents parses and hands to a child agent as its system prompt. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-155-01 | Tampering | `applyKeyLine` writing into the `raw` object literal | medium | accept | Values are always strings and assignment is always plain `raw[key] = value`, so a `__proto__` key assigns a string to the proto slot, which the engine ignores; `constructor` and `prototype` become ordinary own properties that `convert.ts` reports as dropped fields. The existing intercepted-setter case pins that an inherited accessor still governs the write. Adding `Object.create(null)` or a `Map` would break that pinned behavior and change the `RawAgentFrontmatter` contract for no gain. |
| T-155-02 | Denial of Service | `foldBlock`, `stripCommonIndent` and the header regex over attacker-controlled lines | low | mitigate | Every regex is anchored and non-backtracking (`/^[>\|][+-]?\d*$/`, `/^[ \t]/`), and the indent strip uses `startsWith` plus `slice` instead of a RegExp built from file content — no `escapeRegex` path and no ReDoS surface. Work is linear in the frontmatter length, which is already bounded by the file the caller read. |
| T-155-03 | Tampering | Re-emitting a multi-line parsed value into the generated agent file | medium | mitigate | Unchanged and load-bearing: `emitYamlScalar` collapses every newline to a space (AG-8) and `sanitizeProvenanceValue` does the same for provenance, so a block value carrying a line that looks like a key cannot inject a frontmatter key into what pi-subagents reads. This plan makes multi-line values REACHABLE for the first time, which is exactly why the emitter must stay untouched and why its existing newline cases must keep passing. |
| T-155-04 | Information Disclosure | Block continuation lines becoming top-level keys | medium | mitigate | The column-0-keys-only rule removes the phantom-key lift, so plugin prose can no longer surface as fabricated `droppedFields` provenance in the generated file. Case G asserts the whole `raw` object, so a leak fails the gate. |

No package-manager installs occur in this plan, so no package-legitimacy checkpoint applies.
