<objective>
Issue #143: on Windows, materializing any Claude plugin command fails with
EINVAL. `generatedCommandName` joins its segments with `:`, the bridge writes
`<generatedName>.md` into `resources/prompts/`, and `:` is not a legal NTFS
filename character. Every plugin carrying a `commands/` directory is therefore
uninstallable on Windows.

Purpose: make the namespace separator platform-dependent so Windows gets a
legal basename, while POSIX keeps the `:` surface users and Claude Code already
share.

Output: a new `platform/os.ts` leaf exposing `commandNamespaceSeparator()`, the
`domain/name.ts` join site reading it, the two comment blocks that hardcode the
colon rewritten to state the real contract, direct-owner tests for both touched
pairs, and a CHANGELOG entry.
</objective>
