# Quick Task 260807-ur3: Bring the disabled-partial classification repair into v1.18

joins milestone v1.18 rather than being tracked separately. This reverses the

## Framing

The defect is not a new concern. v1.12 shipped **ENBL-04**: "Disabled status
renders distinct from soft-degraded `unavailable` on list/info surfaces
(declared / enabled / available are orthogonal facts)." The buggy conjunct
`compatibility.installable && !enabled` couples enabled-ness to available-ness,
which is precisely the orthogonality ENBL-04 asserts. A disabled
partially-installed record therefore violates a requirement already marked
complete. The new requirements continue that family at ENBL-05 rather than
opening a new prefix.

## Phase placement

`.planning/phases/` is empty — no phase has been planned or executed — so
renumbering is free.

The repair becomes **Phase 97**, and the documentation phase moves from 97 to
**Phase 98**. Documentation must stay last so DOC-08 describes the repaired
behavior rather than the defective one.

The repair does not invalidate Phase 95. INV-04 expects `(disabled)` for the
canonical shape, and that outcome is unchanged by the fix; the partial shape is
simply left uncovered until Phase 97. Phase 95 must not pin the current
partial-disabled rendering as correct — the existing INV-04 narrowing already
prevents that, and Phase 97 widens the coverage.
