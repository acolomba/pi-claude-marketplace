# Quick Task 260909-h38 -- Summary

Made three cross-process concurrency tests deterministic. They passed locally and lost a
real filesystem race on loaded GitHub runners, worst under `--experimental-test-coverage`
in the SonarCloud workflow.

## What was actually wrong

Two different defects, not one.

**uninstall WR-06 and the reinstall removal proof (unsynchronised race).** Both armed an
`fs.watch` monitor on the extension root, waited for a `state.json.<hash>` file --
`write-file-atomic`'s temp name, an implementation detail -- and then swapped state.json,
hoping the swap landed before the orchestrator's next read. Nothing ordered those two
events. The IPC handshake covered monitor readiness only; there was no barrier between
"replaced" and the read it was supposed to precede. The reinstall variant raced harder
still: it stole the temp file *mid-rename* to force the IL-3 migration-save `console.warn`,
which is a race against `write-file-atomic`'s own internals. The CI failure was that
assertion -- `warningMock.mock.callCount()`, `0 !== 1` -- with the monitor reporting a
clean `["ready", "replaced"]` and exit 0.

**RECON-06 (an invariant production does not offer).** Its CI failure was different in
kind: `ENOENT` on state.json after the race, meaning NEITHER child wrote anything. That is
legal. `applyReconcile`'s apply pass deliberately holds no outer lock (CR-01); the read
pass, marketplace add, plugin install, backfill, and routing rebuild each take the
per-scope lock separately with `retries: 0` and soft-fail into a structured row on a loss.
Marketplace source materialization is not atomic across processes either -- instrumenting
the race locally shows the losing child routinely reporting `⊘ mp-a (failed) {unparseable}`,
a torn read of a half-copied manifest rather than a lock loss. A round where both racers
fail every mutating step therefore writes no state.json, and "at least one racer converged"
was never a guarantee.

## What changed

**`tests/orchestrators/plugin/state-fifo.ts` (new).** Serves state.json over a POSIX FIFO
from a second process. `readFile` blocks in `open(O_RDONLY)` until a writer opens and
returns only at EOF, and each open pairs exactly one reader with one writer -- so payload 0
goes to the unlocked resolution read and payload 1 to the locked re-read, in that order,
whatever the scheduler does. No polling, no sleeping, no retrying, and no dependence on
`write-file-atomic`'s temp naming. Two invariants keep a mis-serve loud: the server exits 0
only after serving every payload (so the `served:N` count IS the orchestrator's read
count), and the state path must still be a FIFO afterwards (a write would rename a regular
file over it), which doubles as the no-mutation proof.

**uninstall WR-06 and the reinstall proof** now run on that barrier. Every assertion that
mattered is intact: the `{ status: "converged", name: "hello" }` outcome, zero cascade
calls, zero notifications, and reinstall's byte-exact
`⊘ mp (failed) {marketplace not added}`. Dropped: reinstall's `console.warn` count, which
only ever held because of the temp-file theft. That IL-3 warning is covered directly and
deterministically by `tests/persistence/migrate.test.ts`.

**RECON-06** now asserts what the design guarantees and no more. Of the race: both children
exit 0, any non-ok child carries the `StateLockHeldError` marker, no orphaned staging, and
whatever state.json the race did write is singular. Then an uncontended follow-up reconcile
-- NFR-2's "a /reload converges" contract -- must converge on exactly one marketplace record
and one plugin record. That pass is what keeps the record assertions non-vacuous no matter
who won the race, or whether anybody did. Both children's reported output is carried into
the failure messages so a recurrence is diagnosable from the CI log alone. The near-vacuous
`successes.length >= 1` check is gone: a child reports `ok: true` whenever `applyReconcile`
does not throw, including when every step soft-failed.

## Verification

- `npm run check` green: typecheck, lint, fallow (dead-code + health + dupes), format:check,
  corresponding-tests, unit tests, integration tests.
- FIFO read counts measured against the real orchestrators before the rewrite: exactly two
  project state.json reads in each flow, with outcomes byte-identical to what the tests
  already asserted.
- Zero-winner convergence proved directly: from the end state a both-racers-failed round
  leaves (pristine scope, no state.json), one uncontended reconcile converges on one
  marketplace record and one plugin record.
- Stress: the three tests run repeatedly under `--experimental-test-coverage`, pinned to two
  CPUs, against six busy spinners on those same CPUs -- the loaded-runner conditions the old
  shapes lost on.

## Not fixed, worth knowing

Concurrent marketplace source materialization can serve a half-written manifest to a
competing process, which surfaces as a `{unparseable}` row. It soft-fails cleanly, corrupts
nothing, and self-heals on the next reconcile, so it is left alone here -- but it is the
reason a contended reconcile can end with nothing written.
