<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry -> CI runner | `npx --yes fallow` downloads and executes a third-party platform binary inside the CI job |
| PR head branch -> CI runner | Untrusted contributor code is checked out with `fetch-depth: 0` and analyzed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-h7g-01 | Tampering | `npx --yes fallow` in `lint.yml` and in the npm scripts | medium | accept | The invocation is unpinned by explicit decision (L-2: `npx --yes fallow`, no package.json entry). Residual risk accepted: a new fallow major could execute unreviewed code on a CI runner. The binary is signature-verified by the npx wrapper (`fallow 3.16.0 signed`, observed), the job holds only `contents: read` inherited from the workflow-level `permissions` block, and no secret is exposed to it. Revisit by pinning a major (`fallow@3`) if the gate ever misbehaves after an upstream release. |
| T-h7g-02 | Elevation of Privilege | `fallow` job on `pull_request` | low | mitigate | Keep the job in `lint.yml`, whose `pull_request` trigger checks out the merge ref, not `pull_request_target`. Do not add write permissions or a token to the job; use `--format human` rather than a PR-comment format that would require one. |
| T-h7g-03 | Denial of Service | `fetch-depth: 0` full-history checkout | low | accept | Full history is required for merge-base attribution. The repository is small and the existing `pre-commit` job already checks out with LFS. |
| T-h7g-04 | Tampering | file deletion in Task 2 | medium | mitigate | Every deletion is gated on a fresh exact-path grep for importers, and `npm run check` in Task 3 is the blocking gate that catches a wrong deletion before the commit lands. Four spike-listed candidates are explicitly retained because they still have importers. |

No package-manager install adds a dependency in this plan: `npm install` only
removes three devDependencies. The `fallow` binary is fetched by `npx`, not
recorded in `package.json` (L-2).
</threat_model>
