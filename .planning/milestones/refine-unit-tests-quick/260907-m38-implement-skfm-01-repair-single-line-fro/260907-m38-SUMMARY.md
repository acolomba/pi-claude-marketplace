# Quick Task 260907-m38: Single-Line Frontmatter Scalar Repair Summary

A SKILL.md whose frontmatter fails Pi's strict YAML parse only because a
single-line plain scalar carries an unquoted colon now has that one line
re-emitted as a safe double-quoted scalar, so the skill installs with the
author's real description instead of losing the whole block to the
unparseable-source placeholder.

## What Changed

One commit, `66be4e43`, carrying all four planned files. The plan's three tasks
were executed in order; only Task 3 lands a commit, per the plan.

### Task 1 — The repair and its wiring (tracer, TDD)

The stage-level case was written first and watched fail. It failed on the
placeholder text exactly as predicted: `degraded[]` carried an
`acme-helper` row reading `Nested mappings are not allowed in compact
mappings`, and the staged bytes carried
`description: Source frontmatter could not be parsed.`

`repairSingleLineScalars(content: string): string` was then added to
`frontmatter-degrade.ts`. It is pure, string-in / string-out, and repairs a
line only when every condition of the locked class holds: the line sits inside
the frontmatter block, starts at column 0 with a whitespace-, colon- and
`#`-free key followed by a colon and a space or tab, spans exactly one line by
`keyValueEnd`, and carries a non-empty value that contains a colon and does not
open a quote, a flow collection or a block scalar. Eligibility is decided per
line, so an excluded sibling never vetoes a repairable one. The value goes out
through the existing private `emitSafeDoubleQuotedScalar`, so there is no second
copy of the escaping.

In `stage.ts`, a module-private `repairUnparseableFrontmatter` sits beside
`extractBodyAfterFrontmatter`. It computes the repair, returns `undefined` when
nothing changed, otherwise re-parses and returns `{ repaired, parsed }` —
returning `undefined` when that retry throws. The PARSE-01 catch arm calls it
first. A defined result assigns `content` and `parsed`, which is what routes the
repaired bytes down the existing `parsed !== undefined` happy arm; nothing is
pushed to `degraded`. An `undefined` result runs the previous degrade body
unchanged, recording `errorMessage(parseErr)` — the original source error.

The generated-`name` rewrite and the SKILL-02 / WTU-01 / WTU-02 augment both
apply to repaired content, because the happy arm is reached in full.

### Task 2 — The excluded classes and the fallback arms

Eighteen direct owner cases were added to
`tests/bridges/skills/frontmatter-degrade.test.ts` in the file's existing
table-driven style: fourteen byte-for-byte-unchanged rows (no opening fence, no
closing fence, empty input, double-quoted, single-quoted, flow sequence, flow
mapping, folded block scalar, literal block scalar, multi-line plain scalar,
colon-free value, comment line, indented line, empty value) and four repair rows
(the plain repair, a value carrying both a backslash and a quote, a mixed
document where a sibling flow sequence stays byte-identical, and a CRLF line
whose trailing carriage return is dropped).

Two stage-level cases were added:

- **repair-then-still-unparseable.** Frontmatter carrying both a repairable
  colon line and an unterminated flow sequence still degrades, and the recorded
  `parseError` is the source error. The two errors are genuinely different
  strings — each quotes its own excerpt, so the source error shows
  `description: Use this: when reviewing` while the retry's shows the same line
  already quoted. That difference is what lets the case discriminate.
- **augment on repaired content.** A repaired source carrying `when_to_use`
  folds it into the staged description, proving the repaired bytes reach the
  full happy arm rather than a truncated version of it.

Two honest readings came out of this:

- **The block-scalar rows are discriminated by the single-line guard, not by

  turned RED under plant 3. A block scalar is excluded twice over — its header
  line carries no colon, and it spans continuation lines — so the `|` and `>`
  alternatives inside `UNREPAIRABLE_VALUE` are belt-and-braces. They are
  required by the locked repair class, they cost no coverage shortfall (the
  guard's true and false arms are both taken by the quoted and flow rows), and
  they were kept.
- **Plant 4 was ineffective on its first attempt and had to be redone.** It was
  first inserted after `content` had already been reassigned to the synthesized
  block, so it re-parsed valid bytes, threw nothing, and left the source error
  in place — GREEN for the wrong reason. Re-planted before the reassignment, it
  turned exactly the intended case RED. A plant that stays green is a claim
  about the plant until the plant itself is verified.

## Threat Mitigations

shipped code.

- **T-m38-01 (tampering, re-emit).** The repaired value goes out through

  escaped before a quote and an author value cannot close the scalar and re-form

  pins the emitted bytes.

  the staged bytes unconditionally. The repair adds no bypass — it sits entirely
  inside the PARSE-01 catch arm, above the backstop.

trust boundary was introduced, so no threat flag is raised.
