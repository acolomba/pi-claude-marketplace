<interfaces>
Harness surface to port (features/mcp `tests/e2e/_rpc.ts`):

```ts
export type RpcStep =
  | { readonly id: string; readonly type: "get_commands" }
  | { readonly id: string; readonly type: "prompt"; readonly message: string };
export interface RpcSandbox { readonly home: string; readonly agentDir: string; readonly cwd: string; }
export interface RpcSessionOptions { sandbox; steps; extraExtensions?; hardStopMs?; signal?: AbortSignal; }
export interface RpcNotify { readonly after: string; readonly message: string; readonly notifyType: string | undefined; }
export interface RpcSessionResult { exitCode; timedOut; stderr; responses; notifies; dialogs; extensionErrors; }
export function runRpcSession(options: RpcSessionOptions): Promise<RpcSessionResult>;
```

Child process: `node <cliPath> --mode rpc --offline --no-session --extension <repo extension> [--extension <fixture>...]`.
`cwd` is the sandbox cwd, `detached: true`, and the env is exactly `{ HOME, PI_CODING_AGENT_DIR, PI_OFFLINE: "1", PATH }`.
Never pass `--no-extensions`, because it removes `builtin:mcp`. The hard stop and the abort signal
SIGKILL the whole process group.

Fixture extension (plain JavaScript written into the sandbox root):

```js
export default function (pi) {
  pi.registerCommand("mcp-adapter", { description: "Fixture mcp-adapter command.", handler: async () => {} });
}
```

Built-in state setup: `<agentDir>/mcp.json` with `mcpServers.stub` running a stdio stub that
answers `initialize`, `tools/list` (one tool `echo`) and `tools/call`. Pi then registers tool
`mcp__stub__echo` asynchronously after `session_start`; an inventory-probe fixture command polls
`pi.getAllTools()` (at most 8 s) until an `mcp__` tool appears, then notifies
`JSON.stringify({ tools, commands })`. "Neither" setup: `<agentDir>/settings.json`
`{"extensions":["-builtin:mcp"]}`. Measured cost: about 9 s per state.
