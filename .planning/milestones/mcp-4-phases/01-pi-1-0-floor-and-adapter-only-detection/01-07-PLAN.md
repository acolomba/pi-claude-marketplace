<objective>
Give `/claude:plugin info` a `requires:` line that names the companions a plugin needs and flags
the missing ones.

Purpose: ADET-01 says install, list and info report the MCP component as needing pi-mcp-adapter.
Today no info row carries any companion state (observed live). D-01-18 decides what info gains:
a `requires:` line, not a brace marker. The planner decisions D-01-18 leaves open are settled
here:
- Placement: after the per-kind component lines, before `dependencies:`.
- Order: companion package name, ascending (matches the D-01-18 example and info's alphabetical
  convention).
- Unresolved rows: no line (the field exists only on the resolved arm).
- Disabled rows: the line still shows, because a disabled record keeps its component inventory
  (ENBL-18). Unlike the ENBL-16 brace, the line states what the plugin needs, not that the
  runtime is degraded.
- Severity: unchanged.

The orchestrator determines state and stamps it; the renderer only formats (operator rule:
notify is a dumb renderer).

Before Task 1, record the starting commit (`git rev-parse HEAD`) as `<base>` for the pin check.

Output: the type, the helper, the stamp, the renderer line, the catalog amendment and one commit.
</objective>
