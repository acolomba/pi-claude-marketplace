<objective>
Tell the user when a rewrite removes their JSONC comments, and when an unreadable `mcp-adapter.json` was left alone, starting with `install`; make a failed install restore the file's exact bytes.

Purpose: AFILE-04 ("warned once"). D-02-09 makes the bridge return a structured notice and the orchestrators route it, because MCP bridge `warnings` are a hygiene channel that standalone verbs drop (RESEARCH Pitfall 4). D-02-11 restores bytes on a failed install instead of unstaging from the rewritten file (Pitfall 6). D-02-14 turns plan 02-01's noop warning into a user-visible notice. This plan builds the seam, the catalog contract and the bridge producer, and routes `install` (standalone, dependency cascade, promotion, orchestrated, reload missing-dependency). Plans 02-05 to 02-08 route the other verbs through the same seam.

Output: `McpConfigNotice` and `notifyMcpConfigNotices`, two catalog states and their byte lock, the stage producer, the install ledger's replacement handle, the install routing, and one commit.
</objective>

  export interface McpConfigNotice {
    readonly kind: "comments-dropped" | "left-unchanged";
    readonly scope: Scope;
    readonly file: "mcp-adapter.json" | "mcp.json";
  }
  export function notifyMcpConfigNotices(ctx: NotificationContext, notices: readonly McpConfigNotice[]): void
Exact bytes:
  comments-dropped: summary `MCP config comments removed.`; one line per notice
    `The ${scope}-scope ${file} was rewritten to update plugin MCP servers; its JSONC comments were removed and everything else in it was kept.`
  left-unchanged: summary `MCP config left unchanged.`; one line per notice
    `The ${scope}-scope ${file} is not a valid MCP config, so it was left unchanged. Fix it before you install or update a plugin that has MCP servers.`
  each kind: ctx.ui.notify(`${summary}\n\n${lines.join("\n")}`, "warning")
