<objective>
Finish the move on every staging path, so no plugin keeps a second copy of its servers in `mcp.json` after it is installed, enabled, reinstalled or updated.

Purpose: D-05-08 (extended) and D-05-10. After plan 05-01 the reload step moves a plain plugin, but install, enable, reinstall and update write only `mcp-adapter.json`; a plugin installed by reconcile from `claude-plugins.json` while its old entry is still in `mcp.json` (AMIG-04), or reinstalled after the D-05-02 remedy, would run twice. This plan puts the sweep in the MCP bridge: `replacePreparedMcp` removes the plugin's marked legacy entries after writing the adapter files and restores all of them, legacy first, on rollback; update calls the legacy removal itself because it has no rollback. The same prepare now drops the old-name leftovers the adapter wrote (D-05-10), and skips an adapter rewrite that would not change bytes (D-05-16), which the reload step also uses.

Output: the leftover helpers, the bridge sweep with ordered rollback, the three caller edits, the `leftover-removed` notice and its catalog block, paired unit tests at 100% direct coverage, an end-to-end install case, one commit.
</objective>
