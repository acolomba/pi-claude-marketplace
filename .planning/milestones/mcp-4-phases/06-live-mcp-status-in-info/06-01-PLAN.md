<objective>
Show, on `/claude:plugin info`, the state pi-mcp-adapter last reported for each MCP server a plugin wrote, and say `status unknown` when the extension does not know (ASTAT-01, ASTAT-02).

Purpose: this is the phase's tracer and its main slice. One factory-owned tracker subscribes to the adapter's `pi-mcp-adapter/status/v1` channel through `pi.events` (never importing the adapter), travels through `EdgeDeps` to the info handler and `getPluginInfo`, and a post-pass stamps each written server with a closed token that the renderer prints first inside the server's parentheses. It implements D-06-01 (Claude Code's words, `failed` kept apart), D-06-02 (comma form), D-06-03 (placement), D-06-04 and D-06-05 (no extra detail, no remedy), D-06-06 and D-06-06a (`status unknown` / `not loaded`, deferred-session prose), D-06-07 (unknown beside `(missing)`), D-06-08 (which rows and servers) and D-06-10 (severity unchanged). The shadow token of D-06-09 is plan 06-02; the conformance run against the real adapter is plan 06-03.

Why one plan this large: the required `mcpStatus` dependency must compile at every caller, every new token must land with its catalog state and closed-set lock, and every staged source must reach 100% direct coverage, all in the one commit the hook checks. No smaller commit passes those gates.

Output: `platform/mcp-status.ts`, `orchestrators/plugin/info-mcp-status.ts`, the factory-to-info wiring, the nine-token union and its rendering, the catalog amendment with three new states, the owner tests, and one commit.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Pi's shared event bus -> status tracker | Any extension loaded in the same Pi process can publish on `pi-mcp-adapter/status/v1`; the payload is untrusted input |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Spoofing | `createMcpStatusTracker` | medium | accept | Pi's bus carries no sender identity, so a forged snapshot can make info show a wrong state. | T-06-02 | Tampering | `withMcpServerStatus`, `mcpEntryText` | high | mitigate | No payload string is rendered: names are used only as map keys, statuses only to compare against the seven known values, and info prints only `McpServerStatus` tokens chosen by `withMcpServerStatus`.
