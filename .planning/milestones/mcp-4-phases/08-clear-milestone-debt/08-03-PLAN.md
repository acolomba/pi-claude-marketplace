Store shape (decided here within D-08-02; the member name and location are the operator's):
the top level of `mcp-adapter.json` gains, only when a choice is stored,
`"_piClaudeMarketplace": { "serverChoices": { "<generated key>": { "plugin": "<plugin name>", "fields": { "disabled": true, "openUi": true } } } }`.
The member name is `CLAUDE_MARKETPLACE_MARKER_KEY` from marker.ts, used at the top level.
`plugin` records the owning plugin name, the identity Claude Code's `plugin:<plugin>:<server>`
key carries, so a different plugin whose server normalizes to the same generated key never
inherits the choice. `fields` holds only carried fields, in carried-set order.

Today's entry composer (adapter-doc.ts):
- `withPluginServers(config, pluginName, marketplaceName, entries): RawMcpDoc` keeps foreign
  entries, writes back a leaving owned entry's kept override through `survivingEntry` (which uses
  `restorableOverride` and `restoredOverride`), appends `entries` under the selected key, and keeps
  every top-level key's position. It is called by stage.ts (adapter file), unstage.ts (adapter and
  legacy targets) and legacy.ts `removeLegacyMcpEntries` (legacy file).
- `partitionServers` returns `ours` (owned, selected key first), `overlays` (marker-less stubs under
  the selected key), `theirs`, `keptOverrides`.

stage.ts `prepareStageMcpServers` passes `previous: { ...ours, ...overlays }` and
`keptOverrides: { ...keptOverrides, ...overlays }` to `stampServers`; overlays and owned entries
never share a name under the selected key. `stampServers` copies each carried field the previous
value holds as an own property (`carriedFields`, adapter-entry.ts), skipping the plugin-set ones.

adapter-entry.ts `CARRIED_FIELDS` today: disabled, approveTools, includeTools, excludeTools,
lifecycle, idleTimeout, requestTimeoutMs, debug, searchKeywords. pi-mcp-adapter 5.2.0
`ServerEntry` declares `openUi?: boolean` and `trace?: boolean` (types.ts:497 and :501).

## Flagged assumptions

- The `{ plugin, fields }` value shape is the planner's refinement inside the operator's storage
  ruling (member, location and key are fixed by D-08-02). It keeps a colliding key from carrying
  one plugin's `approveTools` to another plugin, matching Claude Code's `plugin:<plugin>:<server>`
  identity. Rated `costly`, not `one-way`: a later version can read this shape and migrate it.
- A capture replaces an orphaned store entry of another plugin under the same key; both plugins
  cannot hold the key at once (ANAME-03 refuses the second install).
- Choices that earlier builds already dropped cannot be recovered (08-RESEARCH.md Runtime State
  Inventory).
