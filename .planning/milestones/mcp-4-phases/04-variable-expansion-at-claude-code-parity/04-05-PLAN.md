<objective>
Give pi-mcp-adapter what the written entries need from Pi's process, and retire the explicit project-dir injection that the process value makes redundant.

Purpose: AVAR-01 and AVAR-03 runtime half. The split tokens plan 04-01 writes expand to nothing only when `PI_CLAUDE_MARKETPLACE_EMPTY` is set: in a `url`, pi-mcp-adapter refuses a server whose variables are unset (D-04-05). Claude expands `${CLAUDE_PROJECT_DIR}` for every scope, so a user-scope entry keeps the reference and Pi's process supplies the current project (D-04-09), unless the directory name holds an adapter marker (D-04-16). With the process value in place, the explicit `CLAUDE_PROJECT_DIR` injection into project-scope stdio env (MENV-03) is dropped, matching Claude's injected set (D-04-01, D-04-19). The two halves are one concern: where `CLAUDE_PROJECT_DIR` and the reserved variable come from at connect time. The peer range `>=5.1.0 <6` (D-04-17) is plan 04-06.

Output: `applyMcpAdapterEnv` and its two set points, the injected-set change at the bridge, its ripple through the suites that pin entry bytes, one commit.
</objective>

## Flagged assumptions

- Research A3/A4: an extension cannot order its load before pi-mcp-adapter, and Pi keeps one working directory per process, so the factory's `process.cwd()` equals the first `ctx.cwd`. If the adapter loads first and a user override made a user-scope server `eager`, a `url` split token can fail once before this factory runs; the adapter's own `session_start` re-initializes after it (A6). Documented by plan 04-09 (T-04-15).
- A cwd that is skipped (D-04-16) leaves any inherited `CLAUDE_PROJECT_DIR` in place; such a value comes from the user's own environment.

## Trust Boundaries

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-14 | Denial of service | reserved variable unset when the adapter resolves a split-token url | medium | mitigate | Set first in the factory and again in `session_start` (D-04-05, D-04-19); index and session-env cases assert both set points. |
| T-04-15 | Denial of service | adapter loads first and connects an eager user-scope server before the factory runs | low | accept | No extension API orders loading; the adapter's own `session_start` re-initializes after the factory; documented by plan 04-09. |
