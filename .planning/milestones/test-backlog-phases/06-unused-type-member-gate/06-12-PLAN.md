<repair_taxonomy>
Read this before the first task. Every row below resolves to exactly one of five repairs, and the choice is the verdict. Record the chosen repair and its evidence per row in the SUMMARY.

**R1 -- collapse duplicate declarations.** The same shape is spelled at N sites; a reader credits only the site it was written against, so the other N-1 read as unread. Name the shape once and reference it everywhere. Deletes nothing, changes no runtime value, and the existing reader credits the single surviving declaration. This is the repair 06-06 called behaviour-free and well understood, and it is the default whenever a second spelling of one shape exists.

**R2 -- annotate the local with the consumer's type.** An accumulator or patch literal re-declares a shape its consumer already owns, so the build site declares members and the consumer reads through its own declaration. Annotate the local with the consumer's type. The local then declares no member at all. Pure annotation change.

**R3 -- remove a provably dead field.** Adopt only when three things hold together: the analyzer records no witness of any kind in production or in tests; a direct read of the source confirms no consumer reads it, including every phase-ledger `undo` arm and every rollback composer that could populate it; and every consumer that would want the value already holds it by another route. State all three in the SUMMARY per removed field. If any one fails, this is not R3.

**R4 -- restate an absence marker so the refinement proof reaches it.** A slot written `never`, or pinned to a literal, to make the compiler refuse a shape is real compile-time work no run-time syntax can read. The engine refuses it only when the marker *adds* a key the rest of the intersection does not declare. Stop omitting the slot and then re-adding it: keep the slot on the left operand and narrow it there, or select the single arm that declares it, so the marker becomes a narrowing of a slot the rest already declares. Then draft a `type-refinement` entry and let the engine accept or refuse it. Never write an entry the engine refused.

**R5 -- leave it recorded.** The member is a genuine compile-time proof with no readable and no provable form. Record the exact refusal reason and the owner decision in the row note. This is a legitimate ending, not a failure. 06-08 stays blocked on it, and that is the honest state.

**The verdict question for every row.** 06-04 narrowed nested provenance to trace from the operand only: members the walk reached below an operand are credited on the operand's own declaration, and the supplying places are left untraced. That narrowing under-credits and never over-credits, so a return-annotation slot no caller reads is exactly the shape that can produce a false `unread`. Before choosing R3, run `codegraph explore "<declaration or symbol>"` and read the real call paths -- including dynamic-dispatch hops a grep cannot follow. A slot that is read through a *different* declaration is an R1 or R2 case, never an R3 case.

**What is forbidden.** Do not delete a member that a consumer reads through another declaration. Do not widen an existing contract proof to absorb a refusal. Do not add a contract entry the engine did not accept against this tree. Do not add a test whose only purpose is to make a declaration look used (D-02). Do not change a runtime value, a notification byte or a persisted field.
</repair_taxonomy>
