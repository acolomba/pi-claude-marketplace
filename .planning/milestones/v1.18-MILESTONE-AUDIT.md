while its five siblings each did. **That finding was right and its premise was wrong.**

as an inactive hook and advanced the phase without dispatching `secure-phase`. Any
future phase would be skipped the same way until the resolution is read from

threats whose claim is about ordering or bypass (T-100-01, -03, -12, -13), and the two

## Phase 100 human UAT — 3/3, closed 2026-08-12

Phase 100's verification held at `human_needed` with three items no automated suite
could establish. All three closed against a live Pi 0.84.1 host on this worktree build,
driven from a disposable fixture (`tmp/uat-100/`, git-ignored):

1. **End-to-end retention.** After install → disable → manifest-entry drop → `/reload`,
   `info` rendered `(disabled) {not in manifest}` with the full five-kind inventory. The
   `hooks: UserPromptSubmit` line came from the record's `hookEntries` while the
   plugin's `hooks.json` sat untouched on disk, and a second probe prompt did not fire
   the hook — ENBL-12 and ENBL-14 observed rather than inferred.
2. **Concurrency backstop.** Exercised harder than the checkpoint asked: reads issued
   from Pi while an in-process driver held the per-scope state lock across 24
   install/uninstall cycles (1.3-2.8s write windows). No torn record, no truncated
   field, no lock error on a read path. This is a sampling argument, not a proof of the
   absence of a race, but it moves the `verification: backstop` claim from inference to
   observation.
3. **Judgment-tier prohibition.** `(disabled)` held its slot at the head of every
   rerouted row, with description and component lines below it, against a live control
   row and a still-declared disabled sibling for contrast.

**One wording correction, recorded as an observation rather than a gap.** The checkpoint
prose said the disabled row retains "the description and component inventory". The
inventory is retained; the description is not, and that is the documented contract —
`info.ts`'s record-backed arm treats description and dependencies as manifest-only
metadata it deliberately does not reconstruct (INFO-09/10/11, D-96-01), and
REQUIREMENTS.md's own out-of-scope table says the same. The prose overstated the claim;
the behavior is correct. No code change is implied.

## Integration — 5/5 seams wired (0 blockers)

Re-checked against the current worktree with file:line evidence, not from planning prose.

1. **Record shape → consumers.** `hookEntries` is declared at `state-io.ts:112`
   (`PERSISTED_HOOK_ENTRY_SCHEMA`), written at `install.ts:1100,1188` and
   `reinstall.ts:1240-1732,2054`, read at `info.ts:1126-1128`, and deliberately left
   untouched by `update.ts:1522,1868` (the documented ENBL-18 skew). `toDisabledRecord<R>`
   remains the sole producer (`state-io.ts:148,168`), consumed by
   `enable-disable.ts:58,379`. **WIRED.**
2. **Single membership rule.** `lookupDeclaredPlugin` has exactly three call sites —
   `list.ts:905`, `info.ts:824`, `update.ts:1035` — with no re-implementation anywhere
   in the tree. The `unverified` arm sits outside its return type
   (`manifest-lookup.ts:20-32`), so a failed read cannot be returned as `absent`: BOUND-03
   holds structurally, not by convention. **WIRED.**
3. **Phase 97's predicate against Phase 100's retention.** This was the milestone's
   sharpest cross-phase risk — Phase 100 made disabled records carry populated
   `resources.*` arrays, which would break any reader still inferring "disabled" from
   emptiness. `isRecordedButDisabled` (`state-io.ts:200-203`) keys only on `enabled`, and
   a tree-wide grep for the emptiness anti-pattern outside `event-router.ts` returns
   nothing. The reload hydrate guard (`event-router.ts:607`) consults the predicate
   before touching `resources.hooks`. **WIRED, no drift.**
4. **Reason closed sets.** `list.ts:348` (`disabledReasonsField`) and `info.ts:946`
   (`DISABLED_ROW_REASONS`) are reconciled: `applyDisabledRowShape` (`info.ts:991-997`)
   filters through the closed set in the shared block builder rather than in a duplicated
   per-surface switch, so the two surfaces cannot diverge for any input `list` can
   express. **WIRED.**
5. **Network-free `info --fetch`.** `info.ts:865-867` nulls the fetch context itself for
   a disabled record (`blockFetchCtx = isRecordedButDisabled(installed) ? undefined :
   fetchCtx`), so no clone or credential seam is reachable on that path — stronger than
   skipping after invocation. **WIRED.**
