Notes on the reference:
- The edit uses the plugins step, not `a config ... with this text:`. The text step writes its doc string raw, with no `{home}` expansion, and the user-scope config must name the marketplace by its absolute sandbox path (RESEARCH Pitfall 1, P8-DC-04). - Each load reports its payloads twice (RESEARCH Pitfall 2), so each results table states both rows.
- `the user has started a new pi session` requires info-only payloads, so it runs only before the user's edit or the broken config is in place (RESEARCH Pitfall 3).
- The causes: `Unexpected end of JSON input` is identical on Node 22 and 26, and `test/persistence/config-io.test.ts` pins it on CI's Node 24 (P8-DC-06). `/plugins: must be object` has one segment, which `shared/redact-absolute-paths.ts` leaves intact. A pointer with more segments is cut to its last ones (P8-DC-05). Never pin such a pointer.
- `pending` prints the block that the load prints, because both build it with `pending.ts::composePendingReport` (RECON-05). So the load's report stands for `pending`'s too (D-BG-807).
