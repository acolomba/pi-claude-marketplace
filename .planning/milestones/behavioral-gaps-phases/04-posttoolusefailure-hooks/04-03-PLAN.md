The `@builtin-only` twin, proposed title "A failed plugin MCP tool call through Pi's built-in MCP runs the PostToolUseFailure hooks its matchers select (MHK-01)", has the same steps and the same rows, with the `error` cell `echo:ping`.

The failing wrapper (04-RESEARCH.md Pattern 3 holds the probe-validated text) is a `.mjs` file at the plugin root, for example `failing-stub-server.mjs`. It takes the stub's path, the plugin, and the server as its arguments and runs `process.execPath` on the stub as a child, with stdin and stdout piped and stderr inherited. It forwards each stdin line to the child and remembers the id of each `tools/call` request. It forwards each child stdout line, and on the response to a remembered id it sets `result.isError = true`. A line that is not JSON passes unchanged. When its stdin closes, it ends the child's stdin. It exits with the child's exit code, and with 1 on a spawn error. The plugin's `.mcp.json` names the one server `stub-server`, launched with `command: process.execPath` and `args: [<absolute wrapper path>, MCP_STUB_SERVER, plugin, server]`. The absolute path is `path.join(published.root, "plugins", plugin, <file>)`. A dir source installs in place, so that path stays valid.
