<objective>
Finish convergence inside `apply` and retire the backfill (APL-02, D-08, D-10, D-13, D-25). A
growth-only move (a strictly grown supported set at the recorded revision) now runs through
the same runner entry with `skipSameRevision` off for that move, and `apply` reports it with
the backfill row composers it reported before (D-08). The load-time backfill module, its
extension-version gate and `EXTENSION_VERSION` itself are deleted; the stamp stays readable
in state.json (D-13). A scenario proves that `apply` makes a partially installed plugin whole.

Purpose: D-25 defines APL-01's "reinstall" as the partial-plugin backfill; it now lives in
`apply`, on every run, judged by the same planner `pending` uses, instead of behind a
version stamp at load. The cucumber suite cannot change the extension's supported kinds
(RESEARCH Pitfall 6), so the scenario makes a plugin whole through a catalog version that no
longer needs the unsupported component, and the growth arm itself is proved by unit tests
with seeded records.

Output: the growth path, the deletions with their tests and gate entries, a new production
caller for the single-plugin reinstall operation the backfill used to call, the comments
the deletion makes false, the publishing step, and the scenario.

`extensions/pi-claude-marketplace/orchestrators/reconcile/README.md` still names the
backfill module after this plan; plan 29-14 rewrites that README.
