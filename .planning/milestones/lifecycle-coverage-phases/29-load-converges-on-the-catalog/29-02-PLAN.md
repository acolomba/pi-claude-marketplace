<objective>
Make a load read-only (APL-03, D-02, D-04). A new module `orchestrators/reconcile/load.ts`
runs, per scope, the locked read pass (MIG-01 first-run config migration, the legacy
state migration inside `loadState`, the LOAD-01 verdict, the plan), the AMIG-01 MCP move,
the per-session warnings (D-18), and the hook routing rebuild. It never calls `applyPlan`
or the backfill. `index.ts` drives it from `resources_discover` instead of
`applyReconcile`. The read pass moves out of `apply.ts` into `read-pass.ts`, so `apply`
and the load share it.

Purpose: changing installation state becomes an explicit command (D-02). This plan
removes every install, uninstall, enable, disable and backfill from the load. Until plan
29-08 the load reports only what it reported before as report-only rows (invalid config,
layer gap, source mismatch, the two warnings, routing failures), in the same
`reconcile-applied-cascade` form, so the warning scenarios stay as they are.

Output: `read-pass.ts`, `load.ts`, their owner tests, the rewired `index.ts`, the reload
scenarios moved to `apply`, and one new scenario that proves a hand edit plus a new
session changes nothing.
</objective>
