<objective>
Give `pending` the LOAD-01 satisfaction verdict (D-21). `pending` computes the same
verdict `apply`'s read pass computes (`buildScopeSatisfactionVerdict`, offline) and hands
it to `planReconcile`, so the dependency-disable and missing-dependency-install buckets
fill, and the LOAD-02 lift stops proposing an enable the check would undo. A planned
disable of a record the user already disabled is dropped, because `apply` leaves it
alone. This supersedes PENDING-VERDICT-01 / D-06-25 ("pending computes no verdict").

Purpose: D-21 moved the dependency disable to `apply`; until `apply` runs, `pending` (and,
from plan 29-08, the load's block) must name it. Without the verdict `pending` would also
show a `(will enable)` for every held-down plugin, which `apply` never makes.

Output: the verdict in `pending`, the filter, the projection comments, catalog prose and
the dependency-resolution doc, and a pending scenario.
</objective>
