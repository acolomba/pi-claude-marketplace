<scenarios>

`features/plugin/enable.feature` (Background unchanged; dependency scenarios
publish their own marketplace "tools" because the Background's plugin table
has no dependencies column):

- Enabling a disabled plugin offers its skills again and keeps one installation record (ENA-01, exists).
- Enabling an enabled plugin is skipped as already enabled (ENA-03): skipped row, record and config unchanged.
- Enabling a plugin that is not installed fails as not installed (ENA-06).
- Enabling in the user scope leaves the project scope unchanged (ENA-04).
- Enabling in the project scope leaves the user scope unchanged (ENA-04).
- Enabling a plugin enables its disabled dependency too (ENA-05, D-04): both rows, both records enabled, both skills offered.
- Enabling a plugin whose dependency is not installed fails as dependency unsatisfied (ENA-05, D-02, D-05): failed row with the cause, the plugin stays disabled, no skills offered.

`features/plugin/disable.feature`:

- Disabling an enabled plugin offers none of its skills and keeps it installed (ENA-02): `list` shows it installed and disabled.
- Disabling a disabled plugin is skipped as already disabled (ENA-03).
- Disabling a plugin that is not installed fails as not installed (ENA-06).
- Disabling in the user scope leaves the project scope unchanged (ENA-04).
- Disabling in the project scope leaves the user scope unchanged (ENA-04).
- Disabling a plugin that an enabled plugin depends on fails as dependents remain (ENA-05, D-01): the dependency stays enabled and its skills stay offered.

</scenarios>
