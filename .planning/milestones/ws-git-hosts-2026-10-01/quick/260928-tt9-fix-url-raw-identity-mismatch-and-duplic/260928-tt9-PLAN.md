<objective>
Close two security findings in unreleased any-git-host code before the milestone ships.

1. **T-2-10** (phase 2 security audit W-1). `domain/source.ts::urlObjectSource` takes a url object
   source's identity from `url` (via `gatedUrlField`) and its wire url from `raw`. Both pass the
   https gate, but nothing makes them name the same repository. The identity picks the auth host
   and the scope-shared `plugin-clones/` key (`orchestrators/marketplace/add.ts` ~902,
   `orchestrators/plugin/install-clone-probe.ts` ~56, `orchestrators/plugin/clone-cache.ts` ~276);
   the wire comes from `raw` (`domain/clone-key.ts::networkCloneUrl`). Measured on this HEAD:
   `{source:"url", url:"https://trusted.example/o/r", raw:"https://attacker.example/x"}` parses to
   identity `https://trusted.example/o/r` and wire `https://attacker.example/x`, so a manifest entry
   can fill a trusted identity's unpinned mirror from any https url (content substitution; the
   credential is already held back by D-1-03). Manifest entries reach the parser unfiltered
   (`domain/plugin-resolver.ts` ~387). Fix: admit `raw` only when its gated parse is a `url` source
   whose `url` equals the identity's `url`; otherwise reject through the existing
   `unknownObjectSource` path.
2. **T-3-05 / WR-11** (phase 3 code review). `platform/git.ts::listRemotes` reads
   `remote.origin.url` through isomorphic-git's single-value config read, which returns the LAST
   value (`allValues.pop()`, `node_modules/isomorphic-git/index.cjs` ~1912); git fetches from the
   FIRST. Measured: a `.git/config` holding a foreign `url` then the canonical one reports the
   canonical url, so `add.ts::recognizeLeftover` authorizes removal of a tree git treats as another
   repository (D-3-02: recognition is the only removal authority). Fix: read every value with
   `git.getConfigAll` and report `origin` only for exactly one string value.

Purpose: a third-party manifest can no longer redirect what a trusted identity fetches, and
`marketplace add` removes a leftover only when git itself would fetch the source from it.

Output: two `fix(...)` commits (one per finding, tests and fix together) and a green `npm run check`.

Plan shape: three sequential tasks in one checkout. Tracer-first is not applied: the two fixes
share no file and no layer, each task is end-to-end for its own finding (parser to resolver
rejection; config read to the `{stale clone}` row), and the seams are already proven.
</objective>
