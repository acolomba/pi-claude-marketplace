SessionStart `additionalContext` that a hook gave at startup, while Claude Code 2.1.330 writes
that context into the conversation as soon as the hooks finish and its `/reload-plugins` leaves

through the body of `sendQueuedPromptContext` moved into one shared helper, so the session, which
a reload keeps, carries it; the SessionStart buffer then goes. Test first: the five SessionStart
scenarios of `features/hook/additional-context.feature`, ten unit cases, and the integration case

buffer and the integration case HOOK-E2E-04 go; last, the docs and the D-CF5-13 decision row

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| plugin hook output to the session and the model | A plugin's SessionStart hook decides the `additionalContext` text that the bridge now writes into the Pi session as soon as the hooks finish, and that the model reads. |
| one Pi session to the next | A new, resumed, or forked session must not receive the SessionStart context of the session before it. |
