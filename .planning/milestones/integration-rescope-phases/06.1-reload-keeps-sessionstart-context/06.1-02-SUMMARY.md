# Phase 06.1 Plan 02: Resume and Fork Keep One Copy of SessionStart Context Summary

A resumed or forked session's SessionStart now reads the conversation the model sees (`buildSessionProjection().messages`) and sends only the hook values it does not hold. It compares values one by one, by `details.values` or, for an older message, by its `SessionStart hook additional context: ` part, and ignores a saved file's path. Each message carries its values in `details`. Five scenarios prove it, two setup steps support them, and 32 unit cases pin the behavior.

## Product fix

- **Defect (review CR-01):** the SessionStart arm sent the joined `result.additionalContext` for every source. A fork at the first prompt copies the context message, which sits before the first user message, and then the fork's own SessionStart sends it again. A `--continue` resume loads the saved message and sends it again.
- **Duplicate removal (`event-adapters.ts`, all module-private, still 13 `export` lines):** `novelSessionStartValues` returns every value unless `source` is `resume` or `fork`. Otherwise it reads `heldContextKeys(ctx)`, a `Set` built from `ctx.sessionManager.buildSessionProjection().messages.flatMap(messageKeys)` (never `getBranch()`). It returns `[]` when a held key equals `contextKey` of the whole join, and otherwise the values whose `contextKey` is not held.
- **Keys:** `messageKeys` reads only `role: "custom"` messages of type `claude-hook-additional-context`. With `details` defined, it takes the `details.values` that `isSessionStartContextDetails` accepts (object, not null, `in`-narrowed `event` and `values`, `event === "SessionStart"`, an array of strings only, no `as`), and else nothing. Without `details`, it takes the rest of each text part that starts with `SessionStart hook additional context: `. String content and non-text parts give nothing. `contextKey` replaces the `saved to: <path>` tail of a `<persisted-output>` wrapper with `<persisted>` (Claude Code 2.1.330 `gTt`).
- **details:** `sendHookContextMessage(pi, event, values, failureLog, send = {})` spreads `{ details: send.details }` when given. `sendSessionStartContext` always passes `{ event: "SessionStart", values: sent }`. The prompt context path passes `[text]` and no bag, so its message is unchanged. `{ triggerTurn: false }` remains the file's only send option.
- **Read failure:** a throwing projection read debug-logs `adaptObservation: session start context read failed: <error>` and holds nothing, so every value is sent. A SessionStart with no non-blank value returns before any read.
- **Attributed failure line (IN-01):** `adaptObservation: session start context failed for <pluginId>@<marketplace>`, or `for <unattributed>`. The JSDoc now says only a synchronous throw is logged; Pi reports a rejected asynchronous write itself (IN-03).
- **Dispatch (`dispatch.ts`):** `contextValues(outcomes)` is the per-hook list that `joinedContext` now joins. The SessionStart arm of `adaptForEvent` passes `{ event: event as ClaudeSessionStartEvent, values: contextValues(folded.outcomes) }`. SessionEnd and PostCompact keep the three-argument call.
- **Unit cases:** event-adapters 144 (one deleted per IN-02, 22 added), dispatch 303 (2 added), event-router 263 (the stale case now resolves a context, so `messages: []` can fail, IN-02). That is 710 in total, and 32 of them were red before the fix.
