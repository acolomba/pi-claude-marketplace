## Product fix

- **Defect:** the SessionStart arm of `adaptObservationResultForEvent` appended the folded context to a runtime buffer that `startRun` drained after the first prompt. A Pi `/reload` reruns the extension factory, which creates a new hooks runtime and empties the buffers, so the context was lost.
- **Helper:** module-private `sendHookContextMessage(pi, claudeEvent, text, failureLog)` in `bridges/hooks/event-adapters.ts`, holding the old body of `sendQueuedPromptContext`: `hookContextPart` builds the part, no Pi API or a blank context sends nothing, the send is `{ customType: "claude-hook-additional-context", content: [part], display: false }` with `{ triggerTurn: false }`, and a throw is debug-logged as `<failureLog>: <error>` and never rethrown (NFR-2). `sendQueuedPromptContext` is now one call of it with `"adaptInput: queued prompt context failed"`. The helper is not exported (13 exports, as at the base).
- **SessionStart call:** the arm calls the helper with `"adaptObservation: session start context failed"`; Prettier lays it out as the six lines the break files replace.
- **Order change:** the SessionStart context now comes before the first prompt, in a message of its own; the UserPromptSubmit and UserPromptExpansion context still follows the prompt in one message.
- **Why `{ triggerTurn: false }`:** it never starts or steers a run. While Pi is idle, Pi writes the message into the session at once (a reload keeps the session); while a run streams, Pi holds it to the turn end.
- **Buffer removal (Task 2):** `HooksRuntime` lost `appendPendingSessionStartContext`, `pendingSessionStartContextEntries`, and `drainPendingSessionStartContext` and the buffer; `routing-state.ts` lost `PendingSessionStartContext`, its two picks, and `clearPendingSessionStartContext`; `startRun` builds its message from `promptContextParts(runtime.drainPendingPromptContext())` alone; `bufferedContext` was folded into `bufferedPromptContext`; comments in `dispatch.ts` and the barrel `index.ts` follow.
- **Unit cases:** 10 send-asserting cases changed or added in Task 1 (six adapter, three dispatch, one router), plus the cases the plan's tables list as passing on both sides (the unattributed prompt case keeps the `UNATTRIBUTED` branch covered).
- **Coverage:** `coverage-1.log` exit 0 (three pairs) on the fix tree; `coverage-2.log` exit 0 (six pairs) after the removal; `coverage-base.log` on the final tree: six `Direct coverage passed:` lines, `event-adapters.ts` branches 156/156, functions 30/30, lines 832/832; `dispatch.ts` 419/419, 105/105, 1688/1688; `event-router.ts` 245/245, 82/82, 1703/1703; `runtime.ts` 113/113, 58/58, 685/685; `routing-state.ts` 2/2, 1/1, 199/199; `index.ts` 5/5, 4/4, 41/41.
