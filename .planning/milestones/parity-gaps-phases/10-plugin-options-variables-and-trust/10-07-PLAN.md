<objective>
Keep each plugin's declared option schema on its install record, at every site that writes
the record.

Purpose: PG-CORE-03 under D-PG10-14, D-PG10-15, and D-PG10-23. Three readers of options never
open a manifest: the hooks hydrate at load, the built-in MCP registration, and the
process-variable pass. A manifest read at load would cost a parse per plugin, would miss a
plugin whose options live in the marketplace entry, and for a path-source plugin could be
newer than the staged content. So the declared schema rides the record, as `mcpServerConfigs`
does. That field has five write sites, and a site that is forgotten leaves a stale schema, so
this plan lands all of them. Reading the field back, validated, is plan 10-08, with its first
consumer.

Output: the record field with one producer, written at install and at each restage, and two
scenarios that state the installation record.
</objective>

## Planner decisions

- **The field is present only when the plugin declares `userConfig`.** So no record text that
  a test or a scenario pins today changes, and the difference that D-PG10-21 needs between
  "declares none" and "declares options" survives a load.
- **This plan writes the field; plan 10-08 reads it.** The reader has no production caller
  before the hooks bridge, and an exported function with no importer fails the commit hook's
  dead-code check, so the reader lands with its first consumer.
- **The scenarios state the installation record.** The suite already states what a record
  holds (its plugins, its skills); one new `Then` states its options.
