<objective>
Leave out of `mcp-adapter.json`, and report, a plugin MCP server that names an option with no
value.

Purpose: D-PG10-08 as amended by D-PG10-21. Claude Code 2.1.323 throws `Plugin option "KEY"
isn't set` for such a field and catches it per server: that one server does not load, the
plugin's other servers do, and the plugin stays enabled. Only a `--partial` install of a
plugin with a required option, or a reference to a key the manifest does not declare, reaches
this. Today such a server is written with the literal reference in its field. The research's
option B is taken: the decision is made at the bridge, at the one choke point both encodings
share, with no verdict plumbing. This plan lands before the fill of plan 10-17 so that no
entry ever references a variable that has no value. Plan 10-13 applies the same verdict at
update, reinstall, and the load-time move, and plan 10-14 applies it to Pi's built-in MCP.

Output: one pure verdict, the stage's partition and notice on the install path, the notice in
every closed-set home, and `features/mcp-server/options.feature` with its first scenarios.
</objective>

## Planner decisions

- **The notice is the stage's, under both implementations.** The MCP phase writes
  `mcp-adapter.json` whatever implementation is active, so the notice names that file under
  both. The built-in registration of plan 10-14 skips the server with a debug log and no
  second notice (10-PATTERNS.md finding 4).
- **Notice kind `option-blocked`, with `names` and a closed `reason`.** `names` holds the
  option keys, as `variables-missing` holds variable names. `reason` has one member in this
  plan, `unset`; plan 10-15 appends a second for a value that pi-mcp-adapter would
  home-expand. Its severity is warning.
- **The verdict is `mcpOptionBlock(server, options)`** in `domain/claude-mcp-variables.ts`.
  It gives `undefined` when nothing blocks the server, and otherwise a reason and the option
  keys, in first-seen order and once each. In this plan the one reason is `unset`: a key that
  the five fields of the declared server reference and that the MCP value map lacks.
  `undefined` options block nothing. The stage copies the reason and the keys into the
  notice. Plan 10-15 adds its reason inside this function, so the stage does not change
  again for it.
- **The install path only.** The stage input's member is required, so `update-swap.ts` and
  `mcp-migration.ts` state `undefined` here: update, reinstall, and the load-time move write
  a server's entry as they do today, with the reference as written. Plan 10-13 gives both
  their options and changes the unstage fold.
- **Why this plan is 26 files.** Thirteen are the notice's closed-set homes, their owner
  tests, the lock test, and the two catalog files: the architecture tests run in the commit
  hook, so a kind lands in every home in one commit, and each home takes one arm in the
  shape of `ca-file-removed`. The required member forces the three callers of the stage and
  two tests that build its input. A narrower plan would commit a server that is dropped with
  no report.
- **Step module.** A step this plan needs goes in the new
  `features/step_definitions/mcp-server/options.steps.ts`, with text that names plugin
  options.
