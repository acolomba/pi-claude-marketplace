<objective>
Let the MC-5 marker record a default that is a string or a boolean, and let a scenario start
from an adapter entry exactly as release 0.23.0 wrote it.

Purpose: plan 09-03 writes `lifecycle: "lazy-keep-alive"` and `openUi: false` as defaults,
and D-PG9-03 says the marker records each of them so a restage can recompute it. Today the
marker accepts numbers only, and a member with any other value drops the whole record, so the
new defaults would read as the user's values and never be recomputed (RESEARCH Pattern 2 and
Pitfall 6). D-PG9-04 needs a reinstall scenario that starts from an entry an earlier release
wrote, and today's fixture removes only the timeout (Pitfall 8). Both changes leave every
output of the product as it is, so they land before the defaults.

Output: the widened marker with its owner cases, and the release 0.23.0 entry fixture with
its Given, used by the D-PG1-12 scenario.
</objective>
