<objective>
Write the two new adapter entry defaults: `lifecycle: "lazy-keep-alive"` for a stdio plugin
server and `openUi: false` for every plugin server, recorded in the marker beside the
timeout default, and bring every test and scenario that pins an adapter entry or a stub
message table to what the adapter now does.

Purpose: PG-MCP-06 and the UI half of PG-SEC-03 under the decisions D-PG9-01, D-PG9-02,
D-PG9-03, D-PG9-07, and D-PG9-11, with D-PG9-04 for installed plugins. Claude Code connects a
stdio plugin server at session start and keeps it, and pi-mcp-adapter 7.0.1's default `lazy`
stops an idle server after 10 minutes. Claude Code 2.1.323 declares no MCP Apps UI extension
to a server in a CLI session, and pi-mcp-adapter 7.0.1 declares it to every server unless
`openUi` is `false`. The defaults go after the plugin's and the user's fields and before the
marker, never in the closed table, because the table's output is the plugin's (RESEARCH
Pitfall 2). Sampling is not written here: D-PG9-08 records that divergence, and plans 09-05
and 09-06 record it.

Output: one domain table of entry defaults, the generalized entry builder, their owner
cases, the byte pin, one new install scenario, and the changed expectations of every unit
test, integration test, and scenario that pins a staged adapter entry, an adapter stub
message table, or an adapter server status.
</objective>
