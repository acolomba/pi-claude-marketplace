<objective>
Prepare the cucumber harness for adapter entries that keep a stdio server connected, and add
the two resource guards of PG-MCP-08.

Purpose: plan 09-03 writes `lifecycle: "lazy-keep-alive"` on every stdio plugin entry
(D-PG9-01). Under that lifecycle, pi-mcp-adapter 7.0.1 keeps the startup listing connection
open, so the stub never exits. The adapter's listing wait today ends only when no stub
process is left, so about 130 listing steps in 20 feature files would time out (RESEARCH
Pitfall 1, measured by probe A). This plan changes the wait first, while the product is
unchanged, and proves it under both lifecycles. The resource guards need a resource on the
stub, and only an opt-in one, because pi-mcp-adapter lists resources at connect and a
resource on the default stub would change every adapter message table (Pitfall 3).

Output: the stub's logged tool name, one listing rule for both implementations, the hook
step on that rule, a recorded resident-stub measurement, an opt-in text resource, and
`features/mcp-server/resources.feature`.
</objective>
