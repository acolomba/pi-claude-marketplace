<objective>
Attach the files that a command's author mentioned when the user types the command, and only
those.

Purpose: PG-SKILL-01 for commands (it covers the PRD's CMD-01), under D-PG11-02 and D-PG11-05 to
D-PG11-08. Plan 11-03 built the pure parser. This plan adds the reads behind an injected reader
and calls them in `renderCommand`. The security rule is the scan input: Pi has no read permission
rules, and an attachment made in the `input` transform passes no `PreToolUse` hook on `Read`, so
only text the author wrote may name a file. A path that arrives through a typed argument or
through `!` output is never read (D-PG11-02).

Output: one new orchestrator pair, the command wiring, one scenario that is red before the
change, and four guard scenarios that are shown able to fail.
</objective>

## Contract for later plans

Plan 11-05 calls the same function from the skill invocation. Keep the names, or list each
renamed one under `## Lines for later plans` in the SUMMARY.

| Export | Meaning |
| --- | --- |
| `MentionFileReader` | `stat(file)`: `{ isFile, size }` after following a symbolic link; `read(file, maxBytes)`: at most `maxBytes` bytes from the start of the file; `homeDir()`: the home directory for `~` |
| `NODE_MENTION_FILE_READER` | the reader of a running Pi, over `node:fs/promises` and `node:os` |
| `appendMentionedFiles(input: { authored: string; rendered: string; cwd: string }, reader: MentionFileReader): Promise<string>` | `rendered` with the blocks of the files that `authored` mentions; it never rejects |
| `CommandInvocationDependencies.mentions` | the reader, a required member |

`authored` is the body with its variables filled and no argument substituted. `rendered` is the
text after the arguments and the `!` commands. The caller builds both; the function scans only
`authored`.
