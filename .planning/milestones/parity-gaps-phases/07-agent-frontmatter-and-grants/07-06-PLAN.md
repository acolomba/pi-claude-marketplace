<objective>
Restrict a bridged agent by both of its tool lists, and remove the two warnings that state limits pi-subagents no longer has.

Purpose: With `tools` and `disallowedTools` in one source, the converter filters exact names out of `tools`, but a per-tool MCP deny under a whole-server grant only warns that pi-subagents takes no `excludeTools` beside `tools`. An agent with `disallowedTools` and no `tools` warns that `excludeTools` needs a pi-subagents version far below the declared floor of 0.87.0. Both statements are false at the floor: pi-subagents applies `excludeTools` after it resolves an explicit list. Claude Code filters the tool pool by the deny set first and then resolves `tools`. This closes BACKLOG AGTEXCL-01.
Output: the explicit arm of the tool mapping with `excludeTools`, both warnings removed, one scenario per MCP implementation, one `apply` scenario, conformance cases against pi-subagents' own code for both implementations, and the compatibility text.
</objective>
