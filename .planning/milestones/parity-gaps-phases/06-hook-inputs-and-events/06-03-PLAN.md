<objective>
Report `resume` to a `SessionStart` hook when the user continues a saved session, and `fork` when the user forks one.

Purpose: Pi reports `startup` for a launch with `--continue`, `--session`, or `--fork`, so a hook that restores state on `resume` never runs. Claude Code sends `resume` for a continued session and `fork` for a forked one. The harness could not start Pi this way, which is why D-CF5-06 deferred it.
Output: the session option of the harness launch with a saved-session fixture, the launch detection in the `session_start` handler, and the scenarios for a new, a continued, an opened, and a forked session. The detection rule is chosen from the recorded result of spike S7.
</objective>
