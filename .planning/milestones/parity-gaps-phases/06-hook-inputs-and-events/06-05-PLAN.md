<objective>
Tell a hook which MCP server a tool belongs to: send `mcp_server` with the server's name and source for a tool of a plugin's server.

Purpose: Claude Code 2.1.274 and later send `mcp_server` as an object on the three tool events. A hook can then decide by server instead of parsing the tool name. The bridge can name a plugin's server and its source exactly; for any other MCP tool it cannot, and leaves the field out.
Output: a table of plugin servers built in the scope hydrate, the lookup in the two tool handlers, the field in the three tool translators, one scenario for each scope under both profiles, and the `mcp server` column in the tables that hold a plugin MCP tool.
</objective>

## Flagged assumptions

- **A6 (06-RESEARCH.md):** a plugin's MCP servers reach Pi only on a load, so a table built when the bridge hydrates is never staler than the tools. A server that Pi registered in the middle of a session would send no `mcp_server` until the next load. Not run.
- **A non-plugin MCP tool gets no field in this phase.** D-PG6-07 allows the object for such a tool only when the bridge can name its server and its Pi config scope. Under Pi's built-in MCP the bridge has the registered name but not the scope, and under pi-mcp-adapter it has neither, so the field is left out (06-RESEARCH.md finding F6 and open question 2). Plan 06-13 says so on the compatibility page. Pending maintainer review.
- **A server of Pi's own `mcp.json` that is registered under a plugin server's exact name** would read as that plugin's server under the built-in MCP. Pi's registry holds one server per name, so the two cannot be registered together.
- **The runtime value of Claude Code's field was not observed.** The key form `plugin:<plugin>:<server>` and the source `plugin` were read in the 2.1.323 binary (records U4 and U5), not in a run. D-PG6-07 marks the name as pending maintainer review.
- **A cut adapter name.** pi-mcp-adapter keeps the first 55 characters of a long tool name. When the server part fits in them, the prefix still names the server. When it does not, and no hook literal recovered the full name, the field is left out.
- **Size and the second task.** The field, the table, and the sweep are one change: a table that states the column fails until the field exists, and the reverse. So task 06-05-01 holds them all, and task 06-05-02 is a guard scenario with a recorded red run.
