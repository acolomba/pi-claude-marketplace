<objective>
Give a plugin MCP server that declares no usable `timeout` Claude Code's idle window under
Pi's built-in MCP: 30 minutes for a stdio server and 5 minutes for a remote server.

Purpose: PG-MCP-01, decision 4 of the PRD (D-PG1-11). Today a server with no `timeout` gets
Pi's own default of 60 seconds, so a plugin tool that runs longer with no progress message
fails on Pi and not in Claude Code. The domain layer names the default for a server type, and
the built-in translation applies it directly. The adapter side, which must also respect a
value the user wrote on the entry, is plan 01-06 and reads the same domain function.

Output: `defaultRequestTimeoutMs` in the closed server table, its use in the built-in
translation, their unit cases, one `@builtin-only` scenario, and the changed expectations of
every test and scenario that pins a built-in config with no declared timeout.
</objective>
