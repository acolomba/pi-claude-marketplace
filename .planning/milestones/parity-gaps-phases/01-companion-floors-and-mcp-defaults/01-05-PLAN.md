<objective>
Write the name that pi-mcp-adapter registers, not the Claude Code name, into an agent's
`excludeTools` under the adapter, and measure and record the gap in pi-subagents' own naming
of a granted long tool.

Purpose: PG-MCP-02, D-PG1-10. An agent's `disallowedTools` entry is an access control: the
child is not offered a tool whose registered name is in `excludeTools`. The agents bridge
writes the Claude Code token there under the adapter, so a tool that the adapter registers
under a cut name, or one whose name holds a `.`, stays available. The research also found
that pi-subagents 0.88.0 names a granted tool with its own copy of the adapter's code, which
has no 64-character cut. The project cannot fix that; the orchestrator's resolution 5 asks
for a measurement, a record, and a drafted upstream report.

Output: `excludeNameFor` through the profile for both implementations, its unit cases, one
`@adapter-only` scenario, a conformance test or a recorded source reading for the pi-subagents
gap, a BACKLOG entry, a PRD row, and the drafted report.
</objective>
