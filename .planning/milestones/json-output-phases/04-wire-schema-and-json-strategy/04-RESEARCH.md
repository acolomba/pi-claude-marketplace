### Locked Decisions

#### Envelope, kinds, and files

- **D-01:** Every payload carries `schemaVersion: 1` (integer literal),
  `kind`, `severity`, and `needsReload` now, plus `summary` (warning and error
  only, WIRE-05) and a numeric `tally` where the model has one. Phase 6 adds
  `origin` and the command id (WIRE-02) without bumping `schemaVersion`
  (additive). Raw kinds carry `needsReload: false`.
- **D-02:** Kind names are the model's existing kind strings, verbatim, for
  structured and raw kinds alike. There is one vocabulary; the wire does not
  rename kinds.
- **D-03:** Files: `shared/notification-wire.ts` holds the typebox schema (one
  union keyed by `kind`), `shared/notification-json.ts` holds the explicit,
  total-map converter from the resolved model to the DTO (Phase 1 D-09: JSON
  serializes a built DTO, never the model, never with a replacer). A JSON
  Schema file generated from the typebox source is committed at
  `schema/claude-plugin.schema.json`, listed in `package.json` `files`, and
  regenerated by a `scripts/` generator. Exact names are the planner's choice

- **D-04:** Row and block fields follow research FEATURES.md "Per-verb payload
  content": plugin rows carry `status`, `name`, `id`, `version?`, `scope`
  (always, for install-scoped rows), `description?`, `reasons[]`,
  `dependencies[]?`, full `from`/`to` on updates, hint ids, `partial?`,
  `causeChain?` with `truncated`, `rollbackPartial?`; marketplace blocks carry
  `name`, `scope`, `status?`, `details?`, `reasons?`, `plugins[]`.
  `marketplaces: []` replaces the `(no marketplaces)` sentinel. The update
  no-op cascade carries `noOp: true`. Optional fields are absent, never
  `null`; empty collections are `[]`; arrays keep model order; versions and
  timestamps are raw (WIRE-03..06).

#### Credential redaction (PMOD-04)

- **D-05:** Redact URL userinfo and token-shaped strings: GitHub token
  prefixes `ghp_`, `gho_`, `ghu_`, `ghs_`, `ghr_`, `github_pat_`, plus
  `Bearer <token>` and `x-access-token:<token>` forms.
- **D-06:** Replacement forms: userinfo becomes `***@` (for example

- **D-07:** One redaction function, applied in resolve at every serialization

  JSON path.
- **D-08:** Corpus: entries whose bytes change because of redaction are

  mechanically (the Phase 2 D-07 / Phase 3 D-17 pattern). Any other corpus

  unchanged and redaction is proven by owner tests.

## Summary

The model already holds every fact the wire needs. Resolve produces `ResolvedEnvelope` (severity, `summary` on warning and error, `needsReload`, `noOp`, numeric `tally`), `ResolvedMarketplace[]` with `ResolvedRow`s (composed `reasons`, a `failure` with a serialized `causeChain`/`truncated`, rollback entries and leaks, `hint` ids), and `ResolvedRawSurface`. The converter is a total map from these resolved values to plain objects whose type is `Type.Static<>` of the typebox union. Two gaps exist. First, `ResolvedRow` omits `dependencies`, which D-04 lists as optional. Second, the info kinds (`marketplace-info`, `plugin-info`, both `*-cascade` forms) and `prune-committed-warning` are rendered from the raw message in `dispatchInfoMessage`, with no resolve step. `prune-committed-warning` still carries a live `Error`, which dispatch serializes at line 291.

typebox 1.3.34 is installed, not the 1.1.x floor. Its schema objects are plain JSON Schema with no symbol keys, so `JSON.stringify(schema)` is the generator, and the output is deterministic. `Type.Static` gives exact optional properties (`v?: string`) under `exactOptionalPropertyTypes`, which forbids explicit `undefined` at compile time. The compiled `Check` accepts `{ v: undefined }` at runtime, though, so the validation tests must check `JSON.parse(JSON.stringify(payload))` and walk for `undefined` and `null` separately. A fallow probe showed that a type-only `import type { X }` plus `typeof X` keeps a value export alive in production dead-code. The converter can therefore derive its return type from the exported schema value. The schema value then has a production "reader", and the generator and tests can import it without a suppression.

Credential redaction does not change any existing byte. The proposed regex set was run over all 3134 corpus messages and over the whole `docs/output-catalog.md`: 0 changes. It leaves the scp-style subject `git@github.com:foo/bar.git` intact, and that subject appears in two corpus entries and in the catalog. The D-08 ledger is therefore empty, and owner tests with planted credentials must prove redaction.

**Primary recommendation:** Build in four sequential plans: (1) a leaf redactor applied inside `serializeCauseChain` and resolve; (2) a pure "presentation" step that dispatch's text path consumes, with no byte change; (3) the wire schema, the converter, and the LLM tools as its production consumer, all in one plan; (4) the committed schema file, the generator, and the proofs (validation, walk, drift, AUTH-09 JSON).

- `Type.Union([Type.Object({ kind: Type.Literal("a"), ... }, { additionalProperties: false }), ...])` serializes with `JSON.stringify` to `{"anyOf":[{"type":"object","required":[...],"properties":{"kind":{"type":"string","const":"a"},...},"additionalProperties":false}, ...]}`. `Object.getOwnPropertySymbols(schema)` is `[]`. [VERIFIED: probe]
- `Type.Readonly(...)` adds nothing to the emitted JSON (`{"type":"array","items":{"type":"string"}}`). [VERIFIED: probe]
- `Compile(U).Check(...)`: `{kind:"a",n:1}` gives true, `n: 1.5` against `Type.Integer()` gives false, `{}` gives false, and **`{kind:"a",n:1,v:undefined}` gives true**. [VERIFIED: probe]
- `Settings` from `typebox/system` defaults include `"exactOptionalPropertyTypes":false`. `Settings.Set({ exactOptionalPropertyTypes: true })` makes the `undefined` case fail. This is a global, process-wide switch. [VERIFIED: probe]
- `Compile(U).Errors(value)` yields `{ keyword, schemaPath, instancePath, params, message }` records, which is useful for test failure messages. [VERIFIED: probe]
- `Type.Static<typeof O>` with `Type.Optional(Type.String())` under `--exactOptionalPropertyTypes` gives `{ v?: string; k: "x" }`, and assigning `{ v: undefined }` is a compile error (TS2375). [VERIFIED: tsc probe] The comment at `domain/components/plugin.ts:11` ("`Type.Optional` produces `T | undefined` in Static<>") is stale for 1.3.34. Do not copy that belief, and do not edit the comment either (surgical changes).
- A `{ discriminator: { propertyName: "kind" } }` union option is emitted verbatim. JSON Schema validators ignore it (it is an OpenAPI keyword). It is optional, and not recommended. [VERIFIED: probe output]

### Pattern 1: The schema value stays alive through a type-only import
**What:** `notification-wire.ts` exports the union value (for example `NOTIFICATION_PAYLOAD_SCHEMA`). `notification-json.ts` does `import type { NOTIFICATION_PAYLOAD_SCHEMA } from "./notification-wire.ts"` and declares `export type WirePayload = Type.Static<typeof NOTIFICATION_PAYLOAD_SCHEMA>`.
**Why:** A fallow production dead-code probe in this session added a module with two value exports. The module that imported one of them only as `import type` + `typeof` did not get that export flagged. The other export, which nothing imported, was flagged (`ZZ_PROBE_UNUSED`). [VERIFIED: fallow dead-code --format json probe, tree restored]
**Rule:** Export only the top-level union value, plus any sub-schema or `Static` type that a production module imports. Keep sub-schemas module-private. Tools import `WirePayload`-derived row and block types (for example `Extract<...>` or exported `Static` aliases) from `notification-json.ts`.

### Pattern 2: Total-map converter with no spread of model objects
**What:** Each arm builds a fresh object literal field by field: `{ status: row.status, name: row.name, id: \`${row.name}@${mp.name}\`, ...(row.version !== undefined && { version: row.version }), reasons: [...row.reasons] }`. Switch on `kind` and `status` with no `default`, so `switch-exhaustiveness-check` and TS7030 force a new arm when the model grows (memory: missing switch arm fails under `noImplicitReturns`).
**Why:** Pitfall 10: `JSON.stringify` of a model object counts as a whole-object read and blinds the type-member gate. A replacer or `toJSON` is `unsupported-analysis` and fails the gate permanently. Spreading `...row` copies unknown keys (`missingPolicy`, `failure` objects) into the DTO.
**Gotcha:** `ResolvedRowFacts.missingPolicy?: true` is a resolve-internal fact. Do not emit it (no wire meaning). The converter does not need to read it.

### Pattern 3: Presentation seam (format-only peer)
**What:** Move the "compute the resolved inputs" half of each dispatch entry into pure exported functions that dispatch's text path calls. Example: `presentCascade(run, message, rowPolicies) → { kind: "cascade", envelope, marketplaces, advisories?, retainedWorkflows? }`; `presentUpdateNoOp(...)` (envelope from `resolveUpdateNoOpEnvelope`); `presentReconcileApplied(...)`; `presentInfo(message)` (redacts `marketplace-info` `source.url`, serializes the prune cause); `presentRawSurface(surface)` (`resolveRawSurface`). The text strategy formats a presentation. `toWirePayload` converts the same presentation.
**Why:** JOUT-02 requires the JSON strategy to be a format-only peer. If the JSON test re-derives `resolveRows` + `resolveEnvelope` itself, it duplicates dispatch logic, and the duplicate can drift. The presentation functions get a production reader immediately (dispatch), so they pass fallow dead-code in the plan that introduces them.
**Constraint:** The catalog (260 states) and the corpus (3134 entries) must not change by one byte in this plan.

### Pattern 4: LLM tools through the strategy (LLMT-01)
- Plugin tool: keep `renderPluginPayload`'s line text exactly as it is (it reads the unresolved rows and the coarse bucket label). For `details`, filter the unresolved payload by bucket, then run `presentCascade(openNotificationRun(pi), { marketplaces: filtered, label: "Plugin list", cardinality: "plural" }, LIST_CONTEXT.rowPolicies)` and `toWirePayload`. Flatten `payload.marketplaces[].plugins` into `details.plugins`. Status stays verbatim (`upgradable`, `partially-upgradable`, `remote`, `disabled`). The row gains `id` and drops `marketplace`. `openNotificationRun(pi)` already works with `pi: ExtensionAPI` (edge/register.ts:138) [VERIFIED].
- Marketplace tool: `details.marketplaces` becomes wire marketplace blocks: `{ name, scope, details?, plugins: [] }`, exactly what `listMarketplaces` builds today [VERIFIED: orchestrators/marketplace/list.ts:49-80]. Extract that block builder into an exported function that both `listMarketplaces` and the tool call (house machinery reuse). The tool then also reads merged config, so its test boundary gains reads.
- Both tools' empty and error `details` (`{ plugins: [] }`, `{ marketplaces: [] }`) keep their shape.

### Anti-Patterns to Avoid
- **`JSON.stringify(model)` or a replacer:** breaks the type-member gate (Pitfall 10) and can leak `Error` objects.
- **Re-deriving English in the converter:** `summary` is model data (Phase 1 D-10). Read `envelope.summary` verbatim.
- **A second vocabulary:** no `failureCode`, no snake_case, no renamed kinds (D-02, WIRE-03). The cascade's absent kind serializes as `"cascade"`.
- **Redacting names or subjects:** the scp-style marketplace name `git@github.com:foo/bar.git` is a row subject in the catalog and the corpus. Redaction applies only to thrown-message strings and URL fields.
- **Validating in production:** D-12, and REQUIREMENTS Out of Scope ("Adds a throw/drop path inside the NFR-2 boundary").

## Credential redaction design (PMOD-04)

**Function:** `redactCredentials(text: string): string` in a new leaf `shared/redact-credentials.ts` with no internal imports. `errors.ts` can import it without a cycle (`redact-absolute-paths.ts` already imports `errors.ts`).

const X_ACCESS = /\b(x-access-token:)[^\s@/]+/gi;                 // → "$1***"

## Common Pitfalls

### Pitfall 1: The ROADMAP fixture count is stale
**What goes wrong:** ROADMAP success criterion 1 says "205 catalog fixtures". The contract pins `EXPECTED_MODULE_COUNT = 21`, `EXPECTED_STATE_COUNT = 260`, `EXPECTED_UTF8_BYTES = 39_143` [VERIFIED: tests/architecture/catalog-uat/catalog-contract.test.ts:52-55].
**How to avoid:** Iterate the same `FIXTURE_MAPS` and assert the converted count equals the contract's state count. Do not hardcode 205.

### Pitfall 2: The reason vocabulary is wider than `ContentReason`
`ResolvedRowFacts.reasons` is `readonly Reason[]` (it includes the composed soft-dep markers), while blocks carry `ContentReason[]`. Build the wire `reasons` items from the full `Reason` literal list, or validation fails on marker reasons. Keep one literal source; derive the typebox literals from an exported `as const` array only if production reads it.

### Pitfall 3: `undefined` passes the compiled validator
Verified above. Validate `JSON.parse(JSON.stringify(dto))`, and separately walk the DTO to assert no own property is `undefined` or `null`, every object prototype is `Object.prototype` or `Array.prototype` (no `Error`, D-10), and no value is a function, a symbol, or a non-finite number.

### Pitfall 4: The four `emit` fixtures bypass `fixture.message`
`plugin-list.ts` (2) uses `notifyWithContext(..., LIST_CONTEXT, ..., "plural")`, and `plugin-update.ts` (2) uses `notifyUpdateNoOpWithContext` [VERIFIED: grep]. The catalog runner also injects `label: "Plugin list", cardinality: "plural"` for the list section (:251-254). The JSON harness must produce the same presentation. Add an optional `present?: (run) => NotificationPresentation` to `CatalogFixture` for those four, or make `emit` return the presentation. Otherwise the no-op fixtures never prove `noOp: true` (WIRE-05).

### Pitfall 5: Type-member contract pins move
Editing `notification-dispatch.ts`, `notification-types.ts`, `notification-resolve.ts`, `notify-context.ts`, or `platform/pi-api.ts` shifts `line:col` pins in `scripts/check-unused-type-members.contracts.json`. `npm run lint:type-members` then exits 2 with possibly empty stdout. Run prettier first, then remap the LINE only (memories: contracts-json-line-pinned, prettier-invalidates-type-member-pins).

### Pitfall 6: The generated schema must pass `format:check`
`JSON.stringify(x, null, 2)` expands short arrays that prettier collapses. Format through prettier's API in the generator. The drift test deep-compares parsed JSON (D-11), so formatting never makes it flaky.

### Pitfall 7: Fallow dead-code on the generator and exported types
`private-type-leaks: "error"` is on [VERIFIED: .fallowrc.json rules]. An exported `toWirePayload(p: X)` whose `X` is not exported fails. Every exported type also needs a production importer. Register the generator as an npm script (`"schema:generate"`), because operator-only scripts need `fallow-ignore-file unused-file` (see the `notify-corpus.mjs` header). `[ASSUMED]`: fallow treats `package.json` scripts as entry points; confirm with `npm run fallow` when the script lands.

### Pitfall 8: 100% direct coverage per source/test pair
`test:coverage:unit` enforces 100% lines, functions, and branches over `extensions/**`, and `test:coverage:direct` checks each source against its own test file [VERIFIED: package.json:98,105]. `tests/shared/notification-json.test.ts` alone must hit every converter arm: 10 structured kinds, 8 raw kinds, every `PluginStatus` (19 literals), every `MarketplaceStatus`, plus `MpList`, info sub-shapes, and every optional field's present and absent branch. Catalog tests do not count for direct coverage.

### Pitfall 9: The LLM tool `details` change is visible to tests in three files
`tests/edge/handlers/tools.test.ts` (1415 lines, `ExpectedPluginRow` with `marketplace` and the projected status at :128-136; marketplace details with `pluginCount` and `source` at :434-447), `tests/edge/register.test.ts`, and `tests/index.test.ts` reference the tools [VERIFIED: grep]. Strict-mock `pi` doubles need `getAllTools()` once the tool calls `openNotificationRun(pi)`. The line-text expectations must stay byte-identical (LLMT-01).

### Pitfall 10: Row policy changes `reasons` in details
`CENTRAL_ROW_POLICY` sets `available`/`remote` to `contentReasons: false`, while `LIST_CONTEXT.rowPolicies` sets them to `true`, and only `installed` gets markers under list [VERIFIED: notification-resolve.ts:305-325; orchestrators/plugin/list.messaging.ts:56-71]. Use `LIST_CONTEXT.rowPolicies` for the plugin tool so `details.reasons` equals what `/claude:plugin list` shows.
