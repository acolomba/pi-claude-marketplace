cascade overload, the regenerated schema, and owner tests.

The rules in 04-01 "Execution boundaries and sizing" apply unchanged,
including the export rule, the wire DTO rules, type-member re-pinning, the
commit protocol with background full-check pre-commit runs, `TASK_BASE`, and
the 04-01 governance prohibition (no corpus or catalog change). Every task
that edits notification-wire.ts runs `npm run schema:generate` and commits the
regenerated file.

Export rule reminder for this plan: each new presentation type is either
imported by the module that formats it (dispatch's per-kind formatter
parameter types) or written inline in `NotificationPresentation`, so fallow
reports no unused type and no private-type leak, with no suppression.

Planner decisions recorded for review (Claude's Discretion, the "emit what the
text form shows" rule):

1. Raw payloads carry no `summary`: WIRE-05 asks for "the model's summary
   line", and the model computes one only for structured envelopes. A raw
   payload's typed fields (message, causeMessage, header) are its human line.
2. The `async-rewake-summary` payload names its text `text`, because D-01
   reserves `summary` for the warning and error summary line, and this kind is
   info.
3. Plugin-info rows emit `dependencies` (pre-rendered plugin addresses), which
   the info text prints; cascade rows still emit none (04-01 decision 1).
4. `lastUpdatedAt` is emitted whenever the model has it, for path sources too
   (CONTEXT orchestrator follow-up: display gating is text policy, and a
   timestamp is not a path).

See 04-01 "Artifacts this phase produces" for the inventory. Spec-less probe
items carried here: WIRE-01 adjacency and empty.
