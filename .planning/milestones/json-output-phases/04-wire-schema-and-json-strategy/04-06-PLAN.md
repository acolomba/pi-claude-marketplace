## Planner decisions (recorded for review, with evidence)

1. **Where.** Block names and plugin row names are redacted in `resolveRows`
   (resolve). The not-added name is redacted in `presentNotification`
   (present), next to the url-source `url` redaction 04-04 put there. Nothing
   is redacted in a producer (the 04-04 rule).
   - The leak path: `handleAddFailure` names the failed block
     `addSubjectName(err, opts.rawSource)` (`orchestrators/marketplace/add.ts:562`).
     That function returns the typed source for every failure that has no
     derived name (`add.ts:331-346`).
   - The row reaches `resolveRows` through `notifyWithContext`,
     `emitContextCascade` (`shared/notify-context.ts:88`), and
     `presentCascade` (`shared/notification-present.ts:244-260`).
   - `resolveRows` has exactly three production callers, the three
     cascade-family present functions, so one expression covers every
     cascade subject.
2. **The not-added name is reachable with a credential.**
   - `marketplace remove` and `marketplace update` hand the typed positional
     to `resolveScopeOrNotifyNotAdded`, which only looks it up as a state key
     (`orchestrators/marketplace/shared.ts:552-571` and `:599-640`).
   - The plugin verbs split `<plugin>@<marketplace>` at the first `@`
     (`edge/handlers/plugin/shared.ts:29-39`). So
     `foo@https://alice:s3cret@host/x` names the marketplace
     `https://alice:s3cret@host/x`.
   - `emitMarketplaceNotAdded` (`orchestrators/plugin/shared.ts:1406-1440`)
     and the install flow (`orchestrators/plugin/install-flow.ts:1953-1958`)
     report that name verbatim.
3. **Plugin row names need it too: not every one is a validated safe name.**
   - Manifest names pass `assertSafeName` (`domain/plugin-resolver.ts:480`),
     and a typed `<plugin>@<marketplace>` ref keeps no `@` in its plugin half.
   - Reconcile's `parsePluginKey` (`orchestrators/reconcile/plan.ts:86-95`)
     is different. It splits a declared `enabledPlugins` key at its last `@`
     and, by design, validates neither half.
   - A hand-edited key `https://alice:s3cret@host/x@mp` therefore reaches
     `/claude:plugin pending` as a `(will install)` row named
     `https://alice:s3cret@host/x` (`orchestrators/reconcile/notify.ts:426-441`).
     With an undeclared marketplace, the same name reaches a
     `dangling reference` failed row (`notify.ts:210-222`).
   - The fix is one field at the same chokepoint, so it is not speculative.
4. **Not redacted, because they are unreachable (no code):** marketplace-info
   `name`, and plugin-info `marketplaceName` and `plugin.name`.
   - `marketplace info` and `plugin info` report a miss as
     marketplace-not-added (`orchestrators/marketplace/info.ts:122`,
     `orchestrators/plugin/info.ts:2866`).
   - Record names pass `assertSafeName` at `sourceCloneDir`
     (`persistence/locations.ts:321-328`) and in `plugin-resolver.ts:480`.
     That check rejects `/`, so a record name cannot hold `scheme://`
     userinfo.
5. **What this supersedes.** This plan supersedes 04-04's truth "Not
   redacted, by design: row, block, and marketplace names" and RESEARCH's
   "Redacting names or subjects" anti-pattern, for these three name sites
   only. The scp subject `git@github.com:foo/bar.git` still passes unchanged,
   because the userinfo pattern needs `scheme://`. An owner negative case pins
   it.
6. **A redacted name is display data.** The wire `name` and `id` of a
   redacted subject never key a record: a failed add has no record, a
   not-added name matched none, and a hand-edited key names an uninstalled
   plugin. Record-backed names pass through unchanged. Measured on
   2026-10-03: the current `redactCredentials` changes 0 of the 3143 baseline
   messages and no byte of `docs/output-catalog.md`.
7. **The new gate rows compose their text without `notify`.**
   - WR-05 routed the structured rows' text through production `notify`.
     That is why the corpus holds the 9 gate entries D-13 ledgered. A notify
     call from a new row would be a 10th entry that no one approved, and this
     run's byte lock is 3143 present, 0 extra.
   - So each new row reads its text from `formatEnvelopeArguments` over the
     grammar function that `notify`'s formatter uses for that presentation:
     `composeReconcileAppliedBody` for blocks (its block lines match the
     cascade formatter's) or `renderMarketplaceNotAdded`.
   - The dispatch formatter reads only the presentation (`notify` calls
     `presentNotification`, then `emitPresentation`), so a redacted
     presentation yields redacted text.
   - Moving these rows onto the `notify` path would take a D-13-style ledger
     of 3 entries, which is out of scope here.
8. **Residual, accepted (T-04-21).** Some names are cut before the userinfo
   `@`. A malformed key whose last `@` is the userinfo `@` is one example:
   `https://alice:s3cret@host/x` yields the plugin `https://alice:s3cret`. No
   pattern matches such a name. This is the same residual class as IN-06.
