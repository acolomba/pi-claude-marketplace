The commit protocol from 03-01 applies:

- Prettier first.
- The fallow audit.
- `SKIP=trufflehog pre-commit run --files <each path as its own argument>`
  until clean.
- `SKIP=trufflehog git commit -F <file>` with the two trailers.
- Never use `--no-verify`, amend, or `git add -A`.

Scope of the D-16 gate: it judges the dispatch module's notify and `deliver`
call forms. `dispatchInfoMessage` composes bodies for typed `NotificationMessage`
kinds (prune-empty, prune-committed-warning, reconcile-pending-empty), and
`foldAdvisories` folds advisories. Both are formatting of typed kinds inside
the presentation module, not raw surfaces. They reach the sink through
`formatEnvelopeArguments` and stay where they are; RAWS-01 through RAWS-05
cover the raw surfaces only.

House gate rules (03-PATTERNS.md "Architecture gate"):

- Every scan takes a `root`; real-tree cases pass `REPO_ROOT`.
- Targets come only from `tests/architecture/gate-targets.ts`. A gate file
  spells no production path and assembles none from segments (D-07-05,
  D-07-06).
- Every gate asserts a non-vacuity count and deep-compares what it visited
  (D-07-03).
- Controls use `withTempRoot`, `materializeTargets`, `plantOffender`, and
  `plantBenignNearMiss` from `tests/architecture/temp-root-control.ts`, never
  inline `mkdtemp`.
- Offender cases are one data-driven `for` loop per file, with one `test()` per
  row. Each row calls the shared `assertPlantedCopyRejects` that Task 1 adds to
  `temp-root-control.ts`. Two gates repeating the same
  `withTempRoot`, `materializeTargets`, `plantOffender`, `assert.rejects`
  sequence would be a normalized-token clone (fallow `duplicates.threshold`).
- Run `npx fallow dupes` before each commit. If it still reports a clone
  between the new benign or near-miss cases, extract that sequence into
  `temp-root-control.ts` the same way.
- `fallow health` limits (cognitive 15, unit size 60 lines) apply to test files
  too, so keep each helper short.
