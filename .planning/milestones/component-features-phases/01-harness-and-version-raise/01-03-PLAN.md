<objective>
Lead the harness with one end-to-end slice: a scenario starts its own Pi with
the scripted model, installs a plugin with a skill, invokes the skill, and
compares the whole message Pi sent the model. Then add the companions to the
same profile and make the profile hermetic.

Decisions implemented: D-CF1-15 (one profile Pi per scenario that asks for one,
stopped with its process group in the scenario's release), D-CF1-17 for the
scripted model (file-backed script, step index from the call log, no fallback
reply, unused steps fail), D-CF1-07 for the trusted default (a persisted
`trust.json` entry; the untrusted `Given` and its scenario are plan 01-07),
D-CF1-08 (`features/skill/`).

Purpose: every wave-3 seed plan writes its scenarios against the world methods,
the stand-in log convention, and the shared steps this plan creates; a component
phase never edits these files after Phase 1.

Output: the extended RPC driver and process, the scripted model, the turn
records, the companion resolver, the profile world, the shared `model`,
`companion`, and prompt steps, and the skill seed.

Deviation from the roadmap table, recorded here: the CI peer install is covered
by `npm run test:cucumber`, which plan 01-01 changed to install the peers first,
so this plan does not edit `.github/workflows/ci.yml` (plan 01-09 shards it);
the generic plugin file step moved to plan 01-11, its only Phase 1 user; and
`features/lib/run-tokens.ts` needs no change for the skill seed.
</objective>
