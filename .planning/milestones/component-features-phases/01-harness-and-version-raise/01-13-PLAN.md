Build Claude Code's dynamic context injection for user-invoked skills and
commands as two pieces: a pure domain parser and splicer that takes the command
runner as a port, and one new platform module that spawns Bash or PowerShell.
Phases 2 and 3 compose them after argument substitution.

Decisions implemented: D-CF1-02 (run each `` !`cmd` `` and ```` ```! ```` block
after argument substitution and before the content reaches the model; a failure
aborts with upstream's message shape; `shell: bash` and `shell: powershell`
select the shell, with `shell: powershell` running Bash on Linux and macOS
unless `CLAUDE_CODE_USE_POWERSHELL_TOOL` is set, as DUBIOUS-CHOICES DC-13 item 2
accepted; Pi has no permission modes, so every command runs as in Claude Code's
`bypassPermissions` mode and `allowed-tools` does not gate it). D-CF1-03 limits
it to user-invoked skills and commands; the module documentation says so.

Purpose: the spawn needs its own sanctioned `child_process` site with the four
architecture gates updated together, and both component phases must splice
identically.

Output: `domain/context-injection.ts`, `platform/prompt-shell.ts`, their paired
tests, and the rule-pack, gate-target, and whitelist updates. Plan 01-10 already
registered both modules in `.fallowrc.json`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| installed plugin file -> local shell | a plugin's skill or command body names commands that run on the user's machine when the user invokes it |
| user-typed arguments -> command text | arguments are substituted before injection, so they can appear inside a `!` command |
| command output -> model input | the output replaces the pattern in what the model receives |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-21 | Elevation of privilege | `platform/prompt-shell.ts` running plugin commands | high | accept | Licensed by D-CF1-02 (Pi has no permission modes; upstream `bypassPermissions` behavior): the commands come from a plugin the user installed, the same trust as its hooks, which already run any command without being invoked, and they run only when the user invokes the skill or command (D-CF1-03 keeps model-invoked skills out). Recorded in DUBIOUS-CHOICES DC-04 for the user's review |
| T-01-22 | Tampering | arguments inside `!` commands | high | mitigate | Upstream parity: argument values pass `xM` in the argument core, so they cannot open a new `!` pattern; the user's own input runs with the user's own privilege. Canon injection review is referred to `/gsd-secure-phase` |
| T-01-23 | Denial of service | a runaway command | medium | mitigate | 120 s timeout and abort stop the whole process group with SIGTERM then SIGKILL; the run never rejects (Task 3) |
| T-01-24 | Information disclosure | failure output on stdout | medium | mitigate | The domain throws a typed error and writes nothing; the edge reports it through the notify chokepoint; the `no-stdio` rule bans direct writes (Tasks 1-2) |
| T-01-25 | Tampering | widening the D-21 whitelist | medium | mitigate | The rule pack, `SHELL_OUT_EXEMPT_TARGETS`, and the exactly-five assertion change together; `npm run fallow` and the architecture test prove no other site imports `node:child_process` (Task 1) |
| T-01-SC | Tampering | package installs | low | accept | This plan installs no package |
</threat_model>
