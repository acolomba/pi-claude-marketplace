<objective>
Register a GitLab OAuth Device Flow provider descriptor so `gitlab.com` marketplaces
and plugins authenticate through RFC-8628 Device Flow, exactly as `github.com` does.

Purpose: today `findProviderForHost("gitlab.com")` returns `undefined`, so
`buildAuthForHost` yields no bundle and a private gitlab.com clone fails clean with
"no auth provider is registered for gitlab.com". GitLab's Device Authorization Grant
(GA since GitLab 17.9, live on gitlab.com) is byte-identical to GitHub's on field
names, error codes and request bodies, so the existing engine already supports it —
only the descriptor is missing.

Output: `GITLAB_PROVIDER` exported from `domain/auth-registry.ts` and registered in
`PROVIDERS`, plus test coverage in `tests/domain/auth-registry.test.ts`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local process -> gitlab.com OAuth endpoints | Device-code and token requests leave the machine; the response carries a bearer token |
| Device Flow engine -> git credential helper | The minted access token is handed to `credentialOps.approve` and persisted by the OS credential store |
| descriptor `hostMatch` -> clone host | Decides WHICH remote host an OAuth flow (and therefore a token) is bound to |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-a7m-01 | Spoofing | `GITLAB_PROVIDER.hostMatch` | high | mitigate | Exact equality `host === "gitlab.com"`, never a suffix/`endsWith` match — a suffix match would claim `evil-gitlab.com` and `gitlab.com.attacker.net` and bind a real token to a hostile remote. Task 2 pins the rejection of a subdomain, a self-managed host and a ported host. |
| T-a7m-02 | Information disclosure | committed `clientId` literal | low | accept | RFC 8628 device flow has no `client_secret`; the Application ID is public by design. Same disposition already recorded for `GITHUB_PROVIDER` under D-32-03. |
| T-a7m-03 | Information disclosure | `credentialFrom` / descriptor file | high | mitigate | No token field is interpolated into any `Error` or `notifyFn` in `auth-registry.ts` (AUTH-09). Already gated: `tests/architecture/no-credential-leak.test.ts` `PROVIDER_FILES` names this file, and Task 2 re-runs that gate. |
| T-a7m-04 | Elevation of privilege | requested OAuth scope | medium | mitigate | `read_repository` only — least privilege for a clone-only client, deliberately narrower than GitHub's `repo`. Pinned by the Task 2 literals test so a widening cannot land silently. |
| T-a7m-05 | Spoofing | cross-host credential binding | medium | accept | Unchanged by this plan: `buildAuthForHost` returns `undefined` for unclaimed hosts (PROV-04, T-79-04) and keys `credentialOps` on the host. Adding a descriptor does not widen that surface. |

No package-manager installs are introduced by this plan, so no `T-a7m-SC` supply-chain
checkpoint applies.
</threat_model>
