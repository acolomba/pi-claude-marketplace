# Quick Task 260807-q0v: Amend v1.18 planning docs per two-review validation findings

Two independent reviews of the v1.18 Manifest-Independent Installed Plugin Info
requirements and roadmap were validated against the codebase. Every finding below
was confirmed with file:line evidence before being written down. This task lands
the documentation corrections and records the three decisions that remain open.

Doc-only. No source changes. Branch `features/manifest-independent-plugin-info`,
sequential mode in the existing worktree (worktree isolation is unsafe here: the
quick workflow forks from `origin/HEAD`, which is `main`, and `main` does not
contain the v1.18 planning docs at all).

## Confirmed findings driving these edits

1. Eight requirements already describe current behavior: INV-02, INV-03, INV-04,
   BOUND-01, BOUND-02, LIFE-04, LIFE-05, LIFE-06. `list` already unions
   installation records with manifest entries (`list.ts:737-762`), `uninstall`
   imports no manifest or resolver module, and update/autoupdate already emit
   `(skipped) {not in manifest}` (`update.ts:1042`).
2. INV-02's premise is false. Partial records are classified from
   `compatibility.unsupported` alone (`plugin-state-classifier.ts:143`), which is
   manifest-independent; they are neither flattened nor omitted today.
3. INV-01 reverses a deliberate decision. `list.messaging.ts:97-106` hard-codes
   `undefined` for the installed arm's reasons, with the rationale at lines 90-92.
4. The cross-scope orphan-fold path discards the manifest load error
   (`list.ts:977` destructures only `{ manifest }`, unlike `list.ts:853`). A naive
   missing-entry check would stamp `{not in manifest}` on folded rows whenever the
   manifest was merely unreadable.
5. INFO-10 is ambiguous. `info` derives `(partially-installed)` from the live
   resolver on the path-source arm (`info.ts:1279`) and from the persisted record
   on other arms (`info.ts:965`).
6. INFO-11 name fidelity is unaddressed. `resources.*` holds Pi-generated names
   (`domain/name.ts:64,86,113`); `info` today renders raw source names
   (`info.ts:276-286`). MCP names match; the other three kinds do not.
7. INFO-11 hook sourcing needs caveats: `resources.hooks` holds only a slug, the
   materialized `hooks.json` holds only the supported filtered subset (D-71-03),
   and the read needs the `assertPathInside` guard modeled at
   `event-router.ts:628-641`.
8. INFO-12 is currently free by construction, not guarded — the early return at
   `info.ts:720` precedes every fetch-capable builder.
9. The hook sorting contradiction is in the design doc (line 85), not
   REQUIREMENTS.md. Hooks preserve declaration order deliberately
   (`info.ts:358-362`), pinned byte-exact at `info.test.ts:1615`.
10. PRD PL-6 (`docs/prd/…-prd.md:357`) is stale, not authoritative. Catalog, code,
    and tests agree on a bare `(failed)` header with `plugins: []`.
11. `isRecordedButDisabled` is `compatibility.installable && !record.enabled`
    (`reconcile/plan.ts:272-276`), so a disabled *partial* record is unrecognized.
    This is a live defect with fallout across enable/disable/reconcile/update/info
    and is being scoped OUT of v1.18.
