<objective>
Give PROV-03 a code path. There is none today: installing by name a plugin that is
already recorded throws the already-installed refusal, and that throw sits on a
non-mutating arm whose caller never saves — so a promotion written there would vanish.

This plan adds the promotion and reports it honestly, which means amending the pinned
output catalog. D-04-07 sanctions that expansion deliberately and enumerates every
surface it must touch. A token that lands in fewer than all of them fails a gate.

Purpose: PROV-03 is the second half of the one-way ratchet. Without it a plugin pulled
in as a dependency can never become a plugin the user owns, and Phase 5's prune would
eventually remove something the user had explicitly asked for.
Output: one new closed-set reason, a promotion on the mutating arm, and the nine
catalog surfaces moved in one commit.
</objective>

<assumption_delta_decision>
**Noun that is now primary:** the install record's `provenance` — a record states how
the plugin got here, and "the user asked for it by name" is one variant.

**Decision: promote.** This plan closes the ratchet. With it, the two variants are not
two static kinds but two states of one generalized thing, with a defined and one-way
transition between them: a dependency can become a direct install, and a direct install
never silently becomes a dependency. That transition is what makes the generalized noun
real rather than a label. The add-alongside shape here would have been a second record
or a separate "explicitly requested" registry beside the install record; instead the
promotion flips one field on the one record and touches nothing else.

**Accepted debt, named:** the reason set gains a member rather than the status
vocabulary gaining one, because D-04-07 enumerates the surfaces it sanctions and the
status vocabulary is not among them. A promotion therefore rides an existing status
token with a reason brace that carries the real news. What would force a later promote
of the status itself: a second non-install outcome that also needs to say "the record
changed but nothing was materialized". If that arrives, the pair should become a status
of its own rather than a second reason on a borrowed one.
</assumption_delta_decision>
