<objective>
Teach reconcile to keep a cascade-installed dependency because its record says so.

This is step 2 of D-04-04's three-step contract, and the single smallest production
change in the phase: one bound variable and one `continue`. Its proof, however, is
the phase's most easily faked — a test that only shows the dependency is kept passes
just as well against an exemption that keeps everything.

Purpose: this clause is what replaces the config write that wave 5 retires. It must
exist, and be proven correct in both directions, before that write can be removed.
Output: the exemption, a positive case, and a negative control built in the SAME
hand-built state so an over-broad exemption is visible as a missing uninstall entry.
</objective>

**Noun that is now primary:** the install record's `provenance` — a record states how
the plugin got here, and "the user asked for it by name" is one variant.

**Decision: promote.** This plan is where the promoted noun acquires its first
READER. Before it, provenance was written but consulted by nobody; after it, reconcile
asks a record which kind it is rather than assuming there is only one kind. The
add-alongside shape would have been a second bucket or a separate dependency registry
beside the existing plugin records — D-04-05 explicitly refuses that, keeping exactly
one exemption inside the one existing bucket.
