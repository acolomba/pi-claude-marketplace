<objective>
Retire Phase 3's config write, so the desired-state configuration names only what the
user asked for, and prove that a cascade dependency still survives a reload.

This is step 3 of D-04-04's three-step contract, and it is the step the contract is
about. The config write is what has been protecting cascade dependencies since Phase 3;
this plan removes it and hands that job to the reconcile exemption wave 4 landed. It
cannot come earlier, and it must not come as one commit with the exemption, or neither
can be verified independently.

Purpose: `--prune` (Phase 5) reads the separation this restores — what the user asked
for versus what was pulled in to satisfy it.
Output: both write arms removed with their now-unused parameters, the three tests that
assert the dependency IS declared inverted rather than deleted, the CR-01 reload
survival proven through `applyReconcile`, and the three prose statements of the retired
behavior rewritten.
</objective>

<assumption_delta_decision>
**Noun that is now primary:** the install record's `provenance` — a record states how
the plugin got here, and "the user asked for it by name" is one variant.

**Decision: promote.** This plan is the promote's decisive move. The old carrier of
"the user wants this" — a config entry written for every cascade member — is REMOVED
rather than kept beside the new field. Keeping both would have been the
add-alongside shape: two sources of the same fact, free to disagree, with the config
silently outranking the record because it is what reconcile reads first. Retiring it
is what makes provenance the primary representation rather than a second opinion.

Accepted residue, stated rather than hidden: a development tree that installed
dependencies between wave 1 and this wave ends the phase with config entries that
violate the new invariant on that machine. They are inert — reconcile reads declared
plus recorded plus enabled as steady state — and no cleanup is in scope. Say so in the
summary rather than discovering it during UAT.
</assumption_delta_decision>
