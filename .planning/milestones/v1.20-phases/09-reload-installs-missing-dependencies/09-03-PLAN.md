<objective>
Make `/reload` install what is missing. A new orchestrated-only entry point
beside `installPlugin` runs the install cascade rooted at the missing
dependency -- locked transaction, catalog lookup, marketplace resolution,
ledger options with `provenance: "dependency"` for every member, hooks
hydration -- and nothing the standalone verb does for a plugin the user typed.
`apply.ts` drives it between the config installs and the toggles, only when the
host said `reload`, and re-plans the toggles from a fresh read pass when
something landed, so the dependent it satisfied stays up in the same reload.
A failure reports on the dependency's own row with its cause and leaves the
dependent to the LOAD-01 check.

Purpose: MISS-01 and MISS-02 end to end. Plans 09-01 and 09-02 built the
bucket, the token and the cascade inputs; this plan is the wiring that turns
them into behavior a user sees on `/reload`.

Output: `createInstallMissingDependency`, `createDependencyInstallOperation`,
`applyDependencyInstalls`, `refreshTogglePlan`, `applyToggleSteps`,
`ApplyReconcileOptions.reason`, the `index.ts` thread, and the apply-side tests.
</objective>

**Entry point (`install-flow.ts`).** Add `createInstallMissingDependency(transaction, hooksRouting, completionCache)`
beside `createInstallPlugin`, returning
`(opts: InstallMissingDependencyOptions) => Promise<InstallMissingDependencyOutcome>`
over a module-private `installMissingDependencyWithTransaction`. It is
orchestrated-only: it never notifies and never re-throws, the same contract
`installPlugin` documents, so `apply.ts` reads its outcome without a guard.
Inside `transaction.withLockedStateTransaction(locations, ...)`:
1. If `tx.state.marketplaces[marketplace]?.plugins[plugin]` already exists,
   return the `already-recorded` arm (no save): a config install's cascade
   earlier in the same pass materialized it (D-09-06), or it is a disabled
   record this path leaves alone (D-09-04). The outcome is `{ status: "skipped" }`.
2. Call `runInstallCascade` with the SAME `lookup` (`lookupCascadeDependencies`),
   `marketplaceRecordFor` (`resolveInstallMarketplaceSource`), `installedKeys`
   (`collectInstalledKeys`), `knownMarketplaces` (`collectInstallReachableMarketplaces`),
   `capture`, `transaction`, `tagProbe` and `marketplaceTagProbe` arguments
   `installPluginWithTransaction` passes, PLUS `rootRanges: opts.ranges` and
   `treatDisabledAsWall: true` (plan 09-02's inputs; D-09-05 and D-09-04).
   `ledgerOptionsFor` calls `buildInstallLedgerOptions` with
   `provenance: "dependency"` UNCONDITIONALLY (root included -- D-04-01: the
   caller decides; do not copy the `isRoot ? "explicit" : "dependency"`
   ternary), `sourcePin` from `member.pin?.oid`, `pinVersion` from
   `member.pin?.version`, and no `pinVersionOverride`. Narrow
   `buildInstallLedgerOptions`'s first parameter to the `Pick` of the fields it
   reads (`ctx`, `mapModel`, `partial`, `cloneCacheSeam`, `credentialOps`,
   `deviceFlowHttp`, `authMemo`) so both entry points share one assembly.
3. `unwrapCascade(cascade, capture, rootKey, cascadeFailure)` exactly as the
   install arm does. When it returns `undefined` (marketplace absent in both
   scopes), set `cascadeFailure.subject` to a closure subject
   `{ ok: false, reason: "marketplace-not-added", key: rootKey, marketplace, requiredBy: opts.requiredBy }`
   and throw `cascadeFailureCause(subject, rootKey)`: on this path the root IS
   a dependency, so the truthful report is the walk's own not-added message
   (D-03-08: nothing adds or clones a marketplace to satisfy a declaration),
   which D-09-10 names as a cause-line example. `requiredBy` is what the
   bucket entry carries it for.
4. `await tx.save()`, then `hydrateInstalledHooks` over every member (no
   `landedDisabled` filter -- nothing lands disabled here), then return the
   `installed` arm carrying `installed.root` and `installed.members`.

no `resolveInstallDeclaredEnabled`, no disable cascade, no
