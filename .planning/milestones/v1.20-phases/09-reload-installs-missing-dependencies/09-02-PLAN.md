<objective>
Give the install cascade the two inputs the reload path needs and nothing else:
a root-range input so the missing dependency -- this cascade's root -- is pinned
by every declarer's constraint exactly as a constrained member is, and a
disabled-as-wall flag so a dependency that is installed but disabled stops the
walk instead of being re-enabled through it.

Purpose: D-09-05's root range and D-09-04's wall are both cascade-level inputs
(research R2: `liveInstalledKeys` is applied unconditionally today, so no
caller-side set can make a disabled record a wall). Landing them in their own
wave-1 plan keeps plan 09-03's entry point a pure consumer and lets the
standalone install path prove its own behavior is unchanged before anything
calls the new options.

Output: `InstallCascadeOptions.rootRanges`, `InstallCascadeOptions.treatDisabledAsWall`,
the `effectiveRanges` helper, and their cascade-level tests.
</objective>
