    `## Removing a plugin other plugins need` — `uninstall` refuses to remove a plugin
    while another installed plugin in the same scope declares it, a disabled one
    included; the row reads `{dependents remain}` and the `cause:` line names each
    dependent as `name@marketplace`; the remedy is to uninstall the dependents first, or
    to run `/claude:plugin uninstall <dependent>@<marketplace> --prune` (then the plugin
    goes as an orphan); a reload that drops the plugin from the configuration is refused
    the same way and repeats the row on every reload until the configuration is fixed;
    this extension applies to `uninstall` the refusal upstream documents for `disable`
    (A-14). Then the fail-closed rule: if the declarations of ANY other installed plugin
    in the scope cannot be read (its marketplace no longer lists it, its manifest is
    unreadable, or its declaration is not usable), the uninstall is refused, the brace
    carries that plugin's read-failure reason, and the `cause:` line names which plugin
    could not be read; the remedy is `/claude:plugin marketplace update <name>` to
    restore its manifest, or `/claude:plugin marketplace remove <name>` if the record is
    stale. State the two-stale-records consequence plainly: two plugins in one scope
    that are both missing from their marketplace manifests refuse each other's
    uninstall, and `marketplace remove` is the exit.

    `## Pruning dependencies nothing needs` — `uninstall <plugin> --prune` also removes
    every plugin in the same scope that arrived as another plugin's dependency and that
    no remaining installed plugin declares, including dependencies orphaned earlier and
    dependencies of the dependencies it removes; it never removes a plugin you installed
    by name (a promoted dependency counts as installed by name), never one a remaining
    plugin — enabled or disabled — still declares, and never a plugin in the other scope;
    each removed dependency shows its own `(uninstalled) {dependency pruned}` row under
    its marketplace; `--keep-data` keeps the data directory of every plugin the command
    removes and the rows read `{dependency pruned, data kept}`; when nothing qualifies
    the command prints the plain uninstall row; a reload never prunes — an orphaned
    dependency stays installed until you run `--prune`; if one removed dependency fails,
    the others stay removed and its row shows the failure. Cross-reference `## Where a
    dependency lands` for why a reload keeps the record.
