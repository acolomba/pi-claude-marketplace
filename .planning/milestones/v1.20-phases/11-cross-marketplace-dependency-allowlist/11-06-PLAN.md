## Policy interpretation and error precedence

This is the Claude Code 2.1.267 interpretation already authorized by the planning brief and RESEARCH.md, not an open product decision. Upstream's resolveMissingDependencies groups original sources and permits the missing target when any source is same-marketplace or lists it.

Within the locked missing-dependency operation, preserve this order: already-recorded skip; target-source availability; original-source authorization; load B's own policy and run B's cascade. If the target marketplace is absent in both reachable scopes, preserve the existing marketplace-not-added outcome. Missing or unreadable original policies cannot grant permission. A readable same-marketplace declarer grants permission without an allowlist requirement. Test same-marketplace candidates before foreign-policy reads so their ordering cannot make the answer depend on an unrelated policy file. If no source authorizes and a present policy could not be validated/read, preserve its typed read/manifest failure rather than replacing malformed input with an empty list; a valid later authorizer still satisfies the OR rule.

requiredBy remains the first eligible declaring key for diagnostics. An original-edge refusal uses that key and its marketplace for the displayed policy remedy. When B's own cascade refuses C, its structured failure names B as policy root and the actual immediate declarer of C.

## Artifacts this phase produces

- PlannedDependencyInstall.declarers: readonly string[], populated in verdict order without duplicates.
- InstallMissingDependencyOptions.declarers?: readonly string[]; absence means the existing singular requiredBy caller supplied one declarer. The reconcile caller always passes the complete list.
- InstallMissingDependencyOutcome failed arm's optional reason?: "cross-marketplace", consumed by applyDependencyInstalls. This avoids reclassifying a policy error into generic dependency failed.
- Private authorizeMissingDependency helper in install-flow.ts, consuming the eligible keys and scope-aware cached manifest selection; no new module or error class.
- Internal grouped-bucket declarers collection; no persistence schema field and no config field.
